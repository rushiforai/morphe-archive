# Local Downloads

Patch ID: `local-downloads`.

This optional Playback patch adds direct progressive movie and episode downloads through Nuvio's existing manual source picker. It is independent of `local-media`: either patch may be enabled alone. Both use the neutral `playback.local_storage.path` preference through generic storage-path infrastructure, so there is one shared location without either patch owning the setting.

Downloads and automatic local playback default On when their preferences are absent; stored On or Off choices remain authoritative. `Maximum usable selected storage` defaults to 80% and uses the same native slider behavior as Nuvio's Layout controls. No permission screen appears at startup or when the switch is enabled. The first download attempt requests access only if no selected path or direct grant exists; denial leaves Downloads On, reports `Storage access required`, and the next Download action retries. The slider positions are 1%, then 5% increments through 100%. The row and every download-progress popup show the volume containing `Local storage path` as one-decimal used/total GB with the percentage full. Internal storage, removable SD cards and USB drives therefore report their own capacity. A disconnected selected drive reports unavailable and blocks a download with reconnection guidance; it never silently falls back to internal storage.

Playback shows `Local Downloads` before `Local Media`, followed by one unsectioned `Local storage path` row at the bottom. The path row is installed whenever either storage-consuming patch is installed and is greyed and unfocusable only while both feature toggles are off.

When the app has direct storage access, `Local storage path` opens the same patch-owned, TV-native D-pad folder browser on every device. Its Storage devices page enumerates Android's mounted storage volumes and labels removable media with Android's device description. Browsing a mounted drive does not require its top-level directory to be writable. While Local Downloads is enabled, the chosen folder must pass an actual temporary create, write, read-back verification and delete probe before it is saved. If raw access fails, the app asks Android for persisted access to that folder and probes the granted document tree through the same create/write/read/delete sequence. If Android has no usable permission picker or the user cancels it, removable storage offers an explicit `Use private app folder on this drive` fallback; its confirmation warns that Android deletes that folder when the app is uninstalled. No fallback is selected silently. A failed probe remains on the picker with a visible diagnostic code. A read-only Local Media installation retains read-only folder selection. Every Download action revalidates a saved path, so revoked access, a read-only remount, or a missing folder returns to write-capable folder selection before any source transfer starts.

Completed files are indexed by exact catalogue content/video identity. Signed source URLs and headers are held only for the active foreground transfer and are never persisted. Partial files use a `.partial` suffix and are removed on cancellation or failure.

Holding a source in either picker opens a patch-owned `Play` / `Download` card. A short press in Nuvio's ordinary picker remains the unchanged Play action, while a short press in a picker opened through `Download to storage` remains Download. A held-source choice overrides only that source: Download from a Play picker returns later short presses to Play even after cancellation or rejection, and Play from a Download picker bypasses download interception once without changing later short presses. The index stores a privacy-safe source fingerprint made from stable addon and source fields with URL query strings and fragments removed. Downloading the same logical movie or exact series episode again shows `This title was already downloaded from the same source.` with only `Back` when that fingerprint matches. A different fingerprint shows `This title was already downloaded from a different source.` with `Download and overwrite` and `Back`. Confirmed overwrite removes only that indexed title or episode and its patch-owned files before resolving the replacement source; another episode is never treated as a duplicate.

FAT32 volumes use a rolling 3,750,000,000-byte writer. A transfer starts in a readable bundle folder at the same location where an ordinary file belongs: movies use `<movie title>/<original filename stem> [short-id]/`, while episodes use `<show title> - Season N/SnnEnn - <episode title> [short-id]/`. If finalisation finds exactly one part, raw filesystems move and rename it to the original `.mp4`, `.mkv`, or other video filename and remove the temporary bundle; capable document providers do the same. Providers that cannot move documents safely retain a valid one-part bundle. Multi-part downloads keep descriptively named parts, a `<title> - playback manifest.json`, and subtitle sidecars together in that bundle. The short ID prevents collisions without obscuring the filename. Filesystem-unknown removable and document-tree storage uses the same conservative writer because Android does not expose a reliable public filesystem-type flag for every provider. Nuvio receives one read-only seekable virtual URI whose random-access reads are mapped across the ordered parts, so container parsing, seeking, embedded subtitles and external subtitle sidecars retain one continuous playback timeline. Every part handle is opened before the descriptor is exposed to the player, avoiding a storage-provider open operation at a playback boundary. The manifest projects the bundle as the same logical file that an ordinary download would create. The private download index, Settings > Downloads and Library > Storage expose the original filename and combined size as one item. Deleting an item or season removes only its corresponding files or bundles and prunes empty folders. Legacy flat, UUID-only and centralized `.morphe-segments` bundles remain readable and deletable.

The final `Downloads` row opens a scrollable list of entries owned by this patch. Rows have TV-sized separation and a high-contrast focus outline. Pressing an entry plays it immediately; holding it opens one native two-button `Play local file` / `Delete local file` action card. Duplicate TV long-press callbacks are coalesced, so one Back press always dismisses the popup. Individual deletion removes the indexed video and its downloaded sidecars; `Delete all downloads` iterates only the index and never removes files copied manually by the user. The settings count and list reconcile against readable video files whenever they open or resume, so deletion through Library > Storage or an external file manager disappears immediately. An unreadable entry remains privately indexed so a temporarily disconnected USB drive can recover when reconnected.

Supported sources are direct HTTP(S) progressive files. Torrent, YouTube, HLS and DASH selections are deliberately rejected because copying those transports as one movie file would produce invalid or incomplete media.

Movie downloads use a sanitized title folder. Series episodes use `Title - Season n`, such as `Silo - Season 3`. Addon subtitles are retrieved after the video succeeds and filtered to Nuvio's preferred primary and secondary subtitle languages. Ordinary downloads save them beside the video; segmented downloads save them inside the same hidden bundle. Their logical names remain `<video-base>.<language>[.<n>].<extension>`. Subtitle failures do not discard a completed video.

Downloaded episodes carry a circular arrow-down badge in the top-right corner, mirrored against Nuvio's watched tick inset. Every episode options variant, including the resumed-playback menu containing `Start from beginning`, receives the download/local-file actions. Long-pressing a downloaded movie or episode replaces the download action with `Play local file` and `Delete local file`. Confirmed deletion removes the indexed video and downloaded subtitle sidecars, removes an empty download folder, and refreshes visible badges immediately. Only an explicit `Download to storage` picker keeps Download mode active across repeated source choices; one-source actions never rewrite the picker's original mode.

While an exact movie or episode transfer is active, every place that would normally offer `Download to storage` instead offers `Download in progress...`. Selecting it restores the existing progress popup after Hide without starting a second transfer. Other episodes and movies retain their normal download action.

When downloads are enabled, movie detail pages also place a native-sized arrow-down action immediately to the right of Watched. The undownloaded state uses Nuvio's dark action background and white icon; the downloaded state uses the same selected white background and dark icon as Watched. The native action control supplies the same D-pad focus enlargement as its neighbours. Pressing it opens a patch-owned TV popup: an undownloaded movie offers `Download to storage` and hands off to the existing source picker, an actively downloading movie offers `Download in progress...` and restores its progress popup, and a downloaded movie offers `Play local file` and `Delete local file`. Movie detail lookup uses the stable catalogue content id instead of a source-specific video id, with a title fallback for older indexed movie downloads.

Episode transfer notifications and progress, failure, cancellation and completion popups identify the exact item as `Title · SnnEnn`, for example `House of the Dragon · S02E01`. Movie transfers continue to use the movie title alone.
