# Local Media porting notes

NuvioTV 0.8.7-beta already builds playback data sources with Media3 `DefaultDataSource.Factory`, so persisted `content://` document URIs require no replacement transport. The patch adds same-basename subtitle configurations at the existing `PlayerMediaSourceFactory.createMediaSource` boundary and passes the content URI through the native Player route.

The Library mode is a private Kotlin enum with Saved and Cloud values. The patch adds a third enum constant and rebuilds the generated values and entries arrays. It intercepts the third value before Nuvio's exhaustive two-value label and selection branches, then contributes Storage search, refresh and grid content directly to the existing Library composition. Patch-owned runtime state remains isolated behind generic bytecode hooks; playback continues through the native navigation graph and player.

The row fingerprint uses enum-entry iteration and the TV Button signature. The label and selection fingerprints use their Kotlin function interfaces and internal structural calls. The navigation-host fingerprint uses the route controller parameter and host-builder callbacks. The media-source fingerprint uses its stable parameter model, diagnostic parameter names and HLS/DASH constants. None relies on an obfuscated owner or method name.

The Storage label, search, card and dialog renderers call the exact 0.8.7-beta obfuscated Compose bridges discovered from the target during patching. Runtime-only helpers that R8 renames independently are selected by verified signatures: the mutable-state factory is the static non-void `(Object)` method on `e1.j`, and the full-grid-span packer is the static `(int) -> long` method on the supported native owner. Storage search invokes the complete native Cloud search control; its patch hook replaces only the resolved placeholder string before the native label renderer receives it. This keeps the native typography, colors, focus state and typed-text behavior intact. Those bridges are deliberately isolated to this patch and covered by exact-version compatibility; a later Nuvio release remains unsupported until the bridges, fingerprints and runtime test matrix pass again.

The default tree is `primary:Movies/Nuvio`. Storage consent is deliberately contextual: neither process initialization nor the default-On switch opens a system screen. Entering Library > Storage without a selected path or direct grant launches the patch-owned permission proxy, and the access-required state owns a retry action. When the app has the explicit all-files grant required by the default-folder fallback, picker dispatch starts the patch-owned D-pad browser directly so every TV uses a consistent remote-friendly surface. That browser enumerates mounted volumes through Android `StorageManager`, with external-files and `/storage` scans only as compatibility fallbacks, validates the canonical selected path, persists it as a patch-owned `file://` location, and invalidates any in-flight scan before the Library redraws. Without direct access, the Storage Access Framework remains available. The manifest must retain an `OPEN_DOCUMENT_TREE` query because Android 11 package visibility otherwise hides installed third-party handlers from runtime discovery; dispatch tries known DocumentsUI components and then every visible matching activity while rejecting Android TV's framework stub. The all-files fallback creates and uses the raw `Movies/Nuvio` directory after first-use consent is granted.

AnExplorer 6.0.6 is not advertised to Android as an `OPEN_DOCUMENT_TREE` handler even though it supports `OPEN_DOCUMENT`, `CREATE_DOCUMENT`, and `GET_CONTENT`. Forcing its exported `DocumentsActivity` into tree mode is not a valid workaround: that mode filters every available root and renders `No items`. The patch therefore uses AnExplorer only when a version genuinely registers the tree contract; current TV builds fall through to the built-in picker.

Local playback routes leave `contentId` empty while retaining a patch-local `videoId`. The patch records the matching full-screen player only after it reaches Ready, listens for that same player's Ended state, pops the player once, and restores the captured Storage mode selection. This avoids both Nuvio's catalogue-details exit path and false exits caused by unrelated player objects. The root grid is deliberately shallow, while playable-file counting and a selected folder's file dialog recurse through descendants. Metadata scraping, poster generation and offline downloads remain out of scope.
