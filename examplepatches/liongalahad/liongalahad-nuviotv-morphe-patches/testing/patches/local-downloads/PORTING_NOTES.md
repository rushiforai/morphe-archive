# Porting notes

Target: NuvioTV `0.8.11-beta`. The older phase-two prompt described a single `0.8.2` patch dependent on Local Media; the current requirement supersedes that architecture.

The detail-hero and Continue Watching fingerprints wrap the native composable content before NuvioDialog receives it. NuvioTV 0.8.11 keeps episode options in a native action list and adds the overlay-style argument; the fingerprint appends patch actions immediately before the list is finalized while retaining Nuvio's native action renderer. The resumed-episode path uses a separate Compose dialog; its native defaultable TV Button and Text owners are supplied by structural fingerprints rather than obsolete optimized class names.

The stream-route hook captures exact content/video/season/episode identity and may replace a normal route with a completed local player route. The StreamScreen hook wraps both resolved callbacks so the normal source picker and debrid resolution remain Nuvio-owned while a pending download consumes the final direct source.

`SourceCardFingerprint` wraps each source row's click and prepares only that row for the source TV Button. `NativeSourceTvButtonFingerprint` adds a Compose preview-key modifier. Short clicks continue through Nuvio's original callback; a held TV select key suppresses its release click and opens the patch-owned Play/Download activity in either picker mode. Runtime state distinguishes persistent mode entered through `Download to storage` from a one-source held action: held Download in a Play picker clears download interception as soon as that source is consumed, while held Play bypasses interception once and preserves an explicit Download picker. The same wrapper captures a stable, query-free source fingerprint when either the explicit download picker or the ordinary-picker Download action resolves a source. Duplicate decisions compare catalogue content id plus exact season/episode before comparing the stored source fingerprint; legacy entries without a fingerprint are conservatively treated as a different source.

Large FAT32-compatible downloads use the neutral `storage.segmented` manifest and provider. New transfers begin in a readable bundle inside the same movie-title or `Show - Season n` folder used by ordinary downloads. One-part results collapse to the original video file when the filesystem or document provider supports a safe same-volume move; unsupported document providers retain a valid one-part bundle. Multi-part results keep their ordered parts, descriptive playback manifest and subtitle sidecars in the bundle. The manifest's optional neutral logical-parent field makes the bundle indistinguishable from an ordinary file in Library. The Local Downloads compartment owns the human naming policy, filesystem classification, 3,750,000,000-byte rolling policy, collapse decision, index fields and download cleanup; the shared component only validates, exposes and deletes ordered segmented media and removes an empty bundle container. Local Media recognizes mirrored bundles plus legacy flat, UUID-only and centralized hidden-store layouts. Both Local Downloads and Local Media register the same unexported `com.nuvio.tv.morphe.segmented` provider idempotently. Side-by-side installation must rename that authority with the package, and the runtime authority is derived from `Context.getPackageName()`.

The Media3 source-factory hook adds only subtitle URIs recorded in this patch's completed-entry index. The full-screen listener is used only to suppress hidden completion UI during active playback.

`SubtitleWorkerFingerprint` identifies Nuvio's subtitle-fetch coroutine structurally from its repository log strings, `Function2` contract and ten-parameter constructor. The StreamScreen hook passes that exact resolved class to the extension so repository discovery never depends on architecture-specific obfuscated class names. The legacy names remain fallback-only for older already-supported layouts.

The shared path contribution is generic settings infrastructure registered by either Local Downloads or Local Media. It has one neutral preference key, one manifest contribution and no dependency on either optional runtime. Consumers declare only whether an enabled feature requires write access: Local Downloads registers that capability inside its own compartment, while Local Media remains read-only capable. The generic picker requires a persisted SAF write grant or a successful raw-path create/delete probe whenever any enabled consumer requires writes. Local Media alone owns migration from its older patch-specific path key.

Download initiation revalidates the saved location instead of treating a stored URI as proof of access. This is required for permission revocation, removable media remounted read-only, deleted folders, and Android 10 devices where read permission does not imply raw-path write permission. The foreground service repeats the write probe to close the remount/revocation race between source selection and file creation.

Porting to another Nuvio version requires re-verifying every structural fingerprint, including both native TV Button shapes, native Text, the source-card parameter and click positions, the subtitle worker constructor shape, the `StreamPlaybackInfo` property fallback order, the Player route query, source-picker destination detection, and Android foreground-service declarations.

The episode badge is hosted inside Nuvio's existing Compose `Box`. Its runtime bridge must use the concrete `c0.u` BoxScope singleton, not the `c0.t` interface, and the background modifier is the static `w.m.g` helper. NuvioTV 0.8.11 captures `EpisodeCardMetrics` as `na.z0`; its `t`, `u`, and `v` fields are the native `statusBadgeSize`, `statusIconSize`, and `statusBadgeInset`. The runtime requires those exact values and does not silently fall back to smaller or edge-hugging geometry. These target contracts are checked from the patched APK's Smali and DEX strings so an obfuscation or Compose-layout change fails acceptance instead of rendering a misplaced badge.

NuvioTV 0.8.11 uses the `e1.p` composer interface and the native storage-slider renderer in `ua.x5`. Local Downloads resolves the mutable-state factory and updater by their static parameter/return signatures and resolves the native slider icon as a zero-argument static icon factory. These lookups remain inside the Local Downloads compartment and do not introduce patch-specific names into shared settings infrastructure.
