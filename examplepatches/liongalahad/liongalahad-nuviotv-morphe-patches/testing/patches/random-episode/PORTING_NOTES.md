# Random Episode porting notes

The behavior is derived from DeclanSC/NuvioTV branch `feat-random-episode` at commit `96b644f6daf66d2a4787e303d15b7501f7f3216a`. That branch last shared Nuvio history at `0.7.10-beta`, so its source changes cannot be copied into 0.8.11 directly.

The 0.8.11 binary port extends the original one-shot action into persistent per-show random playback while adapting to the current navigation, player startup, progress and post-play implementations. It stores the global availability switch, per-show modes, per-show pools and completed-episode snapshots in Morphe-private device preferences.

The runtime reuses Nuvio's native circular hero action and packaged Material shuffle-on vector. A short press toggles the current show; a long press opens the patch-owned `All` / `Unwatched only` dialog. A committed pool choice stores the pool and enabled state in one preference transaction, while dismissal performs no write. The native Play callbacks are wrapped only while that show is enabled. For a no-progress detail visit, the patch supplies a native `NextToWatch` value for the selected episode so Play's label and eventual route agree. It observes a patch-local Compose state so explicit toggle and pool changes refresh Play immediately. Callback recreation and asynchronous episode-list changes do not change that visit's episode. A patch-owned hook at Nuvio's Home destination ends the visit; the next detail entry then draws a different episode when possible. Initial random Play rewrites the resulting Stream route, while explicit episode and Continue Watching routes keep their requested episode and merely arm random continuation.

Random Next is selected from a process-local shuffled bag and cached for repeated recompositions of the same post-play screen. `Unwatched only` merges Nuvio's completed-episode detail state with the patch's 90%-completion mirror. Native progress loading, persistence, resume seeking, watched marking and tracking are deliberately left intact, so random sessions behave like ordinary playback in Continue Watching, Trakt and Simkl.

Continue Watching integration binds each card payload to its rendered content object, records incomplete progress by show and episode, and removes that authority at Nuvio's 90% completion threshold. While a show is enabled, the recorded episode overrides a mismatched detail Resume value for the displayed native `NextToWatch` and both Play routes; random selection begins only after it. During a single detail visit, a valid native Resume-to-Play transition is treated as the user's explicit Continue Watching removal and invalidates the cached payload before random mode can be enabled. An initially non-Resume native value does not clear an extant card, preserving the card-as-source-of-truth behavior during ordinary loading or stale native state. The card, poster and wide artwork branches add a top-left marker built from the exact packaged Material shuffle path, using a 20 dp white circle, dark foreground icon, native-style shadow and 8 dp outer inset. All settings, UI, state, runtime bridges and tests remain in the Random Episode compartment.

Home `Next Up` randomization captures Nuvio's existing per-show `CwMetaSummary` constructor input, converting its compact episode summaries into a patch-owned in-memory catalogue without a new network or provider call. The public Continue Watching card receives an atomically rewritten native `NextUpInfo` plus a wrapped Play action. A per-show Home-visit cache makes the rendered episode stable through Compose recomposition, while the Home/detail boundary clears the cache for a fresh draw on re-entry and avoids the previous draw when alternatives exist. In-progress card variants bypass this rewrite. `Unwatched only` merges the same persisted and detail-derived completion snapshot used by detail playback; an empty eligible set returns no card content.

The list rewrite runs before Nuvio separates aired Continue Watching entries from unaired Upcoming entries. For random-enabled shows, an eligible aired replacement follows the Continue branch and removes the false Upcoming card. The runtime captures Nuvio's immutable Home state plus its owning state holder and publishes a field-for-field cloned state when a Detail setting changes. Each Home selection also retains its original native Next Up source independently of later recompositions, so disabling after a cold random-enabled Home restores the genuine unaired item rather than reclassifying the current random episode.

Fingerprints use the detail composable's model/callback structure, the Home destination's navigation-callback shape, the structural `CwMetaSummary` constructor, the native hero-action signature, the current Meta detail state, the Stream route schema, Video model calls, the sequential next resolver, progress writes and the three Continue Watching artwork variants. They do not depend on obfuscated class or method names. Every fingerprint must match exactly once on each 0.8.11 asset.

A later Nuvio release remains unsupported until the fingerprints and all application/runtime gates pass again.
