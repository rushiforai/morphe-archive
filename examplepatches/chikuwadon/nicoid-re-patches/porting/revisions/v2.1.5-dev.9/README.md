# nicoid Re v2.1.5-dev.9 — 流れるコメントの描画最適化と全フレーム診断

## 評価基準
- v2.1.5-dev.8 の実機ログ（1.25倍速）
- 約1,500コメント動画、120fps設定・重なり防止OFF: 6区間平均106.38fps、起動直後を除くと111.84fps
- 約235,000コメント動画、120fps設定・重なり防止OFF: 6区間平均52.90fps、高密度区間では27.74fps
- Canvas描画の時間の増加が主要因と考えられるが、コールバック外の時間には正常VSYNC待機も含まれる

## 変更
- Canvas/TextureViewのコメント描画で、画面内の同一Entryを毎回 `drawText` し直さずに済むようCPU Bitmapスプライトを試験導入
- 12MiB/スプライト60,000pxの厳格なメモリ上限、毎フレーム最大2枚の作成上限を設けてGC・初期化負荷を抑える
- 画面サイズ・文字サイズ・フォントスタイル・影・透明度・描画モード・世代変更時にキャッシュ無効化
- 表示を終えたEntryのスプライトは64フレームごとに破棄、キャッシュが満杯でもアクティブなエントリを入れ替えて再生成しない
- ハードウェアCanvas・巨大コメント・メモリ不足時は従来どおりの文字描画へフォールバック
- スプライトのヒット・生成・拒否件数・メモリ使用量を10秒間隔でログに出力
- CommentFramesで `draw.run()` 全体（lockCanvasからunlockCanvasAndPostまでを含む呼出し）とVSYNC配送頻度を別計測
- 高リフレッシュレート（60/90/120/144/165/240Hz）×25/30/60/90/120fpsの30組合せを自動テスト
- 重なり防止ON時の見送り、重なり防止OFF時の全件表示、コメントの移動/寿命、Media3再生・フリーズ対策は変更しない

## 実機検証時の比較
1. v2.1.5-dev.9を適用し、前回と同じ動画区間を120fps/60fps、重なり防止OFFで検証
2. `nicoid-comment-perf`: fps、drawAvgMs、glyphAvgMs、rasterHits/Misses/Builds/Rejected、rasterKiB
3. `nicoid-frame-total`: drawsPerSec、drawWholeAvgMs/P95/P99、callbacksPerSec、missedVsyncIntervals
4. コメントの文字サイズ・位置・色・半透明・影・縁取り、画面切替後の描画品質を目視確認

## 注意
- これは最適化の検証版であり、画面表示FPSや視覚的な等価性は実機未確認
- 事前レンダリングは一部環境で逆効果の可能性があり、FPS・メモリ・視覚品質を測定して正式採用判断
- 入力ソースの毎フレーム全件照合は変更通知の網羅が証明できていないため削除しない
- ネイティブコメント表示・設定初期値・Morpheパッチの既存要素を保持し、正式リリースはしない
