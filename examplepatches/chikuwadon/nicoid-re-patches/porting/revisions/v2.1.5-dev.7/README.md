# v2.1.5-dev.7 — コメント描画周期の原因切り分け

Base: v2.1.5-dev.6 (`3e1e9ece223d5ce14de2816687aca46c52cd021a`)

## 実装
- 235,071件の動画の60fps設定に対して描画コールバック約40fpsであった原因を切り分けるための軽量な診断を追加
- 実際の呼び出しスレッド名と最初の描画コールスタックを1回だけ記録
- 描画関数内の入力照合（scan）、入場処理（admit）、文字描画（glyph）、全体（draw）を10秒区間で集計
- 前回描画関数の完了から次回呼び出し開始までの時間（outside）も計測
- outsideには待機、Canvas取得・投稿、スケジューラ、他の処理が含まれ、単独のsleep時間とは断定できない
- ログは10秒ごと・初回スタックのみで、毎フレームのLogcat書き込みはしない
- v2.1.5-dev.6の重なり防止ON時の見送りと後続8件探索、OFF時の全件表示、既存再生対策は維持

## 意図的に未変更
- ネイティブ描画周期、VSYNC同期（実際の呼び出し経路の特定後に修正）
- `CommentSource280.sameEntries()` の全件照合（更新通知の網羅性が未確認）
- UI設定・初期値・コメント位置/速度/寿命・Media3のフリーズ対策

## 診断
`nicoid-comment-perf` に `callback-path` と `outsideAvgMs / admitAvgMs / glyphAvgMs` を追加
描画コールバックFPSは画面に実表示されたFPSではない。比較は同じ動画・同じ再生区間の60fps設定で行う
