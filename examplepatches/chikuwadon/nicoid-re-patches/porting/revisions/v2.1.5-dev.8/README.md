# v2.1.5-dev.8 — コメントVSYNC描画周期改善

基準: v2.1.5-dev.7 (`7b5c9b3e640fde86d797eaef16681f45173fccea`)

## 根拠
- 60fps設定・120Hz表示にもかかわらずコメント描画コールバックは約39～40fps
- 描画関数の平均: 重なり防止ON約3.8ms / OFF約7.0ms、関数外約22ms / 約18ms
- v2.1.5-dev.7の実MPPを解析し、CommentFramesが60fpsを17msのHandler.postAtTimeに丸めていたことを確認

## 変更
- TextureViewのCommentFramesクラスだけをChoreographer.FrameCallbackによるVSYNCスケジューリングに置換
- ナノ秒単位の累積描画予定時刻に合わせ、60/90/120Hzなどの更新周期に応じた描画間隔を選択
- 遅れたフレームをまとめて再描画しない。画面切替や解放時には古いコールバックを止める
- 旧Q16 SurfaceViewループ、コメント重なり防止ON/OFF、既存FPS設定、コメント位置・速度・寿命、Media3再生フリーズ対策は変更しない

## 自動検証
- VSYNCタイミング数学のJava単体テスト（60/90/120Hz × 25/30/60/90/120fps）
- 遅延フレームのスキップと描画予定時刻の連続性
- 再生18シナリオと重なり防止／画面サイズ回帰テスト
- 正式v2.1.4 MPPをSHA256で固定し、変更したDEXクラスを検証

## 制限
- 実機で60fpsを達成したかは未確認。Logcat上のFPSは描画コールバック頻度であり、実表示FPSとは異なる
- コメント入力リストの全件照合は変更通知の安全性を検証できていないため維持
- Canvas lock/unlockやメインスレッド競合が残る場合、FPSは下がり得る

この版は検証用devであり正式リリースではない
