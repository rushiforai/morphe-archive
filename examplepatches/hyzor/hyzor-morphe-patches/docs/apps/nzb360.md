# nzb360

Package `com.kevinforeman.nzb360`, supported target `25.3` (versionCode `537`, universal APK).
Source: [`patches/src/main/kotlin/dev/hyzor/patches/nzb360/`](../../patches/src/main/kotlin/dev/hyzor/patches/nzb360/).

| Patch | Default | What it does |
|---|---|---|
| Unlock All Access | on | Reports All Access as active, so every service module and the Upgrade Center unlock. The plan toggle is seeded on the yearly plan. |

## Port notes

This is a port of the nzb360 "Unlock All Access" patch in
[rushiranpise/morphe-patches](https://github.com/rushiranpise/morphe-patches), which was
written against 23.4 and last targeted 25.2.1 (versionCode `534`). The 25.3 build keeps the
same design, so the hooks port with only their signatures re-checked:

| Role | 25.2.1 (upstream) | 25.3 |
|---|---|---|
| All Access flag | `NZB360LicenseHelper.isAASubscriptionActive()` | same method, still a `sget-boolean` |
| service gate | `isUnlocked(Service, Z)` plus two `isLocked` wrappers | same three methods; both `isLocked` overloads still delegate to `isUnlocked` |
| Upgrade Center state | `Contract$UIState.isSubscribed()` | same getter |
| plan toggle seed | `UpgradeCenterKt.SubscriptionSection` `"Monthly"` | same const-string, still fed to Compose's `mutableStateOf` |

None of the licensing classes are obfuscated in 25.3, so the fingerprints pin the real class
and method names plus their exact parameter lists. 25.3 adds modules to the `Service` enum
(`Chaptarr`, `Seerr`, `Sick Beard`, `Tracearr` are visible in the add-service sheet); they
need no patch change because the unlock is at the "All Access is active" level rather than a
list of per-service constants. 25.3 also introduces credits and Feature Bounties in the
Upgrade Center; those are separate from All Access and are **not** touched.

The tested artifact is the APKMirror universal APK for 25.3 (`arm64-v8a`, `armeabi-v7a`,
`x86`, `x86_64` in one file, versionCode `537`). nzb360 is published as a plain APK, so the
bundle declares one `APK` compatibility target and there is no bundle to merge.

## How the app decides you have All Access

`NZB360LicenseHelper` (a singleton in `com.kevinforeman.nzb360.helpers`) keeps two pieces of
state:

```text
subscriptionActive : boolean                       the cached All Access flag
serviceStatusList  : List<ServiceStatus>           per-module { service, unlocked }
```

`isUnlocked(service, ignoreAllAccess)` is the only method that combines them:

```java
boolean isUnlocked(Service service, boolean ignoreAllAccess) {
    if (isAASubscriptionActive() && !ignoreAllAccess) return true;
    for (ServiceStatus status : serviceStatusList)
        if (status.service == service) return status.unlocked;
    return false;
}
```

The two `isLocked` overloads are inverted delegating wrappers, and that is what the UI calls:

```java
boolean isLocked(Service service)            { return !isUnlocked$default(service, false, ...); }
boolean isLocked(Service service, boolean z) { return !isUnlocked(service, z); }
```

25.3 has 147 `isLocked` call sites across the dashboard, the module screens and settings. The
flag itself is read by seven call sites and cached from the `account_status` preference on
startup and from the Play Billing result afterwards.

The Upgrade Center has its own copy of the decision: `Contract$UIState.isSubscribed()`
(12 call sites) switches between the purchase screen and the "already subscribed" panel.

The patch therefore rewrites five boolean methods:

- `isAASubscriptionActive()` returns `true`;
- `isUnlocked(Service, Z)` returns `true`;
- both `isLocked` overloads return `false`;
- `Contract$UIState.isSubscribed()` returns `true`.

The two `isLocked` hooks are redundant in 25.3 because the overloads delegate to the patched
`isUnlocked`. They are kept exactly as upstream does: if a future build starts reading the
cached status list in `isLocked`, those two still hold.

The sixth edit is cosmetic: `UpgradeCenterKt.SubscriptionSection` remembers the selected plan
starting at `"Monthly"` and renders the Monthly/Yearly toggle from it. The patch changes that
one seed to `"Yearly"`, so the purchase screen opens on the yearly plan. The patch identifies
the seed by its data flow — the `"Monthly"` const-string whose register is passed straight to
`Landroidx/compose/runtime/l;->h(Ljava/lang/Object;)Lc74;` — rather than by position, because
the same method also contains the `"Monthly"` button label that must stay.

Only client-side decisions change. No purchase is performed, no receipt is forged, and
anything nzb360's backend verifies still sees the real account. Credits and Feature Bounties
are server-side and are not granted.

## Verification

Static checks:

- `tools/verify_fingerprints.py` resolves all five pinned class/method anchors against the
  stock APK, including both `isLocked` overloads.
- Morphe 2.1.1 applies the bundle to the stock APK with `--validate`: all six fingerprints
  match exactly once, and the patch changes 3 of 21,139 classes
  (`NZB360LicenseHelper`, `Contract$UIState`, `UpgradeCenterKt`).
- The three patched classes were stripped from their original DEX files: `classes2.dex` drops
  from 6,619 to 6,618 class definitions and `classes3.dex` from 4,679 to 4,677. The new
  `classes4.dex` contains exactly those three classes, so there is no duplicate definition.
- The patched DEX was disassembled:
  - `isAASubscriptionActive()` is `const/4 p0, 0x1; return p0`;
  - `isUnlocked(Service, Z)` is `const/4 v0, 0x1; return v0`;
  - both `isLocked` overloads are `const/4 …, 0x0; return …`;
  - `Contract$UIState.isSubscribed()` is `const/4 p0, 0x1; return p0`;
  - `UpgradeCenterKt.SubscriptionSection` now loads `"Yearly"` where the stock build loads
    `"Monthly"` before the `mutableStateOf` call, and the `"Monthly"`/`"Yearly"` toggle labels
    are unchanged.
- The output is signed by Morphe (`CN=Morphe`) and still declares
  `com.kevinforeman.nzb360` `25.3` (`537`) with all four ABIs and both native libraries.

Device run on the Android 16 x86_64 emulator (`sdk_gphone64_x86_64`, API 36), installed
fresh (the stock build was uninstalled first because of the signer change). The patched APK
cold-starts with no `FATAL EXCEPTION` (339 ms on the first build, 286 ms on the final one).

The stock and patched builds were then compared on the same emulator through the same
onboarding ("Skip — I'll set up later" → "Start exploring nzb360"):

| Surface | stock 25.3 | 25.3 + Unlock All Access |
|---|---|---|
| Side-menu header | `nzb360` | `nzb360 │ All ∞ Access` |
| Settings → Your upgrades → Upgrade Center | “No modules unlocked yet” | “Everything unlocked — thank you for the support!” with an `ALL ACCESS` badge |
| Upgrade Center body | Monthly/Yearly paywall, “Subscribe for …”, “Restore Purchases”, Lifetime Unlocks with credit prices | “All Access: Active — All modules unlocked”, every module listed as “Unlocked via ∞” |
| Add a service | all services with a `+` | identical — adding a service is not the gate point |

The gate is the `isLocked`/`isAASubscriptionActive` pair, and the Upgrade Center rows are the
clearest proof: every module (Dashboard 2, SABnzbd, NZBget, Torrents, Sonarr, Radarr, Unraid,
Lidarr, Chaptarr, Bazarr, Seerr, Tautulli, Tracearr, Web Interfaces, Indexer Search) renders
as “Unlocked via ∞” on the patched build.

Not exercised: an actual purchase, the Manage Subscription hand-off to Play, adding and
saving a real service connection (no server was available), credits/Feature Bounties, and the
yearly-plan selection itself. The subscribed state hides the plan toggle, so the `"Yearly"`
seed is verified statically only; it is the same edit the upstream patch makes.
