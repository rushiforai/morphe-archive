# NU.nl 26.10.0 upgrade and the NUjij onboarding loop

Target: publisher XAPK `nl.sanomamedia.android.nu` **26.10.0 / 210163**, manifest minimum SDK 32.
26.9.0 support is dropped at the owner's request.

## The NUjij page

After a fresh install of patched 26.9.0 the phone showed a full-height onboarding card,
"Het gesprek van de dag begint op NUjij", with *Ontdek NUjij* and *Naar voorpagina*. Tapping
*Naar voorpagina* brought the same card back. The card text is not in the APK. The BFF
(`graph.nu.nl/graphql`) sends it as an `OnboardingScreen` in the front page's
`OnboardingSheet`, with the same curved-image layout as the notification and account cards.

Two patch policies caused the loop and the missing skip:

1. **Disable tracking** let only three measured `wncCardShownEvent` payloads (`breakingNews`,
   `promoteLogin`, `followTopics`) through the BFF dispatcher. That event is the first-party
   acknowledgement NU uses to stop serving a card. The new card's acknowledgement was
   dropped, so every front-page load served the sheet again.
2. **Skip consent screens** auto-dismissed only `breaking-news-modal` and `promote-login-modal`
   by exact id, so the new card stayed on screen.

Anonymous BFF requests (with and without cookies, notification header and several client user
agents) did not return an onboarding sheet. The NUjij card's exact id and payload were
therefore not captured, so the fix does not depend on them.

## Changes

- The acknowledgement filter admits every `wncCardShownEvent` with a non-empty payload.
  Other event types, including analytics, stay blocked.
- The onboarding policy treats every `OnboardingScreen` card as optional, except topic
  selection (`onboarding-follow-topics`) and the forced-update notice (`deprecatedApp`). The
  check uses the 44-character base64 prefix of `{"type":"OnboardingScreen","id":"`. That
  prefix does not depend on the card name, so later promotions are skipped too. The card's
  own acknowledgement still runs before the automatic dismiss.

## 26.10.0 differences that affect verification

The show coroutine the onboarding patch rewrites is byte-identical to 26.9.0. The following
upstream changes needed only re-pinned verifier digests, because no patch touches them:

- Manual privacy resurfacing now passes a purpose to highlight:
  `PrivacyGateService.resurfacePrivacyGate(Activity, String, String, Continuation)`,
  `ResurfaceConsentUseCase.invoke(Activity, String)` and
  `ContentFragment.resurfaceContent(String)`. `refreshConsent`, which the consent patch stubs,
  is unchanged.
- `ScreenMapper.map(Screen, Continuation)` became suspending.
- `ScreenInteractor.processAction(Action)` delegates to a new two-argument overload.
- `TargetMapper.mapConsentTarget`, `EventProcessor.processCompletableEvent` and the privacy SDK's
  `onCreateWindow` changed bodies.
