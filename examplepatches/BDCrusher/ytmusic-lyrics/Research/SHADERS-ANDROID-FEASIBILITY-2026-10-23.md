# Better Lyrics Shaders: Android feasibility

Research only for BDCrusher's YT-Music. No animated-art, video-capture, audio-analysis, permission, installation or emulator changes were made.

Inspected [Shaders](https://github.com/better-lyrics/shaders) HEAD `d878877cb225e1bcfef205c2937141a26112ebec`, independently rechecked with `git ls-remote` on 2026-10-23 Phoenix time. Retained source is `Better-Lyrics/Sources/shaders-d878877cb225`, package version 1.5.0. The repository is GPL-3.0; any reused code and dependencies need their notices retained. The current lyrics build does not bundle this extension.

| Effect | What upstream actually uses | Android implication |
| --- | --- | --- |
| Moving album-colored background | `@kawarp/core` GPU mesh warp/blur, saturation, dithering, movement, zoom and dimming controls in `contents/lib/kawarpManager.ts` | Feasible inside a hardware-accelerated renderer. Need a scoped native artwork input, a separate background layer behind text, visibility/pause/reduced-motion handling, GPU context-loss fallback and frame/battery measurements. No microphone is needed for ordinary motion. |
| Animated album cover | Metadata lookup in `animatedArtManager.ts`; silent looping `HTMLVideoElement` placed over the website thumbnail | Feasible where the artwork service has a matching animated album. Android must supply metadata, use normal service verification, validate returned URLs, deliver media through a bounded bridge/cache and fall back to the existing still cover. This is an album loop, not an arbitrary song's music video. |
| Background derived from video frames | Kawarp `loadVideo` with sample dimensions/frame rate/smoothing; retains last frame across buffering and changes back to artwork on failure | A native YouTube Music video is not an HTMLVideoElement in our WebView. Needs an explicit native media/texture contract, handling of protected/unavailable frames and a measured copy/update budget. A browser extension cannot simply be injected into the APK to obtain this. |
| Beat-reactive movement | `audioGraph.ts` attaches `MediaElementAudioSourceNode` to the site's media element and feeds an `AnalyserNode` (FFT1024, smoothing0.8, analysis interval100ms) | Our WebView does not own the native audio element. Needs native PCM/visualizer integration and review of applicable permission/platform constraints; no audio capture has been enabled. Ordinary slow movement is independently possible. |

The animated artwork request is `https://artwork.boidu.dev?s=<song>&a=<artist>&d=<rounded duration>&al=<album>`. The extension extracts album metadata from native web responses/DOM and keys its artwork URL cache by artist/album. It retains positive URLs and caches not-found for seven days, aborts pending work on recording changes and rejects late results. The allowed video host is `mvod.itunes.apple.com`; no universal codec/container guarantee is specified by this code. Playback/codec support must be checked from actual responses and Android media capabilities. No remote media was downloaded or played for this research.

`artworkToken.ts` obtains a normal ALTCHA challenge, solves it using the published algorithm, and requests a token from `/mint`. It refreshes at80% of token lifetime. This is the service's own verification mechanism; an Android port must preserve it. No private Apple key, extension token or borrowed credential is required or extracted. The lookup may proceed with an available usable token; absence/failure must fall back normally.

Our current local lyrics WebView has a restrictive CSP (`connect-src 'none'`) and fixed allowed native origins. Future artwork support therefore requires deliberate fixed-origin native transport/media delivery and content-policy changes. It must not become an arbitrary URL/credential bridge. Opening the lyrics page, changing tracks, closing the panel and reduced motion all need explicit resource teardown/pausing. Keep text contrast and current native panel ownership; avoid a second native panel or full-window overlay.

A practical first implementation would be a slow artwork-derived mesh in the existing lyrics body, capped and paused when hidden, with the still/native-themed background as fallback. Animated album loops are a separate capability after matching/service/media delivery is verified. Beat reaction and native-video-derived backgrounds require more native work. These are feasibility conclusions from source inspection, not measured Samsung performance or a completed port.
