# Transparent-only Lyrics navigation - 0.2.11-beta.1

User requested the system navigator be transparent. Scope: the Samsung/Android navigation bar while the native Lyrics panel owns the current window. Native navigation buttons/icon appearance and normal content insets are preserved. Closing Lyrics restores the prior native window state.

Removed the matching-color mode, background sampling/Bitmap/Canvas code and opaque protection overlays. LyricsSystemBars now has only sync(View,boolean active), setting the bar/divider to Color.TRANSPARENT and disabling navigation contrast enforcement where supported. It has no background-color/palette lookup, overlay painting or icon-appearance override. Unchanged values do not cause repeated setters. Native theme updates are retained for restoration. Window-token/focus/inset/owner checks prevent modifying an unrelated activity or undoing a replacement renderer's state.

Removed the Transparent system navigation toggle. Saved transparentNavigation=false is ignored rather than deleted; other rendering preferences and private connections are preserved. Both editions call the same transparent-only helper. Lyrics rendering, source retrieval, controls and status-dot assets are unchanged from0.2.10.

Verification/check_revision31_navigation.py executes the actual helper with explicit Android window/inset simulations:47 checks across API26/28/29/30/36, bottom/side/gesture navigation, unknown panel background, light/dark icon state, native theme updates, focus/hidden navigation, replacement views, cross-activity tokens, restoration, no repeated writes and no sampling/painting. It also verifies the legacy preference is not read and its toggle is absent. This is not a real Samsung rendering test.

Four exact final APK combinations/both source orders and five rejected conflicting selections, compiled native/SDK/isolation audits, JVM tests and lint are bound by Personal-Patches/dist/0.2.11-beta.1/verification.json after staging. The compiled audit requires the two-argument navigation API and rejects helper references to overlay addition, Bitmap sampling and icon-appearance overrides. Source/browser/clock/service evidence from0.2.10 is reused only where exact source and web-asset hashes remain identical; no new performance or provider claims are made.

Exact target remains original YouTube Music9.42.52/94252240 arm64-v8a/minSDK26, official Morphe1.48.0, verification engine2.0.0 with inherited1.15.1 fingerprint semantics. Full alone OR deselect every Full patch and use Lyrics-only Add-on with official defaults, official Third-party lyrics OFF. Same root feed/categories. Enable Pre-release patches/Experimental app versions, refresh and repatch original APK. Settings remain Morphe > Lyrics.

Phone/One UI acceptance is still required: transparent three-button/gesture regions, divider/scrim absence, native icons, theme/rotation/keyboard, close/back and both native/forced Lyrics panels. Transparency reveals what the native app draws underneath; the patch does not globally change insets or hide navigation buttons. Previous phone-stutter/WebView-verification/cold-panel/timeline limitations remain. No device/MuMu/sign/install/uninstall operations or copied globals. Shared Toolkit runs in place, all authored files/artifacts/scratch remain under YT-Music, and no cleanup was requested.

Current helpers: Verification/verify_revision31.ps1, check_revision31_navigation.py and stage_revision31.py. Never rerun completed generators or push private Personal-Patches history. Publication receipt, once complete: Verification/publication/v0.2.11-beta.1/publication-result.json.
