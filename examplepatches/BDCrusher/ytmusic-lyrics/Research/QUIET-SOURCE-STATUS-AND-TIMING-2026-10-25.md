Green means source checks completed without unresolved errors and usable lyrics exist; it does not mean every provider has this recording. ## Concrete timing corrections

Android PlaybackState positions are timestamped. The prior host manager treated a position as current at callback arrival, discarding getLastPositionUpdateTime. For example, a position10000ms as of elapsed1000ms arriving at1200ms was exported as10000 instead of10200 while playing. The personal renderer now has its own timestamp-aware RendererPlayback clock, using elapsedRealtime consistently and rejecting out-of-order samples. One typed callback hook is injected in each edition; official runtime classes are not duplicated and their original callback/control-flow work remains. See the [Android PlaybackState contract](https://developer.android.com/reference/android/media/session/PlaybackState#getLastPositionUpdateTime()).

The JS bridge clock stays continuous during ordinary sampling jitter. Small corrections adjust phase gradually, bounded to8% of playback rate; seeks, discontinuity revisions, pauses and rate changes remain immediate. Real lyric taps update the native clock immediately and pre-seek samples cannot undo them. Track changes reset follow state and hide stale Resume scrolling UI. Hidden windows do not restart animation from periodic visible samples.

Braccato's actual per-line additive transforms, varied duration/stagger, highlight, letter wave, BG vocals and agent placement are retained. Eight scroll animations still match the untouched upstream core exactly, including810ms first effect/cubic-bezier(0.86,0,0.2,1). There is no replacement viewport scrolling algorithm.

Native bridge polling drops from100ms to250ms while visible,1000ms while hidden. Window/navigation/overlay synchronization is removed from the clock loop; native layout/attachment/settings callbacks still own it. Unchanged visibility and keep-screen-on values are not repeatedly written. Unchanged settings avoid re-layout. Equivalent source replies retain the lyric DOM, and a bounded128-entry/1MiB track-local ingestion cache avoids repeated parsing. Failed parses remain retryable. Source completion waits for in-flight parsing before allowing noLyrics; metadata/empty events cannot hide a valid result still decoding.
