## Recording ownership and lyrics

The current repository is keyed by recording ID rather than mutable title/album/duration. Exact-ID Unison and the permanent library can start before native metadata commits. Metadata refinements start other sources without clearing successful results, retry budgets or intentional selection. A pending metadata sentinel prevents an early empty verdict. Native Lyrics data is accepted only when loaded for the current recording. Model delivery before the identity callback no longer discards a valid action model; pending/available remains second, confirmed empty last.

The personal renderer owns and hides competing native lyric content for the entire enabled/open session, including loading. Recording changes invalidate it immediately. Source/display/cache/seek/refresh/offset callbacks carry current recording/generation guards, so a late previous-track response cannot seek, refresh or overwrite the new track. Metadata-only changes retain Braccato nodes and state. The extension engine remains the only text-motion algorithm; no invented timing or alternate host scroll animation.

Four shared transport permits bound foreground and prefetch requests; lease release also covers configuration/open failures and cancellation. Busy permits reschedule without consuming a provider attempt. Existing scheduled transient/recovery retries, normal service verification and renewal remain. Optional playlist/Shaders installations cannot start personal discovery unless its own provider assets are present. Background prefetch uses the same full source selection and permanent one-best library, with bounded jobs/sessions and failure cooldown. No successful lookup guarantees every provider has a lyric or grants access to a rejected endpoint.

## Playlist identity and offline files

A native header action is added immediately after the existing Download action. Both playlist download routes carry the displayed playlist identity, including its native nested endpoint; they do not fall back to the playing song. Unknown non-player contexts return to native handling. Default mode preserves the app's own command/account handling; In-app uses existing local download infrastructure; External sends one canonical playlist URL to the selected downloader's normal review screen. Handoff is never reported as download completion.

Morphe > Playlist downloads > Choose download folder requests read-only persisted Android folder access. Select the folder used by YTDLnis. Files must include their exact recording ID in balanced [ID] or (ID), or use the ID as the basename. Titles alone, ambiguous IDs and unsupported/non-audio files are not guessed. Files are not moved or copied; stale/revoked grants fail safely. Known incomplete external batches recheck only while the UI is active. Manual Check downloaded files refreshes availability. Queue/downloading/complete suffixes are native subtitle text runs, updated only for changed visible rows; external progress remains unknown until a usable file exists.

Authenticated native playlist pages retain their original playlist identity/order/continuations, with exact typed native response reconstruction. The cache excludes search, separates browse ID/token/params/language/native form data/generic form data, and takes one immutable snapshot after native interceptors. The same snapshot is used for lookup and observation, even if the native transport mutates builders. Interceptors run once before the cache, with original transport tracing and cleanup preserved. Cache hits are offline-only; authorization failures are not disguised as offline success. Saved pages are bounded per page; only explicitly tracked playlists persist. Continuation ownership is reconstructed as saved pages load. Static allowed-origin native cover thumbnails are retained separately, written atomically, and served through the installed app's scoped native FileProvider and native URI loader. No duplicate Guava/AndroidX/Morphe implementation payloads.

The cached native page does not create another online playlist. Offline row/whole-play commands retain positions and duplicates and use the existing offline playback service. **That service is still a separate playback backend: integration into the native main-player/Lyrics panel is not established.** The one-best lyric library can be prefetched for saved recordings, but a complete native-main-player offline experience must not be claimed. Online playback/queue behavior remains native. This is an implementation limitation, in addition to untested real phone/download behavior.

## Debugging stutter

Use the existing Morphe > Miscellaneous > Debugging > Enable debug logging, reproduce without screen recording, then Export debug logs. Include the exact song link, affected playback times, Native or Fallback entry, whether Shaders was on and whether it also happens with Shaders off. Compare the same song with its naturally enabled native entry when possible. If logging itself removes the symptom, say so; recording/logging can change scheduling and refresh behavior. Existing logs include bounded recording/source/line/clock, renderer cadence and Android frame deadlines. They do not include private credentials or lyric text; native song/UI logs may remain, so inspect before sharing.

Useful stronger evidence is a short scoped Android System Tracing/Perfetto capture spanning several bad line transitions, plus display refresh/power mode and Android System WebView version. This can distinguish UI-thread stalls, WebView rendering/GC, GPU work and refresh pacing. No trace/device capture was performed here. No universal zero-stutter claim.
