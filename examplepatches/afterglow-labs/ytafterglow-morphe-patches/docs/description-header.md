# Description header copy actions

`descriptionHeaderHookPatch` implements `copyVideoInfo` under the existing **Long-press tools** selection. Its default remains off. The named wrapper must depend on this hook and expose the existing preference; no new preference or standalone selection is required. It depends on the existing Afterglow video-state observer, imported Morphe video-information observer, shared native text-context capture, and its own tag resources. Morphe **Copy text** and native text selection remain unchanged.

Build131 passes runtime menu, full-title copy, full raw-description copy, scroll dismissal, live OFF/ON, and native Close on the unchanged APK using the Windows emulator's host GLES renderer. Build132 also verifies the corrected icon density and placement beside native Close.

The frozen iOS reference, `YTAfterglow.x:4308`, adds a 40-point Copy button before Close in `video-description-ep-identifier`, with Copy title and Copy description actions. Build127 runtime exposed a missing modern path: the native outer header is only the drag handle, while the visible title and Close belong to the `video_title_header.eml-fe` recycler cell inside panel content. `video_description_header` is the separate creator/statistics cell. The original outer-header adapter therefore passed package checks but did not show Copy on that runtime surface.

Build128 then established that the active renderer omits the optional root and weak-reference token from its text context. The corrected path uses the actual native `Lhiy.w/r` bind/unbind lifecycle, which supplies the drawing host, exact mount item, and current component model. The model retains the exact title-header context. The same native lifecycle also unbinds/rebinds an existing mount item during updates; view mount/removal alone would miss those changes. The optional context-root path remains available where native code supplies it.

Build130 reached the actual mounted title (`hit`, 1080×189 px) but found no tagged panel ancestor. The resource table exposed the remaining mapping error: `Lakhj.Z` is `id/footer` (`0x7f0b085f`), a sibling of the content. The controller returns `Lakhj.d`, a native `LoadingFrameLayout` extending `FrameLayout`, from `nx()`. Its named `constraint_default_engagement_panel` layout contains the content subtree and footer. The owner binding now uses this exact returned root, and patch-time resource-name assertions distinguish the footer, outer `panel_content`, and native panel layout.

The current `Lakhh.p` model on that controller supplies the semantic identifier. A separate 40-dp Copy control is placed before Close using the current title cell's geometry. It is removed when the title scrolls out, detaches, changes owner/model, changes active video, or its exact native mount item is unbound/reused. It does not replace or reparent native title/Close views. The outer `Lakiz.k` and legacy `Lakjr.F` paths remain supported; legacy insertion precedes its native Close. Labels and Copied feedback use the existing translations.

For the outer-header adapters, the current `Lakhj.g` header must still be the observed header. The content adapter uses the controller's exact returned root described above. The current `Lakhh.p` model supplies the semantic panel ID through `Lajoz.bJ`. A panel-model change, detach/reattach, preference change, or video change invalidates outstanding copy actions. Every menu action and asynchronous result also checks the current active video, attached visible native root, current Activity, and advertisement state. A result for an old video or closed/reused header never replaces the clipboard.

Android's `Lbhah` player VideoDetails protobuf includes the native title and video ID but omits raw `shortDescription`. Paired native titles are therefore captured through the existing `Lastx.setChannelInformation(Lalfi)` observer. Full descriptions are loaded only after an explicit Copy description action, using the pinned Morphe `ChannelIdRoutes` metadata request (`GET_CHANNEL_ID`, which returns all `videoDetails`). The response's exact `videoId` must match before copying its unmodified `shortDescription`. This reuses Morphe's account-free request policy and client context; it does not start media extraction, probe streams, read account cookies, or reconstruct text from shortened visible labels. Missing or failed metadata leaves the clipboard intact; an explicitly present empty description is valid. Responses are bounded to 1 MiB, text to 131,072 characters, and connection/read timeouts to five seconds each. The loading dialog is cancellable. If the paired native title is unavailable, the same metadata request supplies the title.

This transport is an Android adaptation. It may require a network request where iOS already has the raw description in its player response. The pinned request policy originates from Morphe patches v2.0.0 (`6cb8e6b6ee425eda8a854e026507286359f38a32`), whose existing source and NOTICE attribution remain included in the bundle.

The initial software-renderer runs exited the Windows `qemu-system-x86_64.exe` process with access violation `0xc0000005`; disabling Vulkan alone did not resolve that host failure. The identical build131 APK passed the actions above with host GLES. Streamed Android logs contained no app FATAL/ANR for those attempts. This establishes an emulator renderer limitation in this test setup, without identifying its underlying cause or claiming a physical-device result.

The frozen density-only correction changes CopyIcon's intrinsic dimensions from 24 raw pixels to 24 dp converted to pixels. The existing 24-unit drawing geometry, 40-dp target, 8-dp padding, placement, and listeners are unchanged. Its density regression rejects the actual frozen build131 icon at 2.625 density. The 373-check result passes against the final build132 APK. Its `018-description-density-132` screenshot shows a correctly sized Copy icon beside Close, clear of the tested two-line title; native Close continues to work.

Remaining device QA includes native description selection and cancellation of an in-flight metadata request. Cancel a pending load, close/reopen the panel, or switch videos while loading; clipboard must stay unchanged. Comments and other engagement panels must never gain the button. The lifecycle safeguards have source regressions; only the runtime flows listed above are claimed as verified here.
