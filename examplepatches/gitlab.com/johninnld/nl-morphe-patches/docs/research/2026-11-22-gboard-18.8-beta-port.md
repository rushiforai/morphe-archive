## 2. Toolchain (reusable)

Everything lives in `.tools/artifacts/gboard-port-18.8.0-beta/` and
`~/Scripts/gboard/port/`:

| Tool | Purpose |
| --- | --- |
| `Mapper.java` | Structural class/member mapper between two builds (string anchors → super/interface propagation → body-position unification → shape uniqueness; then member voting by exact body position) |
| `SearchMember.java` | Find every class declaring a method with an exact descriptor (`(IZ)Z` …) — used to recover classes the mapper mis-attributes |
| `FindClass.java` | Dump fields/methods/strings of a class from the APK |
| `MethodShape.java` | Register count, instruction count, return opcodes, try blocks and written fields of one method — required by the stock-shape guards |
| `Fingerprint.java` | Byte-exact reimplementation of `gboardStructuralFingerprint()`; verified by reproducing the two known 18.6.3 Custom Theme hashes |
| `Validate.java` | Re-checks all 244 bindings against an APK and prints renames |
| `port.py` | Extracts/rewrites hard-coded descriptors in the patch sources |
| `portbindings.py` | Parses/regenerates `GboardVersionBindings.kt` |
| `fieldpass.py` | Second pass for `Gboard*FieldTarget(classType/name/type)` member renames |

Run order: `Mapper old.apk new.apk classmap.txt queries.txt resolved.txt` →
`port.py rewrite` → `fieldpass.py` → `portbindings.py regen`.

## 6. How the six previously-failing patches were solved

| Patch | Root cause found in 18.8.0 | Fix |
| --- | --- | --- |
| **Toolbar Editing Buttons** | `AccessPoint.m()` is now the static factory and returns the abstract builder `Laadm;`; the icon setter moved to `l(I)` (writes field `r`) and the click action to `Laadm;->v(Ljava/lang/Runnable;)V` | validation targets re-derived (`Laadr;->m()Laadm;`, `Laaej;->q(String)`, `Laaej;->l(I)`, `Laadm;->v(Runnable)`, `Laaej;->a()Laadr;`, `Laajh;->g(Laadr;Z)V`, `Lauco;->n(Collection)`); extension `Handles` and the catalog-sync reflection retargeted to `aadr/aaej/aadm/aajh` + `aaia/auco` |
| **Enable OCR / Scan Text** | the optional-module *request object* (`Lytk;`) no longer exists — that name is now a protobuf; the request is an `Lxns` provider returning `[Lxli;` | dropped the two stale request targets, pointed `optionalModuleBuilder` at `Lbaki;->a(Lbaje;)[Lxli;`, `moduleManagerRequest` at `Lbakh;->a()[Lxli;`, and changed the delegate cast from `[Lkzf;` to `[Lxli;` |
| **Web Clipboard** | `v9` is live until `invoke-direct {2,9,4}` (index 190), which is *after* `p0` is clobbered at index 172, so the old save window does not exist | moved the scratch register to `v10` (dead from index 168 to the end) and replaced the single-instruction liveness anchor with a proven dead-window check; the post-mutation error message now names the offending index |
| **Parakeet voice typing** | callback interface `Lwkc;` grew to 11 methods and delivers results as a protobuf via `k(Lbbhl;)V` (`onTranscriptionUpdate`); `bbht`/`bbhl` builders live on the generated bases `banv`/`banp`; `krv.m()`/`krv.n()` delegate to the Lite engine so they cannot be copied | result method selected by its log string; new `TranscriptionBundle` contract builds one `bbht` (presence bits 1|2 = text/final) and wraps it in `bbhl` through `banv.n()` / `banp.w()` / `banp.t()`; inherited Lite methods that touch the template are emitted as **programmatic** stubs (`BuilderInstruction10x/11n/11x/21s`) because morphe's inline smali compiler wraps fragments in a void method and cannot parse `return-object` |
| **Parakeet personal dictionary** | depends on the above and on the voice-correction-list discovery | unblocked by both |
| **Rambler contact names** | 18.8.0 replaced the `AddWords(Object,int)` value with a transformer: `store.n(kind, Class, Latri)` and `Lbki;`-style classes implementing `apply(stats)->stats` | discovery now accepts a call site that writes MUSE_STATS without reading the list splitter, prefers the single-word adder (`(String,List,int)`, tags `USER_ADDED`), and the extension chains one transformer per contact name behind a `java.lang.reflect.Proxy` for `atri` (`GboardRamblerContactsRuntime.appendWords`) so Gboard's own protobuf code does the encoding |

### New patch: Beta features (18.8)

`gboardBetaFeaturesPatch` (default off) adds a **Beta features** toggle under More settings and
forces five pure-flag 18.8 gates through a new `GboardFlagFamilyFeature.BETA_FLAGS` entry:

| Flag | Consumer |
| --- | --- |
| `enable_plain_text_chip_for_quick_paste` | `lgj` second chip for a plain-text clip |
| `enable_clipboard_pk_floating_chip` | `shc` floating clipboard chip |
| `enable_invisible_floating_resizing` | `afnh`/`afri` invisible resize band |
| `enable_emoji2` | `acsv` provider swap |
| `enable_remove_suggestion_v2` | `DragConfirmationPopupView` layout swap |

Every name is present in both patched APKs (2 occurrences each, 1 for the layout string) and the
feature marker `dev.jason.gboardpatches.feature.beta_flags` is written, which is what makes the
settings row appear.

Two structural findings worth keeping:

1. There are **four** MUSE_STATS writers (`Lkbi` single add, `Lkbd`/`Lkbm` set add/delete,
   `Lakhr` = DeviceContextMuseStatsUpdater). Picking the wrong one silently writes deletions
   or dcontext words, which is why the discovery now filters on the constructor shape.
2. `Lkbi;` is a *top-level* class with no fragment back-reference, so it can be instantiated
   outside the settings screen — that is what makes the proxy approach safe.

## 8. Limits

- Patch **application** is verified; no feature was run on a device. Native payloads (OCR
  engine, Rambler/Parakeet recognizers) are untouched and per-ABI.
- Early in the port only arm64 was patched. Both ABIs were patched for every verified run from `final9` onward; the arm32 APK has the same dex obfuscation map (release builds
  share it), but the `parity` claim is unverified for 18.8.0: run the same command with the
  v7a APK and compare `failedPatches`.
- The 18.6.3 target is removed from `Compatibility.kt`; publishing both requires splitting
  `GboardVersionBindings` per version.
- `16` unused bindings still carry 18.6.3 values (marked `PORT-18.8`); they do not affect
  patching today but must not be trusted for new work.
- Settings screenshots/menus were not re-checked; the About-page and settings-text patches
  depend on resource ids that this beta renumbered (`0x7f14…`).

## Post-install regression: `aagb` VerifyError (fixed)

First on-device install of the 28-patch build lost the access-point row (toolbar, custom top-row
keys, voice key) with no crash. Logcat showed
`VerifyError: Verifier rejected class aagb ... register v3 has type Reference: wim but expected
Reference: auco`. The access-point delegate injected a literal `check-cast p3, Lwim;` written for
18.6.3, where the parameter was `Lwim;`; 18.8 renamed it to `Lauco;` while still shipping an
unrelated class called `wim`. The cast is now derived from the method signature. Details and the
"never hardcode obfuscated types" rule: `2026-11-22-gboard-18.8-accesspoint-verifyerror.md`.
