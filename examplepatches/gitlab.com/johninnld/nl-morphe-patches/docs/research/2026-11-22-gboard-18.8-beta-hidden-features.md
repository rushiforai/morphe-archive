## 1. How flags are declared in this build

The beta declares flags through one factory, `Ladfk;`, into typed static fields of small
holder classes. This is much easier to read than the 18.6.3 `muq` blob:

```java
public final class aasf {                                  // Rambler / Jetson flag holder
    public static final adfh a = adfk.a("enable_agentic_dictation", false);
    public static final adfh b = adfk.e("agentic_dictation_learn_more_url", "");
    public static final adfh d = adfk.a("enable_jetson_in_toolbar", true);
```

Factory kind → type: `a` boolean, `b` double, `c` long, `d` long+string, `e`/`q` string,
`i` proto, `n` boolean (variant), `p` context+int.

Every flag is read through `Ladfs;->g()Ljava/lang/Object;` (the `Flag` object) or
`(Boolean) flag.g()`. `Ladfs;` holds the name in field `a` and the value snapshot in
`Ladgf;` (field `a`: value, `b`: priority). That is exactly the getter our existing
**flag-family** hook patches, so any flag below can be unlocked by name without new
bytecode work — the patch only has to name it.

## 2. New flags in 18.8.0-beta (83 new, 59 removed)

`83` new declarations vs 18.6.3: 43 boolean, 22 long, 10 string, 5 long+string, 3 double.
The table lists every new *boolean* flag plus the feature-bearing non-booleans, with the

The emoji machinery is new in this beta and is a *separate* subsystem from Rambler's text
rewrite: `knx` constructs an `swa` — the **`EmojiEmbeddingSearcher`**
(`libs/search/emoji/search/EmojiEmbeddingSearcher`) — with `kta.EMOJI_MATCH_EMBEDDING_LATENCY` /
`EMOJI_MATCH_INDEX_LATENCY`, `knv` holds the tuning flags, `knw` is the matcher. `kny` compiles
the marker `\[EMOJI:([^\[\]]*)\]`, so dictation output can emit `[EMOJI:description]` and the
matcher resolves it through the embedding index.

`agentic_dictation_send_emoji_persona_to_s3` is declared but **inert in this build**: `kov`
evaluates `cond ? Optional.empty() : Optional.empty()`, so the persona never leaves the device
even when forced. Treat it as scaffolding, not a privacy switch.

All pre-existing Rambler flags from the 18.6.3 inventory are still present with the same
names and defaults (verified: `enable_agentic_dictation`, `enable_jetson_in_toolbar`,
`enable_rambler_al_toolbar`, `ad_activation_type`, `jetson_enable_cursor_awareness`,

## 4b. Unlocked by this port

**Beta features (18.8)** is a new patch with its own toggle under More settings. It forces the
five pure-flag gates from §4 through a dedicated `GboardFlagFamilyFeature.BETA_FLAGS` and
`GboardBetaFlagRuntime`:

| Flag | Default | Consumer |
| --- | --- | --- |
| `enable_plain_text_chip_for_quick_paste` | false | `lgj` adds a second chip for a plain-text clip |
| `enable_clipboard_pk_floating_chip` | false | `shc` floating clipboard chip (also needs `aabv.t()`) |
| `enable_invisible_floating_resizing` | false | `afnh`/`afri` invisible resize band on a floating keyboard |
| `enable_emoji2` | false | `acsv` swaps to the Emoji2 provider |
| `enable_remove_suggestion_v2` | false | `DragConfirmationPopupView` picks the new confirmation layout |

`jetson_position_cursor_after_last_diff` (new, default `false`) is forced separately by
**Rambler voice typing** — `GboardRamblerCloudRuntime.applyFlagValue` returns `true` for it, and
`kov` uses it at two sites to place the cursor after the last diff. That needed no new wiring
because the Rambler cloud runtime was already in the flag-family chain.

Both unlocks ship in the artifacts: every flag string appears in the patched `classes*.dex`, and
the beta patch writes the marker `dev.jason.gboardpatches.feature.beta_flags` so the settings
row is shown.

The remaining new gates stay inventoried rather than forced: the emoji matcher needs its
embedding index, dcontext needs the feature-cache processors, and the survey/backup flags need
Google services. See §6 for the recipe to add any of them as a proper toggle.

## 5. Limits

- Defaults above are the compiled-in values. Actual Gboard installs receive server values via
  Phenotype; a re-signed build does not, which is why these read as "off".
- "Read by X" is the first referencing class found by a reference scan, not a full data-flow
  proof. A flag can have more consumers than listed.
- Whether a gated feature *works* after forcing the flag (model availability, signature checks
  such as `dcontext_require_first_party_signature`, AICore acceptance) is not established by
  static analysis. `Random` device testing is required per feature.

## 6. How to actually force one of these flags

The existing flag-family hook already does the hard part: at DEX level it prepends a call to
the extension carrier before the single `return-object` of `Ladfs;->g()`, passing the flag
*name* (`Ladfs;->a`) and the stock value. A new flag needs no new bytecode hook — only a name
in a runtime list. Recipe:

1. Add a `GboardFlagFamilyFeature` constant in
   `patches/.../shared/GboardFlagFamilyComposer.kt` (pick a free `compositionOrder` and a new
   `RuntimeCallId`).
2. Register that `RuntimeCallId` in `shared/runtimeabi/RuntimeAbiCatalog.kt` with the
   `(Ljava/lang/String;Ljava/lang/Object;)Ljava/lang/Object;` ABI (there is already one per
   feature; copy `RAMBLER_CLOUD_RUNTIME_APPLY_FLAG_VALUE`).
3. Add the name → value rule in the matching extension runtime class, e.g.
   `extensions/gboard-patches/.../extension/clipboard/...` or a new
   `GboardBetaFlagRuntime`, following `GboardRamblerCloudRuntime.applyFlagValue(name, value)`.
4. Expose a settings toggle in a `*SettingsFeature.java` so the user can turn it on.
5. Declare a public patch that depends on it (`resourcePatch { dependsOn(flagPatch, settingsPatch) }`),
   like `gboardOcrPatch`.

For a *beta-only* bundle the cheapest variant is one `GboardBetaFlagRuntime` holding a
`Map<String, Object>` of the 18.8 names from §4 and a single settings screen ("Beta features")
that writes one boolean per entry; then step 1–2 are done once, not per flag.

Two cautions learned from this build:
- `writing_tools` is already forced by `GboardAiWritingToolsRuntime`; do not add it twice
  (the flag getter must see exactly one delegate per name or the verify pass rejects the
  method).
- Flags whose consumer is native (`enable_user_feature_cache`, `dcontext_*`,
  `agentic_dictation_emoji_match_*`) also need the corresponding model/processor list; forcing
  the boolean alone will not download anything.
