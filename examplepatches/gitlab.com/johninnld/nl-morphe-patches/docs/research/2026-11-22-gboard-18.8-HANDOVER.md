### 3.3 Validate the dex (register capacity only)

```bash
CP=$(find ~/.gradle/caches/modules-2/files-2.1/com.github.MorpheApp.smali -name '*.jar' | tr '\n' ':')
java -Xmx24g -cp "/Users/jneerdael/Scripts/gboard/port/classes:$CP" ValidateDex /tmp/out-arm64.apk
# expect: methods=175963 bad=0
```

`ValidateDex` compares `ins_size` against `registers_size`. It does **not** check register types and
does **not** load classes the way ART does: it reported `bad=0` on the pre-fix `final16` build that
the phone rejected with `VerifyError`. Treat it as a structural check only.

### 3.4 Type audit (source layer)

Run this from the **canonical repo** (`/Users/jneerdael/Scripts/nl-morphe-patches`). The class map it
reads lives under the canonical `.tools/artifacts/`, which is ignored in the worktree, so running it
from a worktree fails to find the map.

```bash

python3 scripts/audit-obfuscated-types.py | tail -2
# expect: provably stale: 0   ambiguous (name reused, needs member check): 105
```

Scoped scan: it reads `Class.forName("...")` literals and type descriptors on smali lines, and it
classifies by the 18.6.3→18.8 class map. It misses strings built inline, reflection constants kept in
other forms, and it reports reused names without resolving their members.

## 8. Known risks, ranked — please attack these first

### 8.1 Coverage claim is the weakest part of the deliverable

Function notes: 36 sections, ~40 subsystems, 1,409/48,718 named classes. The notes themselves say a
per-function map of the whole APK is unreachable with this method. If the reviewer's remit is
"全部 functions documented", the honest answer is **not met**; do not mistake the 34 sections for
completeness. §34 documents the anchoring technique that would have to be repeated per subsystem.

### 8.2 The fixed build has never run on the phone

At handover the phone still has the **pre-fix** Morphe build:

```
lastUpdateTime = 2026-11-22 13:16:48
pulled /data/app/.../base.apk  →  Laagb;->m  CHECK_CAST Lwim
```

`/sdcard/Download/patches-1.94.0-gboard-18.8-beta-dex.mpp` **is** the newest bundle
(`512fdee6…`), but the user must re-patch in Morphe. Do **not** `adb install` a desktop build over
it: Morphe signs with a different certificate and the install will block Morphe's own updates.
Until the user re-patches, every "works on device" claim is emulator-only.

### 8.3 Obfuscated names are reused across versions — the classmap is not a rename oracle

Proven example: 18.6.3 `aagb` **is also** a valid 18.8 class (`AbstractAccessPointOrder`), while the
map says `Laagb; → Lbaps;`. A blanket rename would break working code. That is why
`scripts/audit-obfuscated-types.py` only fails on names whose 18.6.3 class **no longer exists**.
If you extend the audit, keep that distinction; the 105 "ambiguous" entries genuinely need
member-level checks.

### 8.4 The emulator cannot reproduce the strict verifier failure

`final16` (with `check-cast … Lwim`) runs fine on `emulator-5554` and logs no `VerifyError`; the
phone's Android 17 ART rejects the class at load. Offline checks (`EmittedParameterCasts`) and the
phone log are the evidence; a green emulator run proves nothing for this bug class.

### 8.5 Code changed without a way to run it

- `GboardAccessPointsMenuPatch` was rewritten to `Laajh;`/`Lafhp;`/`Laarm;`/`Lagoz;`/`Lagot;` from
  the patch's own resolved field targets. The patch is **not wired into any public patch**, and its
  helper is absent from the shipped APK (`strings` check). It cannot be executed today, so the
  rewrite is inspection-verified only. Try to wire it on a scratch build and see if it applies.
- `GboardAiWritingToolsFlagValuePatch` lost its `Lwgv;->h(Object)` injection because 18.8's `vow`
  exposes `h()Z`. If the 18.8 route-set API can be mapped, that feature should be ported properly.
- `Lqwp;`/`Lqmg;`/`Lkr;` etc. in the English-QWERTY patch remain **ambiguous** (names still exist
  in 18.8 but may be different classes). That patch is unwired.

### 8.6 The field-level emitted check was rejected as unsound

`F.java` reported 758 "missing field" hits on the *unpatched* APK (inherited/interface fields).
It was deliberately not added as a gate. Don't reintroduce it without fixing the hierarchy walk
(interfaces + `ClassPath` from smali would be the right tool).

### 8.7 Parakeet stubs are hand-built smali

`ParakeetVoiceTypingPatch` emits inherited methods as `BuilderInstruction10x/11n/11x/21s` because
morphe wraps inline smali in a void method. `ValidateDex` passes (`bad=0`), but a register-file
mistake here previously produced `ins_size > registers_size`. Any edit needs the dex check in §3.3.

### 8.8 Bundle packaging is fragile

Morphe needs `classes.dex` inside the `.mpp`; a plain mpp shows "no patches". The dex is built with
`d8 --min-api 26` against android.jar + `morphe-patcher-2.0.1` + kotlin stdlib/reflect. If you
rebuild with a different toolchain, verify with:

```bash
unzip -l "$OUT" | grep classes.dex
strings /tmp/mpp/dex/classes.dex | grep -c "Hidden flags (18.8)"   # expect 1
```
