## Structural findings (jadx decompilation of the input)

The 1.0.0 build keeps the audited 2.4.1/beta shapes:

- `app.myspoti.host.android.PlaybackService` still publishes the framework queue natively:
  `setQueue(List)` and `setQueue(null)` are called from the service. The native-queue branch
  therefore applies, and the 2.3.0 reflection export is not used.
- The browser root (`media browser: empty root for `, UID lookup through `getPackagesForUid`,
  object return) and the UID-checked children/search caller (boolean, no parameters) are unchanged.
- The shared browse permission predicate is still a non-static `boolean(String)` calling
  `getApplicationInfo` plus `Set.contains`, admitted by the own package, a Google car-host
  allowlist, the system-app flag, or a Play Store-installed Waze. The audited shape is unchanged.
- Children and search still share the UID-checked caller, and `defpackage/dy4` retains the
  `onSearch must call detach() or sendResult() before returning for query=` diagnostic.

## Changes

- **Allow any Android Auto host** and **Custom branding** now declare `app.orpheon` instead of
  `app.orpheon.beta`. Both remain any-version targets.
- **Android Auto Up next** accepts Orpheon 1.0.0 / 1194 with the Myspoti signer and keeps the
  native-queue branch (`1.0.0` added to the native queue version set).
- Documentation and the catalogue mapping move to `app.orpheon` at 1.0.0 / 1194; the bilingual
  Orpheon pages no longer describe the app as a beta.
