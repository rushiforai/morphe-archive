### Probes (archived in the repo)

`docs/research/2026-11-22-maps-26.47-probes/` holds verbatim copies of the throwaway Java probes used for


| probe | purpose |
|---|---|
| `DexDump` (from the patcher jar) | fields/methods/one method body — the workhorse |
| `SigScan apk name [params…] [->ret]` | find a renamed method by exact signature |
| `EnumC apk [name]` | methods `c(X)X` where X is an enum (distance-unit converter) |
| `Where apk Ltype;` | which dex defines a class, method count, superclass |
| `InstrAt apk class name params ret index` | one instruction + register fields |
| `CU apk class name params ret from to` | instructions with code-unit offsets (branch targets) |
| `GuardScan apk` | generated `Shapes.HIDE_*` guards whose register is later used as a reference |
| `VoiceHash apk refs.txt` | `mapsVoiceFingerprint` SHA-256 for the voice contract tables |
| `Abi apk interface job` | one-argument method coverage across all implementers |
| `NameAudit`, `RefCheck`, `Impls`, `Find`, `ReadSites` | general inventory helpers |

## 2. The rule: resolve by shape, never by name

Every 26.44 name still exists in 26.47 attached to a *different* object, so a name lookup succeeds and
binds the wrong thing. Seen:

```
Lblvb;  26.44 route model      -> 26.47 an Enum with 3 methods
Lycj;   26.44 route path       -> 26.47 67 methods
Lcizm;  26.44 distance unit    -> 26.47 a proto message (extends Lcnod;)
Lbmxs;  26.44 native manager   -> 26.47 an unrelated 7-method class
Llvp;   26.44 nav binder       -> 26.47 an unrelated 2-method class
Lbnfl;  (26.47 warning model)  -> in 26.44 bnfl is something else
```

And within one version, a name can point at a different *member*:

```
component.bR   26.44 guidance source   -> 26.47 a bzyj executor
component.hN   26.44 distance utility  -> 26.47 bngj
component.hU   26.44 native manager    -> 26.47 aywx
presentation.j 26.44 display holder    -> 26.47 the holder is bfgv.i -> bfdp
holder.f(Surface)                      -> 26.47 bfdp.e(Surface)
binder y(I,Parcel,Parcel)Z             -> 26.47 z(...)
```

## 5. How to continue

1. Run the host, then immediately:
   `adb logcat -d | grep -A30 MapsNativeCar` — the buffer rotates; the cause is only there and in the
   host-visible message (which now carries it).
2. For any name in a stack trace: do **not** search for that name.
   `SigScan` for the method, a field-type scan for the field, `Where` for the class.
3. Verify every resolution on **both** APKs before changing the extension, and extend the table in §3.
4. Add the row to §4 as a commit when a link is fixed; keep each fix independent and verifiable.
5. Keep the invariant: no extension code may compare an obfuscated class name. Compare `instanceof`,
   signatures or field types.
6. Before claiming delivery, re-verify the **installed** APK (pull + `DexDump`), not the version label.
