## Writing Tools (was P1) — scope narrowed, not faked

18.8 builds the routed intent set from the flag
`voice_command_intent_types_routed_to_writing_tools_v2` (`aeam.f`, an `adgn` whose value is a `basg`)
and classifies with `ohu.a(oig)`. 18.6.3's route-set builder (`wgv.h(Object)`) does not exist, and
`vow` exposes `h()Z`, so the old `INTENT_AUTO_FIX` insertion cannot be emitted. The acceptance shim
returns immediately on the 18.8 binding.

The public patch therefore no longer depends on `gboardAiWritingTools1863AutoFixAcceptancePatch`, its
unused import is gone, and its description no longer promises proofread/Auto Fix. Rewrite and tone
are still wired through the flag patch. Porting Auto Fix means building the 18.8 intent set, which is
a separate task.

## Toolbar menu shim (was P2) — outside the supported set

`access_points_menu_style` is removed from `GboardContributionWiring`, with the reason in place: the
18.5.x shim binds `Laajh;->k(Lxno;)V` (18.8 defines `k(Laacw;)V`) and calls its helper on `Lnib;`
though the helper is installed on `Laajh;`. The public Toolbar Editing Buttons path and its corrected
`aagb` cast are untouched.

## Hidden Flags (was P2) — three storage states, no writes on view

The first attempt made Off survive by replaying every stored key, but the screen still called
`ensureDefault` for every row, so merely opening it wrote `false` for untouched flags and a cold
start forced them Off. Corrected:

- The screen writes nothing. Building the rows only reads the stored value.
- A toggle writes the value **and** an explicit marker (`hidden_flag_explicit.<name>`), then reads
  back, applies the override and logs `Hidden flag switch did not take: …` if any step disagrees.
- Startup replays only entries with a marker or a legacy `true` value. A legacy bare `false` (which
  the old screen could have written on first view) is treated as *not configured*, which is the
  in-place-upgrade rule the reviewer asked for; legacy `true` records carry forward.
- What remains unproven: the effect on the live consumer, per flag, and the upgrade path on a phone
  that already has screen-generated preferences.

## Why `libdictation_jni.so` is absent (and what that means for NGA)

Neither input APK contains `libdictation_jni.so`: `lib/` holds 14 libraries (graphics, grammar,
scam, opus, mediapipe, `libintegrated_shared_object.so`, …). The formatter is a Play **dynamic
feature module**, not base-APK code:

| Evidence | Location |
| --- | --- |
| Module name `"dictation_feature_split"` (display "Dictation") | `addr` and `addu.b` |
| Install gate `enable_dictation_feature_split_install` (default false) | `akti.k` |
| Readiness `alyi.a()` = flag AND `NativeLibHelper.c("dictation_jni", false)` | `alyi` / `alyh` |
| Formatter construction logs "… library [dictation_jni] …" | `alhn` |

`NativeLibHelper` has an `integrated_shared_object` alias path, but its alias map (`c`) is only ever
set to the empty default (`auhc.b`) in this build, so `dictation_jni` is never mapped there.

The recognition engine is **not** missing: `libintegrated_shared_object.so` exports
`Java_com_google_android_libraries_assistant_soda_Soda_native*` (30 JNI exports) and is loaded by
`ldo`/`ihq` for SODA. It exports **no** `NativeFormatter`/`EmojiNlu` symbols, so the absent piece is
the formatter/NLU, not recognition.

Consequences:

- Forcing `enable_dictation_feature_split_install` cannot deliver the module to a re-signed package:
  Play verifies the installer/signature before installing an app's own feature modules.
- Any NGA path that constructs `NativeFormatterImpl`/`NativeEmojiNluHandler` will fail its
  readiness check and fall back; recognition through SODA may still work.
- Supplying the library means adding the matching-ABI `libdictation_jni.so` from an install that has
  the module to the APK or extension; it is not obtainable from the inputs in this repository.

### NGA hook and eligibility, verified offline

- Hook emission: `GboardAdvancedVoiceRuntime;->afterFlagValue` appears **0** times in the base
  build, **1** in the NGA build and **1** in the NGA+Bluetooth build (dexlib2 scan), so the
  composer injects it on the resolved flag getter only when the patch is selected.
- Readiness is a hard gate, not a formatter-only path: `alzk.getEligibilityMessageV2` returns
  "Dictation is not enabled because native split is not loaded" when `alyi.a()` is false
  (`!alyi.a()` at six call sites), and `alyi.a()` = flag AND `NativeLibHelper.c("dictation_jni")`.
  SODA recognition being bundled in `libintegrated_shared_object.so` therefore does **not** make
  NGA eligible on a base APK.
- The settings screen already surfaces this: rows "Dictation payload (Installed / Not installed /
  Unknown)" from `GboardDictationPayloadDetector`, which scans the target package archives for
  `lib/[^/]+/libdictation_jni.so`.
- Device expectation for the current inputs: the Advanced Voice toggle renders, but dictation
  reports the native-split message and does not start. That is the documented "unavailable
  recognizer" case, not a patch failure.

| Problem | Evidence | Fix |

### Why "Advanced" was missing from Voice typing, and the port

The Advanced Voice settings screen was fully green (payload installed, speech services found) while
Gboard's Voice typing list showed no extra backend. The prerequisites and the entry are separate:
the entry comes from the 18.6.3 selector patch that wrapped `VoiceSettingsFragment` inside an
"official selection" scope, and that patch had been dropped because its 18.6.3 member names no
longer resolve.

18.8 mapping used by the new `gboardVoiceBackendSelectionPatch`:

| 18.6.3 | 18.8 |
| --- | --- |
| `VoiceSettingsFragment.aC()I` | `aE()I` |
| `VoiceSettingsFragment.ac()V` | `ab()V` |
| `VoiceSettingsFragment.f(Bundle)V` | `e(Bundle)V` |
| `VoiceSettingsFragment.aE(Z, ahws, selector, selector)V` | `aG(Z, ahws, selector, selector)V` |
| `Laask;->a(Context)Z` (capability) | not present in 18.8 — dropped |

`Lkov;->gg()V` still resolves and the Rambler reset cleanup was left out (it targets an unused
helper). The four wrappers call enter/exit scope, and `aG` also reports the built selector list via
`RAMBLER_RUNTIME_UPDATE_OFFICIAL_SELECTION`, which is what puts the entry on screen.

### Correction: 18.8 has no separate "Advanced" dictation entry

Earlier in this record I treated the absence of an "Advanced" row as a missing selector port. The
APK's own layout says otherwise: `res/UM3.xml` (`setting_voice_unified.xml`) defines a "Dictation
type" category with exactly two `CustomSelectorWithWidgetPreference` rows — **Rambler**
(`dictation_type_jetson`, summary "Turns natural speech into polished text and edit in your own
words") and **Standard** (`dictation_type_traditional`). "Advanced voice typing" is the engine
behind the Rambler type (the Jetson/agentic stack), not a third row.

The experimental `gboardVoiceBackendSelectionPatch` was therefore removed; it wrapped
`VoiceSettingsFragment.aE/ab/e/aG` for no user-visible gain. What remains relevant is the payload:
with it bundled, the Rambler dictation type can run the advanced engine.
