# Google Maps 26.47: local flag catalogue and new feature surface

Static analysis of the supplied 26.47.00.1022347503 (version code 1068892333) standalone APK,
SHA-256 `28cd7b8f0fb3ac9a520c2b40c362337be6d9fbe6b264a568e711b93c7cc01cac`, compared with the
reviewed 26.44.06.1006895251 build. No device was involved: everything below is read out of the
shipped DEX and resource table, so "available" means *present in the APK*, not *switched on for a
given account*.

## Where the local flags live

Maps keeps its whole settings/flag catalogue in one generated class, `Lbace;` in 26.47
(`Lazqv;` in 26.44). Its static initializer registers every key:

```
b = new babx("settings_version", baciVar2);
c = new bacd("aid#", baciVar);
e = new babv("NO_OP", baciVar);
...
```

- 26.47 registers **659** keys, 26.44 registers **661**.
- The keys are typed by the declaring class: `babv` (222 bools), `bacb` (118 proto/enums),
  `babx` (108 strings), `baby` (104 longs), `bacd` (46 enum/ids), `baca` (40 strings),
  `bacc` (17 sets), `babw` (4 floats/doubles).
- There is **no default-value table** in the APK. Each flag's default is supplied at the call site
  that reads it, for example `this.c.V(bace.bc, false)` or `aT().V(babvVar, true)`. A flag that is
  never read with a literal default is decided by Google's Phenotype/Chauffeur service, or is a
  per-user stored setting rather than a feature gate.

Of the 659 keys, **107** have an observable literal default at a call site in this build:
94 booleans and 13 strings. The rest are either server-only or written/read without a literal.

and **3 removed** (`merchant_messaging_unread_tooltips_shown`,
`personal_route_fetching_enabled_cache`, `ugc_aapn_arrival_timestamp_seconds`). The new feature
surface is visible in the resource table instead: **177 new string resources** versus 42 removed.

## Availability, in plain terms

- **New and reachable in this build**: the Material 3 bottom sheet, the new Ask Maps entry points
  in search/reviews, the contributed-places filters, the route "typical" label, and the trailer
  restriction prompts. Their strings are wired to real classes and no local flag disables them.
- **New but not locally switchable**: airport arrival cards, Gemini start-of-nav announcement,
  GSPLAT, pre-arrival imagery, on-demand reroute prompts, review-editor moderation feedback. Their
  code and strings ship, but nothing in `bace` gates them at the call sites inspected, so Google
  enables them per account/experiment (inferred, not observed).
- **New and gated behind eligibility**: Glasses navigation (`gl_guidance_enabled` exists and
  defaults on, but the switch and the promo only render when the glasses eligibility check passes).
- **Locked features that predate 26.47**: eyes-free walking guidance, car satellite imagery,
  client-side recent history, media controls, wheelchair accessibility — all read with a `false`
  default and, except the last two, no in-app switch.

## Limits

- The APK exposes no global default table; the `false`/`true` values above come from call sites that
  pass a literal. Flags without such a call site are listed as unknown, not "off".
- Phenotype/Chauffeur can change any of these at runtime; the APK only carries the keys and the code.
- No account, device or runtime test was performed. "Available" is a static statement about the
  shipped artifact.
