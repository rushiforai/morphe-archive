# Google Maps 26.47: Android Auto / car surface

Static read of `com.google.android.apps.maps` 26.47.00.1022347503 (1068892333),
SHA-256 `28cd7b8f0fb3ac9a520c2b40c362337be6d9fbe6b264a568e711b93c7cc01cac`, against
26.44.06.1006895251. Focus: car-side behaviour that a user cannot switch in the UI, and which of it
is locally enableable. No device was involved.

New:

## What is locally enableable, and how

1. **Flag defaults that are false can be flipped by a patch at their read sites.** The three
   `car_satellite` reads and the three `satellite_on_at_startup` reads are literal-default calls, so
   forcing them true turns satellite on in the car (and, for the second key, on startup) for users
   who have not chosen otherwise. The same pattern applies to `is_navatar_enabled_state_reset_for_android_auto`
   if the intent is to stop the reset.
   Risk: these are per-user settings; flipping the default changes behaviour for everyone and is
   masked by any stored value the user (or an OEM) already set. It also does not make the car's
   satellite *data* available — that is a server entitlement.
2. **The native car UI** is this repository's own `Native navigation for any Android Auto host`
   patch: Maps' own car interface on any host, including community hosts. On 26.47 it is gated
   because the car ABI moved (§ below). This is the largest AA-facing capability available to a
   patched build and the one worth finishing first.
3. **Car App Library surface**: the car activity, templates and `androidx.car.app` service are
   declared by that same patch; `CAR_APP_*` resources and the Gearslip/DriveDeck adapters live in
   `extensions/maps-gearslip`. Nothing here is a user toggle.
4. **Server/OEM-gated, not patchable statically**: EV charging-network data and cost estimates,
   satellite tiles, traffic/3D layers' data, navatars, and the recent-destination promo are served
   or entitlement-checked. The APK carries the UI and the keys, not the content.
5. **Test hooks**: `car_fake_implicit_destinations` / `car_fake_recent_places` are debug-only proto
   settings; writing them adds fake entries, not features.

## Why `Native navigation` is gated on 26.47

`NativeNavigationPatch` verifies and rewrites the native car facade with ~100 hardcoded 26.44
symbols: the resource cohort (`lvh/lvi/jbz/nnu/lvg` → `lps/lpt/kyp/qqt/lpr`, already mapped), the
cal facade (`blrr/blqy/blrn/blvb/ycx`), the car connection guard (`beop/beqt/pxu/pxt`), the
projected-session focus (`ryt.p`), the guidance component chain and the `tqb.s` microphone action.
The first missing check is `Ltqb;->s`; the rest were never reached. Each needs a 26.47 equivalent and
the injected smali re-targeted. That is mechanical once the class map exists (see the next section),
but it is the largest single port in the set.

## Limits

- Static only: no DHU, no Android Auto host, no install was exercised.
- A flag whose default is "stored" cannot be classified as on/off from the APK alone.
- Enabling a flag default does not create server data (satellite tiles, EV prices, traffic) and does
  not bypass entitlements.

## Shipped as a toggle: `Android Auto options`

The bundle now carries an `Android Auto options` patch whose switches live in the Patches menu next to
the theme/UI patches (both default **off**, so nothing changes unless chosen):

| Option | Flag | 26.47 read sites flipped |
| --- | --- | --- |
| `carSatellite` — "Satellite view in the car" | `car_satellite` (`bace.fW`) | 3 (`uyp`, `plh`, `prr`) |
| `satelliteOnStartup` — "Restore satellite view on startup" | `satellite_on_at_startup` (`bace.N`) | 1 literal default (other reads use a stored value) |

Implementation: each site compiles to `sget-object bace.<flag>` / `const/4 reg, 0` /
`invoke-interface V(flag, Z)Z`; the patch replaces that zero with one, leaving a user's own stored
value in charge. Verified on the exact APK: with both options on the patched `Luyp.a` reads
`CONST_4 v2 1` before `V(bace.fW, ...)` and the run reports 26 controls applied, 0 failed.

Not exposed as toggles: `car_traffic`, `car_three_dimensional_buildings`, `car_layers_state` and the
EV layer filters. Those are stored settings handed to the car components as flag objects, so there is
no literal default to flip; enabling them needs the read site inside the car renderer, which the
native car UI patch (still gated on the ABI port) is the natural place for.
