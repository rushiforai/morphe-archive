# Gboard 18.8 advanced voice and Bluetooth microphone implementation plan

**Goal** · Make 18.8 Advanced Voice Typing usable through Gboard’s own Smart Dictation recognizer and expose the stock Bluetooth microphone setting as a separate opt-in Morphe patch.

**Scope** · Gboard `18.8.0.1022711984-beta`, arm64 build 176124766 and armeabi-v7a build 176124765. Exclude the patch-added zh-TW conversion and its UI. Keep stock Chinese support and the existing Rambler and Parakeet selection behavior. Keep the project’s current batch implementation and device-acceptance workflow.

**Starting point** · Worktree `.tools/worktrees/gboard-188`, branch `gboard-18.8-beta-port` at `73b11a6a`. The preserved offline receipt covers `26d32a101182`: the two base ABI runs and arm64 runs with NGA, Rambler extras and both applied successfully. It establishes patch application. Actual recognizer startup and Bluetooth capture still need evidence. [Offline receipt](../../research/2026-11-22-gboard-18.8-review-acceptance.md#offline-build-checkpoint)

## What is already in place

| Area | Verified current state |
| --- | --- |
| Advanced Voice dependencies | `6435b65f` removed the zh-TW bytecode dependency and `de6aaed8` removed the legacy Rambler selector dependency. The public patch now depends on the settings carrier, Advanced Voice feature marker and flag hook. The patch description and settings screen still advertise zh-TW. |
| Advanced Voice flags | The stock policy has six entries. The original APKs contain `enable_nga`, `enable_advanced_features_in_consolidated_sd_stack`, `enable_dictation_feature_split_install`, `handle_fallback_inside_sd_stack` and `enable_soda_longform_experiment`. Neither APK contains the exact `enable_sticky_mic_background` dex string. The SODA long-form flag reaches `amzf`’s `SbgAsrConfig`. |
| Speech prerequisites | The two tested base APKs have no `libdictation_jni.so` or `libsoda*` entry under `lib/`. The marker adds package visibility for Speech Recognition & Synthesis and Live Transcribe. The actual payload, language model and stock eligibility still determine whether the selected recognizer can start. |
| Bluetooth microphone | The settings UI, marker, runtime policy, flag-family contribution and runtime ABI already exist. The 18.8 public patch list has no patch wired to the Bluetooth marker and flag hook. Stock `aksj.j` declares `enable_use_bluetooth_setting=false`; `jzs` controls the Voice typing row, `anis.c(Context)` reads the flag plus the saved stock preference, and `anhd` uses it for input routing on Android 12 and later. |

Sources for the current state are the [public patch definition](../../../patches/src/main/kotlin/patches/gboard/ToolsPatches.kt#L128), [Advanced Voice settings screen](../../../extensions/gboard-patches/src/main/java/dev/jason/gboardpatches/extension/advancedvoice/GboardAdvancedVoiceSettingsFeature.java#L222), [stock flag policy](../../../extensions/gboard-patches/src/main/java/dev/jason/gboardpatches/extension/advancedvoice/GboardAdvancedVoiceStockPolicy.java#L9), and [Bluetooth flag contribution](../../../patches/src/main/kotlin/patches/gboard/features/bluetoothmicrophone/GboardBluetoothMicrophoneFlagValuePatch.kt).

## 1. Finish Advanced Voice decoupling and verify the recognizer path

- [ ] Keep `gboardAdvancedVoiceTypingPatch` in `ToolsPatches.kt` on its current three dependencies. Inspect the effective dependency graph for both the public patch and any reachable contribution-registry path. The standalone 18.8 NGA selection must emit neither the legacy zh-TW helpers nor the legacy Rambler selector wrappers.
- [ ] Remove the zh-TW punctuation row from `GboardAdvancedVoiceSettingsFeature.java` for this public feature, along with copy that implies the conversion is shipped. Leave stored zh-TW preference values alone. Remove copy promising sticky mic or a third backend selector. Describe the Advanced Voice toggle and the speech assets that may be required. Update the research feature guide and source settings text where they make the same promises.
- [ ] Verify the active `GboardFlagFamilyComposer.kt` contribution calls `GboardAdvancedVoiceRuntime.afterFlagValue` on the resolved 18.8 flag getter and that the hook reads the correct flag name from `Ladfs;->a:Ljava/lang/String;`. Fix the binding or use the composer’s existing name argument if emitted code shows drift. Verify unrelated flags, non-Boolean values and the disabled preference preserve stock results.
- [ ] Trace the 18.8 stock eligibility and readiness path starting with `alyi.a()` and `alzk`. Map any required core hook against each APK before adding it. Keep real model/native readiness and platform checks. If a payload is missing, use Gboard’s supported module/model path and confirm an actual successful load. Document an unavailable recognizer as such if the release input cannot supply it. The legacy zh-TW helper must stay out of the core path.
- [ ] Confirm Advanced Voice can run with only its own patch selected. Exercise the runtime toggle Off and On, recognizer selection, transcribed text, and a long utterance. The receipt must identify the recognizer that started and whether the long-form configuration was effective. A setting row or a successful transcript through Standard/Rambler is insufficient proof of NGA. Keep sticky mic outside the acceptance claim unless an actual 18.8 consumer is independently identified and tested.

## 2. Expose the existing Bluetooth microphone feature

- [ ] Add a separate default-off public `Use Bluetooth microphone` Gboard patch in `ToolsPatches.kt`. Reuse `gboardPatchesSettingsPatch`, `gboardBluetoothMicrophoneFeatureMarkerPatch` and `gboardBluetoothMicrophoneFlagValuePatch`. Use the existing Gboard compatibility target. The patch and its extension toggle must work with NGA and Rambler extras omitted.
- [ ] Keep the existing `pref_use_bluetooth_microphone_override_enabled` preference and `GboardBluetoothMicrophoneRuntime.applyOverriddenFlagValue(Object,Object)` ABI if they resolve on both inputs. With the extension switch enabled, the hook should expose Gboard’s own **Voice typing → Use Bluetooth microphone** row through the stock flag. The stock row then controls routing. With the extension switch Off, pass through the stock flag value.
- [ ] Check the stock lookup against both APKs: `Laksj;->j:Ladfh;`, the 18.8 flag getter and the existing row keyed by resource `0x7f140aa7` in the arm64 decompile. Verify the key by resource meaning and resolve it per input if needed. Follow the result into `anis.c(Context)` and the stock routing paths. Use the existing route and permissions flow. The stock code has Android-version and input-device checks, prioritizes wired/USB inputs and can exclude car devices.
- [ ] Document the two switches and the distinction between making the row visible and routing the recording. For the first acceptance use a headset that exposes a microphone input. Leave output-only Bluetooth devices and the car route under stock policy.

- [ ] **Regression and receipt.** Confirm typing, toolbar/mic, and existing Rambler and Parakeet selection still work for the configured patch set.
