# Changelog

Every HushPinterest release, newest first.

## Unreleased

* **Pinterest:** The patches now target Pinterest 14.42.0, version code 14428010. APKMirror has it as a plain APK for Android 10 or newer. Older Pinterest versions are refused.
* **Pinterest:** The patches are now built on Morphe patcher 2.1.0, so you'll need Morphe Manager 2.3.0 or newer to apply them.
* **Pinterest:** Long-press download now covers the newer list-style long-press menu too. Download shows up there and saves the pin you pressed, and the switches that hide Save, Send and Search image work on that menu as well.
* **Pinterest:** With GmsCore support, Continue with Google no longer does nothing when microG-RE can't be reached. You get a message saying to install it, turn it on or open it, and the setup guide says to add your Google account there first. Export report has a new Google sign-in section (no account names, no tokens) so a failure can be traced.
* **Pinterest:** Two new switches under Pin actions, both off to start. Save pins you download also saves a pin you download from its menu, and Download pins you save downloads whatever you save, from any screen.
* **Pinterest:** New `Hide Assistant` switch under Interface takes Pinterest's AI Assistant out of search, boards and pins on accounts that get it. Regular search keeps working. It starts off.
* **Pinterest:** New `Hide pins you've already saved` switch under Feed takes pins you've saved or own out of your home feed. Your boards and search still show them. It starts off.
* **Tooling:** Release walks now bind the bundle, stock build and patch selection to the signed APK installed on the test device. Publish rejects missing or mismatched evidence, unsupported app versions, invalid times and reported problems. A survey of an installed app without matching build evidence stays diagnostic only.

## 0.0.13 (2026-10-23)

* **Pinterest:** New GmsCore support patch, for phones that run microG-RE instead of Google Play services. Pinterest's Google sign-in and push notifications go through microG-RE, so Continue with Google opens microG-RE's sign-in. Before, it asked Play services and the account got turned down. It's left out of the default selection since without microG-RE those requests have nowhere to go. Pick it in Expert mode and Spoof signature for Google sign-in comes along with it. (#15)
* **Pinterest:** The patches are now built on Morphe patcher 2.0.0, so you'll need Morphe Manager 2.0.0 or newer to apply them. Older Manager builds can't load the bundle.
* **Tooling:** A release can't go public until the whole app has been walked with that exact bundle on a release phone or an emulator. The publish stage now takes the walk's receipt as `-Walk` and stops before GitHub or the index if the walk wasn't a full pass, saw a Pinterest crash, ran on some other device, or patched with a different bundle.
* **Tooling:** A device lease another session happens to be reading no longer stops a run partway. The check waits a moment and tries again, and a lease that stays locked still stops it.
* **Tooling:** New `scripts/walk-app.ps1` patches Pinterest from the release bundle and installs it on a leased phone or emulator. Then it opens the home feed, the patched screens and every Hush settings page, and writes the receipt publish asks for. Only a full walk with no Pinterest crash earns a PASS.

## 0.0.12 (2026-10-18)

* **Pinterest:** The patches now target Pinterest 14.41.0, the newest stable release. 14.40.0 is no longer supported. So far APKMirror has 14.41.0 only as an arm64 bundle (`.apkm`) for Android 12L or newer, and Manager merges it before patching.
* **Pinterest:** Download pin now shows in the full-screen pin menu some accounts get from the three dots on a pin, along with the other Hush rows, and Pinterest's own Download row in that menu gives way to it. Before, only the smaller pop-up menu had them.
* **Pinterest:** Download pins has a new switch, Copy image, that starts off. It adds a Copy image row under Download pin, in the small pin menu and in the full-screen one, and puts the full-size picture on the clipboard so you can paste it into a chat or a notes app. Video pins don't get the row. If the picture is too big, isn't really an image, or takes too long, you're told so and your clipboard stays as it was. (#11)
* **Pinterest:** Download pins also has Share image, another switch that starts off. Its row sits under Copy image and opens Android's share menu with the full-size picture itself rather than a link, so the app you pick gets the image. Video pins don't get it, and if the picture can't be fetched you get a short note instead of the share menu. (#11)
* **Pinterest:** Long-press download has three new switches on the Pin actions page: Hide Save, Hide Send and Hide Search image in the long-press menu. Each takes that one Pinterest button out of the round menu you get by holding a pin in a grid, and the pin itself still saves, shares and searches as before. They work with Download off too. If everything would be hidden and Download is off, the menu stays Pinterest's own rather than opening empty. All three start off. (#11)
* **Pinterest:** Black comments now covers the strip under the status bar too. On 14.41.0 the comments fill the whole screen, and that strip stayed dark gray above the black list on photo and video pins alike.
* **Pinterest:** Downloads no longer save the smaller copy now and then when the original is there. Finding the original asks Pinterest's media server a few quick questions, and one asked just as both lookup helpers were wrapping up the last was turned away, so the download settled for the size the feed showed. It now waits a moment for a helper to come free.
* **Pinterest:** Copy media link no longer overwrites something you copied after it. When a pin shows only a smaller size, the link to that size goes on the clipboard right away, and it becomes the original's link once Pinterest's media server answers, but only if the clipboard still holds that copy. Before, nothing was copied until the answer came, and a slow answer could replace whatever you'd copied in the meantime.
* **Pinterest:** Save list no longer hangs when the app holding the picked file stops answering. Each save gets 30 seconds in all, then you're told to check the file, and a late answer from that app doesn't add another message or remove anything. While that app is still busy, a new list says to try later instead of opening a picker. Everything that talks to the file's app now runs on its own helper, never on the screen's thread, including the clean-up after a list that couldn't be written while HushPinterest was paused.
* **Pinterest:** A list that isn't written no longer deletes an empty file you picked to write over. Only an empty file made since the picker opened gets removed. Any other file is left where it is, and you're told so.
* **Pinterest:** Save list leaves out a source link that hides a session code behind an encoded `;` (`%3B`, that encoded again, or a longer spelling some servers still read as `;`), the way it already left out a plain `;jsessionid=`. The pin's ID, title and Pinterest link still go in. Ordinary encoded spaces and accented letters stay exactly as given.
* **Pinterest:** Queue selected and Queue pins stay off until something chosen can actually be saved. A pin with no picture address, or a video Pinterest only streams, doesn't turn them on anymore, though Save list still takes those pins. A mix still queues what it can and counts the rest as unsupported.
* **Pinterest:** Morphe Manager lists every change of the release your Pinterest was patched with, not just a short summary. For that one release Manager shows the patch bundle's description instead of this changelog, and the description was one paragraph while every older release listed its changes. It now goes on with the release's changes after the summary, starting with this one.
* **Pinterest:** Hide comments has a second switch, Hide suggested replies, for the row of ready-made replies like "Yum!" and "Came out great!" next to the comment box. You can still write your own comment. It starts off, and the two switches don't turn each other on. (#14)
* **Pinterest:** Hide AI-labeled pins has a second switch, Hide pins that say they're AI, for AI pins Pinterest doesn't label. It takes a pin whose title or description says something like "AI art", "AI generated", #aiart, "made with AI", Midjourney, Stable Diffusion or PixAI, and pins from sites that only host AI images, like pixai.art and Civitai. It goes by the pin's own words, so a pin that just says "AI" stays, and names like Ai Weiwei or the Portuguese "aí" are left alone. Boards named that way stay too. It starts off, and diagnostics count these pins apart from the labeled ones.
* **Pinterest:** Hide closeup buttons has a third switch, Hide Search image label on pins. Pinterest puts a "Search image" label on the lens button for your first two pins each day, and with this on the lens shows without it, the way it looks from the third pin on. Tapping the lens still searches. It starts off and sits under Hide lens button on the Interface page. (#13)
* **Pinterest:** New Filter feed patch, with a Hide video pins switch on the Feed page. It takes pins that play a video out of your home feed, search, related pins and boards, idea pins with video included. Photos and GIFs stay. It starts off.
* **Pinterest:** Filter feed also has Muted words, a row on the Feed page where you type words and phrases you don't want to see. A pin whose title or description has one of them leaves the same lists. Capitals don't matter and only whole words count, so "cake" takes out "Wedding Cake Ideas" but not cupcakes. The list holds 50 entries of up to 40 characters, starts empty, and goes into settings files with your switches. Boards named after a muted word stay.
* **Pinterest:** New Keep Home feed patch, with its switch on the Feed page. Pinterest reloads Home with new pins on its own when you come back after five minutes or more, when you pick the Home tab again after a while and when you back out of a search, and the pin you were about to open is gone. With this on, Home stays where you left it. Pull down whenever you want new pins. The new pins prompt, a second tap on the Home tab and a pin you open from a notification still load as before. It starts off.
* **Pinterest:** New Show posted date patch, with its switch on the Interface page. Pinterest sends the day each pin was posted but never shows it, and with this on you see "Posted" and that day under the title when you open a pin. A pin without a date just doesn't get the line. The date follows the language HushPinterest shows and your phone's time zone. It starts off and shows from the next pin you open. (#11)
* **Pinterest:** With Debug logging on, the line for a kept pin also says whether Pinterest marked it as a repin or as saved to one of your boards. It shows only that the field is set, never which board.
* **Pinterest:** The Feed page has a new row under the AI switches, Pinterest's own AI setting. It opens the page where Pinterest lets you see fewer AI pins among the ones it picks for you, since neither that page nor the switches catch every AI pin alone. It's there whenever Hide AI-labeled pins is patched in.
* **Tooling:** The pin model fixture test also checks the fields Hide video pins reads, the two inside Pinterest's video and idea pin models included, and the grid title that the AI words and video filters use to tell a pin from other models.
* **Tooling:** The pre-push and release checks take a declared build kept as APKMirror's `.apkm` bundle, since that's the only way 14.41.0 ships. The bug report form's example names a bundle too, and the release step keeps whatever kind of file the form names.
* **Tooling:** The release gate's advisory check works in Windows PowerShell 5.1 again. Since 0.0.11, any failed OSV request stopped it there with an "Unable to find type" error. A dropped connection or a busy server now gets asked again in 5.1, the way it already did in PowerShell 7.
* **Tooling:** The README's Help now goes through why Android might refuse the install. It says where Manager keeps its signing key, so an update that won't go over your patched copy can be fixed without losing your settings. It also covers stock Pinterest and the unknown apps prompt.
* **Tooling:** The README sends people on v0.0.11 to Pinterest 14.40.0 again, the build that release patches, and names 14.41.0 as the next release's build. It had pointed them at 14.41.0, which v0.0.11 refuses. The release's prepare step now stops while the README still names a next release, so it gets rewritten for the new build before a release is cut.
* **Tooling:** The patch verifier checks how the long-press hide switches tell Pinterest's buttons apart. The sorter has to read the held button's own id and send Save, Send and both search ids to the right answer, with the ids found the way the patch finds them, and a build without them has to keep the plain answer.
* **Tooling:** The bug report form lists Filter feed among the patches you can tick. It was the one patch the form left out, and the release check stopped on that.
* **Tooling:** The release check and the publish step leave a GitHub description alone when it names no version, patch count or Pinterest build, since there's nothing in it to go stale. One that names any of them still has to match the release. This release would have stopped on the shorter description the repository uses now.
* **Tooling:** The source census reads Jman's bundle registry again. On October 14 the registry took down the files the audit read and now serves the same list from its own site, so every audit since stopped on a missing file. It reads all of the site's pages, not only the first hundred releases.
* **Tooling:** The device scripts write their lease times in UTC with a `Z` at the end. They used `+00:00`, and the other tools sharing the test phone took a lease written that way as already expired. They also read a `Z` time as UTC now. Before, a busy phone's expiry was read as local clock time, so an expired lease looked hours from ending.
* **Tooling:** The script tests now clean up after themselves. The pre-push cases remove the worktree the hook builds in, and a passing host reference run deletes its report folder. Each run used to leave both in the temp directory.

## 0.0.8 (2026-10-13)

* **Pinterest:** Long-press the Pinterest logo at the top of your home feed to open HushPinterest settings. It works even while HushPinterest is paused. The app icon shortcut and Android's App info page still open them too.
* **Pinterest:** Share file in Download history shows a frame of a saved video in Android's share sheet on Android 11 and later, where it used to show a plain file icon. The app you share to still gets the video itself with its name. Images already had a preview and work as before.
* **Pinterest:** Disable update nag checks that the spot it guards still comes before Pinterest's call to the Play Store update prompt. A future Pinterest build that asks Play Store first now stops patching with a clear message, rather than getting a guard that would run too late to stop the pop-up.
* **Pinterest:** New patch, AMOLED black. Its Black bottom bar switch paints the bottom bar pure black in dark mode, so it no longer sits as a gray strip under Pinterest's black pages. It works whether Pinterest shows the bar as one rounded piece or each tab as its own rounded button, and the strip behind the gesture handle turns black with it. Menus and buttons that share the bar's gray keep it, and light mode stays as it is. It starts off and lives on the Interface page.
* **Pinterest:** New patch, Hide closeup buttons. Two switches hide the back arrow and the visual search (lens) button that float over a pin you open, so they stop covering the picture. Your phone's back gesture still leaves the pin, and Search image in the pin menu still works. Other icon buttons in the app aren't touched. Both start off and live on the Interface page.
* **Pinterest:** Media details has Check the file for image pins. One tap reads the first 64 KB of the file a download would save and shows its real width, height, type and file size, since Pinterest's numbers can describe a smaller display copy. Nothing is fetched until you tap it, and every value says whether Pinterest supplied it or the file showed it. When the media host is too busy or slow to say whether it has the original, the result isn't kept, so the next tap asks again. Reading the file gives up after 15 seconds, even when the host never answers.
* **Pinterest:** Download visible pins has All, Images and Videos filters with counts above the list, so they and the buttons stay on screen however many pins you can pick from, and each row shows the picture its cell already has, so pins are easier to tell apart. Nothing extra is downloaded for those pictures. Download board now asks whether to queue all of a board's loaded pins, only the images or only the videos.
* **Pinterest:** Save list, in Download visible pins and Download board, writes the pins you chose to a JSON file you pick. Each pin has its Pinterest link, its title and the source link Pinterest supplied. A source link with a query, a fragment, a sign-in part or a private or reserved host name is marked as omitted instead of being cut down. Your account and cookies never go in the file. Save list works on a board even when every loaded pin is already in Download history, and when a list can't be written, the empty file the picker made is removed again. A file you picked to write over is never removed.
* **Pinterest:** Dialogs that only show something now close with Close, and ones that leave a choice untaken say Cancel. Save in Download again is now Use Download again, and the pin menu's Media details lines read Width, Height and Size. Card edges stand out more against the dark background, the overview card's color follows a right-to-left language, and a finished batch no longer repeats its whole summary in a toast while its dialog still shows it.
* **Pinterest:** A review of all five translations fixed 87 lines. Turkish now talks to you the same informal way everywhere, puts the right ending on HushPinterest, and shows an import change as old → new where it used to say "instead of". German no longer runs the Download pins and Download board names together. Spanish and Brazilian Portuguese stick to one word for switches, Portuguese calls boards "pastas" everywhere like Pinterest does, and Indonesian points to the Downloads folder by its Indonesian name.
* **Pinterest:** At large text sizes, when a dialog's buttons stack, all of them show now. Download visible pins used to show Queue selected and a sliver of Cancel, with Save list hidden until you scrolled the buttons. The list or message above scrolls instead, and the buttons never take more than half the screen.
* **Pinterest:** Toasts from a pin batch and Save list fit in the two lines Android 12 and later show. A batch whose dialog has closed gives its counts in one short sentence, and a note about pins already in Download history or a file left behind comes up as its own toast.
* **Pinterest:** Every other HushPinterest toast now fits in those two lines too, in English and in German, Spanish, Indonesian, Portuguese and Turkish. Over 40 of them used to stop partway with "...", mostly around settings import and export, download retries and the file and folder pickers. They say the same thing in fewer words. When no app can open a link, the toast now just names the address, so more of it shows.
* **Pinterest:** The Notifications page shows whether Android lets Pinterest show notifications, and one tap opens Android's notification settings for the patched app. It never changes a permission for you.
* **Pinterest:** The update check gives up after 20 seconds even when GitHub answers slowly or a connection stalls, and Check now can be tapped again right away.
* **Pinterest:** With Debug logging on, a feed module's line now names each entry that isn't a pin by its type, never its content, so a report shows everything the module carried.
* **Pinterest:** Download pins has two new switches, both off to start. One waits for an unmetered network and the other holds downloads while roaming. They cover single pins, visible pins, boards and retries, and changing them never cancels a download that's already queued. A download held back for its network shows as Queued in Download history, not as a failure, and starts by itself once an allowed network is back. Wi-Fi marked as metered doesn't count as unmetered.
* **Pinterest:** A finished download can be opened or shared straight from its Download history row. History asks Android first, so a deleted file or a download removed from history won't open anything stale. Set as wallpaper makes the same check now. The other app gets the file under its own name, like `Pinterest_123_456.mp4`, where it used to see every download as "Download pin".
* **Pinterest:** Download board keeps far less in memory while boards are loaded. Each pin is kept as its id and the media found for it instead of the whole pin. A Download history too long to read keeps its newest entries instead of starting over empty.
* **Pinterest:** Strip link tracking and Plain pin links no longer swallow text that sits right after a link with no space, like a Japanese caption after `?utm_source=x`. A hashtag or date in that text stays text, and a second link glued on after it is cleaned on its own. A link written into another link's query, like a share text with `&utm_source=` after it, stays part of that link so its tags still come off. A link longer than 4,096 characters is left as it is, so a huge pasted text can't hold up a share. Links with non-ASCII paths or queries stay whole.
* **Pinterest:** The quick checks Plain pin links makes against pin.it short links, and Download pins against Pinterest's image host, go out without any cookies the app holds for those hosts. A cookie Pinterest's short-link service sets on its answer is dropped again, so it can't stop the next lookup, and cookies Pinterest itself stores meanwhile are left alone.
