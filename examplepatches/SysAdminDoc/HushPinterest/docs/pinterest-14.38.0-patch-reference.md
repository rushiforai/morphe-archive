# Pinterest 14.38.0: Patch coverage and customization

Inspected October 9, 2026. Part of the [factory app audit](pinterest-14.38.0-audit.md). Source baseline `932f0c5`. See the audit entry point for the APK identity, live observations, and evidence limits.

## Current patch reference

This inventory describes the 23 entries in the current [patch catalog](../patches-list.json). It maps the source hooks to their intended behavior. It does not substitute for a signed-in factory comparison or prove that an account receives every server-controlled surface.

**Runtime** means a saved switch chooses between the extension and native behavior. **Mixed** includes runtime hooks plus permanent manifest changes. **Manifest** means the installed APK must be patched again to undo the change. **Infrastructure** is the settings and lifecycle wiring used by the other patches.

Current [Settings.java](../extensions/pinterest/src/main/java/app/hushpinterest/extension/pinterest/settings/Settings.java#L43) starts Hide ads, Disable analytics, Strip link tracking, and Hide advertising ID on. Optional interface, feed, and action switches start off. The patch catalog selects every patch except Spoof signature for Google sign-in. Installing those defaults is not a factory baseline. Pause disables switchable decisions but cannot restore manifest declarations or rewind requests and actions that already occurred.

Use these version-specific names for tracing; keep the actual fingerprint tied to semantic anchors and serialized field names. ## Maintenance checklist

1. **Fix the baseline.** Record original APK hash, version/code, signer, manifest, DEX inventory, and selected patch set. Keep factory, runtime-off, Pause, and repatched-without-manifest-edits as different states. A runtime-off build is not a stock control for permanent changes.
2. **Resolve semantic targets first.** Prefer serialized model fields, resource entry names, readable model descriptions, typed enum identities, and method annotations. Treat obfuscated names and numeric resource IDs as build-specific notes. Require one complete target per supported fixture or an explicit partial-capability result.
3. **Trace callers and ownership.** Check whether a menu also handles boards/profiles, a coroutine handles unrelated tasks, a size set feeds idea pins, or a generic view hosts multiple modules. Retain enough identity at the correct lifecycle boundary, then revalidate at click time.
4. **Preflight before mutation.** Resolve status stubs, host members, type shapes, inheritance, instruction order, and free registers first. Missing targets must not leave half an injection behind. Do not relax uniqueness to make a new build pass.
5. **Keep capabilities truthful.** Wire a new feature through [PatchFamily](../extensions/pinterest/src/main/java/app/hushpinterest/extension/pinterest/settings/PatchFamily.java), [SettingsStatus](../extensions/pinterest/src/main/java/app/hushpinterest/extension/pinterest/settings/SettingsStatus.java), [Settings](../extensions/pinterest/src/main/java/app/hushpinterest/extension/pinterest/settings/Settings.java), and the settings page. Add only intended transferable values to [SettingsBackup](../extensions/pinterest/src/main/java/app/hushpinterest/extension/pinterest/settings/SettingsBackup.java). Defaults and restart boundaries must be explicit.
6. **Preserve native fallback and data.** Off/Pause/cold-start/unknown-model paths should retain host behavior. Unknown URLs and signed links stay intact. Download retries require an owned, failed request and a still-valid supplied address. Avoid account data, URLs, and screen text in diagnostics.
7. **Review exact manifest deltas.** Any new metadata, permission, property, query, or component needs the selected-patch contract in [manifest-delta-allowlist.txt](../scripts/manifest-delta-allowlist.txt) and [release-receipt.ps1](../scripts/release-receipt.ps1). Runtime controls must not claim to undo permanent changes.
8. **Use focused contracts.** Extend the relevant [fixture tests](../patches/src/test/kotlin/app/morphe/patches/pinterest) and [runtime tests](../extensions/pinterest/src/test/java/app/hushpinterest/extension/pinterest). Cover changed/missing target refusal, register/reference integrity, disabled paths, and the specific regression. Reuse exact fixture/bundle evidence; do not assume a test's existence proves it passed for the current artifact.
9. **Exercise the real surface.** The account must actually show the targeted row, prompt, or media type. Compare off/on/Pause/restored states. For ads and analytics, distinguish hidden content, skipped initialization, attempted upload, and actual network traffic. For notifications, local plumbing does not prove live delivery. For downloads, worker submission does not prove a saved file.
10. **Check presentation and cost.** Confirm layout gaps, accessibility focus, TalkBack, large text, rotation, and theme contrast where relevant. Measure data/CPU/memory when making savings claims. Retain compatibility with Pinterest's own texture/network/lifecycle constraints.
11. **Refresh the reference when targets move.** Update catalog descriptions, capability limits, exact APK facts, semantic anchors, and open acceptance gaps together. Keep the live observation date/account state separate from static build facts, and record whether a feature is released, present only in source, or still a candidate.
