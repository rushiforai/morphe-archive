# Changelog

Every Hushfacebook release, newest first.

## 0.3.4 (2026-09-27)

* **Facebook:** This public release includes all changes recorded below for development builds 0.3.0 through 0.3.3. Those builds weren't published separately. There are now 43 patches, up from 27 in v0.2.0, for the same supported Facebook 580 and 577 bundles. Morphe Manager 1.32.0 or newer is required.
* **Facebook:** Settings now open to a searchable overview. Six main categories lead to their own pages, with the rest under More settings. Search keeps the real controls in its results. Back returns through the pages, and rotation keeps your location and search.
* **Facebook:** The settings pages have clearer spacing and consistent dark surfaces, with Material icons and refreshed dialogs. The existing light and wallpaper themes still work. Pause and Resume are available from the overview, with Undo before restarting.
* **Facebook:** Video file names now show an example while you type. The field appears before its help text, so it's easier to reach above the keyboard. Several long descriptions are shorter, with updated translations in all five supported languages.
* **Facebook:** Opening a page starts at the top, and Back restores the category list's scroll position. The overview action leaves more room for status text. All six download quality choices fit at the normal text size.

## 0.3.3 (2026-09-27)

* **Facebook:** Tap to play now clears the initial Reels play button when playback starts. Facebook only cleared that state for certain viewer configurations, which could leave the button over a moving video. The fix uses the existing control cleanup and keeps paused controls and the off setting unchanged.
* **Facebook:** A quick swipe after tapping Play no longer carries that tap into the next video. Swipes expire the previous tap and its player bind grace, while the current video and direct media controls keep working.
* **Facebook:** Checked on the S22 with Facebook 580: the play button clears during playback and returns on pause, and both ordinary and rapid swipes leave the next reel waiting. Turning Tap to play off or pausing Hushfacebook restores native playback. The reporter's exact viewer configuration still needs confirmation.
* **Facebook:** Marketplace mode passed S22 checks for cold launch, listing details, seller profiles and the listing's message composer. Return to regular Facebook restored six tabs and kept the saved startup choice. No message was sent. Incoming notifications and shared-listing links still need live checks.

## 0.3.2 (2026-09-27)

* **Facebook:** Marketplace only is now included in the default patch selection. Its switch and Open on a chosen tab start off, so a normal installation keeps Facebook's navigation. Stored values are kept; older development builds that never stored their default-on choice need the switch enabled once after upgrading.
* **Facebook:** Marketplace settings now show the mode's actual state, explain a missing or hidden Marketplace tab, and disable the startup choices the mode overrides. Return to regular Facebook restores normal navigation at the next restart without resetting other settings. The Menu settings entry is included with the mode.
* **Facebook:** Quiet social notifications can silence entertainment suggestions, memories, birthdays and friend suggestions while Marketplace mode is selected. It starts off and preserves the individual notification settings. Messages, trading updates and unknown types pass through.
* **Facebook:** Skip feed preloading can hold back two feed warm-ups once Marketplace mode is active. It starts off, preserves the screen-on scheduler cleanup and leaves early startup fetching alone. No data or battery reduction has been measured.
* **Facebook:** The new controls and status messages are translated into all five supported languages. Offscreen Android view captures cover the active and regular modes; live listing, messaging and notification checks remain pending.

## 0.3.1 (2026-09-27)

* **Facebook:** Compatible video saves now keep a known H.264/AAC pair even when an unchecked single MP4 has the same or higher resolution. Previously that file could take priority and bring back the sharing problem reported in #11.
* **Facebook:** Normal video saves prefer AAC-LC or HE-AAC sound when available, while keeping the selected video resolution. A manifest with sound in an unsupported format now falls back to the complete MP4 instead of producing a silent video. These changes address download paths relevant to #14; Xiaomi Gallery playback and WhatsApp import still need confirmation on the affected apps.
* **Tooling:** The stale-save test now uses a retired notification ID. Its fixed ID could collide with the next save after other tests ran, making a correct cleanup fail the test.

## 0.3.0 (2026-09-27)

* **Facebook:** This was a development build. The published bundle remained v0.2.0 while the remaining phone checks and reported failures were investigated. The README now records the Media settings and Xiaomi Gallery reports and removes stale notes for checks already recorded below.
* **Tooling:** A first push of a feature branch now checks its code without treating the branch's copy of `patches-bundle.json` as a new release. The old hook compared unreleased patch counts with v0.2.0 and blocked the push.
* **Facebook:** New patch, Marketplace only, for people who open Facebook just for Marketplace. The tab bar keeps Marketplace, Notifications and your profile or Menu, and Facebook opens on Marketplace. Home with the news feed goes, and so do Video, Friends, Feeds, Groups, Gaming and Events, the same way a tab you hide in Facebook's own tab bar settings goes. It's off in Morphe Manager, and once it's in, its switch sits under Opening Facebook in Hushfacebook's settings and takes effect when Facebook restarts. Notifications and links to posts still open, and a tab bar without Marketplace is left as it is.
* **Facebook:** Choosing a font file can no longer leave Hushfacebook's settings naming one font while Facebook draws in another. The file's name is saved before its copy takes the old one's place, and if either step fails, the font you had stays, name and all. The old copy is never deleted before the new one is in place, so a failed pick can't lose both. Use your phone's font also shows up whenever a copy is left over with no font named, so there's always a way to remove it.
* **Facebook:** Open on a chosen tab now stops asking for the tab if Facebook still hasn't built its main screen about 12 seconds after the screen first shows. From then on Facebook's own start decides, so a tab bar it builds late or reloads later can't be pushed onto the chosen tab. The diagnostic report's tab bar reading also waits until the screen shows a tab, so Hushfacebook never sets up Facebook's tab bar data before Facebook does.
* **Facebook:** Open on a chosen tab didn't open the chosen tab when Facebook started from scratch on accounts where Facebook's own setting for it is off. Those starts still landed on Home. Facebook's start-up swaps the request from the icon for a copy with no tab in it, and its tab bar ignores the tab a start asks for unless that server-side setting is on. Now the tab goes back into the copy and the tab bar uses it, but only while the screen started from the icon is being built, so notifications and links still open where they lead. That lasts until Facebook has built the screen, which on a cold start happens behind its splash screen after the screen has already shown. The diagnostic report also reads the tab bar right after a cold start now, where it used to call it unreadable.
* **Facebook:** A saved video whose name is already in the save folder now gets the time of the save on the end, like `Some Page_20260925_143005.mp4`. With a name like `{owner}_{posted}`, a second video one person posted that day used to be left to Android, which numbers each repeat up to (31) and then refuses the save. The Video file name dialog says so too.
* **Facebook:** The Hide sponsored reels and Hide AI-detected reels and videos rows now say that a change starts with the next batch of reels Facebook loads. Both filters work on each batch as it arrives, so reels already loaded stay as they were. The README says so too.
* **Facebook:** The README now says why Meta's Facebook builds for Android 9 and Android 8 can't be patched. They keep all of their code except a small startup part in a compressed archive the patcher can't read, so none of the patches apply, rather than lacking the code some patches need, as it used to say. Android 11 and newer is the only range Hushfacebook supports.
* **Facebook:** Patching a Facebook build for Android 9 or older now stops at once and says why. Such a build keeps nearly all of its code in a compressed archive the patcher can't read, so the message points to the (arm64-v8a) (Android 11+) build instead. It used to stop with a note that no class of FbMainTabActivity's hierarchy declares onCreate, which named the symptom and not the build.
* **Facebook:** New patch, Open on a chosen tab. Starting Facebook from its icon opens the tab you pick, which is Marketplace unless you change it. Home, Feeds, Video, Friends, Notifications and Menu are the others. It asks Facebook for the tab the way Facebook's own shortcuts do, so notifications and links still open where they lead, and a tab your tab bar doesn't have opens Home instead. It only acts as Facebook starts, so the tab you tap afterwards stays. The patch starts off in Morphe Manager, and once it's picked, its switch and the list of tabs sit under Opening Facebook in Hushfacebook's settings. People on the r/MorpheApp thread who only open Facebook for Marketplace asked for it.
* **Facebook:** A saved video's quality in the diagnostic report, and in the ranking that picks which file to save, no longer comes from the video's length. A 640x360 video that ran 1485 seconds was listed as 1485p and could outrank a real 720p file. A file that doesn't say its quality now reads unknown.
* **Facebook:** Hushfacebook's settings page has a Jump to a section row at the top. It lists the page's sections, so Downloads or Links is two taps away instead of several screens of scrolling, and Back returns you to where you were once before it closes the page.
* **Facebook:** The check that runs on every patched build now holds Don't send reel watch history to what it promises. Facebook's one call that sends the batch has to be gone and Hushfacebook's stand-in has to take its place, reading the same values. Before, a build that kept the old call beside the new one and still sent every batch could have passed.
* **Facebook:** A new test ties each patch to its own switch in Hushfacebook's settings. A patch that turned on a misspelled switch would have applied without a word and then shown as not patched.
* **Facebook:** Use the system font can now draw Facebook in a font file you pick. A new Font file row under Appearance in Hushfacebook's settings opens Android's file picker for a TrueType or OpenType font of up to 20 MB, and Hushfacebook keeps a copy in Facebook's own storage once Android has shown it can draw with it. If that copy ever stops loading, your phone's font takes over, and Use your phone's font drops it. The screens Facebook builds with React Native, such as parts of Marketplace, follow the patch now too. The patch keeps its name and its switch, so an update from 0.2.0 keeps your choice in Morphe Manager and the switch as you left it. The picked font stays out of exported settings files, since a file can't carry the font itself. Asked for in issue #1.
* **Facebook:** The check that runs on every patched build now reads Facebook's code the way the patcher sees it, with what the extra download files carry merged in. On 580 the in-app browser brings its own copy of some of Facebook's methods, and read against base.apk alone they showed up as about 15,000 changed or new methods the patches never touched. Now only the methods a patch really changed or added are listed. A method Facebook defines twice is checked in each copy a patch changed, so a copy nothing touched can't hide a bad one. Meta's signature is still checked on base.apk, and the merge has to carry base.apk's code byte for byte.
* **Facebook:** New switch under Downloads, Save videos other apps can open. It's off by default. Facebook's sharpest version of a video is often AV1 with xHE-AAC sound, which Gallery and VLC play but apps like WhatsApp turn down with "Can't send this video". With the switch on, every video you save, from Reels, Stories, the feed or Watch, is H.264 with AAC sound within your Download quality, and when Facebook offers no such pair you get its own single MP4 file instead. So a save can come out below the sharpest version. A video that has neither saves the way it always did. Reported in issue #11.
* **Facebook:** The README now points to Facebook's own setting for taking the Reels tab off the tab bar: Settings, Tab bar, Customize the bar, then Hide next to Reels. It worked straight away on a test account, so Hushfacebook doesn't add a switch of its own for it.
* **Facebook:** New patch, Hide the Get Messenger card. Facebook's own Chats kept a big "Get the Messenger app" card above your chats even with Messenger installed. Facebook does drop that card when Messenger is there, but it only counts a Messenger signed with its own key, and a re-signed Facebook never matches Meta's. The patch hides the card while Messenger is installed and leaves your chats, search and notes alone. Without Messenger the card stays, so you can still install it from there. It's on by default, with its switch under Chats in Hushfacebook's settings.
* **Facebook:** New patch, Tap to play. Videos, reels, stories and music wait for your tap instead of starting by themselves, and a tap plays them as usual. People reported profile Stories, Reels, Marketplace ads and songs on posts starting on their own, some of them with Facebook's Autoplay setting already off. It works in Facebook's two video players, where a start goes ahead only within a second of a tap, from the media controls or the seek bar, or on something a tap already started. What Facebook starts because a video came into view or because you came back to a screen still waits. Facebook's own Autoplay setting reads Off while the switch is on, so the feed and the Reels controls draw their own play button, and it reads what you chose again when the switch is off. The patch starts off in Morphe Manager, and once it's picked, its switch sits under Playback in Hushfacebook's settings. With Debug logging on, the diagnostic report says what each start was and why it went ahead or waited. It hasn't been checked on a signed-in phone yet.
* **Facebook:** With Tap to play on, a reel that's waiting for you now shows Facebook's own play button right away, so one tap on it plays the reel. It used to take one tap to bring up the button and a second to play. Ad breaks keep Facebook's own controls.
* **Facebook:** New patch, Hide Menu promotions. It takes the Upgrades and Also from Meta sections out of Facebook's Menu, the list you open from the Menu tab or from the corner of your profile. Upgrades is where Facebook puts its offers, and Also from Meta lists Meta's other apps next to ads for its headsets and glasses. Each section has its own switch under Menu in Hushfacebook's settings, and both start on. Settings and privacy, Help and support, Log out and your shortcuts stay where they were. Hushfacebook knows the two sections by the names Facebook's code gives them rather than by their titles, so it works in any language. Reported in issue #9.
* **Facebook:** New patch, Hide Meta AI in search. Facebook's search can put a Meta AI answer on top of your results, mix Ask Meta AI prompts in among them, and send a search to Meta AI when you tap a suggestion. With the patch those answers and prompts stay out, and a suggestion opens ordinary results. People, groups, pages and posts are left alone, and the Meta AI button beside the search box and the Meta AI tab on the results page still work when you want them. It's on by default, with its switch under Search in Hushfacebook's settings. On a test phone, a search for pizza lost its Meta AI summary while the Meta AI tab still answered.
* **Facebook:** New patch, Default comment order, for people tired of comments reverting to Most relevant. Pick Most relevant, Newest or All comments under Comments in Hushfacebook's settings, and a post's comments open that way wherever Facebook would otherwise choose. An order you pick in a post's own sort menu still wins, and it now stays for that post when the comments reload or you open them again, until Facebook restarts. A link to one comment, like a reply notification, still opens in Facebook's order, and so does a post opened on its own page. It's off in Morphe Manager, and once it's in, the order starts as Facebook's own, so nothing changes until you pick one. Settings files carry the order too. On a test phone, comments opened in the chosen order and kept the order picked in a post's comments.
* **Facebook:** The README's notes on Tap to play now match what a test phone showed. Opening the Reels tab counts as your tap, so the first reel plays and the next one you swipe to waits, and feed videos and reels were checked on a signed-in phone.
* **Facebook:** Two new patches take ads out of search and profiles. Hide sponsored search results leaves the ads out of Facebook's search results. Facebook gives each block of results a role and keeps its own list of the roles that are ads, and only those blocks go, so the people, pages and posts you searched for stay. Hide sponsored profile posts leaves out the ads between the posts on someone's profile or a Page, the ones Facebook tags as sponsored there. The profile's own posts stay. Both are on by default, with their switches under Search and News feed in Hushfacebook's settings, and the diagnostic report counts what each one saw. The search one shares its place in Facebook's code with Hide Meta AI in search, and each keeps its own switch. On a test phone both ran on every search page and profile row without finding an ad to take out, because the test account isn't being shown these ads. Marketplace ads have a patch of their own, further down. Ads inside videos were already blocked by Hide sponsored reels.
* **Facebook:** New patch, Hushfacebook in the Menu. Hushfacebook's settings now have a row in Facebook's own Menu. Open Settings and privacy and it's the last row, called Hushfacebook settings in your language. The logo long press and the launcher shortcut still work, and like them the row stays while Hushfacebook is paused, since the settings are where you turn Pause off. Facebook's record of which Menu rows you saw and tapped leaves this one out. On a signed-in test phone the row sat at the end of Settings and privacy and opened the settings.
* **Facebook:** The "People you may know" switch of Hide suggested and promoted posts now also takes the carousel of friend suggestions off your own profile, the one under Add to story and Edit profile. It used to reach only the row in the feed. Your profile's header, friends and posts stay. Hushfacebook finds the carousel by the name Facebook's code gives it, not by its title, so it works in any language. The diagnostic report counts how often your profile built it and how often it went. On a signed-in test phone the carousel was gone and the rest of the profile was still there.
* **Facebook:** Hide AI-detected reels and videos can now read the reels on the Reels tab. A test phone showed it never removed one there: all 20 reels it checked were counted as "no model". The Reels tab keeps each reel's video and post one step further in than the filter looked. The filter now also reads Facebook's own detection flag on those by the field's name, the same flag Facebook's Reels menu reads to offer its AI info row. A reel flagged that way is taken out, and one it can't read stays. The diagnostic report counts these reels under kinds that start with "tree". Back on the test phone, all 44 reels it saw were read this way. None of them carried the flag, so a flagged reel going away is still to be seen.
* **Facebook:** Hide suggested and promoted posts has a new switch, Hide suggested groups (issue #8). It takes out the row of groups to join that Facebook puts between posts, the one under a "Suggested for you" header with a Discover more groups button. Facebook's app tells that row apart from People you may know and friend requests by its own type, even though all three share one piece of code, and the switch goes by that type. Posts from groups you're in and friend requests stay, and you can still look for groups from the Groups tab. It's on by default, and it hasn't been checked on a phone yet, since the test account hasn't been shown the row.
* **Facebook:** Hide suggested and promoted posts has another new switch, Hide "Stories you might like" (issue #10). It takes out the row of Stories from people you aren't connected to that Facebook puts between posts. Facebook's own code marks that row with a flag and opens its Stories as suggestions because of it, and the switch reads the same flag. A row of your friends' Stories stays, and so do the Stories tray and a link straight to a Story. It's on by default. It hasn't been checked on a phone yet, since the test account hasn't been shown the row.
* **Facebook:** New patch, Block promotional notifications. People asked for Facebook's trending and other promotional pushes to go quiet while messages, friend requests and login alerts keep coming. Every push Facebook sends carries a type its own code names, like BIRTHDAY_REMINDER or TOP_TRENDING_VIDEO, and the patch reads it just before Facebook posts the notification. Six switches under Notifications in Hushfacebook's settings cover trending videos and reels picked for you, memories, birthdays, group and Page highlights, People you may know, and nearby places and weather. They all start off. A type Hushfacebook doesn't know always comes through, and so do messages, friend requests, comments, mentions, calls and login alerts. Android's own notification categories for Facebook keep working too. It hasn't been checked on a phone yet.
* **Facebook:** New patch, Hide suggested stories, for the stories Facebook puts in the Stories tray from people and Pages you visited but don't follow (issue #7). Facebook marks those itself: the tray's own card writes Suggested under a story when the story carries Facebook's suggested flag or its first label is SUGGESTED, and the patch reads those same two marks, so it works in any language. Only those stories leave the tray. Your friends' stories, the Pages you follow, your own story and Create story stay, and so does anything Hushfacebook can't read. It's on by default, with its switch under Stories in Hushfacebook's settings, and a change shows the next time Facebook loads the tray. On a test phone it took two suggested stories out of each load of the tray, and no story marked Suggested was left in it.
* **Facebook:** New patch, Hide sponsored Marketplace listings. Marketplace is drawn by React Native, so its ads never pass through a list Hushfacebook could filter, but the requests its React Native code sends go through Facebook's own network code first, and the patch changes those requests on their way out. The feed's request has a setting of its own that asks Facebook's servers to leave the ads and boosted listings out, and the patch turns it on. The four requests that fetch nothing but ads aren't sent at all. The listings people post stay. It's on by default, with its switch under Marketplace in Hushfacebook's settings, and with Debug logging on the diagnostic report names each Marketplace request and what was done to it. On a test phone the ads-only requests never went out, the feed's own request already asked to skip its ads, and a dozen screens of Marketplace showed no sponsored or boosted listing between the ordinary ones.
* **Facebook:** Use the phone's emoji now reaches the big emoji a chat shows on its own, like the one a chat's emoji button sends. Facebook drew that one as a picture of Meta's emoji it downloads, so it kept Meta's look. With the switch on, Facebook now skips that picture and draws the emoji with your phone's emoji font, the way it already showed it while the picture loaded. Reactions and stickers stay as they are. This hasn't been checked on a phone yet.
* **Facebook:** Open links in external browser now only unwraps the links Facebook's own code treats as its click tracker. It used to take any Facebook link carrying a `u` for one, so a share link such as `facebook.com/sharer/sharer.php?u=...` would have opened the shared page in your browser instead of Facebook's share page. What it unwraps now is the list Facebook 577 and 580 check for themselves: `/l.php` on Facebook's domains, the older link forms Messenger's cards use, and the warning page Facebook shows before a suspicious link. Links in chats that Meta wraps on `l.messenger.com` still open in your browser too. A link wrapped twice unwraps all the way. This hasn't been checked on a phone yet.
* **Facebook:** New patch, Hide posts by words. Under News feed in Hushfacebook's settings you list words or phrases to hide, one per line, and a second list of words that keep a post whatever else it says. A post goes when its own text, or the text of a post it shares, has a word from the first list and none from the second. Matching is plain text anywhere in the post, capital letters don't matter, and there are no patterns. Each list holds up to 50 phrases of 2 to 60 characters. A post with no text, or one whose text can't be read, stays. Hushfacebook reads the words the author wrote, not Facebook's translation, and never puts them in the diagnostic report or a log, which only count the posts each list matched. The lists go into exported settings files with the rest. The switch starts off and the lists start empty. On a test phone one common word took 17 of 30 posts out of the feed, and putting the same word in the keep list brought every one of them back.
* **Facebook:** New patch, Tag suggestions only after @, for people tired of a list of people to tag popping up over ordinary words. Facebook's text boxes look people up for any longer word they take for a name, even with no @ in front, and a tap in the wrong place turns that word into a tag. With the patch in and its switch on, only a word that starts with @ brings up people to tag. Hashtags still come up after #, tagging people in photos isn't touched, and what you type is never changed. A list an earlier @ left open closes once you type on. It's off by default, with its switch under Writing in Hushfacebook's settings. On a test phone, names typed into a comment brought up nobody to tag, and typing @Ma still brought up the list.
* **Facebook:** New patch, Resume long videos. A video longer than two minutes that you stop partway now picks up where you left it the next time it plays, once each time it opens, even after Facebook restarts. Drag the seek bar first and your spot wins, and so does a place Facebook carries over itself, like a link to a moment in the video. Stopping in the last 10 seconds counts as finishing it. Reels, live videos, ads, looping videos and songs start as usual. Hushfacebook remembers up to 200 videos for 30 days, on your phone only, and the diagnostic report counts what it saved and resumed without saying which videos. The patch is in by default with its switch off, under Playback in Hushfacebook's settings. It hasn't been checked on a phone yet.
* **Facebook:** Hushfacebook's edit dialogs now shrink to fit above the keyboard: Save folder, Video file name and the two word lists. With a large font size, the video file name's explanation pushed Save and Cancel under the keyboard on a phone screen, where nobody could reach them. On an emulator at double text size the dialog now keeps its title, scrolls its explanation and shows both buttons above the keyboard.
* **Facebook:** Hide AI-detected posts has a new switch, Also hide posts labelled as AI. On a test phone with the feed switch on, group posts showing "AI content" next to the poster's name stayed in the feed, and all 14 posts the switch read had Facebook's detection flag off. Facebook shows that label for two reasons, its own detection or the poster saying the post was made with AI, and each has a flag of its own. The feed switch goes by the detection flag alone and still does. The new switch, right below it under News feed, reads the poster's flag too, so a post with either flag goes. It starts off, and a post whose flags can't be read stays. The diagnostic report counts the posts it read under Creator AI label flag, and with Debug logging on, each feed post's log line says what both flags read. It hasn't been checked on a phone yet, so whether those group posts go with it is still to be seen.

## 0.2.0 (2026-09-26)

* **Facebook:** New patch, Use the phone's emoji. Facebook draws the emoji in its text with Meta's own emoji font, which it downloads to your phone. This patch has it use your phone's emoji font instead, so emoji in posts and comments look like the ones on your keyboard, and so do the smileys Facebook makes from text like :). Reactions and stickers are pictures rather than text, so they stay as they are. The patch starts off in Morphe Manager, and its switch, under Appearance in Hushfacebook's settings, starts on once you pick it. Restart Facebook after changing the switch. Asked for on the r/MorpheApp thread.
* **Facebook:** The Video file name setting takes two more tokens. `{owner}` becomes the name of whoever posted the video and `{posted}` the day it went up, so `{owner}_{posted}` names a saved video `Some Page_20260925.mp4`, whether it came from Reels, Stories, the feed or Watch. Both are left out when a save doesn't know them, the way `{video_id}` is, and the settings dialog names all four (issue #6).
* **Facebook:** The Hide Stories tray switch now says, in its settings row and in the README, that it takes effect when Facebook restarts. Facebook builds the feed's fixed rows once, when the feed is set up, so pulling to refresh or coming back to the feed neither brings the tray back nor takes it away. The README used to say the tray comes or goes the next time the feed is built.
* **Facebook:** New patch, Stop update prompts. A patched Facebook can't install Meta's updates, so this stops Facebook asking. It turns off the two things Facebook does for Meta App Manager, the update promotions it shows for it and the push message that has the manager look for an update, and it drops the chat promotions aimed at older versions. Its switch sits under Updates. Meta App Manager's own notices come from that app, which the patch can't reach, and the README says what to do about them.
* **Facebook:** New patch, Use the system font. It draws Facebook's text in your phone's font instead of Meta's Optimistic, at the same weight and slant, and leaves the icons and the text you put on a story alone. The patch starts off in Morphe Manager, and its switch, under Appearance in Hushfacebook's settings, starts on once you pick it. Restart Facebook after changing the switch. Asked for in issue #1.
* **Facebook:** You can now open Hushfacebook's settings from inside Facebook by long-pressing the Facebook logo at the top of your feed, handy on a launcher with no long-press menu (#2). A tap on the logo still does what it always did, and the Hushfacebook item on Facebook's launcher icon stays.
* **Facebook:** Hide AI-detected posts now reaches Reels and Watch. A new switch under Reels and Watch takes out the reels and videos Facebook's own detection marked as made with AI, going by the same flag the viewer's own AI label reads, so a reel only its creator labelled stays. Like the feed switch it starts off, and a reel whose flag can't be read stays.
* **Facebook:** The README has a Troubleshooting section for the Morphe Manager messages people have run into: Unsupported Version on another build of 580, a damaged .apkm, running out of storage, an outdated Manager and install conflicts. It also says what Meta can see of a patched Facebook and where to ask for help, and its install steps name the exact APKMirror bundle to take.
* **Facebook:** Block background ad prefetch, Block ad telemetry, Disable Audience Network and Hide suggested and promoted posts now name, in the patch log, each target a Facebook build lacks. They still apply to whatever the build has, and they still stop when it has none of their list. Before, a build that had renamed most of a list patched without a word. Patching Facebook 580 lists six feed units it no longer has.
* **Facebook:** New patch, Don't send reel watch history. The Reels viewer sends Facebook the reels you watch in batches, as a list of their ids that Facebook ranks your Reels feed with and nobody else sees. The patch holds each batch back at the moment it would go out, after it has left the queue, so a batch it holds back isn't kept to send later. Reels you've already watched may come back in the feed. The patch starts off in Morphe Manager, and its switch, under Reels and Watch in Hushfacebook's settings, starts on once you pick it.
* **Facebook:** The diagnostic report now also leaves out a Facebook address with nothing in front of it, like facebook.com/ followed by a profile name. It used to catch one only with www. or another prefix. No line in a report prints such an address today, so this covers the next one that might.
* **Facebook:** A debug setting stored with the wrong type used to make Facebook crash as it started. Now Hushfacebook clears that value and starts with the default, and the diagnostic report says which setting it was. Nothing writes such a value today, but a hand-edited or restored preferences file could.
