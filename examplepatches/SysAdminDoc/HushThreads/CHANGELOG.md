# Changelog

Changes in the source build, then released versions.

## 0.0.18 (2026-11-13)

* Meta's own Instagram won't open Threads posts in HushThreads, and the note about it under Links in HushThreads settings now tells you what to do instead. Patch Instagram with HushGram in the same Morphe Manager so both share one key, and Instagram opens Threads posts and profiles right in HushThreads. Asked about in #8.
* New `Spoof SIM region` patch. Threads sees a SIM and network from the country you pick, with one of that country's real carriers, instead of your own. There are 69 countries to choose from. It starts off, so turn it on and pick one in HushThreads settings > Privacy. Meta can still go by your connection and your account, so it won't hide where you are by itself. Asked for in #25.
* HushThreads now patches Threads 455.0.0.55.72 only, on all nine APKMirror variants (arm64-v8a, armeabi-v7a, x86_64 and x86). Update Threads to 455 before you patch. v0.0.17 is the last release for 454.0.0.54.79.
* Hide ads and Hide suggested users keep up with how Threads 455 stores For You. It writes every page and every single post straight into the feed cache now, and it can slip an ad into a page you're already scrolling. All of those go through the filters, and a page keeps its posts as they were when an ad gets turned away.
* Hide suggested users also takes the suggested threads off the bottom of a post you open. It has its own switch, `Hide suggested threads`, under the other two on the Feed page, and it starts on. The post and its replies stay. Asked for in #24.
* New `Full size profile pictures` patch. When you open someone's profile picture on their profile, it shows full size in a viewer of its own instead of Threads' small circle. You can pinch to zoom, and with Save media on there's a Save button too. It's in Manager's default selection, but its switch under Appearance in HushThreads settings starts off. Asked for in #22.
* The bundle is built on Morphe patcher 2.3.0 now, the one that comes with Morphe Manager 2.5.0 and Morphe Desktop 2.1.0. Older Manager builds can't load it, so update Manager to 2.5.0 or newer first.
* With `Show exact post times` on and a large font, a post's time stays in one piece. Under a long name it used to break after the month or the day, with "Nov" on one line and "5, 2:30 AM" on the next. Now the whole time moves under the name when it doesn't fit beside it.
* New `Change package name` and `Change app name` patches. Keep your regular Threads and install HushThreads next to it as a second app with its own sign-in. Neither patch is in Manager's default selection. HushThreads settings show the copy's package name and app name under Set when you patched. Asked for in #23.
* **Tooling:** The full patch check, which applies every patch, passes with `Change package name` in the bundle. It used to read the renamed package and its renamed permissions as an unknown app asking for new permissions. The checks that compare a patched build with the clean one follow Threads 455 too, where three of the places they read had moved.

## 0.0.17 (2026-11-05)

* New `Show exact post times` patch. Posts and replies show the date and time they went up instead of 3h or 2d, in your phone's 12 or 24-hour format, and TalkBack reads that same time out. It's in Manager's default selection, but its switch under Posts in HushThreads settings starts off.
* New `Filter comments` patch, contributed by @Cuhosuaxemay in #21. Replies to a post that match words or domains you list are left out before Threads builds its rows from them, so a spam reply ending in a shop link never shows. A reply and the replies shown under it are checked as one. A second switch under it also hides any reply with a web link, and a bare site name like shopee.vn goes in your list instead. Both start off, the matching ignores letter case, and the replies that stay keep their order. The switches and the list are in a new Comments section in HushThreads settings.
* The HushThreads settings look like the other Hush packages' now. The logo and name sit at the top and scroll away under the top bar. Each section opens in place on the main page instead of on a page of its own, and Pause moved up into the bar. A toggle under search shows every setting in one long list. Support at the bottom has Report a problem, a Restart Threads button and the Ko-fi link, and the build line sits under everything in small type.
* HushThreads settings and messages come in Italian, Korean and Traditional Chinese now. Phones set to Chinese for Taiwan, Hong Kong or Macau get the Traditional Chinese, which started from the translation NikolaJyun made in their fork.
* A section near the bottom of the settings opens with its first setting in view. Before, its settings went in below the edge of the screen, so it looked like the tap did nothing.
* Each way into HushThreads settings has its own switch under Pause, backup and diagnostics now, so you can take away the app icon shortcut, the row in Threads' settings or the long press on the logo. The last one that's on stays on, so there's always a way back in, and App info opens the settings whichever ones you keep. The row only counts on a Threads build that can show it. Asked for in #18.
* **Tooling:** Before anything gets tagged, a release checks the signature on the bundle copy it's going to publish, which it takes right after the build so nothing else in the checkout can swap it. That copy has to match the checksum the build wrote, and its signature has to verify against the key in `morphe-signing.pub`. One that changed after it was signed stops the release there instead of reaching Morphe Manager. The fixture runs, the release receipt and the index update read that same copy too, so they describe the bundle that's tagged and not whatever a later build left in the checkout.
* **Tooling:** The whole-app walk follows the new settings layout. It opens each section on the main page and folds it again, and it checks the one-list view from the toggle under search before putting the toggle back the way it was.
* **Tooling:** Changelog entries don't open with a "Threads:" label anymore. HushThreads only patches Threads, so it repeated itself on every line. The release scripts stopped adding or asking for it, and they drop it from any bullet that still has one when a release is cut.
* **Tooling:** The bundle signing key comes from `HUSHTHREADS_BUNDLE_SIGNING_KEY` first and `MORPHE_SIGNING_KEY` second, so a shell that kept another repo's key doesn't fail the key check.
* **Tooling:** A fresh checkout builds again. Dependency verification was missing the hash for junit-bom 5.13.1's module file, so Gradle stopped before compiling anything unless that file was already trusted locally.
* **Tooling:** A release walk ties the installed APK to the bundle and the inputs it was patched from. Publish checks its manifest and identity again, and wants every screen covered with a clean result. A walk on an install that was already on the phone needs that install's patch receipt, and a stale or incomplete one is refused.
* **Tooling:** The release description fixtures test conflicting build claims in the current facts now, ahead of the historical notes.
* **Tooling:** The notice mirror check waits 400 ms between requests, so it doesn't draw rate limits when other Hush repos check the same mirrors at the same time.
* HushThreads now patches Threads 454.0.0.54.79 only, for all eight APKMirror variants across arm64-v8a, armeabi-v7a, x86_64 and x86, including the ARMv7 and x86 builds APKMirror added a day after release. The build is matched by version name, not pinned to one code, so a reupload of the same version works too. Update Threads to 454 before you patch, and use Morphe Manager 2.4.0 or newer. v0.0.16 is the last release for 452.0.0.50.64.
* HushThreads builds on Morphe patcher 2.2.0 now, so patching needs Morphe Manager 2.4.0 or newer. Older Managers refuse the bundle. On a computer, use morphe-desktop 2.0.0 or newer.
* Patching goes through on Threads builds that keep a shared link, a post or a long press override in a high register. `Sanitize sharing links` and the Copy text hook used to stop the whole run there, and 454's ARMv7 and x86 builds do it with Share to Instagram's link. Their hooks now read a copy of the value. Reported in #20.
* Save photos and videos now works on text posts that show a video from somewhere else. When a post has no media of its own, the Save row finds the post it links, quotes or reposts, and saves that post's video or carousel under that post's details. A post's own media still comes first.
* The share sheet's Messenger tile opens a re-signed Messenger now, same as More > Messenger always did. Threads' launcher only accepts Meta's own signature and the tile ignored the refusal, so nothing happened. Every tile in that sheet falls back the same way. It's part of `Restore screens on re-signed builds`, with no switch.
* Patched 32-bit Threads starts normally on the ARMv7 and x86 variants whose manifest asks for extracted native libraries. Merging the bundle compresses those libraries, and Threads tried to read them straight out of the APK. It loads them from the folder Android unpacked them to now.
* A crash in Threads' first minute is kept now, so the next diagnostic report has its stack trace, the Threads build and which switches were on. Safe mode used to count those crashes without keeping any of them. A crash later on is kept only while Debug logging is on, and an error Threads recovers from on a background thread leaves the earlier crash in place. `Clear diagnostic data` removes a kept crash too.
* Hide ads and Hide suggested users now also clean up For You when Threads keeps it in its spool cache. On some accounts Threads stores For You there instead of in the feed cache, and pages that went that way skipped both filters. A diagnostic report counts spool pages separately, so it shows which cache your For You uses.
* Hide ads also catches an ad Threads slips into a For You page you already have. Threads places some ads into the page it's holding instead of sending them with a new one, and those never passed through either filter. A diagnostic report counts the inserted items it checked and the ads it kept out.
* Hide ads and Hide suggested users also cover the other ways Threads writes For You into its cache. Refreshes, the cold-start page and some paging write their posts in directly instead of through the usual page merge, so on either cache those skipped both filters. So did a single post or card Threads adds, slots in after a post, or swaps in for one it already has. A diagnostic report counts these writes on their own.
* Hide suggested users also takes away the row of accounts to follow that For You puts under a post right after you follow its author. Threads puts that row together on the phone, without the server's suggestion tag, so it never matched the filter. A diagnostic report counts it with the other suggestion cards.
* When Hide ads or Hide suggested users breaks on one of For You's cache writes, the diagnostic report names that write. Before, every failure there was blamed on the feed page, even when the page was fine.
* Patching stops with a clear error if a future Threads build answers For You's one-item writes with something other than its plain "done" value. Hide ads used to take whatever every write returned, and a lookalike could have slipped past it.
* The patch bundle is signed now. Morphe Manager shows who signed it when you add or update the source (`d0d2 eda0 b978 70da`), remembers that key, and won't take an update signed by anyone else. If someone swaps the file on the way to you, Manager refuses it. The README says how to check the key.
* **Docs:** The README says where HushThreads really comes from. Someone's copy of this repo under another account offers a Windows download, and HushThreads has never shipped one.
* **Docs:** The README says what a Threads ban can reach and how to lower the risk, why passkey sign-in can't work on a patched Threads, what Android's 2027 developer verification changes for installs, and what `INSTALL_FAILED_NO_MATCHING_ABIS` means. The bug form names that error too, and the README now says how reports close.
* **Docs:** NOTICE and the Licenses page credit De-Vanced now. The list of supported Threads builds and the patch list generator came from there through tiktok-patches-for-morphe, and their headers used to point at ReVanced paths that never held either file.
* **Tooling:** Fixture tests keep what they work out per build in soft references, with a 3 GB heap, so every variant fits in one run.
* **Tooling:** The whole-app walk waits for each screen and scrolls to the row it wants, so a slow phone no longer reads as a failed walk. It also patches the same default selection Morphe Manager does. It used to apply every patch, `Change version code` included, and that left the phone on a build number no ordinary build could install over.
* **Tooling:** The signed-app contracts find their sites by strings and shape instead of naming one build's classes, since a release checks every variant. They'd fallen behind on the move off 452 and again on 454, and caught up both times. On 454 they follow the feed merge's extra parameter, analytics sites that Threads now jumps onto, share tiles spread over several lambdas, and videos that reach the player through a helper holding autoplay off.
* **Tooling:** A release build patches every variant of the Threads version it declares and stops if it finds none. Before this it picked one of two variants of the same version without saying so.
* **Tooling:** Patching is checked with fingerprint validation on, in the fixture tests and in verify-all-patches.ps1, so a fingerprint that fits two methods of a build fails its patch. Before, the patcher hooked whichever of the two it found first.
* **Tooling:** The source census can finish on GitLab again. It reads the watched paths of ReVanced's mirror through GitLab's GraphQL, a few questions for every branch at once, where it used to spend one of the roughly 60 hourly REST requests on each branch and path. Branches that share a head share one comparison. Forks GitLab has scheduled for deletion aren't counted, since a scanner keeps making and deleting them. A rate limit that resets more than five minutes out fails that source right away and says when to run again, so a run no longer sleeps for most of an hour.
* **Tooling:** The source census report keeps two hits in a recorded repository apart when their paths differ only by case. It used to list one of them.
* **Tooling:** The source census flags a recorded fork or copy when code search finds Threads files in it that its own lineage doesn't hold, even if another recorded source has them. Forks used to count as plain copies of their parent, so new Threads work in one passed a clean census unless an index listed it. GitHub's code search leaves most forks out, though, so this only reaches the ones it indexes. NexAlloy-XES, now gnadgnaoh/SexAlloy, is one it can't see. It has its own reviewed entry in the ledger now, with its files' blob ids pinned.
* **Tooling:** A phone install doesn't stop halfway anymore when another session reads the phone's lease file at the same moment. It tries the file again for up to about four seconds before giving up.
* **Tooling:** The source census asks GitLab for each branch's head together with its watched paths. A branch deleted partway through a run gets its own note now. It used to read as a branch that had moved to no Threads code. GitLab code search hits in a recorded fork or copy get their blob ids too, so new Threads files in a GitLab fork flag it the way GitHub hits already did. Several forks share one request for those ids, kept under GitLab's limit on how long a question can be, and two paths or branches that differ only in case each get their own blob id.

## 0.0.16 (2026-10-23)

* HushThreads now patches Threads 452.0.0.50.64 only, the newest stable version, and drops 451.0.0.51.80. Update Threads to 452 before you patch. The bundle is built with Morphe's 2.0 patcher, so you'll need Morphe Manager 2.0.0 or newer.
* Hide ads now also takes out the ads that show up among the replies when you open a post. Threads sends those with the post instead of through your feed, which is how they slipped past before. Turn Hide ads off, or pause HushThreads, and they show the way Threads draws them. The Hide ads switch says so in all six languages.
* New `Disable swipe to Search` patch. On accounts where a sideways swipe on your feed slides into Search, the swipe stops and your feed stays put. The Search button still opens Search. Only some accounts have the swipe, and on the others nothing changes. The `No swipe into Search` switch is on the Feed page of HushThreads settings and starts off. Restart Threads after you flip it.
* A download that runs out of its ten minutes now always says it was too slow. Every so often its last wait ended a fraction of a millisecond early, and you were told the network failed instead.
* **Tooling:** A release can't go public until the whole app is walked with that exact bundle on a release phone or an emulator. The publish stage now takes the walk's receipt as `-Walk` and stops before the tag or GitHub if the walk wasn't a full pass, saw a Threads crash, ran on some other device, or patched with a different bundle.
* **Tooling:** `scripts/walk-app.ps1` does that walk. It patches Threads from the release bundle and installs it, opens the feed, Search, Activity, a profile and a post by their links, then goes in through the Profile tab, the profile's Settings button and the HushThreads row in Threads' settings and opens every HushThreads settings page. A screen only counts when Threads shows that screen's own view, since a link Threads doesn't handle still opens Threads, on the feed. Any Threads crash or ANR since the walk began fails it, and the receipt it writes is the one publish asks for. Its only taps are those three steps and the settings rows, each checked on its own screen, so it can't follow, block or message anyone, or like a post.

## 0.0.15 (2026-10-18)

* Don't want HushThreads settings in the menu you get by holding Threads' icon? Turn off the new `Settings shortcut on the app icon` switch on the Pause, backup and diagnostics page and it leaves that menu right away, while Threads' own shortcuts stay. A long press on the Threads logo and the HushThreads row in Threads' settings still open the settings, and Pause leaves the switch as you set it.
* Pressing and holding the text of an opened post brings up Copy text again, the same as in your feed, so you get the whole post with its links. It had stopped doing anything on 451. A new `Copy text on long press` switch under Posts in HushThreads settings turns this on or off. It starts on and comes with every build.
* Open links in browser now also covers the places on 451 that used to skip it. An ad's link button and a swipe up on an ad in the media viewer send the ad's web link to your browser the same way post links go, and so do the privacy policy and disclaimer links on a lead form. Meta's own pages still open in Threads.
* Search's Follow suggestions row is gone too. It has its own switch, `Hide follow suggestions in Search`, right under Hide suggested users on the Feed page, and it starts on. Nothing takes the row's place, and search results and topics stay as they are. Turn the switch off, or pause HushThreads, and Search looks the way Threads draws it.
* Save photo and Save all work on phones with smaller screens again. On a 720 px wide screen Threads only keeps a photo at up to 750 px, and HushThreads took every one of those for a thumbnail and saved nothing. It now saves the largest copy there is, still prefers a full size one when Threads has it, and still never saves an avatar-sized copy.
* Disable video autoplay now also tells Threads' video prefetcher to hold off. The switch only held a feed video at its cover frame, so Threads could still start downloading a held video ahead of time. The patch now answers the prefetcher's autoplay-off question itself, only where the prefetcher asks it, so Instagram's older autoplay checker is left alone. With the switch off, paused or in safe mode, Threads' own answer goes back as before. Checked on a Galaxy S22 with Threads 451. The prefetcher got the hold answer with the switch on and Threads' own with it off, and a tapped video still played full screen.
* The HushThreads settings home page has two new rows. `Quick setups` changes a set of switches in one tap: Quiet hides ads and suggested accounts, Privacy stops most usage reports, takes tracking off shared links and hides your screenshots from Threads, and Back to defaults puts every feature switch back. A toast says how many changed. `Report a problem` opens a new GitHub bug report with your HushThreads and Threads versions, your phone and the switches you have on already filled in.
* More settings is now a heading on the HushThreads settings home page, with Appearance, Links, Updates, Set when you patched, Pause, backup and diagnostics and About listed under it. Every page is one tap from home and Back always goes home. Report a problem and Support HushThreads are still the last two rows, and the patch descriptions and bug report form point to the shorter paths.
* Don't use Quick setups? Press and hold its row on the settings home page and it's gone, and its help line says so. To bring it back, tap the Quick setups row on the Pause, backup and diagnostics page. Screen readers get the same press and hold on that row, and no other row offers one.
* HushThreads settings stay open when Threads redraws itself, after you change the font size or switch dark theme from the quick settings, or when Android closes Threads in the background and you come back. They used to close. They now come back on the page you were on. That holds with the settings open over two Threads screens and one of them closed, and on Android 9 in split screen when the Threads side sits for more than 30 seconds before you tap back into it.
* A settings file you pick for Import or Export isn't lost anymore when Threads redraws itself while the file picker is open, after a font size or dark theme change, or when Android closes Threads in the background to make room. The settings came back as if you hadn't picked anything. The file picker now opens through a small invisible screen of HushThreads' own, which keeps your pick until the settings are back. Access to the file ends once it's read or written. If Android closes Threads before that, it ends the next time Threads starts. Two quick taps on Import or Export open one picker, not two.
* After an export or import, the Export settings or Import settings row says how it went, in full, until you run another. That message used to show only in a pop-up, and newer Android versions cut those off after two lines, so a refusal like a damaged file lost its "Nothing was changed."
* Save's messages are short enough to read whole on Android 12 and later, which cut a message after two lines. On an S22 the proxy message stopped mid-word, and the slow-download one was just as long. A carousel's result now shows each line as its own message, so a line under the counts, like a proxy asking for a password, isn't lost. The German, Spanish, Indonesian, Portuguese and Turkish wording was shortened to fit too.
* A download that only trickles in now stops after ten minutes per file and says it was too slow, instead of holding one of the three save slots for as long as the server likes. A host lookup that never answers gives up after 20 seconds, and Cancel now ends a save that's still waiting on one.
* Cancel and the download time limit now end a save even when the phone's proxy service stops answering. Waiting proxy calls share the fixed limit on background network checks, so repeated attempts can't keep creating threads.
* A save's download now has a connection of its own that never asks Threads' cookie store or sign-in prompts for anything, so it can't send a cookie or a password, and it drops every cookie a server or a redirect sets. It still goes through the proxy your Wi-Fi or phone settings name and checks the server's certificate the same way. If that proxy asks for a password, the save stops and tells you, since it never sends one.
* On Android 9, a save without Threads' Storage permission now stops before it downloads anything and tells you where to turn the permission on. A carousel stops fetching its remaining pages if the permission is taken away partway through.
* Joining the picture and sound of a VP9 save (or AV1 before Android 14) now stops before it would take more than 24 MB of memory, and the save falls back to the single file. A file built from millions of tiny parts can't run Threads out of memory that way anymore. Cancel is also noticed while the join is still reading the tracks.
* When a save finds no picture or video it can keep, the diagnostics report now lists the kind and size of every address it looked at, so a bug report shows why. It never includes the addresses themselves.
* When the regular Instagram app from Meta sits beside your patched Threads, the Links page in HushThreads settings says Instagram won't open Threads posts or profiles here. That's Instagram's own check, and it's why Instagram says it couldn't load the website.
* When the settings list can't be put on the HushThreads screen at all, the screen shows Retry and Back instead of staying blank. Retry opens the page you were headed to, with your switches as you left them.
* When Threads rebuilds its screen with the settings open (after a text size change, say, or when Android closed Threads in the background), a settings page that fails to come back now gives way to a fresh page. Before, that failure would have crashed Threads, since it happens where the settings' own Retry and Back can't catch it.
* TalkBack now reads the Threads logo at the top of the feed as "Threads". Before, it stopped on the refresh spinner inside the logo and said "Progress bar". The README also says the logo ignores taps and holds while the feed loads or refreshes.
* TalkBack no longer stops on the HushThreads settings list as a whole to offer a long press that does nothing there. Quick setups, the one row with a long press, still offers it.
* HushThreads now keeps a note of how each switch starts in the build you patched. When a later build changes how a switch starts, one you never changed keeps the setting it had. Earlier builds left no such note, so this starts working with the update after this one.
* Settings file access stays tracked when a disk write or Android's permission service fails. Cleanup retries after a restart, and retrying the same file can't keep lasting access without a saved cleanup record.
* Morphe Manager lists every change of the release your Threads was patched with, not just a short summary. For that one release Manager shows the patch bundle's description instead of the changelog, and the description was a paragraph while every older release listed its changes. It now goes on with the release's Threads bullets after the summary. You'll see it from the next release on.
* **Tooling:** A GitHub description that names no release, patch count or Threads build now passes the release facts check and stays as written when a release publishes. Both used to refuse it, though a description like that has nothing a release can leave out of date. One that names any of those is still held to this release's and rewritten as before.
* **Tooling:** The release cut now moves the release check test's User-Agent from whatever version it names. The v0.0.14 prep left that test on 0.0.13, so the next cut found nothing to move and stopped.
* **Tooling:** The file picker behind Export settings and Import settings now has its own entry in the source ledger. Its two classes never had one, so the provenance test failed on every full run since they were added.
* **Tooling:** When the final APK check catches the direct browser hook overwriting something Threads still needs, it now says which case it found. The register can be past the method's own locals, or Threads reads it right where the hook goes in, or Threads reads it once the link has opened. Each test build has to fail for its own reason, so one that trips the wrong part of the check doesn't pass anymore.
* **Tooling:** Save's contract tests now cover the two other ways into Copy link's row call that would skip the Save row, a switch case and an exception handler aimed straight at it. The patch and the final APK check already refused both, but only a plain jump had a test, so losing either refusal would have gone unnoticed.
* **Tooling:** The final APK check now holds Disable video autoplay's prefetch hold to its contract. Where Threads' prefetcher asks Instagram's autoplay-off question, the answer has to go through the extension right after it's read and come back in the same register, and every jump to the test that reads it has to pass through that call too. Nothing else may make the call. The question itself, its Olympus twin, Instagram's older autoplay checker and the prefetch dispatcher have to stay as Threads wrote them, and a build without the patch leaves every one of them alone. Each rule has a test build that only it refuses.
* **Tooling:** The final APK check's browser guard has a test build only its completion half can catch: a link hook on a register that's free where the hook goes in but read again once the link has opened. No test build failed that half alone before, so losing it would have gone unnoticed.
* **Tooling:** Save's final APK contract got stricter. A branch inside the post menu's Copy link case that jumps straight to the row call would skip the Save row, so the patch and the check both refuse one now. Share's jump onto Copy link's row still works. Every static method on the media bridge class has to be a bridge the patch writes, and written, so one left empty or one the patch doesn't know fails. A build without Save has every bridge and the activity reader checked as shipped, and a changed menu is reported at the first instruction that differs.
* **Tooling:** The final APK check now holds Save photos and videos to its own contract. The post menu's Copy link path has to carry exactly one Save row, drawn with the calls Copy link's own row is built from and handed the menu and its composer, while every other menu item still reaches Copy link as before. The row's readers, its click and all fifteen media bridges have to point where the patch found them. A build without Save has to leave the menu and every stub as they shipped, and a bundle from before Save had a status reads as leaving it out.
* **Tooling:** The build classpath inventory refuses to write when a project's buildscript graph is missing, instead of quietly leaving it out. That happens when a build doesn't evaluate every project, as under configure-on-demand, and the refusal names each one. Its Guava probe also stopped failing every Gradle command when it can't find one of the two plugins. It records no jar for that plugin now, and only the inventory refuses. A refused run also deletes the previous inventory, so nothing reads an old one as this run's.
* **Tooling:** The same classpath now resolves commons-lang3 3.18.0 instead of the 3.16.0 the Morphe plugin asks for, which is inside GHSA-j288-q9x7-2f5v (CVE-2025-48924, 3.0 to 3.17.0). That was the last advisory OSV reported for the build's 114 plugin components, and the build advisory gate now finds none. It's a floor too, so it goes quiet once the plugin asks for 3.18.0 or later.
* **Tooling:** The classpath the build plugins run from now resolves Guava 33.7.2-jre instead of 33.5.0-jre, which is inside GHSA-xxph-c9ww-hj94 (CVE-2026-102554, 4.0 to 33.7.1). It's a floor, so a plugin that later asks for a newer Guava still gets it. The build classpath inventory also records which jar the Morphe and Android Gradle plugins really load the advisory's three classes from, and it refuses to write when that isn't the Guava the classpath resolved. The bundle build and the focused registry tests pass with it.
* **Tooling:** The source census now waits out a rate limit for as long as the answer says. GitLab throttles unauthenticated reads and answers 429 with the time its limit resets, and the census used to wait a flat 61 seconds, so a long reset used up its three tries and failed the run. It waits until the reset that Retry-After (seconds or a date), RateLimit-Reset or X-RateLimit-Reset names, plus a second, capped at 15 minutes by `-MaxRateLimitWaitSeconds`. An answer that names no reset still waits `-RateLimitWaitSeconds`, and a fourth limit in a row still fails the source.
