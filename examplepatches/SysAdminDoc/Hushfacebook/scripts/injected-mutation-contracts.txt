# Call sites a patched Facebook must have, checked across every dex of the APK by DexDiff.java.
#   single-call <method reference> in <caller method name>
#   first-call <method reference> on <class>
#   first-call <method reference> on-type-named <GraphQL type>
#   first-call <method reference> outside <package prefix>
#   start-call <method reference> [in [static|instance] <(parameters)return, * for any run>] holding <string> [<string> ...]
#   no-call <method reference> outside <package prefix>
#   next-call <method reference> after <method reference> [in [static|instance] <shape>] holding <string> [<string> ...]
#   sole-call <method reference> replacing <method reference> [in [static|instance] <shape>] holding <string> [<string> ...]
# A start-call, next-call or sole-call rule picks its method by every string it names and its
# shape, and exactly one of Facebook's methods may answer that; name as much as the patch itself
# finds the method by.
# Two feed guards stacked on addNewEdgeToCollection is the shape that broke builds before, and a
# guard anywhere else filters nothing.
single-call Lapp/morphe/extension/facebook/feed/FeedFilter;->hideEdge(Ljava/lang/Object;Ljava/lang/Object;)Z in addNewEdgeToCollection
# Each story-flag stub has to call GraphQLStory's renamed accessor before it returns. A patch that
# stops filling one leaves the stub answering its marker, and the rule keeps every post.
first-call Lapp/morphe/extension/facebook/feed/GenAiLabel;->detectedInfo(Ljava/lang/Object;)Ljava/lang/Object; on Lcom/facebook/graphql/model/GraphQLStory;
first-call Lapp/morphe/extension/facebook/feed/RecommendationLabel;->recommendationContext(Ljava/lang/Object;)Ljava/lang/Object; on Lcom/facebook/graphql/model/GraphQLStory;
# The GenAI reel stub has to call Facebook's attribution finder before it returns. The finder's
# class and name are Redex's and it answers no type name, so the rule asks only that the stub's
# first call leaves the extension. Left unfilled it answers its marker, and the Reels rule keeps
# every reel with nothing but a Hook status line to say why.
first-call Lapp/morphe/extension/facebook/feed/GenAiReelFilter;->transparencyAttribution(Ljava/lang/Object;Ljava/lang/String;)Ljava/lang/Object; outside Lapp/morphe/extension/
# The Stories tray patch asks the extension first thing in both of the feed's tray adapters: the
# classic one, holding its trace name, and the unified one, holding its create-adapter start and stop
# names and "tofu". The tray controller's constructor holds the start and stop names too.
start-call Lapp/morphe/extension/facebook/feed/FeedFilter;->hideStoriesTray(I)Z holding NewsFeedAdapterConfiguration.addStoriesAdapter
start-call Lapp/morphe/extension/facebook/feed/FeedFilter;->hideStoriesTray(I)Z holding stories_tray_create_adapter_start stories_tray_create_adapter_stop tofu
# The reels patch fills the showcase stub with the story type accessor of the one class whose
# getTypeName() answers ShowcaseFeedUnit, a class Redex renames, so the rule names it by that type.
first-call Lapp/morphe/extension/facebook/feed/ShowcaseType;->storyType(Ljava/lang/Object;)Ljava/lang/Object; on-type-named ShowcaseFeedUnit
# And it asks the extension first thing in the pre-EOF injector, which holds its adapter's name and
# adds its own Reels row at the tail of the feed without passing the feed guard.
start-call Lapp/morphe/extension/facebook/feed/FeedFilter;->hidePreEofReels()Z holding PreEofIfuSectionAdapter
# The background-return gate starts the controller's resume callback, which is distinct from the
# NewsFeedFragment swipe-refresh callback. A later call would refresh before asking the switch. Five
# methods hold the controller's name on 580 and 577; the callback alone holds "onRefresh" beside it.
start-call Lapp/morphe/extension/facebook/feed/ReturnRefresh;->skip()Z holding FeedRefreshTriggerController onRefresh
# Clean up Reels asks the extension first thing in Facebook's Follow check, which a reel's author
# row asks before it builds a Follow button, and which names the two surfaces where Facebook holds
# the button back for a friend. Left out or put later, the Follow button stays on every reel of an
# author you don't follow, the Reels tab's among them. Nineteen methods name both surfaces; the check
# is the one that's static, takes the session first and answers a boolean.
start-call Lapp/morphe/extension/facebook/reels/ReelDeclutter;->hideFollowButton()Z in static (Lcom/facebook/auth/usersession/FbUserSession;*)Z holding friendly_feed friends_tab_ifu
# Use the phone's emoji asks the extension first thing in Facebook's emoji typeface provider, the one
# method holding the end-to-end flag for the phone's emoji font and the provider's log tag. Left out

# Facebook ranks its own launcher shortcuts ahead of the Hushfacebook one with these calls, so the
# settings patch sends every one to SettingsEntry, which makes it and puts the Hushfacebook shortcut
# back in front (#2). One left in Facebook's code would let it drop out of the long-press menu.
no-call Landroid/content/pm/ShortcutManager;->pushDynamicShortcut(Landroid/content/pm/ShortcutInfo;)V outside Lapp/morphe/extension/
no-call Landroid/content/pm/ShortcutManager;->addDynamicShortcuts(Ljava/util/List;)Z outside Lapp/morphe/extension/
no-call Landroid/content/pm/ShortcutManager;->setDynamicShortcuts(Ljava/util/List;)Z outside Lapp/morphe/extension/
no-call Landroid/content/pm/ShortcutManager;->updateShortcuts(Ljava/util/List;)Z outside Lapp/morphe/extension/
no-call Landroid/content/pm/ShortcutManager;->removeAllDynamicShortcuts()V outside Lapp/morphe/extension/
# A long press on the Facebook logo at the top of the feed opens the settings screen, the way in
# for a launcher with no shortcut menu (#2). The settings patch sends the call that gives the logo
# its touch listener to SettingsEntry, in the top bar's logo builder, right after the logo gets its
# tap. Left out, the long press does nothing; on another call or register, another view takes it.
# The builder holds both of the logo's trace sections, and Redex makes it static and hands it a
# context and the bar, which keeps its name (580 and 577 have one more static method of that shape
# in the bar, holding neither section).
next-call Lapp/morphe/extension/facebook/settings/SettingsEntry;->setLogoTouchListener(Landroid/view/View;Landroid/view/View$OnTouchListener;)V after Landroid/view/View;->setOnClickListener(Landroid/view/View$OnClickListener;)V in static (Landroid/content/Context;Lcom/facebook/navigation/navbar/legacy/search/WordmarkNavigationBar;)V holding WordmarkNavigationBar#createWordmarkView WordmarkNavigationBar.initContents
# Don't send reel watch history takes the place of the Reels viewer's hand-over of each batch of
# watched reels: the one Executor.execute call in the batcher's flush becomes ReelWatchHistory.send,
# on the executor's and the send's registers in that order. The flush is the one method holding the
# mutation's name and its input field, an instance method taking nothing (on 580 and 577 no other
# method holds the mutation's name). Left out or left beside the stand-in, the batch goes out; on
# other registers, the stand-in gets the send as its executor.
sole-call Lapp/morphe/extension/facebook/reels/ReelWatchHistory;->send(Ljava/util/concurrent/Executor;Ljava/lang/Runnable;)V replacing Ljava/util/concurrent/Executor;->execute(Ljava/lang/Runnable;)V in instance ()V holding FbShortsSeenStateMutation video_ids
