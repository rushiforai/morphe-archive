# The view ids the extension looks up by name on the phone, one group per line:
#
#   source|group|names|package|owner|tell
#
# source   the extension file, under extensions/tiktok/src/main/java/app/morphe/extension/tiktok/
# group    the constant that holds the names, or "inline" for a name written into the lookup call
# names    the names, in the order the code tries them. One written 47.0.3:g6r is that build's
#          name and resolves on it alone (BuildNames in the shared extension); one with no build
#          in front is the same on every declared build. Each declared build is held to the
#          names that apply on it, its owner and its tell
# package  app for com.zhiliaoapp.musically, otherwise the dynamic feature module the id lives in
# owner    a class of the declared TikTok target whose code loads the id of the first name the
#          target defines; layout:<class>, a class whose code loads a layout that sets that id;
#          method-string:<text>, one method that loads both the id and a semantic string;
#          layout-method-string:<text>, one method naming a semantic string loads a layout that
#          sets the id (for a layout an obfuscated class inflates); or
#          class-method:<name>, a class that declares a real method name and loads the id. Use -
#          only where none exists. A dynamic feature module's classes count: its code ships as
#          lib/<abi>/libdex_<module>.so, which the test reads
# tell     what tells the id from the other ids the same owner loads, since an owner that loads
#          many ids would pass any of them. on:<type>[#n], the id is set on, cast to or stored
#          as a view of that type (the receiver of setId in a generated inflater, the check-cast
#          after a findViewById, or the type of the field the found view lands in), and with #n
#          the n-th distinct such id in code order; tag:<tag>[#n], for a layout owner, the id
#          sits on an element with that tag, the n-th such id over the owner's layouts in the
#          order of their ids; to:<class>, the id is handed to a method of that class other than
#          a find or setId; at:<n>, the n-th distinct id the owner loads, for an id nothing else
#          tells apart. A type may be written in full or by its simple name, never by an R8 name
#          (X.05y1 is a different name on every build). - only where the owner loads one id.
#          A method-string owner's order is that of the one method; a class-method owner's is
#          the whole class's
#
# RuntimeViewIdAnchorsTest holds every line against the code and against the target fixture.
# TikTok hands the same short names out again on every build, mostly to other views, so every
# short name here exists in every build from 46.2.3 on and a name that resolves proves little.
# The owner is what shows it is still the view. When the target moves, each owner that fails
# names a group to read off the new build's live view tree again. An owner shared by two groups
# (VideoDiggAssem holds the like button and its count) shows both ids are still its own, not
# which is which, so two names swapped between such groups pass; read those pairs off the tree.
