# What HushTumblr's patches write into Tumblr's code that no compiled contract validates, read by
# DexDiff.java. Each line is what the register report's dex delta section prints for one change:
#   method <signature> <sha256>     a Tumblr method a patch added or changed, or a method of the
#                                   bundle's extension a patch filled in
#   implements <type> <interface>   an interface a patch added to a class
#   field <reference> <sha256>      a field a patch added to a class
#   class <type> <sha256>           any other change to a class's shape, for the whole class
# A method's SHA-256 covers its flags, annotations, register count and normalized body, a field's
# its flags, initial value and annotations, and a class's its flags, superclass, interfaces,
# annotations and fields. Anything a run changes that a contract doesn't validate, the rebuild
# didn't only re-encode and the bundle doesn't carry as it is fails the run unless it's here.
#
# A section names a patch, or several with " | " between them for a bridge they all pull in, and
# applies only when the run selects one of them or a patch that depends on one, and every section
# applies to a run that names no selection. Interface and field lines for one class from two patches
# add up, so any selection of them passes. A method two patches write, or a class one reshapes while
# another adds to it, hashes differently for each selection: list the variant for both under a
# header that joins them with " + ", which applies only when the run selects both. For a run that
# does, its lines stand in for the lines that member has under a section it takes in: [A + B] for
# [A], and [A + C | B + C] for the bridge [A | B]. Lines under sections that only overlap stay in
# effect together. A run that names its selection fails on a line in effect it didn't need, an
# out-of-date hash included.
# Changing a patch's bytecode, or retargeting Tumblr, means reading a fresh register report and
# redoing that patch's lines.
