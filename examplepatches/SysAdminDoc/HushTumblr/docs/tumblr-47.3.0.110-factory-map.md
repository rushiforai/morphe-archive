# Tumblr 47.3.0.110 app map

Static notes on the Tumblr build HushTumblr targets, first taken from 46.9.1.100 with a dexlib2 probe on 2026-10-31, moved to 47.0.0.108 on 2026-11-05 (names through a whole-dex rename map, the paging, palette and font counts measured again) and to 47.3.0.110 on 2026-11-24 (obfuscated class names through a map traced between the two builds, member names where the trace or a probe dump settled them). Instruction positions and counts are still the ones read on 47.0.0.108 unless a line gives a newer date. Use it to find hooks again when Tumblr ships a new version. Obfuscated names (three or four lowercase letters, like `jo8`) change with every release, so each one below says how to find it again by shape.

## Feature flags

Tumblr reads about 220 server-controlled flags from `/v2/config` (the enum has 224 constants in this build, 218 in 46.9.1.100). They live in one enum, `jo8` in this build.

- **Find it:** the enum whose static initializer holds the string "Whether or not we should show the Tumblr Blaze landing page banner". It also has fields named `FEATURE_BUCKETS`, `immutableFeatureStateMap`, `analyticsFeatureReadStateMap` and `analyticsFeatureExposedStateMap`, and its companion holds "You're checking for Feature.isEnabled() with a non-boolean bucket!".
- **Constant names are kept** (`IN_APP_UPDATE`, `AD_FREE_CTA_BANNER` and so on). `toString()` turns them into the API's camelCase (`inAppUpdate`, `adFreeCtaBanner`).
- **The check path:** the static checks `l(jo8)Z` and `p(jo8)Z`, the instance checks `n()` and `o()` and the varargs `i(jo8[])Z` all end in the companion (`jo8$b`). `d(jo8)Z` caches the answer in `immutableFeatureStateMap` after asking `e(jo8)Z`. `e` calls `f(jo8, bucket)Z`, which calls `g(jo8, String)Z`.
- **`g(feature, expected)`** reads the server value through `nm5.d(nm5, jo8, Z, I, Object)String` (a default-argument bridge to `nm5.c(jo8, Z)String`), compares it with `expected` ignoring case, logs the exposure through `l(jo8, Z)` and returns the result. Hooking the result right after its `move-result` (before the `l` call) overrides every boolean check, including the cached one, since the cache stores what `e` returned. A flag override applies after Tumblr restarts.
- `nm5` is the configuration holder. It also carries `AdPlacementConfiguration`, `Gdpr`, `Privacy`, `ClientControl` and `Dismissals`.

## Timeline

- `com.tumblr.rumblr.model.TimelineObject` wraps one feed item: `getData()` returns a `Timelineable`, and the metadata adds `isShowSponsoredLabel()Z`, `getSponsoredBadgeUrl()`, `getRecommendationReason()`, `getPlacementId()` and `getServeId()`.
- `Timelineable.getTimelineObjectType()` returns `com.tumblr.rumblr.model.TimelineObjectType`. Its ad and promotion constants in this build: `GEMINI_AD`, `FACEBOOK_BIDDAABLE` (Tumblr's spelling), `NIMBUS_AD`, `DISPLAY_IO_INTERSCROLLER_S2S_ADS`, `VUNGLE_AD`, `CLIENT_SIDE_AD`, `CLIENT_SIDE_MEDIATION`, `DISPLAY_IO_INTERSCROLLER_AD`, `GOOGLE_NATIVE` and `BLAZED_POST`. Other notable ones: `COMMUNITY_CARD`, `COMMUNITY_ROW`, `VIDEO_HUB_CARD`, `VIDEO_HUBS_ROW`, `TRENDING_TOPIC`, `TAG_RIBBON`, `BLOG_CARD`, `CAROUSEL`, `TIMELINE_MESSAGE`, `BANNER`, `RICH_BANNER`, `ANNOUNCEMENT`. `SINGLE_LINE_CTA` (`single_line_cta`, model `SingleLineCTA`: `ctaId`, `serveId`, `display` with media, `sponsored` and title, `resources` with description and options; wrapper `vxj`, binder `wuj`) is the one-line promotion between a tag's posts and in search results, "Made with WordPress" with an Install button whose tap opens the served link and logs `SINGLE_LINE_CTA_TAPPED`. Hide ads takes it out by kind. `COMMUNITY_CARD` (`list_item_community_card_dashboard`) is the card a feed suggests, alone or in a carousel. `COMMUNITY_ROW` (`list_item_community_row`, root `community_row_root`) is a line of a list of communities: a category of Communities' Browse page (`CommunitiesBrowseActivity`) and a search's Communities tab. Browse, its categories and the Communities landing page load through `TumblrCommunitiesTimelineService` as a `WrappedTimelineResponse`, the dashboard's own response, so the call stack can't tell them from a feed and Hide suggested communities takes cards only. A suggested tag carousel is a `CAROUSEL` whose items are `TAG_CAROUSEL_CARD` (model `TagCarouselCard`: `isFollowed`, `items`, `borderColor`), headed by a `TITLE` ("Check out these tags", "Trending on Tumblr today", "Related tags" on a search's Posts tab, "Explore more #tag" on a tag's page). A page of lone `TAG_CAROUSEL_CARD` items is the carousel loading more of itself. `FOLLOWED_TAG_CAROUSEL_CARD` (`FollowedTagCarouselCard`, no follow state) is a tag you follow. `SIGNPOST` (`Signpost`: `display` with title and media, `resources` with description and options) is "Know someone who'd love #tag?" between a tag's posts and the "Follow tags to get updates here" message of an empty Your tags tab, a page with no posts. A search's Tags tab is `TITLE`, `COMMUNITY_HUB_HEADER_CARD`, `TITLE`, `TAG_CARDS_COLLECTION`.
- Ad models: `ClientAd`, `NimbusClientAd`, `advertising.ServerSideAd`, `advertising.SimpleAd`, `BlazedPost` (which wraps a `post.Post` and a `blazerBlog`).
- **Lists to filter**, both reached from Moshi with the parsed list as the first argument:
  - `Timeline.<init>(List, PaginationLink)` (wrapped by `WrappedTimelineResponse`, the dashboard path).
  - `TimelineResponse.<init>(List, PaginationLink, Map)`, the base of `PostsResponse` (blog posts), `LikesResponse` and `BlogSearchResponse`.
- **What a page was parsed for.** A page with items is only built inside a generated Moshi adapter's `fromJson`, so that adapter is on the call stack when the list hook runs, and Moshi finds these adapters by name, so their names are kept. `Timeline.<init>(List, PaginationLink)` is called from `TimelineJsonAdapter.fromJson` alone. Ten adapters read a `Timeline` field, and each asks Moshi for it in its constructor (`const-class Timeline`):
  - Search: `response.SearchResultsResponseJsonAdapter`. Every search tab is a `GraywaterSearchResultsFragment` (`SearchActivity$f.X(I)` builds nothing else). It loads `TumblrCommonService.searchTimeline` (`GET timeline/search`) and then `searchTimelinePagination`, the only two calls that return a `SearchResultsResponse`. Blog and community cards here are results, so the two suggestion switches leave them.
  - Feeds: `response.WrappedTimelineResponseJsonAdapter` (dashboard, Explore, hubs, the Communities tab; in `TumblrService` also `postPermalink`, `postPermalinkSingle`, `postsReview`, the Blaze lists `postsBlazeActive` and `postsBlazedAll`, and the `like` and `unlike` answers), `response.CommunityHubResponseJsonAdapter` (`/v2/hubs/{hub_name}/timeline`, a tag's page) and `model.RelatedBlogsJsonAdapter` (the blogs offered beside a blog card).
  - The rest, where the cards are left alone: `response.PostNotesResponse`, `response.PostResponse`, `response.VideoHubResponse`, `model.post.PostReplyPreview`, `model.note.RichNote` and `model.answertime.AnswertimeResponse`.
  - `TimelineResponse.<init>` is called from the `fromJson` of the `TimelineResponse`, `PostsResponse`, `LikesResponse` and `BlogSearchResponse` adapters, the last three through their own constructors. All four count as feeds. There's no `user/likes` call: your own Likes, like anyone's, is `TumblrService.likes` (`GET blog/{hostname}/likes`) and `likesPagination`, both `LikesResponse`.
  - `TumblrCommunitiesTimelineService.browsePage` (`/v2/communities/categories`) and `categoryPage` load a `WrappedTimelineResponse` like the dashboard does, so nothing on the stack tells those two lists from a feed.
- **How a loaded page reaches the screen.** The dashboard, a blog's posts and likes and every search tab are built on `com.tumblr.ui.fragment.TimelineFragment`, and each page they load is handed to `TimelineFragment.p4(type, items, links, extras, fromCache)`. The type is the renamed enum `k0m`, whose constant for a next page is `PAGINATION` (that's the name its `<clinit>` passes, so `name()` reads it).
  - The items `p4` gets are a converted copy of the parsed list, built on another thread, and the dashboard's first page can come from a read made before the screen opened. Nothing ties that list to the one the list hook saw.
  - `p4` asks `items.isEmpty()` first. An empty `PAGINATION` page calls `T5()` when `z5()` isn't null and returns. The finished request stays in `TimelineFragment.Y` (a `retrofit2.Call`) and the links in `PaginationFragment.k` aren't replaced. An empty page of any other type sets `PaginationFragment.l` (no more pages) and calls `P4()`, which shows the empty view, the "No results" screen.
  - A page with items clears `Y`, calls `U5(type)` (it stops a refresh's spinner, or hides the loading row for `PAGINATION`), stores the links in `k` and clears `l`.
  - The next page is asked for from a row bind. `Z3()` posts a runnable (`ywl`) that ends in the synthetic `e6()`, which is `B6(PAGINATION, true)`, but only while `Y` is null, `l` and `Z` are false and two seconds have passed since `y`. `B6(type, flag)` is protected. It reads the link through `M5(type)`, which for `PAGINATION` is `k.d()` (`TimelinePaginationLink.d()`, a `Link` or null), and starts the request. So one empty `PAGINATION` page ends a feed for good, because `Y` is never cleared again.
  - The paging hook goes right after `p4` keeps the `isEmpty()` answer (in `v7`, which held the extras), where the local `v1` is about to be written and so is free. `U5` and `B6` are protected, so the next load has to be made from code inside the fragment.
  - The blog rules of Mute posts locally, Hide liked posts, Hide your own reblogs and Hide reblogs of your posts go at the very head of `p4`. `invoke-static {p0, p2}` hands the fragment and the page to `RootPostMutes.dashboardPage`, and `move-result-object p2` puts the page it keeps back before `isEmpty()` reads it. Only a dashboard tab gets a filtered page. The parse-time filter can't do this, since Tumblr enqueues its requests and Moshi parses on OkHttp's thread, so nothing on that stack says which screen asked. `WrappedTimelineResponse` doesn't help either: the dashboard shares it with `postPermalinkSingle` (the audio player and `efh.j`), your blog's review queue (`TumblrBlogService.postsReview*`), the Blaze lists (`postsBlazedAll`, `postsBlazeActive`) and the `like`/`unlike` answers.
  - Hide followed blogs in For you uses the same head hook, but only on the For you tab. Every dashboard tab but Following is a `GraywaterTabFragment`, built with the arguments `tab_title`, `tab_timeline_uri`, `tab_logging_id`, `tab_position` and `roundtrip_params`, which its `onCreate` reads back through `requireArguments()`. `/v2/tabs` gives For you the logging id `stuff_for_you` and the address `/v2/tabs/for_you`, Your tags `hub_of_hubs` and `/v2/timeline/hubs`. The rule reads the two through `Fragment.getArguments()`, which keeps its name. Explore's own For You tab is the same class under `TabbedExploreHostFragment`, so `hushDashboard()` answers false there and it's left alone. Whether the account follows a post's blog is the "followed" key the paid post bridge already reads.
  - Those four switches and the For you one share one unnamed patch (`dashboardPagePatch`) that owns the head hook, the `hushDashboard()` markers and a facts capture. The page's cards are `f3g`/`b5k` whose payload is the `ze1` wrapper, and `ze1.<init>(Post)` keeps no liked or can-edit flag, so the capture hands the post to `DashboardPosts.facts(Object)` in that constructor and stores the bits in `ze1.hushPostFacts:I` (1 liked, 2 your reblog, 4 a blog you follow), read back through `HushPostFacts`. Mute's own `ze1` capture goes first, then the facts.
- `post.Post` is partly renamed. Its Blaze data is `BlazeCampaign` (field `O1`, getter `G()`) and `BlazeControl` (field `a2`, getter `h0()`). A post on your own blog can carry both, so they don't mark a paid placement on their own.
- **Root and posting blog.** `PostJsonAdapter.toJson` writes "reblogged_root_id" from `Post.K0()`, "reblogged_from_id" from `G0()`, "id" from `z0()`, "trail" from `B0()` and "blog_name" from `M()`, which returns the private final field `b`. Each getter is found by the key string just before its call, so a rename doesn't break the lookup.
- **Reblog source.** `PostJsonAdapter.toJson` writes "reblogged_from_name" from `Post.H0()` and "reblogged_root_name" from `Post.L0()`, both `()String`. An original post has neither. Hide reblogs of your posts reads them through `HushReblogSource`, found by key the same way, and leaves a post Tumblr marks `can_edit` (`hushCanEdit()`) alone, since that's a reblog of yours.
- **Dashboard fragments.** The dashboard's tabs are `com.tumblr.ui.fragment.GraywaterDashboardFragment` and `com.tumblr.tabbeddashboard.fragments.GraywaterTabFragment`. Both extend `GraywaterFragment`, which extends `TimelineFragment`, the same base a blog's posts and search use. The class alone doesn't settle it, though. `TabbedExploreHostFragment` builds Explore's tabs from `GraywaterTabFragment` too, and `CommunityTabFragment` extends it.
  - Every tab host hands its pager a `otk` adapter built on the host's own `getChildFragmentManager()`, so a tab's `getParentFragment()` is the host that holds it. The patch gives both dashboard classes `hushDashboard()Z`. `GraywaterDashboardFragment` answers true, and `GraywaterTabFragment` answers `getParentFragment() instanceof TabbedDashboardHostFragment`.
  - The tab's `ScreenType` can't stand in for that. Both hosts' providers (`TabbedDashboardHostFragment$d`, `TabbedExploreHostFragment$c`) pick `DASHBOARD_TAB` or `EXPLORE_TAB` from the tab's logging id with the same code.
- **Filtered posts.** A post that matches one of your filtered tags or words arrives with a note, `post.asset.Filtered`, which `PostJsonAdapter` writes under "filtered" through `Post.c0()`. The note's adapter writes "tags" through `Filtered.b()List` and "content" through `Filtered.a()List`. The post's view model copies the two lists (an empty list when the note is null), and `GraywaterFragment` covers the post with "This post contains filtered tags" or "... filtered content" when either has an entry.
- **A post's community.** `PostJsonAdapter` reads "community" into `Post.U0()`, a `ShortCommunityInfo`. Posts in a community's timeline carry it, reblogs with no text or tags included (seen 2026-11-18 on `/v2/communities/cat-pics/timeline`). Keep reblogs in communities reads it through the `hushCommunity()` bridge, as an object, because only its presence matters.
- **Full-screen video fit.** `com.tumblr.videohub.b$c.<init>` compares a video's width over height with 0.8. Below it the page skips the blurred poster and `ng8.i` calls `PlayerView.D(2)`, ExoPlayer's fixed-height mode, so a 1080x1920 video on a 1080x2400 screen draws 1314 pixels wide and loses 117 from each side. Fit full-screen videos changes the answer just before the flag takes it.
- **Feed video taps.** `c1m` is the overlay on a video in a feed. Its root view's click goes through `a1m` to `c1m.L`, which calls the `c1m$a` callback. The feed's callback, `pom$b`, opens the full-screen player through `dgm.e`. `pom$a` and `n71$b` are the ad callbacks, and the composer's `cen$b` toggles its own preview. `c1m.F` and `c1m.G` are the play and replay handlers, wired to the buttons only for ads and for `k`. `media_autoplay_mode` in `tumblr.xml` is Tumblr's Media auto-play setting (1 is Never, absent is Always).

## Settings hub

The Settings screen is Jetpack Compose: `com.tumblr.settingshub.impl.hub.SettingsHubActivity`.

- **Rows:** the view model `settingshub.impl.hub.d` builds them in `K()List`. It starts a list builder (`y14.c()`), adds one `ul0` per row and freezes the list with `y14.a(List)List` just before returning. Appending a row means adding to the builder before that last call.
- **Row model `ul0`:** `<init>(vl0 kind, int titleRes, qra icon, Integer subtitleRes)`, plus a default-argument bridge. The getters are `b()` kind, `c()` title, `a()` icon, `d()` subtitle.
- **Kinds `vl0`:** `PREFERENCES`, `NOTIFICATIONS`, `SUBSCRIPTIONS`, `LABS`, `PANEL` (only when the view model's `s83` field `f` answers `a()` true), `ACCOUNT`.
- **Icons:** `com.tumblr.compose.ds.icons.outline.<Name>Kt.get<Name>(Lpu7;)Lqra;` with `pu7.a` as the argument. The set includes `Hide`, `Shield`, `Settings` and `Sparkle`.
- **Clicks:** the row's click lambda `hub.b$a` (fields `a` the event sink, `b` the `ul0`) sends `hub.c$b(kind)`. The view model's `G(vl0)` maps the kind to an Intent through `caj` and the activity's `A3(a$b)` starts it, toasting "This section isn't available yet." when the target is missing. A row of our own is recognized in the click lambda by its title resource before the kind is read.
- **Row keys:** the list's key function is private static `hub.b.m(ul0)`, which returns the kind's `name()`. The lambda `maj` reaches it through the synthetic accessor `hub.b.d(ul0)`.

## Dashboard logo

The "t" at the top of the dashboard is `com.tumblr.ui.widget.TLogoView`, a `FrameLayout` holding a `SimpleDraweeView` (`t_logo`, layout `view_t_logo`). Its layout names the class, so the name is kept.

- **Bind:** `tabbeddashboard.fragments.TabbedDashboardHostFragment.o6(View)`, called from `onViewCreated`, picks `t_logo_view_top_bar` when `APP_TOP_NAVIGATION_UPDATE` is on and `t_logo_view` otherwise, makes it visible and gives it a tap (`fsk`) with `TLogoView.setOnClickListener`, the only call to it outside the class itself. The logo is in `v1` at that call.
- **Listeners:** `TLogoView.setOnClickListener` wraps the listener in `qsk`, which runs the logo's own `d()` first when its flag `a` is set, and the constructor sets one too, so the view always reports a click listener. Nothing sets a long press or touch listener on it, so the settings patch's long press leaves the tap alone.
- `n6(TLogoView)` only recolors and animates the logo for `HUNGRY_HUNGRY_DASHBOARD`.

## Blaze buttons on posts

None of these has a feature flag, so Hide Blaze prompts answers each one where Tumblr reads it. Read on 2026-11-13.

- **The flame under your own posts:** the row's state is the data class `n01`, whose `toString` prints "AuthorActionsState(showDelete=" and later ", showBlaze=" followed by `append(Z)` of its own boolean field. ## Themes and colors

Tumblr colors a screen in three ways, and a palette's background has to change in all of them. Read on 2026-10-31.

- **Activity themes:** `jm0$a.I(uj0, int)` calls `setTheme` with the palette's style for that activity, but only when the palette's map names the activity (`ss6` for Dark, read through `bm0.b`). Screens the map leaves out never get a palette theme, and the Compose settings (`settingshub.impl.hub.SettingsHubActivity`, `settingshub.impl.preferences.SettingsPreferencesActivity`) are among them. Find it as the one instance `(activity, int)` method that calls `setTheme(int)` on its first parameter and then reads its own companion.
- **Older Compose theme:** `TumblrTheme` is `prl.e(jg5, pim, bom, pi9, sh5, int, int)`. Its colors come from `ejm.<init>(Context, int)`, which wraps the context in the style `kg5.a(jg5, boolean)` picks (`BaseTumblrTheme`, `.Dark`, `.GothRave`, `.LCD`, `.Pride`). The palette parameter defaults to True Blue and several callers leave it there whatever the person picked (the dashboard's `TitleViewHolder.r1`, the Blaze screens), so a True Blue theme turns up in a Dark session.
- **Design system:** `DsTheme` is `hw7.e(jg5, du7, pi9, sh5, int, int)`, found by its Compose note `com.tumblr.compose.ds.DsTheme (`. Its colors (`du7`) aren't read from a theme. Each palette has a holder whose static initializer builds them once from the color list `lt7`: `rs6` Dark, `fem` True Blue, `sac` Low-Contrast Classic, `nw9` Goth Rave, `dlg` Pride. System asks `csk.a(Configuration)` and takes `rs6` at night, which is how to tell the Dark holder from the rest.
- **The Dark holder's grays:** in `rs6.<clinit>` the gray behind a screen is `lt7.z()` (#0d0d0d, `ds_colorGray95`) at 37, 123, 284 and 288, filling `Chrome.chrome`, `Content.mobileContainer`, `Global.sideMenu` and `Global.topMenu`. The next gray up is `lt7.y()` (#1a1a1a, `ds_colorGray90`) at 39, 49, 113 and 292, filling `Chrome.panel`, `Chrome.mobile`, `Content.panel` and `Global.modal`. The group classes keep those names in `toString` (`su3` Chrome, `yu5` Content, `bu9` Global). The settings screens draw their bar and rows with `Content.panel` (`yu5.g()`).
- **Rows on a card that read `Content.panel`:** the post footer is `xnf.d` (note `PostFooterSplitNotesCountContent (`), `yu5.g()J` at 176 handed straight to `androidx.compose.foundation.b.c(Modifier, J, Shape)`. ## Fonts

Tumblr's own fonts reach the screen two ways, and post fonts share the first. Read on 2026-10-31.

- **AndroidX loader:** `uoh.n(Context, int, TypedValue, int, uoh$e, Handler, Z, Z)Typeface`, private static, found by its `Font resource ID #0x` failure text. Every resource font passes through it: `uoh.c`, `h`, `i`, `j`, `androidx/appcompat/widget/f0.j`, Compose's `c80.c` and `d`, `o8l.f`, `g` and `m`, `s79.a`, `TabbedDashboardHostFragment$h` and exoplayer. Tumblr's own code never calls `Resources.getFont` or `TypedArray.getFont`, but Android's plain `TextView` does, past this method. A waiting callback gets its face from `uoh$e.d(Typeface, Handler)V`.
- **Pre-inflated rows:** `as0` (its tag is `AsyncViewProvider`) is built by `GraywaterDashboardFragment.W7` and `GraywaterExploreTimelineFragment.W7`. It inflates rows on the background inflater `sr0`, which has no AppCompat, so they're plain `android.widget.TextView` and `Button` objects that read `android:fontFamily` inside Android and never reach the loader. `dumpsys activity top` shows both kinds side by side on a cold dashboard under the same ids (`blog_name`, `header_cta`). Those rows leave through `as0.c(int, ViewGroup)View`, found by its `Returning rpe-inflated View for resId: ` log line. Its fallback `as0.r` uses the parent's inflater, which gives AppCompat views.
- **Font picker:** `s79.a(Context, com.tumblr.font.a)Typeface`, static, called from 68 methods. Its Favorit cases go through `uoh.h`, and `ROBOTO_REGULAR` and `ROBOTO_MEDIUM` answer `Typeface.SANS_SERIF` and `Typeface.create("sans-serif-medium", 0)` without loading anything. `UNKNOWN` answers null. The enum's own static initializer also holds `sans-serif-medium`, so a search on that string needs the picker's shape too.
- **Resource ids:** `0x7f090000` boop_spleen, `01` calluna_regular, `02` clarendon_text_pro_webfont, `03` clearface_regular_webfont, `04` fairwater_script_regular, `05` favorit_tumblr (an .otf), `06` favorit_tumblr_bold_700, `07` favorit_tumblr_medium, `08` favorit_tumblr_regular_400, `09` roboto_medium_numbers, `0a` source_code_pro_regular, `0b` ziclets_webfont. The ones a post's author can pick stay out of App font's list. Resolve ids by name, as they move between builds.
