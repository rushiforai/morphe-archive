# futatabi

**正式版 v0.4.4** — [ダウンロード](https://github.com/rikunode/futatabi/releases/tag/v0.4.4) ／ [リリースノート](docs/release-v0.4.4.md)

**ふたったー 3.1.1（`com.Nanasaki.ftutter`、versionCode 65）専用の非公式 Morphe パッチセット。** arm64-v8a（64bit）専用です。armeabi-v7a（32bit）は非対応。64bit端末でも32bit版APKやARM64分割APKの欠落は対象外です。GPL-3.0。元アプリの使い勝手を保ちながら、標準6板の閲覧・投稿に対応します。

## 導入

### URLでパッチソースを追加（推奨）

1. [Google Play](https://play.google.com/store/apps/details?id=com.Nanasaki.ftutter) からふたったーをインストールし、バージョンが **3.1.1** であることを確認します。[Morphe Manager](https://github.com/MorpheApp/morphe-manager/releases) も用意します。
2. スマートフォンで **[ふたたびをMorpheに追加](https://morphe.software/add-source?github=rikunode/futatabi)** を開きます。Morphe公式案内では、Managerにリポジトリが渡され、追加前に確認画面が表示されます。追加を承認してください。
3. リンクからManagerに移動できない場合は、Managerの Sources → + → Remote に https://github.com/rikunode/futatabi を入力して追加します。ソースの版が **0.4.4** であることを確認します。
4. Expert mode の「Select other apps」からインストール済みのふたったーを選択し、ふたたびのソースからパッチを選択して適用します。Manager の案内に沿って署名・インストールします。既定では元のアプリと共存するクローンになります。

このリンクは公開作業時にHTTP 200を確認しました。URL追加とRemoteの手順は [Morphe公式のパッチソース案内](https://github.com/MorpheApp/morphe-manager/blob/main/docs/patch-sources.md) に基づきます。このリンクからの実端末での登録・パッチ適用・インストールの一連の操作は今回未検証です。Managerの版やリンクの関連付けにより操作が異なる場合があります。

### .mppを手動で追加（予備）

[Releases](https://github.com/rikunode/futatabi/releases/tag/v0.4.4) から .mpp と SHA256SUMS を取得し、SHA-256を照合してください。Managerの Sources → + → Local から .mpp を選択し、上記4の手順で適用します。公式案内ではLocalソースは自動更新されないため、更新時は新しいファイルを指定します。

Google Play で対象版を入手できない場合は [APKPure の 3.1.1 XAPK](https://apkpure.net/jp/%E3%81%B5%E3%81%9F%E3%81%A3%E3%81%9F%E3%83%BC-%E3%81%B5%E3%81%9F%E3%81%B0%E5%B0%82%E7%94%A8%E3%82%A2%E3%83%97%E3%83%AA/com.Nanasaki.ftutter/download) が予備の入手先です。Manager の[公式案内](https://github.com/MorpheApp/morphe-manager/blob/main/docs/patching-process.md)ではスプリット APK の統合に対応していますが、このアプリのインストール済みスプリット／XAPK からの一連の操作は Manager の版・端末構成によって異なり、ここでは実機での再検証は行っていません。手動マージを必須とはしていません。[インストール済みアプリの選択に関する公式案内](https://github.com/MorpheApp/morphe-manager/blob/main/docs/home-screen.md)。

**クローンを使わない場合:** Clone app を OFF にしてください。既定のクローンパッケージ名は `com.Nanasaki.ftutter.morphe` で、元アプリとはデータを共有しません。署名やパッケージ名が変わると上書きできない場合があります。元アプリを不用意に削除しないでください。

## 設定バックアップ・画像表示

旧ふたったーからHTTPS設定を復元しても、追加3板の端末内ブリッジだけはHTTPのまま利用します。純正板のHTTPS設定は変更しません。

純正バックアップを復元した後はアプリを完全に終了して起動し直すと、意図的に削除していない標準板・追加板の不足分を補完します。旧形式の板リストも純正デコーダー経由で補完します。板一覧から自分で削除した板は再起動しても復活しません。削除を取り消す場合や既存の板が表示されない場合は板一覧の「＋ 板追加」からURL欄を空欄のままOKを押し、追加3板の登録状態を確認して「終了して復活」を選び、アプリを起動し直してください。この操作は削除済みの標準6板も含めて再登録します。v0.4.2以前の削除意図は記録されていないため、更新時に一度復活する場合があります。追加板の配色は復元された明示値を優先し、欠けた場合だけ端末内に保持した控えから復元します（控えがない場合は既定のダーク）。

純正の設定バックアップ／復元は FlutterSharedPreferences.xml 全体を対象とするため、追加板リスト（flutter.itaList）も含まれます。復元後は既存の不足板補完が動作し、独自板・既存設定を保持します。拡張ホームの「追加板の配色」でダーク（既定）／ライトを選択でき、この選択も同じ設定ファイルに保存します。対象はブリッジ生成HTMLと専用リーダーで、純正Flutterの描画テーマは変更しません。別ファイルにある認証情報、投稿履歴、仮想ID対応表は移行対象外です。古いお気に入り等の仮想ID移行は未対応。実機でのバックアップファイルの作成・復元は未検証です。

めぶきちゃんねるのスレ画像は公式の原画像URLを使用し、240px縮小・JPEG再圧縮を廃止しました。原画像は許可された公式ストレージURL・非センシティブ画像に限定し、12,000,000 bytes・各辺16,000・4,000万画素の上限があります。専用リーダーでは大きな画像を画面表示用にサンプリングします。カタログのサムネイルは従来どおりです。

純正スレ画面内の静止画の表示サイズは全6板で長辺280論理pxを上限に統一し、画面幅・既存の小さい設定上限・縦横比を尊重します。寸法不明の画像は正方形の表示枠に収めるため余白が生じる場合があります。拡大用画像の取得経路は変更していません。めぶきのスレ立て成功照合後は、作成したスレの純正スレッド画面へ自動遷移します。あいもげ・あにまんの新規スレ自動遷移は未対応です。元の書き込み画面が残る場合も同じ内容を再送しないでください。

## デザイン・キャッシュ管理

設定 → デザイン → メインカラーの末尾（19番目）は、ふたたび色 #1192C9（白い双葉マーク付き）です。初期色 #2196F3 と他18色の順序は維持します。以前 #800000 を選択していた場合は起動時に #1192C9 として読み替えます。Default dark mode はテーマ未設定時だけダークモードにします。統計情報と端末情報にはパッチ版を表示し、不具合・要望の案内は [GitHub Issues](https://github.com/rikunode/futatabi/issues) へ遷移します。

Manage viewing cache は Android 8.0以降のコールドスタート時に、純正の2つの閲覧キャッシュ領域で古い孤立ファイルを回収し、完全に確認できた領域の合計が1 GiBを超えると再取得可能な古い登録ファイルを整理します。1 GiBは厳密な常時上限ではありません。不明・使用中の可能性があるファイル、確認不能な台帳、設定、認証、保存画像、投稿用一時ファイルなどを保護する設計です。再取得が必要になる場合があります。拡張ホームの「キャッシュ診断（起動時）」で集計を確認できます。肥大した実機データでの効果は未測定です。詳細は [キャッシュ管理の実装記録](docs/release-v0.4.0-beta.36.md) を参照してください。

## カタログ取得と並び替え

あいもげは100件ずつ最大10ページ（1,000件）、あにまんはトップページの重複を除いて最大1,000件、めぶきの認証済み一覧は最大2,048件を表示します。めぶきのおためし人気順は上流の返す件数に依存します。ページ取得中に上流が更新される場合は完全な同一時点の一覧を保証しません。

あいもげは新順・古順・多順・勢順・そ順を公式APIで、少順を取得全件のレス数で処理します。あにまんは多順・少順のみ。めぶき認証済みは新順・古順・多順・少順・勢順（経過時間と投稿数による近似）、おためしは多順・少順のみ。データがない順序は既定順を維持します。個別板のURL追加は未対応です。

## 閲覧・ログイン・投稿

標準6板は may → img → jun → めぶきちゃんねる → あいもげ → あにまん の相対順で登録・補完します。img/may とめぶきちゃんねる（旧名：めぶき）の既知名称を正規化し、独自板の位置・順序と既存の板設定を保持します。利用者が削除した板は削除記録を保持し、再起動では再追加しません。純正「ねこ」の削除は未移行かつ純正構成の場合のみです。

通常のふたったーの板一覧・カタログ・スレ画面から閲覧し、純正の書き込み画面からスレ立て・レス投稿を開始できます。純正ふたば板の投稿には干渉しません。ランチャー入口は **futatabi** のみです。拡張の投稿・認証・診断機能は、既存の Board login button パッチ（既定ON）によるあいもげ・めぶきちゃんねるのカタログのログインボタンから開けます。

| 板 | ログイン | 純正欄でのレス投稿 | 純正欄からのスレ立て | 拡張ホームの投稿 |
| --- | --- | --- | --- | --- |
| あいもげ | 公式 PKCE 認証・承認 | 対応 | 画像必須、題名は本文先頭へ結合 | 新規スレ・レス、画像添付 |
| あにまん | 専用ログインなし・PHP セッション自動保持 | 対応 | 題名・画像必須、投稿時にカテゴリ一覧からタップ選択 | 新規スレ・レス、画像添付 |
| めぶきちゃんねる | アプリ内 WebView で X／Discord 認証 | 対応 | 純正本文→公式スレタイ、画像引継ぎ、公式本文欄で入力・本人確認・送信 | テキストレス |

あにまんの純正スレ立てでは書き込みボタンを押すとアプリ内カテゴリ一覧が開きます。先頭の既定カテゴリは ID 7（通常スレ／その他話題）です。公式フォームの画像上限（5 MiB）を投稿前に検証し、画像アップロードのHTTP 2xxを成功として扱います。本文が受理された後に画像アップロードがHTTPエラーになった場合は、スレが残る可能性とHTTPステータスを表示し、再投稿せず更新して確認するよう案内します。めぶきちゃんねるでは純正の本文欄にスレタイ（1行・100文字以内）を書き、画像を1枚選んで開始します。公式フォームでスレタイ・画像を確認し、別の本文欄を入力してタグ・スレ落ち設定を選び、Turnstile の本人確認後に公式の作成ボタンを押します。純正の題名欄にも入力があれば公式本文の初期値に引き継ぎます。公式フォームのPWAホーム追加案内は非表示にします。公式の添付処理がファイル名を `upload_` から始まる名前に正規化する仕様に合わせ、スレ画欄のプレビューを確認してから操作を解放します。画像が引き継がれない場合は公式画像欄から選び直せます。タグは1つ以上必須です。作成ボタンが反応しない場合、画面上部の案内をタップするとボタンの有効状態・タグ入力有無・入力エラー・公式作成リクエストの観測状態を確認できます。未観測は未送信の証明ではありません。認証済みカタログは公式 `/api/catalog` の既定では最新更新順で最大2,048件を取得し、取得できない場合は従来の5分遅延おためし一覧にフォールバックします。認証トークンの抽出・再利用や自動送信は行いません。元の書き込み欄には未送信の案内が返るため、公式画面で作成した後に同じ内容を再送しないでください。保存済み認証と WebView のアカウントが一致しない場合は、既存のログイン画面で確認してください。

あいもげはカタログのログインボタンまたは拡張ホームから公式認証を行います。認証の期限切れ時は再ログインしてください。あにまんは専用ログイン不要です。めぶきちゃんねるはアプリ内の WebView で本人が認証し、公式サイトへ戻った後にセッション確認・保存を行います。Google 認証は対象外で、公式トップのGoogleログインボタンは非表示にします。既存の診断機能も利用できます。投稿結果が不明な場合はスレを更新してから再送を判断してください。

## 端末内データ・通信

- ブリッジは端末の `127.0.0.1:18765` で動作します。認証情報や投稿履歴はアプリの非公開 SharedPreferences に保存されます。外部への独自収集サーバーは使用しません。
- 既知の制限（1a）：純正 Flutter 投稿経路は送信先のプロセスを検証しないため、ポート競合時に投稿内容が同一端末上の別プロセスへ渡る可能性があります。
- あいもげの公式アプリ認可フローでは、初回生成して端末内に保持するランダム UUID `installation_id` を公式 API の `installationId` として送信します。認可をアプリのインストール単位に関連づけるための永続的な擬似端末識別子です。端末のハードウェア ID ではありません。
- 各板への通信は対応する公式サービスへ行います。画像添付のファイル名は対応 MIME 型に基づく `attachment.<拡張子>` に正規化します。
- 板一覧の書き換え前の値をアプリ内に退避します。クローンのデータは元アプリと分離されます。

## 検証状況

所有者実機報告では、追加3板の純正欄からのレス投稿、あにまん・めぶきちゃんねるのスレ立て、めぶきの作成済みスレへの純正画面自動遷移、画像サイズ統一、葉っぱ付きふたたび色の表示が確認されています。junの実投稿、設定バックアップ／復元、キャッシュ肥大データの効果測定、その他の未確認ケースをすべて実機検証済みという意味ではありません。旧赤色が再出現した報告の発生条件は特定できていません。

正式版は所有者確認済みの beta.43 の機能コードを維持し、版数と公開文書を更新したものです。今回の公開作業では実投稿・実ログイン・実機操作は行いません。対象版ハッシュと変更前命令が一致する場合のみ適用します。

過去のローカル検証は [統合試験記録](docs/bridge-v0.2.0-emulator-gate-20261122.md) および [リリースノート](https://github.com/rikunode/futatabi/releases) を参照してください。
