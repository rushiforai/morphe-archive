## Mebuki authenticated thread reader (beta.18)

- Adds an in-process, non-exported reader for authenticated thread content. Stock catalog -> thread notice -> internal reader link, or extension home -> Mebuki reader list. The public catalog remains the trial catalog; the stock Flutter thread screen is not replaced.
- Revalidates the app-private saved session at the official get-session endpoint before each full initial thread read. Uses /api/thread/:slug/messages?initial=1, no redirects, bounded response size, and explicit failure states. Missing/expired/unverified sessions do not yield private content.
- Implements the bounded synchronous Turbo Stream subset observed in the official client (JSON scalars, dates, references, undefined). Unsupported formats fail closed. Initial order, replyTo mapping, escaped body and deleted/hidden notices are supported. Differential t updates, full markup and unsupported stream variants are not implemented.
- Normal image thumbnails are fetched only on selection from the exact official storage host; sensitive/unknown attachments are not automatically displayed. Full-size images, video and live attachment fetch remain unverified.
- Authenticated thread data never enters the public loopback response/index. Reader WebView disables network, script, DOM storage, file/content access and caching. Existing login/session storage behavior remains.
- Evidence: official use-thread-messages bundle SHA-256 67a1dc2f60dace2c400449e7e34910c73b8323a576be62cfbaaaff5ff03b482c; official Turbo Stream decoder SHA-256 c56ac057146db4052d728f012f355bc3052ca7d737078ce99eb0ecde5176a4eb. Official decoder accepted the synthetic fixture; Java test passed 55 assertions, including public-route isolation with a synthetic saved cookie.
- All seven patches applied; existing AOT gate 23 cases passed. Final APK on isolated AVD: actual stock catalog -> notice -> reader link worked, NOT_SAVED shown without a session. Actual Android visual-state screenshot of synthetic converted content confirmed body, reply link, image entry and deleted notice; accessibility extraction did not expose WebView body. Manifest confirms reader exported=false.
- Owner reported OAuth consent screen reached in beta.17; saved session and actual authenticated response are not yet verified. No real owner credential, login, post or authenticated read was used in development. This is a partial prerelease pending owner validation; prior unrelated limitations remain.
