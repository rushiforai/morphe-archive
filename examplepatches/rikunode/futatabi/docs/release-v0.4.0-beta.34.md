# v0.4.0-beta.34

## A1 めぶきの画像品質

beta.33 は投稿フォームへ元の画像バイト列を引き継いでいたが、閲覧時は公式の _sm サムネイルを取得し、さらに長辺240px以下・JPEG品質80へ再圧縮していた。専用リーダーも _sm を取得していた。公式の保存済み message-content-Byuwwrz1.js / utils-BJPiTKUD.js は filePath とサイズ別サムネイルを区別している。

2026-11-27、公開おためしカタログ（GET /api/trial/catalog、HTTP 200）から非センシティブJPEGを1件選び、同じ添付の原画像と _sm をGETして実測した。双方HTTP 200。原画像 JPEG 1622×2115 / 254,402 bytes、小画像 WebP 196×256 / 7,456 bytes。これは別の公開サンプルで、所有者が投稿した画像の実寸・サイト保存時圧縮率は未確認。

スレ画像の参照を filePath に変更し、互換HTMLのスレ内画像と拡大画像に原画像のバイト列・実際のMIMEを返す。カタログは既存の小画像経路を維持。原画像取得には12,000,000 bytes、各辺16000px、4000万画素の安全上限を設ける。専用リーダーでは非常に大きい画像のみ表示用にサンプリングする。センシティブ画像の除外、公式ストレージ制限、セッション照合・非永続の画像対応表を維持。公式サイト保存以前の画像に戻せることを保証するものではない。

## A2 投稿後の遷移

めぶきのみ、公式画面遷移後に既存の投稿者・作成時刻・添付照合が成功し、保存セッションが変わっていない場合に、スレIDを既存の非永続マッピングへ登録して MebukiReaderActivity を開く。確認できない場合は公式画面に留まり、結果未確定と表示。純正書き込み画面への成功応答の仕組みは変更していないため、戻った際は同じ内容を再送しないこと。

MUSEの範囲判断により、あいもげ・あにまんの純正Flutter画面での自動遷移は未対応。既存の成功確認経路を維持し、別の閲覧Activity新設や新規AOT逆解析を行わない。

## A3 設定バックアップ

純正 3.1.1 の AOT Setting_BackUp の backUp / restore とオブジェクトプールを確認。両者は同じ /shared_prefs/FlutterSharedPreferences.xml をファイルとして読み書きする。追加板リスト flutter.itaList は既にそのファイル内にあり、既存の不足板補完を維持。復元したリストに独自板・順序・既存設定が保持されることをホストテストで確認。純正バックアップ機構の変更は不要。実機ファイルのエクスポート・インポートは未検証。

別ファイルの認証情報・投稿履歴・仮想ID対応表は対象外。古いお気に入り等の仮想ID移行は未対応。

## A4 配色

拡張ホームの「追加板の配色」からダーク（既定）／ライトを選択。独立キー flutter.futatabi.bridgePalette を同じ FlutterSharedPreferences に保存し、純正設定バックアップに含まれる構成にする。対象は追加3板のブリッジ生成HTMLとめぶき専用リーダーのHTML。純正Flutterの独自描画や公式WebViewの配色は対象外。
