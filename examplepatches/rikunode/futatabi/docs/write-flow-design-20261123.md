# futatabi 書き込みフロー設計（2026-11-23、MUSE監督・設計）

## 前提（AOT解析で確定済み）
- ふたったーの純正投稿は宛先を <ホスト先頭ラベル>.2chan.net へ組み立て直すため、Bridge板への純正投稿は構造的に不可能。閲覧は完全統合のまま、書き込みは拡張側フローで提供する
- 実ふたば板の純正投稿には一切干渉しない

## 全体構成
- 拡張ホーム画面（新規 Activity、ランチャーから起動）→ 板ごとの状態・入口
- 投稿は拡張の投稿画面から Bridge（同一プロセス内サーバー、127.0.0.1:18765）へ渡し、Bridge が各サイトの実API／実フォームへ直接リクエストする
- /ext/* エンドポイントはインストール毎のランダムトークンで保護する（同一端末の他アプリからのローカルアクセス対策）。トークンはアプリ専用ストレージに保存し、拡張画面と Bridge で共有する

## 拡張ホーム画面
- Bridge板の一覧（あいもげ／あにまん／めぶき）と各板のログイン状態
- 各板の入口：「新規スレ」「スレ一覧から返信」「ログイン／ログアウト」
- 自分の投稿履歴（削除キーと紐づく投稿の管理、対応APIのみ削除可能）

## スレ一覧（返信先ピッカー）
- Bridge がアダプタ経由で取得したスレ一覧（カタログ変換と同じデータ源）から選ぶ
- 選択後に投稿画面（返信モード）へ遷移する

## 投稿画面（板の能力に合わせて項目を出し分ける）
### あいもげ
- 項目：本文（上限4,000字、カウンタ表示）、画像添付（返信は最大3件）、削除キー（自動生成・編集可・保存）
- タイトル／名前の独立項目は API に無いため出さない
- 送信：Bridge → POST /threads/aimg（新規）／POST /threads/{threadId}/posts（返信）、ヘッダ x-aimg-token＋X-Api-Version: 2026-11-11
- レート制限を UI に反映する：スレ立て60秒・レス10秒のクールダウン表示、threadsPerHour=60 の注意
- 添付：POST /attachments/presign → uploadUrl への実アップロード方式は実装の最初に契約を実測確認すること。未確認の間はテキスト投稿のみ先行し、添付は確認後に有効化
### あにまん
- 項目：タイトル、カテゴリ、名前、本文、画像（新規スレは画像必須と明示）
- 送信：Bridge が3段階を代行する — comment.php?preCheck → comment.php（成功JSONの number/thread/jump を使用）→ 画像は成功後に upload/ へ FormData
- セッション Cookie（PHPSESSID）は Bridge が取得・保持する。ログインは存在しない前提
- 読み取りアダプタ（v0.2.0 で延期分）も本フェーズで実装する。パーサは独自実装とし、参考元は README に明記（GPL-3.0）
### めぶき（次フェーズ v0.4.0、本設計では予約のみ）
- ログイン：拡張内 WebView で Better Auth のソーシャルログイン（X／Google／Discord）→ CookieManager から mebuki.moe のセッション Cookie を取得しアプリ専用領域へ保存
- 投稿：画面ルートへの multipart POST（Turnstile が絡むため、送信時の扱いは実装フェーズで実測して決める。回避はしない）

## ログイン：あいもげ PKCE
- Bridge が POST /app-authorizations（redirectUri／installationId／state／codeChallenge S256）を発行
- redirectUri の第一候補は Bridge 自身：http://127.0.0.1:18765/ext/login/aimoge/callback。ブラウザ承認後の戻りを Bridge が受け、POST /app-credentials（code／codeVerifier）で資格情報化する
- ループバック redirectUri が API に拒否される場合は、勝手に別方式へ進まず報告すること（代替案は監督が判断する）
- 資格情報は固定21日有効・refresh なし。再認証はユーザーの明示操作でのみ開始する
- installationId はアプリ専用ストレージに永続化する

## 資格情報・削除キーの保管
- 保存先はアプリ専用ストレージ（拡張側の SharedPreferences、MODE_PRIVATE）のみ。FlutterSharedPreferences（kakikomiData 等）には絶対に置かない
- ログ・クラッシュレポート・リポジトリへ資格情報を出さない
- 削除キーは投稿ごとに生成し、投稿履歴とともに端末内だけに保持する

## 成功／失敗の扱い
- 成功の偽装をしない。実APIの応答をもって成功とし、失敗時はサイト側のエラー内容をそのままユーザーへ見せる
- 429／クールダウン中は送信せず、残り時間を UI に出す
- 投稿結果（成功した投稿の ID・URL）は投稿履歴に記録する

## 実装の段階（v0.3.0 スコープ）
1. あいもげ：presign アップロード契約の実測、PKCE の redirectUri 可否の実測（← 最初の関門。結果を先に報告）
2. Bridge：/ext/*（トークン保護、スレ一覧、投稿、ログイン開始／コールバック）
3. 拡張 UI：ホーム画面、スレピッカー、投稿画面、ログイン導線
4. あにまん：読み取りアダプタ＋投稿の3段階代行
5. 検証：契約を再現したフィクスチャ相手のエミュレータ E2E（実サイトへの投稿・実ログインはしない。実投稿の検収は所有者の実機操作で別途）

## 禁止事項（従来どおり）
- 実サイトへの試験投稿、実ログイン、実トークン発行を ChatGPT 側で行わない
- 範囲の拡大（未指示の板・機能の追加）をしない。詰まったら推測で進めず報告する
