# v0.4.0-beta.43 — ふたたび色スウォッチへの葉っぱマーク表示のみ

対象：ふたったー3.1.1 / ARM64 / versionCode 65。beta.42の所有者実機フィードバックに対する修正。

## 原因・修正
- 純正 ChooseMainColorDialog.build (0x8dc94c) は、0x8dc9ec–0x8dca0cでスウォッチのColorと共有旧テーマ色 #800000 (PP+0xe728) を等価比較し、一致時のみ0x8dca10から葉っぱSVGを描画していた。beta.42の新色 #1192C9 は一致しないためマークが消えた。
- 0x8dc9c4–0x8dc9c8で既に保存される1始まりの枠番号 (fp-0x18) を用い、19番目だけ既存SVG描画経路へ進む。その他18色は従来どおり子ウィジェットなし (0x8dcab8)。変更は0x8dc9ecから36 bytesのみ。新規割当・呼出し・保存処理なし。
- 純正 assets/images/futaba.svg、サイズ30論理px、既存カラーフィルタをそのまま再利用。生成APK内SVGのSHA-256 3d42134a73e7ae4fe99c8aee510b6a1ea2a129a6a59db73f084353a20f011c64、beta.42と完全一致。
- 19色の順序・値、選択コールバック、flutter.mainColorのARGB整数保存とbeta.42の旧色読み替えを変更しない。旧テーマ互換用定数も保持。対象の全体SHA-256と変更前命令を既存ガードで検証する。

## 第2スクリーンショットの調査
- 既存AOTの静的調査では、19色の固定配列 (PP+0x28840、ref 0x227ef) の参照は ChooseMainColorDialog.build の0x8dc998–0x8dc99c。元の赤色オブジェクト ref 0x233c9 はこの配列とPP+0xe728に存在する。
- メインカラー選択ダイアログの定数 (PP+0x21da8) の参照は0x8dc8a8–0x8dc8ac。葉っぱSVGの参照は選択ダイアログの0x8dca70–0x8dca74と、設定行の選択済み旧テーマ色表示0x8d8f30–0x8d8f34。後者はパレット生成ではない。
- 個別カラー用 ChooseKobetsuColorDialog.build (0x8e5214) は別の選択画面。tapColor (0x8e5f64) の描画はContainer/BoxDecorationであり、同じ葉っぱ付き19色パレットを作る別経路は確認できなかった。個別カラーおよび設定行は変更しない。
- 第2スクリーンショットの赤い末尾色・暖色テーマの発生条件は未確定。今回の変更でその現象まで解消したとは主張しない。実行時状態は所有者の確認待ち。
