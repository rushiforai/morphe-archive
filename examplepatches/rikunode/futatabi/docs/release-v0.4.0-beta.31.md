# v0.4.0-beta.31

めぶきの画像引き継ぎ確認が、画像が正常に表示されていても失敗する問題を修正。

## 根本原因

2026-11-26 に公式配信中の app._main.new-DfgTN12t.js、use-file-attachments-DEVUA6os.js、utils-BJPiTKUD.js をHTTP 200で再取得し、保存済みスナップショットとの一致を確認。

公式スレ作成フォームの drop とファイル選択 change は同じ添付追加処理を呼ぶ。追加処理は未正規化の File を upload_ から始まるランダム名に変更し、バイト列・MIME・lastModified を維持した File を React の添付配列に登録する。公式のサムネイルはこの配列から作られ、alt は正規化後のファイル名、src は blob URL。削除・設定ボタンもその添付要素に対応する。公式の入力検証と multipart 組み立ても同じ添付配列を使用する。

beta.30 は元の attachment.jpg 等との alt 完全一致を要求していたため、正常な添付のプレビューを誤って未確認と判定した。公式の drop 受け取りそのものの失敗ではない。

## 修正

- 公式 drop 経路は維持する。input[name=attachments] は hidden の検証用フィールドであり、実ファイル選択 input ではない。
- 確認はスレ画専用 fieldset 内の1枚の blob プレビュー、公式の正規化名、元画像と同じ拡張子に限定する。ページ上の別の画像、元の名前、異なる拡張子、複数画像は合格としない。
- 入力検証・送信・Turnstile・他板・カタログは変更しない。確認はプレビューの根拠であり、投稿成功の証明ではない。

## 検証

公開された公式JSの該当処理をローカルの模擬React状態で実行。drop からファイル名の正規化、添付配列、公式 multipart 組み立てまでを検証し、バイト列・MIME・更新時刻の維持を確認。beta.30 の確認条件は失敗、beta.31 は成功。実投稿・実ログイン・共有エミュレータの使用なし。

StockNewThreadContractTest、フォームJSモック、オフラインビルド、全7パッチのAPK適用、新しい確認条件のDEX同梱 PASS。beta.30の生成済み確認スクリプトそのものでも失敗を再現。端末のWebViewでの動作と実際のスレ作成は所有者確認待ち。
