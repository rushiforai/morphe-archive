# v0.4.0-beta.41 — 画像表示サイズの統一のみ

対象：ふたったー3.1.1 / ARM64 / versionCode 65。beta.40に対する変更は純正スレッド画面内の画像表示寸法だけ。

## 原因と確認結果
- beta.40のめぶきは原画像寸法をそのまま申告していた一方、あいもげ・あにまんのスレ内HTMLは50×50固定。純正のimg/may/junは通常のサムネイル寸法を受け取る。純正SureProviderはHTMLのwidth/heightをdoubleとして取り込み、共通ResuImg.build (0x89ba88) は表示設定と申告寸法から制約を決めるため、板間で表示サイズが異なっていた。
- あいもげ公開カタログの匿名GETはHTTP 200で、添付width/heightが数値として存在（確認例600×600）。保存済みのあにまん公開HTML active-thread.html / thread.html には画像タグがそれぞれ14/10個あり、画像寸法属性は確認できなかった。
- 原本バイト列、取得・再圧縮経路、カタログ、拡大画面、投稿、認証、板順、設定保存は変更しない。beta.34 A1およびbeta.39 A2の経路を維持する。

## 修正
- 共通の表示目標は長辺280論理px（端末の物理ピクセルではない）。追加3板のスレ内HTMLはThreadImageSizeで280を基準に寸法を正規化する。既知寸法は縦横比を保って整数丸め（1280×720→280×158、728×1000→204×280）。不明・不正寸法は280×280の表示枠とする。あにまんの不明寸法も同じ枠を使い、既存MyCachedNetworkImageのBoxFit.contain（0x9205bc–0x9205c0、pp+0x18b88）により画像を引き伸ばさず収める。余白が生じ得る。追加の画像取得はしない。
- 純正板にも適用。共通ResuImg.buildの静止画/GIF側の2経路で、サムネイル寸法による上限縮小を除き、既存設定から選択された幅・高さ上限をそれぞれ280で制限する。既存の設定値は書き換えない。設定上限が280未満ならそちらを優先する。既存のアスペクト比計算、画面幅の制約、mp4/webm専用分岐は変更しない。6板で同じ表示枠規則になるが、画像の縦横比・実際の表示可能幅・設定により描画サイズは異なる。純正が既に小さい設定上限に達している場合は拡大しないことがある。
- AOT差分は0x89c7c8, 0x89c8bc, 0x89c3bc, 0x89c940と、到達しなくなった同一関数の旧min処理内の2つの短いリーフ断片 (0x89c7f0, 0x89c810) のみ。新しいDart呼出し・GC地点・ELF拡張はない。既存4組み合わせの入力SHA-256と変更前バイト列を検証し、出力ハッシュも固定。対象外は拒否。
