## 実測した色と初期値
- 選定素材 branding/icon-candidates/futatabi-r3-01-black-diagonal.png：512×512、12,176 bytes、SHA-256 823f2260d0d9dab237f25e7248905a7549a44baed7ddb716d4c4d6413e0c2460。青〜ティール系の不透明画素17,783個の平均に最も近い実在画素 #1192C9 (ARGB 0xFF1192C9、RGB 17,146,201) を採用。
- 原APKのlibapp.so SHA-256 dd542fe3af5f266096e07f823da3880d3a6e7c771aa80afe6324137e63c5041a。dae v0.1.17 (c60c5f40669f6794509c47938cdf3079772cdb39) の読み取り専用ローカル出力を追加し、Dart 3.6.1 compressed profileでPP+0x28840 → ImmutableArray 0x227efの19参照とColorのRGBAフィールドを取得。
- 初期メインカラーは第6色 #2196F3 (0xFF2196F3)、ref 0x23495、PP+0x68a0。第19色は #800000 (0xFF800000)、ref 0x233c9、PP+0xe728。異なるため所有者の停止条件に該当しない。初期メインカラー・ダークモード初期化を変更しない。

## 実装と互換性
- #800000 は旧テーマ互換判定にも用いられる共有定数（例 0x7501d4, 0x872ed8, 0x8d8f08）。直接上書きせず、ChooseMainColorDialog.build の19番目でのみ純正Colorを生成して既存の色ローカルに置換する。配列長19、先頭18色、順序、選択コールバック、ColorScheme.fromSeed (0x749674) を維持。
- 既存のContext割当呼出し 0x8dc9d0 の呼出し位置・戻りPC 0x8dc9d4・フレームを再利用して、最終枠だけ純正Color割当スタブ0x48b0ecを先に呼び、純正Colorコンストラクタ0x48df60と同じRGBA/ColorSpaceを設定する。その後同じ呼出し位置から通常のContext割当に戻る。新規GC呼出し位置を追加しない。固定配列・共有定数の書き換えなし。
- 純正の保存形式は番号ではなく flutter.mainColor のARGB整数（0x8dc880–0x8dc894で色値取得→setInt、0x929890–0x9298c4でgetInt→Color生成）。以前 #800000 を選択していた利用者は、起動時にその保存値を #1192C9 として読み替えるため、表示テーマが変わる。保存済みの整数そのものは起動時に書き換えず、他の色・設定キーや保存形式は変更しない。次に色を選択すれば従来のsetIntで選択色が保存される。旧互換判定の定数を保持するため個別カラー判定の他のコードは変更しない。
- AOT変更は0x8dc9cc–0x8dc9d7、0x9298bc–0x9298bf、検証済みゼロパディング0xaa67ecから192 bytesとELF RX長のみ。既存の入力全体SHA-256、変更前命令、パディングを検証。対象外は拒否。その他は自動版数更新のみ。
