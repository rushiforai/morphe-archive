# v0.4.0-beta.20 - Native Mebuki and stock reply composer

- Mebuki threads now render inside the stock Flutter thread UI. Removed the beta.19 automatic private-Activity navigation. Existing saved-session revalidation and official Turbo Stream decoder are reused. OP/replies are translated into Futaba-compatible markup with local numeric identifiers, quote targets, timestamps and deleted/hidden placeholders. Public catalog and unauthenticated notice/manual reader fallback remain.
- The local bridge grants authenticated body and private-image access only when an open client socket with the exact reverse local/peer endpoint pair is found among the bridge process's own descriptors (Android public OS APIs). No URL token or cookie is sent to Flutter. Other processes receive the notice or image denial. This is a same-process boundary, not protection against root or code already executing in the process. Image mapping is session-bound in memory; at most one supported thumbnail per message, not full multi-attachment or video rendering.
- Restored the stock reply composer for Aimoge and Animanch. Patched only the verified ARM64 posting URL construction at 0x88d7a8, 0x88d7b8 and 0x88d820. Exact HTTP/HTTPS loopback host, port and board are routed to the local bridge; ordinary may/img keep the original URL construction. The original four concatenation call sites are preserved. An initial HTTP-only match failed in the actual composer; connection tracing identified the attempted 127.2chan.net lookup and accepting the exact HTTPS-normalized internal URL resolved it.
- The bridge accepts only same-process stock reply POSTs, rejects browser-origin/fetch metadata, and parses bounded multipart forms. Aimoge reuses its existing private app credential and official ALTCHA/post transport. Its success number is confirmed by matching the accepted UUID, thread and sequence against an official readback; no number is invented. Animanch reuses the official form, preCheck, comment and optional upload; returned reply numbers are mapped using the existing local display-ID convention. Missing/ambiguous confirmations do not return a stock success response.
- Supports replies, not new-thread creation from the stock composer. Unsupported title/name/email combinations are rejected instead of silently mapped; supported Aimoge email options are sage/age. One supported image is parsed by the bridge, but image-picker-to-upload E2E has not been verified in this round. The existing extension home remains available.
- Verification on the final APK: all seven patches applied; 18 ARM64 URL/forceHttps CPU cases passed. Isolated AVD actual stock Mebuki catalog selection rendered synthetic authenticated content with quotes and reply text; external body request returned only the notice and external private-image request was denied. In-process image GET returned JPEG. Actual stock composer button presses for Aimoge and Animanch each reached an official-contract synthetic POST exactly once; Aimoge ALTCHA and matching numeric readback, Animanch preCheck and numeric mapping, and both bridge thread readbacks passed. Stock Flutter logged the matching thisno success response on both boards. Automatic immediate refresh showing the new post was not independently confirmed.
- External shell POSTs to both stock reply endpoints returned HTTP 403. The isolated app UID was blocked from external IPv4 and IPv6 during mock posting; no real upstream post or owner credentials were used. Isolated AVD stopped; shared AVD untouched.
- Owner device revalidation is still required for actual authenticated Mebuki and actual replies. Formal Latest remains v0.3.0.
