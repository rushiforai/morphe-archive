## あにまん
- 純正Flutter SureProviderの親投稿・返信の画像解析は width / height を取得して double.parse する（取得 0x72103c / 0x721074、0x721c8c / 0x721cc4、解析 0x7212f4 / 0x721330 / 0x7220d4 / 0x722110）。beta.11の変換HTMLは両属性を欠いていた。純正ふたばの実HTMLでは両属性が数値。既存あいもげと同じ表示用50x50の数値属性を追加した。元画像の実寸ではなく、画像の事前一括取得を避けるための固定表示寸法。
- 実上流4スレ 7675261 / 7675282 / 7675321 / 7672808 をJavaで変換し、HTTP 200 text/html; charset=Shift_JIS、投稿数29/25/20/150、日時同数、画像1/3/3/18件の寸法属性を確認。画像thumb/srcもHTTP 200 image/jpeg。
- 隔離AVDの全7パッチ適用APKで実上流の別々の2スレを開き、タイトル・本文・日時・画像付き投稿とスクロール後の返信表示（5投稿）を確認。直近ログに Invalid double null / Null check operator の記録なし。所有者端末の再検収待ち。

## あいもげ
- 所有者からbeta.11のChrome認可とLogin complete成功が報告済み。ログイン方式・資格情報保存処理は変更していません。
- 公式OpenAPIの /altcha は投稿前PoWを取得し、投稿JSONのaltchaフィールドに送る契約。従来未実装だったため、公開GETで新しいチャレンジを取得し、ALTCHA v1公式仕様（SHA-256）に従って計算し、所定のBase64 JSONを付与します。署名・チャレンジは公式応答を使用、上限を守り、失敗時は送信を中止。参照 https://github.com/altcha-org/altcha-lib-java
- 公式仕様では新規スレの画像が必須。UIとブリッジで未添付を拒否。レス画像は任意。従来の画像限定、添付上限・合計20MiBを維持します。
- アプリ専用資格情報は公式に定義されたx-aimg-tokenとして既存の公式APIへ送る。ブラウザCookie移植、追加ブラウザトークン取得、認証チェック迂回はなし。
- 実上流OpenAPI HTTP 200（156913 bytes）、client-policy HTTP 200、/altcha HTTP 200（SHA-256、maxnumber 100000）。新規実装で取得した実チャレンジのローカルハッシュ一致を検証（PC 74ms）。投稿は送信していません。
- 合成通信で、資格情報なし・画像なし新規スレ・チャレンジ失敗の拒否、レス・画像付き新規スレの最終リクエスト構築（認証ヘッダー、板、APIバージョン、UUID、本文、削除キー、添付ID、PoW）、上流拒否の伝播を確認。実資格情報や実投稿は使用していません。所有者の失敗応答が未取得のため、実際の失敗理由がすべて解消したとは断定しません。
- 投稿は拡張ホームの投稿UIから行ってください。純正Flutter投稿経路は既存どおり403 Read only。過去のHTTP errorトーストとの因果は端末リクエストログがなく未確定。
