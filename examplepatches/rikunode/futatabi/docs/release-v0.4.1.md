# ふたたび v0.4.1 — 正式版

対象：ふたったー 3.1.1（ARM64、versionCode 65）。v0.4.0の機能を維持し、端末情報の先頭表記と純正バックアップ復元時の追加板補完を修正します。

## 端末情報の先頭を純正に戻す

純正APKのアプリラベルは「ふたったー」、versionNameは3.1.1。純正のInitApp.initはPackageInfo.appNameと「 ver」、ホスト版数、メーカー・機種・OSを連結する（0x9296f8–0x929750）。v0.4.0ではブランド変更後のアプリラベルが先頭に入っていました。

Append futatabi version to device info（既定ON）で、対象のpackage_info_plusのappName応答のみを純正名に戻し、既存のdevice_info_plusのOS版末尾へのパッチ版付記を維持します。生成APKのDEXを読み戻し、map.put("appName", "ふたったー") と Build.VERSION.RELEASE.concat("/futatabi 0.4.1") を確認しました。ホスト版数・ランチャー名・ホームタイトル・Androidシステム情報は変更しません。

結果の形式：ふたったー ver3.1.1/メーカー/機種/OS/futatabi 0.4.1

## 純正バックアップ復元時の追加板補完

- 純正のrestoreは復号した内容で /shared_prefs/FlutterSharedPreferences.xml 全体を書き戻す（AOT 0x8aa4bc–0x8aa4c8、0x8aa638）。書き戻しの完了待ちの後に戻り、終了確認側にはexitの呼び出し（0x8d06e8）がある。純正バックアップに追加板・ふたたびの配色キーがない場合、それらは置換対象となる。
- 既存の起動時補完はJSON形式のリスト（VGhpcyBpcyB0aGUgcHJlZml4IGZvciBhIGxpc3Qu!）に対応する一方、純正SharedPreferencesプラグインが扱う旧Javaシリアライズ形式（末尾!なし）は処理を見送っていた。利用者の実バックアップは未取得であり、今回の報告の発生条件がこの形式だったとは断定しない。
- 新形式は既存のコールドスタート時補完、旧形式は純正プラグインLg6/a;のgetAll（b）による復号済みリストを利用し、Dartへ渡す前に不足する板を補完・保存する。新しいJavaデシリアライズ経路は追加しない。
- 標準6板の相対順序は may → img → jun → めぶきちゃんねる → あいもげ → あにまん。追加済みURLは重複登録しない。既存の純正板の名称・お気に入り・カウンタ等は復元後の補完で維持し、独自板の位置も維持する。既存の初回移行処理および旧めぶき名称の正規化は保持する。
- ふたたび固有のFlutter設定キーは flutter.futatabi.bridgePalette。これだけを既存の別ストアに控えとして保存する。復元された明示値を優先し、欠けた時だけ控えを戻す。控えがない場合は既定のダーク（既に失われた過去の値は復元不能）。
- 拡張ホームに「追加板を復活（再起動）」を追加。確認後にアプリを完全終了し、ユーザーが起動し直すと自動補完と同じ処理を実行する。純正復元直後に古いFlutter/Android設定キャッシュでXMLを上書きしないための方式で、稼働中の即時反映ではない。既存の拡張ホーム入口（あいもげ／めぶきのカタログボタン）は変更しないため、全追加板が消えている場合はまず通常の完全再起動を行うこと。
- 認証情報、投稿履歴、仮想ID対応表のバックアップ・移行は従来どおり対象外。その他の純正設定や投稿経路は変更しない。

## 確認結果

- MebukiBoardNameTest：純正バックアップ相当の全設定置換、新旧の板リスト、カスタム名・レコード・他の設定の保持、相対順序、再実行の冪等性、配色控えの復旧と明示値優先を確認。旧形式テストは純正デコーダーが返すリストを模擬したもの。
- 全9パッチの実APK適用PASS。生成DEXからappName、末尾付記、getAllの補完呼び出し、手動復活の確認ダイアログと終了処理を読み戻した。v0.4.0とのlibapp.so比較は統計の版数文字列のみの差分。配布バンドルの版ファイルは0.4.1。
- 実機操作・実投稿・実ログインなし。実際のバックアップ復元、端末情報の画面／投稿表示は所有者確認待ち。
