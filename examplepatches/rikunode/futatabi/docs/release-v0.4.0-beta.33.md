# v0.4.0-beta.33

あにまん新規スレ立ての公開確認・純正投稿結果の返却を修正し、ランチャーを1つに統合。

## あにまん：確定したコード上の欠陥

- beta.32 は comment.php の number/thread/jump と画像送信の HTTP 2xx を得た後、スレページの最初の res1 に任意の img タグがあるだけで成功としていた。異なる題名・本文・古いスレ・無関係な画像・非公開または承認待ちのスレを排除できていなかった。
- 旧カテゴリ選択 Activity は開いた時点で純正 Flutter の投稿 HTTP リクエストへ未送信のテキスト応答を返して終了していた。選択後の成功は別 Activity 内にのみ表示され、純正投稿画面へ成功の thisno が返らなかった。
- 2026-11-27 の公式トップ・カテゴリ7・新着一覧・main.js の GET は HTTP 403。当該実機投稿の上流 HTTP 応答、実際の公開有無、承認待ち・削除・アップロード拒否のいずれかは未確認。上記欠陥を当該事象の唯一の原因とは断定しない。

## 修正

- 公式保存済み HTML（2026-11-23）の og:url、h1 threadTitle、res1、resposted、resbody、img/{thread}/1 と thumb_m/{thread}/1 の構造に基づき、作成応答と新規スレの同一性を照合する。時刻は日本時間として解析し、投稿開始時刻との照合を行う。
- comment.php の OP 番号と HTTPS の同一スレ遷移先を検証。preCheck・本文・画像送信で明示的なエラー HTML/JSON を認識した場合は HTTP 200 でも成功扱いにしない。リダイレクトは追わない。
- スレページと選択カテゴリ一覧をキャッシュなし、保存した投稿 Cookie を付けずに取得。同一のスレID・題名、本文、日時、正式な添付画像の構造を確認できた時だけ publicConfirmed を立てる。画像アップロードの2xxだけでは成功しない。公開確認失敗は再投稿を促さず、段階・HTTPステータスまたは照合不一致を表示する。
- スレ立ての同じ純正HTTPリクエストを結果待機させる。カテゴリ画面の選択・確定結果を返し、公開確認済みの成功ではカテゴリ画面を閉じ、既存の純正 thisno 成功経路へ返す。キャンセル時は未送信。待機上限120秒。送信開始後の通信断や待機終了は結果未確定で、再送しないよう案内する。失敗時に純正下書きを消さない。
- 公式の本文・画像の別リクエストを維持する。画像失敗時のサーバー側ロールバックや承認制の詳細は未確認。本文受理応答だけでは公開を保証しない。
- 公開ページの形式変化、本文のサイト独自変換、一覧の反映遅延等によって、実際には作成済みでも未確認となることがある。安全側に倒し、自動再投稿は行わない。実機の Flutter 側待機・閉鎖・入力クリアは未検証。

## ランチャー

FutatabiHomeActivity の MAIN/LAUNCHER 登録を削除し、非公開 Activity とした。BoardLoginLaunch の既存明示 Intent（あいもげ・めぶきのカタログにある Board login button、既定ON）を維持。ThreadReplyActivity、認証、診断、本体の各処理は変更しない。Board login button を無効化した場合は独立した拡張ホーム入口がなくなる。
