# Hoshiori v0.6.0 — アプリ内設定とドロワーカスタマイズ

Hatena Bookmark 5.80（versionCode 58000）のみ対応。

- 元アプリの設定画面に「Hoshiori」を追加し、専用の設定画面（記事一覧／記事の閲覧／表示のカスタマイズ／アプリ情報）を開けるようにしました。
- 6機能のうちクローン化以外の5機能はアプリ内の専用SharedPreferences `hoshiori_settings` を参照します。クローン化は状態表示のみで、インストール時に決まります。
- 広告フィルターの自動更新もアプリ側でON/OFFできます。設定の切替は次の画面読み込みや対象処理時に反映されます。
- Cookie保持は、従来の削除呼び出しの単純な `nop` ではなく、設定がOFFの場合に元の削除処理を実行するガード方式に変更しました。初期値はONのまま。既存のCookieを設定変更と同時に削除するものではありません。
- ドロワーの既存項目を表示／非表示にし、既存グループ内で並び替えられます。「設定」は常に表示されます。既存の項目ID・遷移先は変更していません。
- Morphe Managerのパッチ構成と既存オプションを維持しています。Manager側で組み込まれない機能はアプリ内設定では有効化できません。
- Manager上では既存の6パッチに設定Activity登録・Hoshiori設定入口・ドロワー制御の3件が増え、合計9件になります。すべて既定ONです。

## PR記事専用タブについて

この版には収録しませんでした。5.80のDEXでは `CategoryHotEntryPagingSource.withDate()` の手前で `BookmarkEntry` を取得できますが、各カテゴリは別々の `getCategoryHotEntries` とページング位置を使っています。複数カテゴリを統合したPR専用のページングと、それを `TopScreen$Tab` に安全に組み込む一貫した実装経路を確認できず、フェーズDの成立条件は未達です。通常フィードのPR除外は維持します。

元APKへのパッチ適用とDEX・Manifestの確認を行います。設定UIの実機操作、リストのON/OFF、ドロワーの並び順の保持は端末での最終確認が必要です。
