Version **12.7.1 / 1558**, Android 12L+. [Implementation audit](../../rtl-nieuws-audit.md) and [research evidence](../../research/2026-10-28/rtl-nieuws.md). The user confirmed the main reading/playback behavior and approved stable publication on 28 October 2026 after v1.10.0-dev.4. The audit records the earlier startup and campaign follow-ups and their verification limits.

| Patch | Effect |
| --- | --- |
| Hide ads | Suppresses native placements, client-side video ads and all audited native/Swrve in-app campaign paths before UI creation, including session, cached, event, message-center, deeplink and embedded routes. Retains normal media completion. |
| Disable tracking | Includes ad removal; suppresses audited app/video analytics, optional advertising/profile identifiers, diagnostics and known persisted measurement batches. Keeps initialized account, push, configuration and playback services. |
| Skip consent screens | Includes both controls; skips the startup cookie/privacy screen and notification setup/reminders before presentation. Completes the genuine privacy busy/ready state without recording a consent choice. Fresh notification groups stay off; the native startup route requests no permission. Manual notification settings, existing opt-ins and privacy settings remain available. |
| Disable Swrve (expert) — off by default | Includes the standard controls and uses the SDK’s native disabled implementation. Stops Swrve background jobs and disables push delivery/automatic registration, including fallback Firebase handlers. **Push notifications and Swrve channel synchronization stop working.** Shared Firebase authentication, installation and configuration services remain. |

The default campaign controls retain push functions and manual notification settings. The expert option also stops the remaining Swrve user/device/configuration activity and background push work, reducing SDK-related data exchange. It disables push notifications and Swrve channel synchronization; existing local choices are retained for a later build without that option. Campaign code/resources remain in the APK but their shared selection and pre-display boundaries are disabled. This also blocks newly configured messages using these supported-build campaign paths.

These controls preserve genuine accounts, purchases, media authorization and DRM. Remote embeds and server-inserted media remain separate boundaries. The original legacy TFK player references a missing Source overload; that upstream compatibility issue is unresolved.
