# 9292

**Supported app:** 2.48.1 · **Build:** 32189 · **Input:** APKS

`nl.negentwee`

[Download the original APKS](https://buzzheavier.com/owlolzxsfin0){ .md-button .md-button--primary }

Select this file in Morphe Manager to apply the patches.

Planning a journey can generate Firebase events with your planner choices, screens and device properties, linked to the app's own user ID. The app also passes a rounded location to advertising, shows station ads and voucher offers after a payment, and sends separate Usercentrics session pixels. 9292 is part of the stable bundle from v1.17.0.

## What remains and what is still unknown

The app's user ID still identifies you to 9292's own API. Precise location, journey requests, Maps, Firebase Remote Config, Installations and FCM, real payments and 3DS, and Donkey and Linka rental and lock operations remain, as do Adyen setup telemetry with its checkout attempt ID and operational Donkey and Linka events. Regional Usercentrics consent services can still connect. Functional consent, explicit data deletion and notification settings keep working. First-party home banners without a paid-ad marker stay so travel and service notices are not lost. Local diagnostic files may remain. Functional services still receive data and ordinary network information such as your IP address.

Earlier development builds could leave a saved flag that brings back the prompt to delete your local data. From v1.17.0 the consent patch clears that flag at startup and keeps functional consent given. If an older development build shows the prompt, upgrade instead of confirming deletion.

Live route planning, Maps and real payment and lock acceptance still need testing. The original native libraries remain. Use the complete original Android 12L+ (API 32) Play split set of this exact version.

## Available controls

Disable tracking, Fix PairIP startup, Hide ads, Skip consent screens.

All four are on by default. Hide ads includes Fix PairIP startup, Disable tracking includes both, and Skip consent screens includes all three.

Skip consent screens submits all consent decisions in one write. The consent SDK stores timestamps in whole seconds and keeps the first write when a later one has the same timestamp, so a rejection followed by a separate functional approval could leave functional consent denied. The setting allows local data only; advertising and analytics consent stay denied.

The evidence comes from source inspection, checks of the original and rebuilt APKs, and bounded execution of retained instructions. Native regressions also cover an interrupted explicit deletion, stored consent timestamps that are equal or newer, and consent-storage failures.
