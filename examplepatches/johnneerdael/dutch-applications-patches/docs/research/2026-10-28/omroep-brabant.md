## Narrow candidates and contract risks

These are **inferred research candidates**, not implemented or proven on a device. Fingerprint package/version/signer/method contracts; never target a short obfuscated class name without its surrounding descriptors, resource strings and caller evidence. No existing Buienradar/DPG patch has a demonstrated matching binary contract here.

1. **Display:** suppress ad-only section construction/placement at model boundaries (`r8` consumers/`ja.R0`) while leaving feed/article/news sections and pagination intact. An alternative is a deliberate no-fill at `OptOutAdView.e(Lk9;)V` that resolves the caller's existing failure once; validate XML and both Compose listener state contracts, view cleanup and logging. A silent return there would strand loaders; the bridge's concrete `w56` cast prevents treating every listener as an arbitrary SDK wrapper.
2. **Outbrain/StartApp:** use the existing `pi6.d=false`/no-widget branch before `ty` insertion, then separately audit startup/provider traffic. Suppress the widget before remote JS/MREC instantiation to avoid hidden requests. Keep app-owned article-click/navigation handlers for ordinary content. Manifest splash/return flags alone do not remove embedded MREC.
3. **Vertical video ads:** take the existing null-config/original-list path in `xc0` or map only `verticalVideoAd` to absent at the typed app config boundary. Preserve selection/index compensation and no-ad list emission; simply making `Ly5a` blank leaves a pager item. This is independent of regular ad scheduling.
4. **Regular video:** prefer the original no-scheduling/no-services content path in `kj7.A0`, preserving EmbedObject clip/playlist data. Both scheduling and service renderers matter, including explicit renderer mode and late data. `EmbedObject.getAdSchedulingData/getAdServicesData` are compact fingerprint anchors, but nulling both is **not yet proven** sufficient for the renderer branch. Do not replace `u8.r`, errors or completion with void no-ops; they own state transitions.
5. **Tracking:** isolate app Firebase sends (`xd.d/b/c`) and push direct sends; use the app's false result gate in `t77.a` for Piano events while retaining non-null singleton/startup contracts. Preserve `nt.l` cleanup while preventing ContentInsights article activation at its specific point; `nt.n` is mixed and cannot be dropped wholesale. Isolate `nt.j` network read telemetry after local DB history; preserve its Kotlin result return shape. NMO needs separate registration, UUID persistence/read and Piano forwarding coverage. An intentionally absent ID must follow a proven nullable/error branch, not a fabricated UUID/token.
6. **SDK tracking/privacy:** disable/fence individual collection paths/providers only after dependency mapping. BB noStats options can be overwritten by TCF; generic reject-all consent is not a stable all-tracking switch and can break embeds. Do not remove crash handler installation or task schedulers blindly; retained original handlers/futures must terminate normally.

**Seen security/startup risks:** publisher signer changes under patch signing; Google/Firebase configuration and any backend app/package/cert restrictions may react. Manifest contains location/AD_ID/referrer declarations; certificate-sensitive Maps, API clients, cast/FCM/integrity and remotely loaded services require patched-signature testing. Scans found OkHttp CertificatePinner implementation/default strings and Play Integrity SDK definitions, but no app-owned configured pin or integrity-token request caller was demonstrated. No TLS or integrity bypass is proposed. Re-signing success is not proof of working publisher/Google services; release integrity behavior remains unknown.
