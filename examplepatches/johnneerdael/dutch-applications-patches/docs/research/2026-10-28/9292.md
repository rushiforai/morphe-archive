## Callback, coroutine and lifetime contracts

**Seen:** both ad adapters are callback-driven. `f58.d0` passes onLoaded `Li55` and onError `Ll55` to `e58`; `u48.d0` passes them to `t48`. On load they mark/cache state through app lambdas and on failure they store an error used by `AdvertisementPlaceHolder`. Adapter constructor exceptions follow the same error path in `mh.NTAdView`. Leaving a request uncompleted can leave a reserved rectangle/error state; emitting a fake success with no view can expose a null-view branch. Prefer bypassing the already guarded render/init paths rather than stubbing request calls alone.

**Seen:** `mh.h:ArrayList` stores `tk` blocks (`unitId`, `ny2 adView`, `isLoaded`, `c97 error`). Base fragment `Ltb8;->onStop()V` iterates these adapters, calls `ny2.g0()`, then replaces the cache (`decoded/smali_classes4/tb8.smali:1249-1345`). Preserve disposal when moving between screens or backgrounding, including if an old process/cache contained ads before an override changed. PubMatic `f58.g0()` and Google `u48.g0()` are the respective destroy methods.

**Seen:** dependency startup, current-location acquisition, consent reset, widget updates, ticket status polling and payment telemetry setup are Kotlin suspend state machines. A patch must return the expected Unit/domain/error result, preserve `COROUTINE_SUSPENDED` behavior where still awaiting real work, and complete exactly once on every bypass/error path. Exact ad flag lookup overrides are synchronous; whole-method replacements of `ep0.c`, `uu2.c` or `x43.a` would discard unrelated work.

## Entitlements, public delivery and signing risks

**Seen:** no Android BillingClient class/type was found in all DEX inventories, and app resource/model searches did not reveal an ad-free subscription, premium entitlement object, purchase-token validation or ad-removal SKU. Ticket upsell/payment/cart flows purchase actual transport products; WMO/rental options are not proof of an ad-free tier. **Conclusion, bounded:** no app-specific paid ad-removal gate was identified in this build. Dynamic/server content and future versions remain unknown.

**Seen:** the only explicit PAYWALL control-flow graph found is Pairip Play licensing. `LicenseClient.processResponse(int,Bundle)` validates the licensing response; an unlicensed response obtains PAYWALL_INTENT and starts LicenseActivity. This can affect sideloaded/re-signed installs independently of the ad system. It is not a local subscription Boolean and should not be presented as a premium unlock opportunity.

**Seen:** functional API access uses native-key-backed HmacSHA256 token construction, correlation ID and anonymous user ID. **Unknown:** anonymous public body delivery, server account/order checks, key certificate restrictions and status/content returned by `wrapper.9292.nl/v2.15/*` without the app protocol. No token was extracted into Git or used in a request. No public read probe was required to support the static findings; therefore no claim of publicly delivered protected data is made.

**Inferred:** re-signing changes the package certificate, so Play licensing, signature-restricted Google Maps/API configuration, payment/lock SDK checks and app-link verification are regression risks. Static JNI/export inspection cannot establish acceptance. No named Play Integrity/App Check client implementation was found in the class/type inventories (the sole `integrity` definition is Chromium WebViewMediaIntegrityApiStatus); Pairip binder checks still exist. Encrypted assets and stripped `libd124.so` prevent a blanket claim that every integrity mechanism was ruled out.

## Regression and negative-test plan

The following checks were **not executed**: this assignment authorizes research only, without device, emulator, ADB, builds, accounts or purchases. They are acceptance boundaries for later implementation.

Feed mixtures with ads at first/middle/last positions and all-ad/empty input must produce sensible content. Station ad removal must not remove stop/platform/timetable messages.
- Consent first-run/accept/reject/change/error/offline: preserve decision storage, functional-consent header semantics, completion callbacks, explicit user-data deletion and widget refresh. Optional telemetry must remain disabled after a later grant/remote config refresh.
- Planning by address, stop, via, current location and saved route; high accuracy/last known, permission denied/permanently denied, GPS off/unavailable: preserve precise functional location/error. Assert the separate coarse OpenWrap publication is gone.
- Live travel advice, maps, vehicle/train information, rental map and route links: retain API/map bodies, keyed service access and decoding. No broad Google/Firebase/9292/Adyen/Donkey host outage.
- Wallet/cart/order/status/activation: preserve genuine server authorization and pending/failure/success states, payment return intents, cancellation/back behavior and ticket visibility. Use authorized test fixtures/sandbox only; no fabricated ticket or payment result.
- Notifications: retain POST_NOTIFICATIONS handling, calamity and departure-alarm channels, scheduled alarm receiver, FCM delivery/token work and deep links. Firebase Analytics/Crashlytics/Sessions traffic must remain absent while FCM/Remote Config work continues.

- Re-signing/install-source matrix: original certificate versus test certificate, exact supplied split set, minimum API32 device plus current target behavior; watch Pairip licensing, Maps and payment/lock initialization. A successful build/install is not proof of retained functionality.
