# Marktplaats — static research, 2026-10-28

Status: **static research complete; runtime and server validation outstanding**. Research only: no application patch, build, signing, device/emulator, account, login, transaction, purchase, commit or push action.

**Seen:** this build has multiple independent advertising paths and several app-wired telemetry systems. SDK display banners, Google custom native banners, first-party native advertising and sponsored content are distinct from the marketplace's real seller listings. Removing every class or endpoint containing “ad” would break its core product. No reader ad-free subscription gate was identified; business subscriptions and seller promotion purchases are genuine server-backed products.

## Startup, consent and re-enable paths

**Seen:** `HorizonApplication.onCreate()V`, classes.dex `0xe2ef4` (`decoded/smali/com/horizon/android/HorizonApplication.smali:1435`), initializes Firebase/App Check objects, ThreatMetrix, app configuration, crash analytics and WorkManager startup; it explicitly enables FCM BigQuery delivery metrics (`:1653`). Do not replace the entire application startup method.

**Seen:** `Lc37;->c()V`, classes3.dex `0x1fba4c`, inlines Google MobileAds initialization. `c37.d()V`, `0x1fbbec`, initializes OpenWrap, sets application info/store URL and profile configuration. `c37.a()` performs WebView crash/workaround setup; **c37.b() manages functional category cache**, so class-wide neutralization is unsafe. `Lwg;->onActivityResumed(Activity)V` invokes c37.c/c37.d/c1c.a from a first-resume bootstrap guarded by c37.i (`decoded/smali_classes4/wg.smali:528,1090,1112,1150`). That same callback also updates categories/chat counters/saved-search data: preserve it and remove only ad/telemetry substeps. Google MobileAdsInitProvider runs before this app code. Manifest also wires FirebaseInitProvider, Datadog DdRumContentProvider (initOrder 999), Adjust SystemLifecycleContentProvider, FacebookInitProvider and Firebase registrars for performance, App Check/Play Integrity, Remote Config, crash, analytics, sessions, installations and messaging (`decoded/AndroidManifest.xml:907,1007-1048`).

**Seen:** manifest defaults deny Google ad personalization/storage/user data and analytics storage, disable automatic screen reporting, disable Crashlytics collection, and disable Facebook automatic event logging/advertiser ID collection. These are starting defaults, not proof of no telemetry. Crash startup reverses its own default, and consent callbacks actively configure multiple trackers.

**Seen:** Sourcepoint listener `Lcg3;->onConsentReady(SPConsents)V`, classes4.dex `0x1dfb90`, persists TC string/vendor grants/Google Consent Mode flags, updates consent cache/state flow, configures Prebid/Google ads and calls GA `cz9.d(km6)`. It creates Adjust/Criteo wrapper via `Lei;->d(ZZLkm6;)Lwq;` and enables Facebook tracking when granted (`cg3.smali:765-975`). That helper returns real `yq` when Adjust consent is granted and a disabled wrapper when denied (`ei.smali:359`). A no-op wrapper is an existing design pattern; replacing the whole CMP callback would lose required state transitions.

**Seen:** consent vendors include Adjust, Braze, Criteo, Facebook, Gemius, Google Ads Products and Google Analytics. Criteo behavioral/transaction event metadata is sent through the Adjust wrapper; a separate Criteo SDK definition was not found. Gemius has a consent key/feature switch, but the inspected callback only reads its grant without an uploader call; an active Gemius SDK/upload graph was not established.

**Seen:** `cg3.onUIFinished(View)` removes the CMP view, clears its showing flag and signals `dg3.i` with true (`cg3.smali:1454-1500`). onUIReady/onError are separate callbacks. Preserve completion and error behavior, current grant/acknowledgment persistence and settings reopening; do not strand startup waiting for CMP or fabricate consent grants. Sourcepoint's `js_receiver.js` is a WebView message bridge, not a generic reason to disable all web content.

**Inferred:** these are seller/business listing products and server-authorized orders, not a local reader ad-free entitlement. Do not grant eligibility, successful subscription/payment state, promoted ranking, quota, shipping insurance/buyer protection or paid listing features by changing presentation Booleans. UI gate removal cannot create the corresponding server service. Real listing metadata, prices, seller offers and paid business status remain functional content.

## Regression and negative tests for later implementation

None of the following were executed: this research task excludes builds, device/emulator use, accounts and transactions.

- Cold/warm start, restored preferences, process death, upgrade and background return: no ad SDK auto-init/config/bids, GAID/ad-services access, third-party creative WebViews, native-ad event/metrics uploads, Adjust/Braze/GA/Datadog/crash/performance/session telemetry or FCM delivery export. Include queued files and later consent grant/revoke/login/logout re-enable attempts.
- Anonymous/guest listing search, category/attribute/postcode/radius sorting, pagination, saved searches, map suggestions, category cache and deep links must retain valid content and server totals. Test mixed first/middle/last ad rows and all-ad/empty response; no blank spacing, retry loop or stale native cache.
- Compare default/ICAS/promoted seller listings with SDK native/display ad slots; preserve item titles/prices/images, seller reputation/contact, bids, watchlist/favorites, shipping/buyer protection and legal/DAC7 disclosures. No indiscriminate filter on the word “ad”.
- VIP has top/description/custom banner and native video paths; preserve listing photos/video player, click actions for real seller content, full description, location and navigation. Pause/destroy any existing banner views/timers on background/detach.
- CMP first-run/settings/offline/error/accept/reject/revoke must finish normally and retain real decisions; optional tracker branches remain disabled after every callback/observer transition. Verify no Sourcepoint UI remains over the app.
- Guest and logged-in token refresh,401 retry/logout, two-factor/biometric/Google/Facebook auth, captcha/security checks and ThreatMetrix timeout/result paths must remain correct; do not emulate successful auth to make tests pass.
- Chat/new-message notification, dismissal/click, order/security notification and requested search alerts must work without marketing engagement reporting. Push subscription changes remain server-authenticated; background FCM cannot be disabled wholesale.
- Checkout/buy-now/payment offer, shipping location/price, listing publication, business bundle eligibility/order/cancel, invoices and buyer protection must keep genuine server pending/failure/cancel/success states. Use authorized sandbox/fixtures later, never real unauthorized purchases or fabricated entitlements.
- Network assertions must cover app OkHttp, Firebase transports, WebView/remote JavaScript, native profiling and SDK background workers. Static host lists cannot prove zero tracking or exhaust creative redirects. Remote flags/campaigns/user cohorts may select alternate branches.
- Re-signing/split matrix: original/test certificates and all supplied splits, minimum API 32/current API behavior; test OAuth/Maps/Places, Play/AppCheck/security, anti-fraud and payment SDK behavior. Absence of a static pin does not prove acceptance of a modified build.

## What remains unknown

No runtime app execution or network request sample was performed. Static request contracts do not establish public body delivery or server authorization without normal guest/account tokens. Actual ad campaigns, creative domains, Prebid demand execution, UserZoom study permissions, paid/promoted content selection, security backend acceptance, optional Adyen telemetry activation, native/encrypted logic and signature-dependent behavior remain unknown. SDK/feature presence has been distinguished from app-owned calls and from execution evidence throughout. No proprietary source/key material was added to Git; only this research report was written.
