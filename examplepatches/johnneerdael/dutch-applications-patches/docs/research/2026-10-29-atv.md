## KIJK controls

`Hide ads` pins the hosted ad configuration, suppresses pause-ad display, returns an empty VMAP for identified FreeWheel decisions, and removes the inspected Theo adapter's client ad-schedule attachment. It preserves the original content source. Broadcast and server-stitched advertising are outside this evidence.

`Disable tracking` removes the native advertising-ID result, reports advertising limitation, pins hosted ID5/Conviva/GA/Sentry settings, clears the inspected ID5 cache, and supplies bounded sinks for TVA/Tealium calls. Identified optional measurement destinations receive local empty responses. Real OneTrust consent, accounts, content, DRM, subtitles and media services remain available. Functional backend requests still reveal information to their operators; this is not a claim of anonymity or zero traffic.

The wrapper delegates the publisher's WebView callbacks, including bridge initialization. HTML rewriting runs before executable bundles. The player guard is changed only when its inspected pattern occurs exactly once; unknown layouts retain the original response and produce a diagnostic message. The hosted frontend can change independently of the APK version.

The frontend service worker can bypass `WebViewClient` by returning cached, unmodified assets. The bootstrap therefore rejects registration of the exact KIJK `/android/sw.js` worker, including query variants, and unregisters matching active/waiting/installing registrations. Other worker URLs delegate normally. This removes the app-shell cache, not media playback. **Use a clean installation for acceptance testing.** Unregistering a worker does not release its current document, and cached HTML can prevent the new bootstrap from running at all. Upgrading an earlier diagnostic APK with `adb install -r` is not proof of cache migration. Clearing application data also clears account and consent state.

`Enable WebView debugging` is an optional, off-by-default diagnostic control. Keep it off in normal-use candidates.

Observed on a rooted API 28 UGOOS: storefront rendered; the real OneTrust preference flow stored necessary-only consent; a full-length free episode played and advanced; Widevine requests succeeded; media pause/resume worked; a FreeWheel decision was intercepted. The earlier diagnostic session exposed the service-worker gap. After unregistering the old worker and opening a new document with the final bootstrap, no worker controlled the document or remained registered, the actual hosted player guard was removed, the wrapper logged schedule suppression, and free VOD played again. A direct HTML video seek outside its buffered range stalled; returning inside its buffer resumed playback. Remote seeking is not accepted by this test. These observations are a bounded smoke test, not a complete packet capture or long-form playback audit. Live streams, midroll transitions, casting, account pairing and premium media remain separate acceptance checks.

## NPO controls and runtime recovery

`Hide ads` returns null from the five concrete nullable preroll getters and the optional IMA ads-loader factory. `Disable tracking` changes NPO Tag/Topspin, DAM, player session/Ster input, Sentry and Bitmovin analytics boundaries with the caller's actual return type. It removes the identified advertising permissions and disables inspected automatic analytics/crash/session initialization metadata. Functional providers, configuration and messaging are retained. Both public controls default off; select both for the combined build.

PairIP startup restores 1,437 immutable strings in 32 holders and nine reflected method references across four holders. The nine lifecycle helper classes come from the original startup asset's embedded DEX, checked by exact asset and DEX SHA256 before merging. The generated constants contain no captured account/session state. ART reflection on API 34 independently reproduced all restored values and methods.

Frida Gadget inside the app's UID established that the later `+0x3cb28` fault occurs during `executeVM`, after the native library has loaded. It consumed the unchanged `RhLj4nQzA8FodOQ7` program for the network/audio receiver; a negative count led a hash loop into a guard page. Calling this a library-initialization failure was incorrect. Suppressing that receiver exposed an independent AppAuth discovery task crash at `+0x5e28c`. A signature-only control retaining the original bootstrap fails at `+0x43378`. The underlying native rejection/interpreter state remains unproven; broad VM no-ops are not a functional recovery strategy.

The handover restored real [AppAuth Android 0.11.1 discovery behavior](https://raw.githubusercontent.com/openid/AppAuth-Android/0.11.1/library/java/net/openid/appauth/AuthorizationServiceConfiguration.java), preserving configuration parsing, typed errors and the original completion callback. The user confirmed live TV playback from `startup-appauth-discovery.apk`; the installed APK hash matched `285e76c142d3dc2caf806538b590627d3a9312fff63f24739c8c0f782fa136a2`. That diagnostic still suppressed the network/audio receiver and did not select the ad/tracking patches. It is a preserved acceptance baseline, not a release artifact.

Production integration now restores both receiver variants: network classification stays on the existing executor/runnable, and audio-route changes publish the original `BecomingNoisy` event to every registered player flow. AppAuth also closes its stream if error wrapping itself throws. The patcher inserts instructions without transferring inline `.catch` metadata, so the integration explicitly registers all five exception entries. An independently decoded APK test reproduced the missing-table failure before this correction. The corrected emitted method bodies pass 12 ART behavior cases on the spare API 28 box, including listener snapshots, typed errors and exceptional cleanup. The native VM remains intact; unmodified protected callbacks retain their original execution, while the tracking selection also suppresses the telemetry-only alarm receiver; the two recovered methods retain their original unreachable VM tails for full-method comparison.

The current work follows [the completed handover](../NPO_START_TV_PAIRIP_HANDOVER.md). Preserve the installed account/playback state; use a matching-signer update instead of automatically restoring the publisher APK. Full TV receiver, network-change, audio-route and repeated lifecycle acceptance remains separate from synthetic ART testing. The free-account and telemetry audit below supersedes the earlier startup-only acceptance status.

KIJK is installed on both TVs with debugging off. The user confirms ad-free playback on `.12`, and the matching installer was copied to `/Volumes/EXT-SSD1/phone-apks/KIJK-TV-7.2.7-adfree.apk`.

## Free-account playback and privacy audit

The user changed from Plus to a free account. The receiver-restored startup-only build crashed at playback entry in `libpairipcore.so +0x687d4`. Its program-buffer size matched the IMA HDMI measurement receiver, but the exact VM asset was not logged; that attribution remains an inference. The matching official IMA callback updates OMID advertising-output measurement. Functional player audio routing is separate.

The active TV engine is Media3: its sole application player-factory caller passes `useExoplayer=true`. Returning null from the optional IMA ads-loader factory follows Media3's existing content-only branch. The five preroll gates remain in place. The non-null Bitmovin player factory and content/DRM configuration are preserved. With this change, the user confirmed free-account playback, and the installed APK matched `npo/free-adloader.apk`, SHA256 `72ad0dd4b8559fbe67fc9cd2d029801d9821d912ea12ee41e650b324129a5090`. That acceptance selected **Hide ads**, without tracking.

The subsequent tracking audit adds these exact TV boundaries to the original nine tracking edits:

## Token-request regression and device validation

The combined build later crashed on `AsyncTask #1` at `libpairipcore.so +0x66924`. The earlier cold start and cached-session playback checks had not exercised this protected token-request path. On the target TV, Shizuku/rish launched the same-signer diagnostic and Frida Gadget captured the failure inside NPO UID 10251. The VM entry log identifies `UeibxlO3N5eP2BBY` from `zt.i.doInBackground`; its 176,414-byte asset matches register `r9`. This is a confirmed caller, not a length-only attribution. No token values, request bodies or credentials were logged. Rish runs as shell UID 2000; Gadget provides the observation inside the app process. The TV's actual Shizuku manager is `com.hamondev.shevery`, reached through its compatibility stub.

`TokenRequest.kt` restores genuine AppAuth token-request behavior through the shipped HTTPS connection, request parameters, public-client ID, Accept helper and UTF-8 form encoder. It reads the real success/error JSON and maps IOException/JSONException to the original typed errors. Four explicit exception entries close the response stream even when error wrapping throws. The unchanged `onPostExecute` retains OAuth errors, token parsing, ID-token validation and the original callback. No token or entitlement is synthesized, and general VM execution remains intact.

The old emitted method reaches the protected VM in the regression harness. The replacement passes all 17 source and emitted-method ART cases on the spare TV, using the original Accept and form-encoding helpers with synthetic HTTPS responses. The 145 host tests, all 107,858 method/startup/helper contracts, binary manifest equality and signer checks pass. Independent review found no critical or important issues.

`npo/token-restored/all.apk`, SHA256 `197cf02c945f42f20b53d3f5cc7ecb3b043a8a8ddb95e0e5180dff24f20d25f4`, updated `.12` with the same signer and preserved UID/account data. It contains both ad and tracking controls and no Gadget. Three forced-stop/cold-start cycles produced new surviving processes. Content then played in NPO's own Media3 session: position advanced from 0 to 81,077 ms, with 134,400 ms buffered, speed 1 and no playback error. These observations cover repeated startup and playback entry; long-duration, physical route/network, fresh sign-in and complete traffic acceptance remain separate.

Private evidence: `npo/regression-115533/{finding.json,frida.jsonl,vm-caller.log,rish-id-shevery.log}` and `npo/token-restored/{install.json,cold-starts.json,playback-observed.json,token-art.log,verify.log}`. The older ad-only baseline also retains the protected token task, so reverting to it is not a reliable remedy after credentials need renewal. Preserve the current working patched build and account state.

## Access boundaries

No subscription purchase, account entitlement, media token or DRM license is forged. No local flag has been shown to grant backend-withheld media. Free-tier playback is the supported research target; cosmetic tier changes would not prove access.

## Reproduction

Build with the repository's normal JDK/SDK requirements:

```sh
./gradlew buildAndroid
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/run_npo_runtime.py --serial 192.168.50.89:5555
python3 tests/run_npo_token.py --serial 192.168.50.89:5555 --decoded PRIVATE_DECODED_APK
python3 tests/run_npo_privacy.py --serial 192.168.50.89:5555 --apk PRIVATE_CANDIDATE.apk
```

Patch each selection separately with Morphe Desktop 1.19.1, `--exclusive --validate --bytecode-mode FULL`, the bundle in `patches/build/libs/`, and original publisher APKS input. Use `-e 'Hide ads'`, `-e 'Disable tracking'`, or both. Stage input and output on a filesystem that does not create AppleDouble APK sidecars during split extraction.

After independent APK decoding, compare output to the original decoded trees:

```sh
python3 tests/verify_kijk_atv.py ORIGINAL PATCHED --ads --tracking
python3 tests/verify_npo_atv.py ORIGINAL PATCHED --ads --tracking \
  --startup-data PRIVATE_TV_CAPTURE_JSON --embedded-original ORIGINAL_HELPER_DECODED
apksigner verify PATCHED.apk
```

The optional ART harness installs no APK and uses synthetic dependencies. Pass `--decoded PATCHED_DECODED` to exercise the actual emitted callback methods and ensure their retained VM tails stay unreachable.

Use only the selection's flags; add `--debug` for the KIJK debugging candidate. The KIJK verifier checks all 12,807 original methods. The NPO verifier checks all 107,858 original methods, startup data and helper bodies. Canonical graph comparison normalizes only unreachable alignment padding before a payload; executable instructions and branches remain part of the comparison. The phone NPO input shares a version name but has a different version code and is rejected by the TV guard.

Keep raw captures, APKs, decompiled publisher trees, signing keys and account-bearing logs outside Git. Private validation artifacts for this session are under `/Volumes/MorpheResearch/tmp/atv-validation-20261029/`; private capture evidence is under `/tmp/re/atv-2026-10-29/npo-start/capture/`.

The refreshed tracking-only selection also passes all 107,858 original-method/startup/helper/manifest checks and the matching-signer check; this is output verification, without a separate free-playback acceptance claim.
