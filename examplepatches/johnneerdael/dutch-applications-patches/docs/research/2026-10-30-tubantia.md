# Tubantia 9.23.2: comparison with the AD patch family

All five AD controls are ported to the supplied Tubantia build: Hide ads,
Disable tracking, Skip consent screens, Hide Premium banner, and Read full
articles. The port follows the actual Kubus/Popular DTO and service boundaries;
it includes the newer custom-auth router and relocated tracking initializer.

The DTO review checked 24 constructor boundaries and 48 field contracts. Twenty-three
constructor remainders retain the same normalized structure as AD. The changed
BreakingNewsTeaser constructor removed an old derived-title field; fields used by
the filter retain their meaning. The filters preserve input immutability,
editorial child identity/order, mixed overlays, editorial inline defaults and
whole-body handling for explicitly commercial article metadata.

The FIAM startup assignment moved out of MainApplication into
`com.kubusapp.startup.TrackingStarterInitializer.b(Context)`. Guard this optional
consumer plus MainActivity and `j1i.b(ss3)`; retain the initializer's later work.
Firebase messaging methods also changed: AD's `di5.M/N/W/x` correspond to
Tubantia's `sgj.y/z/H/r`. The advertising-collection predicate is `u4k.H3`.

## Validation

The original baseline, each of the five controls, and all controls together pass
Desktop FULL patching, the explicit patch report, APK signature verification,
and independent checks after decoding the emitted APK. The selected-effect check
fails on the unmodified original, as expected. Logs are retained in
`build/validation/tubantia/` and `.local/tubantia-hbvl-20261030/tubantia-matrix.log`.

The verifier pins 867 unchanged methods and 42 original remainders with locals,
access flags, exception tables and branch/switch targets. Separate constructor
and startup contracts cover modified non-prefix instructions. The onboarding
verifier pins 113 methods and executes emitted router/topic/state instructions
at Android and encrypted-storage boundaries. It checks absent/existing choices,
guest continuation, both OS permission states, city selection and manual resume
choices. DTO fixtures execute the actual emitted helper instructions; SDK method
and invocation-kind checks use the installed API31 android.jar, below minSDK32.
No private article prose or credentials are committed.

The combined patch bundle builds and its generated catalogue contains all five
Tubantia controls and all four HBVL controls with the verified identities. The
Python regression suite passes 267 tests (four skips). The four new bilingual
app pages pass the fixed template and target-metadata checks; the documentation
build and rendered local-link/language checks pass.

The all-control output is `build/validation/tubantia/tubantia-all.apk`, SHA-256
`d39d5108a2cf3d58901ccc0b80a8052a769e899f3842726a9997a1e74928428c`.
All four original ARM64 libraries and all 120 source assets are byte-identical
in that merged output. Each source split is included in validation; the
original APKS digest is unchanged.

## Remaining unknowns

No new device installation, app startup, playback test or network capture was
performed. The article patch requests complete content through the shipped API;
no Tubantia response containing a complete Premium body was captured. This does
not establish rights or delivery for content the server withholds. Separate
audio delivery/session coordination and remote editorial embeds keep the AD
research limitations. Static and controlled instruction tests do not establish
exhaustive runtime network suppression.
