# Penguin Patches

- Independent GPL-3.0 patch collection compatible with Morphe; preserve LICENSE, NOTICE and source attribution.
- Put app patches under `patches/src/main/kotlin/io/github/pengusto/patches/<app>/` and runtime extensions under `extensions/extension/src/main/java/io/github/pengusto/patches/extension/<app>/`.
- Use official Morphe APIs and existing Gradle tooling. No embedded APKs, signing keys or tokens in Git.
- Work on dev. Publish only patches tested against specified original APK versions, including signature/package identity, install, UI and save/data regression checks. Document original APK provenance and checksum.
- Bundle each logical change with its tests and documentation; squash iteration commits when merging. Collect final acceptance evidence in one closing commit and preserve published history.
- For visual fixes, include matched original/patched APK screenshots in the upstream PR/issue and Penguin acceptance. Keep device size, theme, sort/filter and synthetic data consistent; exclude keyboard/dialog obstruction. Preserve raw PNG/XML, hashes and APK/source provenance. Label widget renders separately from installed-APK evidence.
- Keep a labelled before/after pair for every released patch in `docs/PATCH_EXAMPLES.md` and regenerate its direct README preview; a gallery link alone does not meet README screenshot coverage. Keep feature counts generated from release metadata.
- For open-source app fixes, deliver a focused upstream source PR alongside the Penguin work; reuse an existing PR when it covers the fix. Follow the upstream contribution policy and record a concrete blocker when submission is unavailable.
- Before selecting new issues, read `docs/ROADMAP.md`, then refresh the issue discussion, open/merged/closed PRs and source on the contribution branch and active release/hotfix/maintenance branches. Inspect the relevant file history for direct commits: an open issue and no linked PR do not establish that a fix is absent. Record the branch/ref and commit for existing fixes; reuse them upstream and assess version-pinned APK backports separately. Group related symptoms as investigation candidates; establish their common cause with a regression before combining fixes.
- For Flutter/Dart app changes, use the source-contribution route documented in `docs/FINAMP.md`; establish original-APK compatibility separately before adding anything to the Morphe catalogue.
- For native Flutter snapshots, pin the original APK and engine/snapshot ABI, publish exact source for every selectable combination, and verify each composite output with the real patcher. Follow `docs/FINAMP_NATIVE.md`; never turn a rebuilt APK into a compatibility claim.
- Keep optional native-backport preferences readable after patch removal. Test the original settings adapter without new enum adapters and verify same-key APK update/removal/reapply with disposable state.
- Do not claim compatibility with untested versions or silently rewrite stored app data. Fail clearly on unsupported bytecode.
- Keep release workflow manual until the first patch is verified. Use the template semantic release pipeline; do not manually edit generated patch metadata.
- Local build: Java 21, Android SDK, `./gradlew :patches:buildAndroid`. GitHub Packages needs read:packages; pass credentials via environment, never store them in project files.
- Calendar's existing fork is the reference implementation, not an already converted Morphe patch. Preserve exact HTML on unrelated event edits.
- Before Android setup, inspect existing ignored local setup notes (especially `.scratch/android-tests/README.md` and `env.sh`, if present) and verify their tools before downloading a second SDK/emulator environment.
- Bundle repeatable emulator acceptance in scripts with explicit APK paths, serial and disposable-fixture checks, so required sandbox approvals cover a coherent test run. Reject stale UI dumps and distinguish setup failures from actual product regressions. Resolve, stop and start activities with the observed foreground Android user explicitly; activity-manager defaults can target user0 after a profile switch.
- Isolate app-specific extensions from the shared Fossify runtime: update the common-source exclusion in `extensions/extension/build.gradle.kts` and the expected module set in `tests/release/VerifyReleaseBundle.java`, then verify prior MPEs remain byte-identical. Compile-only app signatures do not establish runtime compatibility: verify extension references against the actual R8-shrunk target APK and run real UI acceptance; shrinking may remove Kotlin assertions, facades and Compose compiler helpers.
- For Java-only MPEs, exclude the Gradle plugin's implicit Kotlin stdlib runtime dependency. Inspect the packaged DEX classes to reject bundled app stubs or unrelated runtime libraries, and compare existing MPE payloads when adding an app module.
- Validate bounded Morphe options inside patch execution. Morphe Desktop 1.18.1 silently falls back to the default when a patch option validator rejects an explicit value; an execution-time check makes invalid input fail visibly.
- Surface shared-composition failures through selected patches. Manager 2.x filters unselected dependency results before checking their errors; a hidden dependency's finalizer alone cannot establish a fail-closed result. Verify selected-patch failure reporting with the current patcher too.
- Store temporary UIAutomator dumps under `/data/local/tmp`, outside document-provider roots. Writing/removing the dump in `/sdcard` makes DocumentsUI reload its visible root during every snapshot and produces partial hierarchies.
- Android UIAutomator can expose controls behind bottom sheets or the keyboard. Confirm the visible surface and IME state, and disambiguate identical labels before tapping; accessibility bounds alone do not establish that a control is reachable. DocumentsUI search uses `AutoCompleteTextView`; type into its fresh field before dismissing the IME, since hiding an empty search keyboard closes the search.
- R8 can reuse parameter registers for unrelated types inside a method. Verify live register types at every hook site; capture parameters at entry when necessary. When independent patches touch one class, normalize debug items in bytecode guards, since Morphe's mutable conversion can strip them from otherwise unchanged methods.
