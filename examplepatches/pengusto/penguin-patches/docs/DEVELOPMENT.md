# Build and contribute

Prerequisites: **Java 21**, an **Android SDK**, and authenticated read access to Morphe's GitHub Packages registry (`read:packages`). Supply `GITHUB_ACTOR` and `GITHUB_TOKEN` through your environment; never put credentials in tracked files. See the [official patcher setup](https://github.com/MorpheApp/morphe-patcher/blob/main/docs/2_1_setup.md).

```sh
git clone --branch dev https://github.com/pengusto/penguin-patches.git
cd penguin-patches
./gradlew :patches:buildAndroid
```

Patch declarations live in `patches/`; Android runtime helpers live in `extensions/extension/`; app-specific build modules keep their packaged runtimes isolated. Follow [AGENTS.md](../AGENTS.md), work from `dev`, and submit changes for review. Native regression instructions are in [tests/README.md](../tests/README.md); they require an isolated emulator and disposable signing certificate. A successful build alone does not establish app compatibility.

The template's release workflow is **manual only**. Patch metadata, the [README catalogue](../README.md#generated-patch-catalogue) and changelogs are generated by the release pipeline; do not edit them manually.


Open-source fixes are paired with focused upstream source PRs. The [contribution queue](ROADMAP.md) records issues, competing PRs and next verification steps. [Finamp source contributions](FINAMP.md) are separate from the [native APK patches](FINAMP_NATIVE.md).

Documentation generator checks (Python standard library only):

```sh
python3 -m unittest discover -s .github/scripts -p 'test_*.py'
python3 .github/scripts/generate_patches_readme.py pengusto/penguin-patches main
```

Use the branch and metadata belonging to the release when regenerating. The current checked-in metadata describes the stable `main` release even on `dev`. Omit `EXPANDED` from the README marker to keep the catalogue closed at every release size. The optional summary markers also update release counts and version in the introduction. Guide destinations belong to the generator; never change generated patch metadata to add documentation links.

For a new patch, add a section with its explicit patch-name slug and an accurately
labelled image pair to [the comparison gallery](PATCH_EXAMPLES.md). The generator
uses that evidence to embed every released pair directly in the README, grouped
by app between `PATCHES_PREVIEWS_START` / `PATCHES_PREVIEWS_END`. It rewrites
gallery-relative paths for the README and keeps baseline labels intact. The
Finamp feature count also follows metadata through `FINAMP_COUNT_START` /
`FINAMP_COUNT_END`; do not hard-code a separate patch count in the introduction.
The regression suite checks every released pair, reachable local paths, distinct
anchors, idempotent regeneration and stale feature counts. Missing comparison
evidence aborts README generation instead of silently omitting a released patch.
Keep remote captures pinned to immutable commits and state the actual comparison
baseline beside the pair; see [asset guidance](assets/README.md).

Before merging documentation, check the complete PR range with
`git diff --check <base>...HEAD`. A clean working-tree check alone does not inspect
already committed changes.
