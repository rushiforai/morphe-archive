# Linimal

[English](README.md) | [日本語](README.ja.md) | **繁體中文** | [ภาษาไทย](README.th.md) | [Bahasa Indonesia](README.id.md)

Linimal 是適用於官方 LINE Android 用戶端的 Morphe 修補套件（GPL-3.0）。它可以隱藏廣告與用不到的功能，並讓你控制已讀的傳送。所有功能都能在 LINE 的設定畫面中個別開啟或關閉，關閉時的行為與官方 LINE 相同。

![Linimal 介紹影片（32 秒，無聲音）](docs/media/linimal-promo.webp)

介紹影片畫面中出現的名稱與聊天內容皆為虛構。

Linimal 是獨立專案，並非 LINE 或 Morphe 的官方專案。

## 功能

- **隱藏廣告**：聊天列表的 Smart Channel、主頁的廣告，以及社群的廣告。
- **隱藏 Agent i・LINE AI 的入口**：主頁、錢包、聊天列表搜尋列、聊天、聊天的 ＋ 選單、照片・影片檢視畫面、設定畫面等 9 個位置。
- **隱藏用不到的項目**：下方分頁、聊天列表上方的圖示、聊天的 ＋ 選單，以及主頁的各個區塊。
- **不顯示已讀閱讀**：從長按選單或通知開啟的聊天，可以在維持未讀的狀態下閱讀。讀完後可用「全部標示為已讀」標示為已讀。
- **查看群組中誰讀了訊息**：在「已讀」旁或他人的訊息上顯示已讀人數與成員的大頭貼，也能點選「已讀」或從長按選單開啟已讀與未讀成員的清單。
- **深色模式使用純黑背景**：為 OLED 螢幕將背景與下方分頁設為黑色（`#000000`）。
- **其他**：隱藏 LINE Premium 提示、停用預覽或讓預覽可捲動、以外部瀏覽器開啟連結，以及支援通知與 Google 登入・備份。

廣告、Premium、Agent i・LINE AI 僅隱藏顯示，不會改變廣告投放、付費與 LINE 的通訊。

## 安裝

### Morphe Manager（Android）

在 Android 裝置上開啟以下連結，即可將 Linimal 新增為 Morphe Manager 的修補來源。Morphe 會自動偵測新版本。

[**➕ 將 Linimal 新增至 Morphe**](https://morphe.software/add-source?github=uta-a/linimal)

若要從 `.mpp` 檔案新增，請在修補來源畫面點選 `+`，選擇 `Local`，再指定[發行版本](https://github.com/uta-a/linimal/releases)中的 `patches-*.mpp`。此方式不會自動更新。

選擇 LINE 的 APKM，並套用 `Linimal`。

### Morphe Desktop（CLI）

需要 Java 21 以上。

```sh
java -jar morphe-desktop-*-all.jar patch \
  --patches patches-*.mpp \
  --out line-linimal.apk \
  <LINE 的 APKM>
```

### 從官方 LINE 移轉

套用修補的 LINE 與官方版的簽章不同，因此無法覆蓋安裝在官方應用程式上。請依下列順序移轉。

1. 完成 [MicroG-RE 的準備](#透過-microg-re-進行-google-登入與備份)。
2. 在官方 LINE 中，將聊天備份至 Google 雲端硬碟。
3. 解除安裝官方 LINE，再安裝套用 Linimal 的 LINE。
4. 登入後，從 Google 雲端硬碟復原。

## 使用方式

LINE 設定畫面的最下方會新增 `Linimal`。設定分為 `廣告`、`Agent i・LINE AI`、`隱藏項目`、`已讀`、`已讀成員`、`主題`、`一般` 共 7 頁。

Linimal 的設定畫面、提示與通知會配合 LINE 的顯示語言，以日文、英文、繁體中文、泰文或印尼文顯示。其他語言則顯示英文。

預設值為全新安裝時的值。更新後會沿用先前的設定。因 LINE 變更等原因而無法找到目標的功能，會自動停用，且無法在設定畫面中操作。

隱藏畫面元素的顯示類設定，會在應用程式重新啟動後生效。切換時會詢問是否要重新啟動。

## 不顯示已讀閱讀

只有從長按選單開啟的一般聊天，在該次閱讀期間會停止傳送已讀與解除本機未讀。

### 開啟方式

在 LINE 26.16.0 中，可使用可捲動預覽的帳號長按聊天時，會開啟預覽畫面而非選單。此時會在預覽下方選單的最上方加入相同的項目。在「一般」中開啟「停用聊天預覽」並重新啟動後，長按會開啟原本的選單，該選單中也會顯示相同的項目。點選後會關閉預覽，並以不顯示已讀的方式開啟聊天。預覽是否可捲動，預設依照官方的處理。在「一般」中開啟「讓預覽可以捲動」並重新啟動後，即可捲動。此設定不會為未提供預覽的帳號加入畫面，也不會改變付費與通訊。暫時切換到背景、鎖定螢幕、檢視照片・影片，或長時間閱讀時，都不會解除抑制。因設定變更而重新建立畫面時，只有在已儲存的工作階段標記一致時才會延續。

### 閱讀中的顯示與「全部標示為已讀」

不顯示已讀期間，聊天名稱標題列正下方會持續顯示「目前不顯示已讀。傳送訊息後就會顯示已讀」。標題列本身的位置不變。從背景或鎖定畫面返回時會再次顯示，並在因傳送訊息而恢復已讀，或離開聊天時消失。以一般操作開啟的聊天不會顯示。

「全部標示為已讀」會浮動顯示在輸入欄上方。
清單底部會預留與按鈕高度相符的空間，避免最新訊息被按鈕遮住。

點選後會執行官方的已讀處理與未讀解除，成功後結束閱讀工作階段並回到一般的 LINE。
若在傳送前中斷，工作階段會繼續。通訊失敗時，官方的已讀處理會保留並重新傳送，因此會直接回到一般的 LINE。
即使「傳送訊息後仍不顯示已讀」或「停止一般聊天的自動已讀」為 ON，也可以執行此操作。

沒有只將部分訊息標示為已讀的操作。我們在實機上確認，即使只傳送點選的位置，對方的官方 LINE 網頁版仍會將所有訊息標示為已讀，因此已移除此功能。

### 傳送訊息時

預設情況下，閱讀中傳送訊息會結束抑制，並透過 LINE 既有的處理反映當下的本機未讀與對方的已讀。適用對象為從已確認的聊天 UI 送入傳送佇列的文字、貼圖、圖片等操作。取消輸入或在送入佇列前失敗時不會解除。不會等待網路傳送完成。即使「停止一般聊天的自動已讀」為 ON，也只會允許這一次已讀，之後依照既有設定。

「傳送訊息後仍不顯示已讀」預設為 OFF。開啟後，從選單或通知以不顯示已讀開啟的聊天，傳送訊息後也會維持抑制與未讀標記，上方提示也會變為「目前不顯示已讀。傳送訊息後也不會顯示已讀」。以一般操作開啟的聊天的已讀不會改變。既有的設定值會沿用，更新時不會擅自開啟此新設定。

**注意：即使閱讀或回覆，對方仍會看到未讀。實際的互動與已讀狀態不一致，可能造成誤會或糾紛，請只在必要時開啟。**

### 閱讀結束

關閉聊天、切換到其他聊天，或關閉用來開啟聊天的不顯示已讀功能設定時，會解除抑制。以一般操作重新開啟同一個聊天，先前的抑制不會恢復。只關閉「傳送訊息後仍不顯示已讀」時，會在下次傳送訊息時反映已讀。只有無法確認聊天畫面已建立的預約，會在單調時鐘經過 30 分鐘後捨棄。若無法確認擁有者或觀察到結束，會回到官方的已讀處理。

### 從通知開啟

開啟「從通知開啟時不顯示已讀」後，從訊息通知開啟的一般聊天也會套用相同的閱讀工作階段抑制。僅收到通知並不會開始抑制。從聊天列表等以一般操作開啟，以及通知中的回覆・已讀動作，不在此設定的適用範圍內。社群等其他途徑也不在適用範圍內。關閉通知端的設定時，只會解除由通知開始的工作階段。

## 已讀成員

清單是根據 LINE 為顯示「已讀 N」而儲存在此裝置上的已讀紀錄建立，人數與「已讀 N」一致。Linimal 不會自行記錄已讀，也不會傳送已讀。

- 適用於群組與多人聊天。一對一聊天與社群不會顯示。
- 未讀成員是從目前的成員中扣除已讀成員。自己與傳送者不會列入清單。
- 顯示名稱以自己設定的名稱優先。大頭貼會從與 LINE 相同的公開 CDN（`profile.line-scdn.net`）取得縮圖，且只保存在記憶體中。
- 開啟 `開啟清單時與伺服器同步` 後，每次開啟清單時，會只針對該聊天執行與 LINE 定期進行的相同已讀同步，然後重新顯示。關閉時只使用裝置內的紀錄，不會進行同步通訊。

## 通知與 Google 整合

### 關閉應用程式時也接收通知

套用修補的 LINE 簽章會改變，因此在應用程式關閉期間無法直接收到通知。此設定會在註冊通知時，將傳送給 Google 的簽章資訊替換為官方 LINE 的資訊。不需要特別的準備。

### 透過 MicroG-RE 進行 Google 登入與備份

套用修補的 LINE 無法直接使用 Google 帳號登入，也無法備份至 Google 雲端硬碟或從中復原。此設定只會透過 [MicroG-RE](https://github.com/MorpheApp/MicroG-RE) 進行該驗證。使用前需要以下準備。

1. 安裝 [MicroG-RE 的官方發行版本](https://github.com/MorpheApp/MicroG-RE/releases)。官方發行版本以外的版本（其他 fork 或自行建置的版本）不會被使用。
2. 將 LINE 登入與備份所用的 Google 帳號新增至 MicroG-RE。備份時，只有已新增至 MicroG-RE 的帳號會出現在選項中。若先前已用其他帳號設定自動備份，請在備份設定中重新選擇帳號。

在未安裝 MicroG-RE 的狀態下嘗試使用 Google 帳號登入、備份或復原時，會顯示引導安裝的訊息與通知。即使剛全新安裝、尚未允許通知，也會顯示訊息。

備份或復原因「無法存取 LINE」而失敗時，會以「Google 雲端硬碟驗證失敗」通知顯示與 MicroG-RE 的連線失敗，或 MicroG-RE 傳回的錯誤（例如 `NetworkError`）。通知中也會列出 MicroG-RE、LINE 與 Android 的版本（不會列出電子郵件地址）。回報問題時，請附上此通知的內容。若失敗時沒有出現通知，請先確認是否已允許 LINE 的通知（包含「Linimal：備份驗證錯誤」類別）。若已允許卻仍未出現通知，可能是在取得 token 以外的環節（例如與 Google 雲端硬碟的通訊）失敗。

> [!WARNING]
> 通知與此 Google 整合功能，會向 Google 謊報應用程式的簽章為官方版。這可能違反 Google 或 LINE 的使用條款，也無法排除對 Google 帳號造成影響的可能。此外，也可能因 Google 端或 MicroG-RE 的變更而無法使用。

## 開發

建置需要 Java 17，以及讀取 Morphe GitHub Packages 的認證資訊。請在 `~/.gradle/gradle.properties` 中設定 `gpr.user` 與 `gpr.key`，或透過環境變數 `GITHUB_ACTOR` 與 `GITHUB_TOKEN` 傳入。請勿將認證資訊放在儲存庫中。

```sh
./gradlew test buildAndroid
```

修補套件會輸出至 `patches/build/libs/patches-*.mpp`。APK、APKM、簽署金鑰與反編譯結果不會提交。設計決策位於 [docs/adr](docs/adr)，分析文件位於 [docs/analysis](docs/analysis)（皆為日文）。
