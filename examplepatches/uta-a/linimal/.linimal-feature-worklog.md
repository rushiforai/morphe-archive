## 2026-09-22 Google ドライブ連携の MicroG-RE PoC

- 再署名版でトークのバックアップのアカウント選択が失敗する原因は、端末本体の Google Play services が LINE の実際の署名で OAuth client を照合すること。LINE 内の書き換えや LSPatch では届かない。
- MicroG-RE 7.1.1 は、呼び出し元の meta-data `app.revanced.android.gms.SPOOFED_PACKAGE_SIGNATURE` を client_sig として使う。バックアップは `GoogleAuthUtil` の token 要求だけを使うため、GoogleAuthServiceClient の判定を false にし、`GetToken` の bind 先を MicroG-RE に差し替える実験用パッチを作った（鎖に入れない、既定で無効）。
- SDK 36 の端末で、公式 LINE 26.14.0 を消して PoC 版 26.11.0 を入れ、復元とバックアップが完了した。logcat で MicroG-RE が公式証明書の SHA-1 で申告し、drive.appdata の token が発行されたことを確認した。方針は ADR 0003（提案）。
- 同じ APK で、通知の復旧パッチが `FisCertificateHeaderShapeMismatch` で当たっていなかった。FIS の `ct.c.c` では値が 3 経路（SHA-1、null、NameNotFoundException で null）から `const-string "X-Android-Cert"` で合流し、キーと値の区間に分岐先と例外 handler の先頭があるため、安全確認が拒否していた。
- 安全確認を「キーの const-string の直後から呼び出しまでに入口がないこと」に改め、値の出どころは問わないことにした（ADR 0002 決定 6 を改訂）。再現テストを先に追加した。Patch Status 50 件すべて OK。
- 実機で、スワイプで LINE を終了させた状態で LINE 宛ての FCM が届き、`FirebaseInstanceIdReceiver` で LINE が起動し、通知の表示とタップでのトーク表示まで確認した。
