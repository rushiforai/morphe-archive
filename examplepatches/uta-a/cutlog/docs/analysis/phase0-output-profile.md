# Phase 0 出力仕様（OutputProfile の基準値）

対象: setlog `com.newchat.setlog` v1.3 / versionCode 76
手段: 端末の `/sdcard/Movies/Setlog/` にある「保存」機能の出力 6 本を `ffprobe`

## 重要な前提

これらは setlog の**「保存」機能（MediaStore 経路、`u20.java`）の出力**であって、**投稿アップロード経路（`y31` の media3 Transformer + GL シェーダ再変換後）と同一とは限らない**。アップロード経路の厳密な仕様は、投稿経路の生ファイルが内部キャッシュにあり root 無しでは取れないため、Phase 0 では確定できなかった。Phase 1 の差し替え PoC で「この OutputProfile で出した動画が投稿を通るか」を実地で確認し、サーバーが受け入れる実制約として詰める。

（内部キャッシュ `cacheDir/camera/collection_camera_*.mp4` は製品版が非 debuggable のため `run-as` 不可。今回撮影したクリップはギャラリー保存していないため共有ストレージにも無い。）

## OutputProfile ドラフト（Phase 1 で要検証）

cutlog の書き出しは入力に関わらず以下へ揃える:

- コンテナ: MP4
- 映像: **HEVC (H.265) Main**、yuv420p、bt709、tv range、約 30fps
- 解像度: 短辺 720・長辺 1280（録画の向きに合わせて 720x1280 か 1280x720）
- 音声: AAC-LC 48kHz モノラル（公式が音声を載せているため無音化しない）
- 長さ: 公式の固定長 **2.065978 秒**（最新版で確認済み）

## 注意（実装への影響）

- **Media3 Transformer のデフォルト出力は H.264 (AVC)。** 公式は HEVC なので、Transformer に明示的に HEVC を指定する必要がある。サーバーが HEVC を前提にしている場合、AVC で出すと再生結合や検証で弾かれる恐れ
- 音声モノラル 48kHz も明示指定が要る
- 2 系統の解像度は録画時の向き依存。cutlog は入力動画の向きに応じて縦横を選ぶ

## 残課題（Phase 1 へ）

- 投稿アップロード経路の厳密仕様（保存経路と差があるか）
- 撮影〜投稿の UI フロー実機観察（プレビュー画面 `w20` の実挙動、collection 系 / chat 系の使い分け）

## 長さの上限（Phase 3 後に実地確認）

アプリ側には投稿動画の長さを検査する処理が見当たらない（録画は `CollectionCameraConfig.recordDurationMs=2000` で止めるだけ。アップロード URL の要求と投稿本文にも長さは含まれず、メディアは端末で暗号化されるためサーバーは中身を検査できないとみられる）。

検証用の差し替え動画（HEVC 1280x720 30fps、AAC-LC 48kHz モノラル）を「そのまま投稿」で dev グループへ送り、別端末で再生を確認した。

| 長さ | 結果 |
| --- | --- |
| 5 秒 | 最後まで再生された |
| 10 秒 | 最後まで再生された |

30 秒以上は未確認（ユーザー判断で打ち切り）。ファイルサイズによる制限が別にある可能性は残る。cutlog の取り込み（F4）は現状 2.066 秒に固定して切り出している。
