# 本家への追従方法（twitch-patched-ja）

このリポジトリは [ryykitty/twitch-patched](https://github.com/ryykitty/twitch-patched) の日本語化コピーです。本家には迷惑をかけないため、次のルールを絶対とします。

## 絶対ルール

- 本家リポジトリへのプルリクエスト、Issue、コメント、マージなど、書き込みは一切しない。
- 本家は `upstream` リモートとして fetch 専用で登録し、push URL は `DISABLED-NO-PUSH-TO-UPSTREAM` に設定して誤pushを防ぐ。
- 変更の流れは一方向のみ: `git fetch upstream` → `git merge upstream/main` → 翻訳の競合を解消 → `git push origin`。
- このリポジトリはフォークではなく、Ayufa アカウント上の独立したコピーとして作成した。

## 追従の対象

- 追従するブランチは本家の `main`（安定版ライン）のみ。本家の `dev` は参照だけにとどめ、このリポジトリには作らない。
- semantic-release の backmerge（main から dev への逆マージ）は、このリポジトリに dev が無いため `.releaserc` から外している。これが本家との差分のひとつ。

## マージ時の競合

- 日本語化はソース内の文字列を直接書き換えているため、本家が同じ行を変更すると競合する。競合したら、本家の新しい英語文字列を確認し、日本語訳を付け直してから解消する。翻訳行以外で解釈に迷う競合が出たら、マージを中止してユーザーに報告する。
- 翻訳対象の文字列が本家で増えたら、その分も翻訳して取り込む。対象範囲と方針は `docs/LOCALIZATION.md` にある。
- 翻訳済み文字列を検証するテスト（`UiFeatureRegistryTest` と `scripts/tests/` 配下の一部）の期待値も、日本語化に合わせて更新している。これらが本家で変わった場合も同じ扱いにする。

## リリース

- リリースは GitHub Actions の Release ワークフロー（semantic-release）が行う。リポジトリ変数 `PATCH_RELEASES_ENABLED=true` が必要。
- 日本語化コミットには規約型 `i18n` を使う。`.releaserc` に `i18n` は patch リリースとして登録済みで、本家のバージョンに対して末尾をひとつ上げた日本語版リリースになる（例: 本家 v1.5.0 → 日本語版 v1.5.1）。
- リリースノートには今回の変更内容（特に不具合修正と翻訳の追加分）を記載する。

## 本家が公式に日本語対応した場合

- 本家がパッチ設定UIの公式な日本語訳を提供し始めたら、この日本語化の役目は終わる。その時点でユーザーに知らせ、定期的な追従ジョブを止める。
