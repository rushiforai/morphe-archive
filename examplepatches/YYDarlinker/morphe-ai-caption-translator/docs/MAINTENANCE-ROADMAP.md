## 1. 要达到的结果

项目应逐步做到：新环境可按文档建立构建；一次改动的影响范围清楚；错误能定位到明确环节；关键行为由可重复测试保护；候选包能对应确切源码和验证结果；升级保存设置和凭据；依赖更新、版本适配和回退都有常用入口。

评价进步看这些结果，不把源码行数减少、文件数量增加、测试总数增长、框架更换或新名词数量作为成果。每次重构必须说明它降低了哪一种实际维护成本。

用户负责使用偏好、体验取舍及少量集中真机复测；技术方案、实现细节、自动验证和证据整理由 Codex 承担。不能承诺 AI 可以永远无人复核地维护项目；可追溯设计、自动检查和小批次变更用于降低后续接手成本。

## 2. 必须保留的有效设计与行为

- 保留独立补丁源、独立命名空间、单一公开 AI 补丁根、现有发布所有权和订阅身份。现有多 API profile、14 种界面语言和外观能力，不因“看起来专业”而预先删除。
- 继续仅声明已有 21.x 支持范围；不从本路线推导出增加 20.x、改变最低 Android 版本或升级 Patcher 的任务。
- YouTube / 官方 Captions 决定本次选中的语言和 CC。插件只持久化自己的 AI 开关，不恢复独立语言记忆。AI 开关不偷偷改原生 CC 或语言。
- AI 关闭时保留恢复原生字幕的能力。原文会话不请求翻译 API；译文失败不把原文作为失败兜底。原文模式与译文失败是不同状态。
- 退出、切视频、换配置和重建会话后，旧异步结果不得取得新会话的显示或缓存提交权限。保持当前 publication/epoch/generation 契约及主线程不等网络清理的行为。
- 保留 N74/N75 的有效机制：主线程不解密日志凭据、不进行同步文件写入；Shorts 评论区不因无关宽度变化反复分页；就绪协调事件合并并校验归属，不增加永久轮询来掩盖时序问题。
- 翻译调度的现行 focus 2 + prefetch 2、修复/重试和分页规则作为基线。重构不默默增加请求量、不改提示词字面量、不改缓存身份或默认用户设置。
- 保留现有源码来源、受保护 ABI 和提示词/协议校验。需要更新适配记录时，先完成实际复核和验证，再更新记录；不能只重算哈希来消除失败。
- 不重写已发布资产、历史交付、原始日志和历史报告。源码回退与用户数据回退分别设计，不能把旧 MPP 等同于可恢复已经迁移的数据。

### M1 — 让验证和产物身份可靠

优先处理 `.devenv/`、`tools/Verify.ps1`、`tools/Enter-Workspace.ps1`、`.github/workflows/validate.yml`、`release.yml`、`.releaserc`、`verify_bundle.py`、`verify_integration.py`、CONTRIBUTING 和 RELEASING。先明确哪些是历史固定基线工具，哪些是当前常用工具；保留历史用途，避免多个“完整验证”互相矛盾。

建议用同一组检查实现四种执行层级，具体参数命名由实现确定，不能把下列描述当成已经存在的命令：

1. **源码检查**：本地化、来源/依赖边界、两组单测和配置/发布契约工具的自检。默认不使用真实模型 API，也不要求读取用户的模型密钥。
2. **候选包检查**：在源码检查后构建当前 MPP，读取实际路径，核对 build ID、版本、内嵌/独立 MPE、必要类、资源和凭据扫描。保留候选模式，不要求候选与仍在线的旧版本号相同。
3. **组合验证**：显式指定本次候选、官方 MPP、原始 APK、Patcher 和选择集合，完成真实 patcher/DEX/资源检查。缺少输入报告“未覆盖”，不以旧包替代，不自动下载或分发专有 APK。
4. **发布验收**：由现有 semantic-release 唯一发布链调用；在公开发布前完成本次必需测试和产物校验。发布后的匿名下载核对属于额外闭环，不能替代发布前检查。实际发布授权独立于维护。

每次输出一个候选清单：源码 commit + 工作树指纹、版本/build ID、工具版本、任务、测试结果、产物路径/哈希、组合输入哈希及未覆盖项。命令退出 0 但没有本次应有报告、测试数为 0、模块测试漏跑或报告来自旧轮次，都不能显示为验收成功。不固定总数永远为 699，也不强迫无必要地重复运行已经有效的同批次测试。

CI 支持项目实际使用的开发分支和目标 PR；修正报告归档目录；将 core 测试加入 PR 和发布 prepare。GitHub Packages 等构建依赖所需的仓库读取凭据与用户翻译 API 凭据分开；缺凭据给出明确失败原因，不输出密钥。验证工具的临时文件遵守 AGENTS 的 E: 和进程环境规则。

用有意义的失败案例自检入口：漏掉一组结果、候选 ID 不匹配、传入旧包、构建失败、无 APK 输入，确认状态分别正确。涉及脚本行为的测试值得添加；单纯文档路径替换无需创建形式化测试。

### M2 — 删除没有现行职责的负担

审查过时入口、重复版本常量、旧 helper 和构建路径说明。历史脚本按用途标注或从当前入口解绑，不重写其原始证据，不为了整洁删除 recovered、旧包和共享缓存。

### M3 — 状态职责明确，测试覆盖事件顺序

先把现有类的职责写清楚，而不是再增加一套与当前权威并行的状态中心：

| 状态 / 决策 | 现有主要归属 | 必须避免 |
| --- | --- | --- |
| 用户持久 AI 意图 | CaptionSessionIntent | 播放器回调覆盖用户选择 |
| 当前原生选轨和 CC 事实 | CaptionNativeProjection / NativeCaptionBridge | 预取请求或旧选轨夺取当前语言 |
| 当前播放器/表面归属 | CaptionPlayerAuthority / CaptionSurface | 旧 owner、旧 Shorts open 获得显示许可 |
| 根据当前事实协调启动/停止 | CaptionSessionReconciler | 重复事件重复建引擎，或只有额外 tick 才能恢复 |
| 翻译任务、epoch 和缓存提交 | RebuildController 及 publication 契约 | 退出后继续提交旧结果、主线程等待清理 |
| 页面计划及可见几何 | presentation / UI | 为位置变动重新翻译或无谓分页 |

事件发生处说明“谁能写、在哪个线程写、失效条件、幂等性、恢复触发”。跨模块不再依靠新增魔法字符串暗中改变语义；只在容易出错的边界逐步引入明确事件/原因类型，避免全仓库重命名。

测试优先使用可控时钟与任务队列，覆盖有限、现实的事件排列：选轨前/后就绪、退出前已投递任务、同视频重新进入、CC OFF/AI OFF、配置切换时旧请求完成、连续拖动与原文/译文切换。沿用 N75 的真实应用端口与模拟服务器，不给测试人为补上真实故障中没有发生的回调。

验收至少证明：旧结果不能显示/提交；重复就绪只启动一次；原文模式请求数为 0；关闭后不再发出新的翻译任务；退出后的旧任务无权恢复；恢复不依赖必然不会再来的回调。已经发往服务商的请求可能仍被计费，不能承诺取消等于退款。测试应检查这些独立行为性质，不照抄实现分支生成“永远通过”的判据。

### M4 — 按真实职责逐段提取

CaptionOverlayV2 优先区分宿主发现/绑定、视口与样式测量、页面计划复用、绘制/触摸应用。优先利用已经存在的 CaptionPageLayout、CaptionPresentationClass、样式度量等组件；不创建只转发一次调用的新抽象来增加文件数。

RebuildController 优先区分任务调度/重试、会话归属与提交、页面输出协调。先提取有明确输入输出、可单独测试的决策，保留主流程和对外钩子；再根据收益处理静态状态。引入时钟/执行器替身仅限有测试需要的边界，不在第一轮把全部 singleton 改成依赖注入框架。

将对 Morphe 类名、签名、反射、官方播放器及菜单能力的认识集中在宿主适配边界，记录支持的官方版本和匹配条件。独立包无法像官方内部功能一样直接消除所有适配代码；目标是让上游变化集中在少数位置。无法匹配时给出可诊断的构建错误，不使用猜测寄存器或不透明 catch 继续生成可安装但损坏的包。

先用现有源码/compiled 边界检查落实依赖方向。需要新增 Gradle 模块、移动大量 package 或打破现有 ABI 前，证明当前检查确实无法约束依赖且收益值得编译/迁移成本。保留独立 namespace，不全仓库替换 DeepSeek 旧名字、设置键和缓存路径。

每小批只改变一种职责；机械移动与逻辑修复分开。旧/新在相同输入下比较语义结果（请求数、页面内容/时间、权限撤销、几何结果），而不是要求诊断时间戳逐字一致。改到 core 的阶段同时维护受保护来源记录与协议校验。

### M5 — 故障、配置和存储有稳定契约

统一传输失败、取消、服务限流、凭据/配置错误、结构输出拒绝和终态的原因分类；支持根据类别决定重试或提示，避免 UI 猜测错误文案。复用现有 FailureCategory、Retry-After 和 deadline 能力，先清点重复逻辑再扩展。

单次会话使用不可变 profile/endpoint/model/credential 引用；切换 profile 后旧结果不能进入新缓存或新诊断身份。缓存命中必须覆盖源轨、目标语言、配置、协议及相关布局身份，保持原有 CAS/清空屏障。缓存格式需要版本时给出失效路径；不要为了统一类名改坏缓存语义。

配置迁移、KeyStore 不可用、损坏缓存、写盘中断、磁盘满、服务返回 401/429/5xx/截断流等通过现有工具和模拟服务做故障验证。密钥读取失败不得静默清空 profile 或替换成别人的 key。用户数据升级与回退分别记录；不要求卸载清数据解决常规升级。

明确网络/解析线程、锁持有范围、取消和关闭顺序；检查是否存在高层等待底层、循环等待或无界排队。保留合理请求上限；调整预取、修复次数、用户计费或失败显示属于显式行为变化，与纯重构分开说明和验收。远端 HTTPS 策略与用户自设 HTTP 兼容服务的取舍另列设计，不借维护名义无提示阻断现有配置。

### M6 — 有基线的性能和诊断

继续保留普通用户能够导出问题的能力，减少依赖用户安装 adb。常规诊断优先少量决策事件和最新状态；全文/提供方响应仍受显式调试开关控制。保留大小/时间/队列限制、脱敏和一键清理，评估是否能减少重复归档和线程。诊断默认策略若改变，作为产品行为变化说明，不能悄悄关闭导致新故障无法定位。

优先度量：补丁主线程 I/O/KeyStore 访问、会话启动与恢复延迟、稳定视口的重排次数、重复 API 请求、退出后存活任务、缓存占用、长会话后内存与监听器。保留 N74 的调用线程 key read 0、20 记录 writer 解密 1、Shorts 宽度不变时分页次数不增长等机制证据。

设备性能用同一设备/官方补丁/APK、同一操作和相近条件做前后对照；注明网络和模型不确定性。帧时、内存、耗电等要有真实测量，不能从单元测试耗时或诊断日志反推出所有原生卡顿。先测再设项目预算，不虚构统一毫秒门槛。

### M7 — 让接手和日常维护简单

逐步将 ARCHITECTURE 更新为 N75 后的有效架构、状态所有权和依赖方向；CONTRIBUTING、RELEASING、COMPATIBILITY 只指向当前入口，历史资料单独索引。少量重要设计决定在当前文档中写明“为什么”，不再用长聊天和 N 系列施工日志替代设计说明。

将 PROJECT-STATE 收敛为当前身份、有效入口、已知问题、最近验证与下一步；若移动现有长历史，先原字节归档并核对哈希，保留旧引用，镜像继续逐字节相同。当前 N*、recovered 和历史交付不做清理删除。

兼容表区分声明目标、真实组合通过、运行观察、已知限制，记录输入哈希与最后验证版本。新增官方/YouTube 版本先适配验证，不能只更新列表。稳定目标、必要实验目标和 Android 场景按风险选择覆盖；不承诺每次跑全组合笛卡尔积。

沿用锁定工具链、Wrapper 校验和、现有依赖维护配置；依赖和 Patcher 更新单独批次，先读官方变更并做相应组合验证，不为“最新”一起升级。维护节奏写在文档中，不由本路线自动创建提醒或后台自动发布。

## 5. 每批次交付与停止条件

每批都给出：改了什么及维护收益；本批源码/产物身份；实际执行的检查与结果；尚未覆盖的设备/语言/供应商；恢复办法；下一批前置条件。只构建当前阶段需要的候选，完成必要检查后不无理由重复全套。

有效断言失败、来源/协议不符、归属泄漏、重复付费请求、证据来自旧包或包身份混淆时，先修复该批次，不将问题带入下一轮核心改动。不通过删断言、更新黄金结果或重算哈希掩盖变化。确属需求改变的预期更新，先解释新旧行为并用对应证据验收。

出现不可重建的新依赖或缺少原始 APK 时，可以继续不依赖它的工作，但相应组合/运行结论保持“未验证”。需要用户提供的设备观察集中在会影响实际体验的节点，使用短操作清单，不让用户逐项决定类名、框架或测试参数。

本路线不要求每个可逆的小改动重新征求技术选型许可。发布、推送、签名安装、删除用户数据、付费真实模型调用及不可逆迁移按实际授权处理；本轮的规划不构成这些动作的授权。常规验证默认不调用真实付费 API。
