# 1.0.4 连续性、同步和设置界面修复

## 诊断判断

第一份日志 28 次请求全部 2xx，但多个窗口被本地拒绝，三次后永久失败。第二份同样存在这一链路。报告不包含原始模型 JSON，因此不能断言每次拒绝都是误判。源码中已确认存在隐式数词编号、严格拒绝等价 JSON 表达、同时间源文本形成重叠 1ms 原子等可避免失败路径。

## 本次实现

1. 向模型发送明确的 [编号, 原文] 和 last_id，不再让模型数数组位置。仅规范化语义等价的整数/数组/对象表示；遗漏、越界、不连续、时间错误及译文质量检查保留。既有重试携带具体约束错误，不增加重试上限或独立分句 API。上下文每侧最多 160 字符，后台可合并更多既定前瞻窗口。
2. 同时间文本合成一个真实时间区间，避免构造重叠的毫秒级边界。播放回调与显示时钟统一，连续播放时小回退不再重播前一字幕片。校时偏移小于 3 倍锚点 MAD 时不强行应用；未添加统一提前量。
3. 去掉 API Key 弹窗和按钮，恢复 Android EditText 原地编辑和系统长按选择/粘贴。只拦住 API 配置行的路径复制；其他 Morphe 页面功能不变。
4. 字幕样式区增加 16:9 横屏示例，拖动字号和不透明度滑杆时即时变化；松手保存。真实播放器和预览共用字号缩放、背景 alpha 计算。
5. 启用/调试开关使用自管理 Preference + Switch 控件，避免被官方当作未注册 Setting。未关闭全局调试或吞掉所有错误提示。

- main/dev 清单和发布文件匿名 HTTP 200；版本 1.0.4；1 个补丁；发布工作流成功。

## 更新与复测

刷新源到 1.0.4 后重新改包安装，不能只刷新源。诊断顶部应显示 explicit-anchors-r3。原有 API 配置保留，不需要重新填写。

新时间原子/协议使用新缓存标记，旧翻译缓存不会混用；第一次看同一视频可能重新翻译，之后正常复用。不要为比较成本额外重复清缓存。可清空诊断，按同模型、同语速、相同视频片段比较；新的 ANCHOR_RESPONSE_REJECTED 会报告原因、last 和 ends，不包含返回正文。
