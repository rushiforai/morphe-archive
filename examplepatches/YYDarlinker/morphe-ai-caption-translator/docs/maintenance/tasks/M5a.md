## 3. 先核对的实际链路

按需读取 RebuildApi/TransportFailure/Failure、ProviderRequestPolicy、ProviderEndpoint、RebuildStream、NetworkDeadline、RetryAfter、SourceRecoveryPolicy、RawCaptionSource/SourceLoadFlights、RebuildController的load/run/失败/调度分支、TranslationAudit以及必要的配置快照/诊断显示映射。保留M3a已经核验的Session/Publication语义，不重新发明一套统一epoch。

至少解释下列事实，并链接源码方法和检查过的测试断言：

1. **错误来自哪一层**：连接/读超时、deadline主动断开、用户取消、HTTP状态、provider内容检查、参数协商、JSON/流/协议拒绝如何表达；区分原始错误、逻辑失败、控制器决策和诊断类别。当前 TranslationAudit.FailureCategory、RebuildApi.Failure.configuration、SourceRecoveryPolicy.Failure.retryable 含义不同，不因都叫failure便当作同一开关。
2. **实际请求数**：逻辑翻译块、HTTP attempt、参数协商重发、结构/页面修复、源格式/轨道回退分别计数在哪里、上限在哪里；并发槽位与一次请求重发不是同一个限制。记录实际付费请求可能增加的路径，不能以“每块一次”概括所有失败。
3. **时间**：deadline、elapsed/monotonic clock、Retry-After delta/date对应的wall clock、serverDelay与本地backoff如何结合；取消和超时谁优先，重试调度在哪里落实。文档写现有边界，不能为测试缩短生产常量。
4. **终止与恢复作用域**：凭据/模型/endpoint等配置错误阻断哪一配置，限流/5xx如何等待，内容检查和结构错误是否作用于块；reset/配置切换后哪些记忆失效。HTTP403在源获取、内容检查和普通provider错误中可能有不同路径，不能统一声称“都是密钥错误”。
5. **不可变配置与凭据**：会话/请求使用何时捕获的profile/endpoint/model/key身份；切换后旧任务的后续请求/结果/记账是否仍归旧作用域、如何避免进入新缓存或新画面。旧请求已发出与尚未发出要分开；取消不等于退款或证明服务端没有处理。

文档保持便于接手，不复制整份代码。结论至少对应“实际方法/分支→行为→已有或新增测试”，限制和待确认项单列。当前诊断类别较粗不自动等于控制器错误重试；如两层不一致要准确标出影响，不能从一个枚举名字推导用户实际行为。

## 4. 离线故障矩阵与补测

先审阅既有单元/集成测试，建立一个小矩阵（正文表或同目录文档均可；机器摘要/详细fixture放证据）。每项写请求初始身份、注入方式、观察层级、实际响应/错误、分类/终止或等待、attempt/请求计数、复核来源及限制。

优先覆盖下列类别；已有有效断言可以复用，不机械要求每类新增一项：

- provider401/普通403/配置类错误不会无界重发；有内容检查或参数不支持响应时按其真实路径区分。
- 429 的 Retry-After秒值与日期解析/调度，服务端等待不会被本地较短backoff提前；无效/缺失header的当前回退有证据。
- 5xx或短暂网络中断的当前retry/退避边界，避免把解析拒绝当作同一类无限网络重试。
- 连接/读取超时与本方deadline、显式取消区分；最少有一个经过真实传输入口或受控连接的分类/取消证据，而不是只测字符串标签。
- JSON/流截断或结构输出拒绝不会发布不合法结果；模型输出修复与HTTP重发的次数分开观察。
- 配置/目标切换或退出时扣住请求/回复；未发出的旧请求不能因恢复事件转入新配置，已发送旧请求不会取得新会话输出/缓存身份，记账的归属按现行契约解释。优先复用M3a对应证据，补其尚未观察的实质缺口。
- 原始字幕获取的401/403/格式回退与provider故障分开；只验证本轮需要的最小源恢复路径，不重建整个YouTube网络栈。

**所有测试只访问受控本地fixture服务。** 使用测试密钥，不读取用户实际profile去发请求。源鉴权/回退可能触发FreshYouTubeCookies或另一条HTTP路径，必须使测试所有连接分支显式路由到fixture或立即拒绝未映射连接，不能让失败测试回退到真实YouTube、Cookie地址或模型服务。

用可控响应、latch/barrier和已有模拟时钟观察次序，等待有上限。不等待完整生产级长重试、不通过增加sleep碰运气、不污染系统代理/全局网络配置。不能仅调用分类函数后声称完整控制器的请求计数/退避已验证；不同层级分别报告。

如新增状态性测试，可靠清理连接、服务器、拦截器和静态配置；失败时也应恢复。对相关新增用例做少量重跑/顺序独立性检查，不能让旧配置阻断记录泄漏到下一测试。
