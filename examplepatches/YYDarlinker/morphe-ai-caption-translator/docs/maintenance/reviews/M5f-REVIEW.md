## 发现的处理决定

| 发现 | 统筹决定 |
| --- | --- |
| C1真实部分flush及运行配置未刷新 | 优先下一M5g，采用现有逐字段自动保存语义：成功字段生效，失败草稿保留，切换失败active不变，但已保存值必须同步运行作用域。不是跨store原子事务，也不自动将旧key绑定新URL |
| C2多store部分失败 | 保留P2候选，后续结合真实可达性/资料可达性选择最小恢复或说明；不因代理能抛异常就重写全部持久化为事务 |
| C3坏数据异常/不一致 | 配置收尾下一优先项，明确保留原资料、可读错误和恢复入口；不得自动清空或选别人key。当前未修复 |
| C4代理after/drop与错误提示不一致 | 保留与底层替身限制；同步审查后置通知被误当保存失败的路径，实际可达部分单独处理，不宣称磁盘写入成功可从apply返回确认 |
| C5重建/后置回调风险 | 后续针对性证实再决定修复范围；未复现部分不计已关闭或已确定用户故障 |

此次读取失败的正常保护可接受为有限事实：未自动删密文、未取其他profile key，并可在测试依赖恢复后重新读取。但真实硬件Keystore、持久化完成、杀进程重读/断电/磁盘满、设备/远端CI/其他组合及真实服务未验证，不能称整个配置存储可靠性已完成。
