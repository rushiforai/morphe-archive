## 对测试与结论范围的判断

ready 测试扣住真实 Runnable，并在撤销后直接释放旧对象，因此不只依赖 Handler.removeCallbacks；owner/新视频等正向对照能排除“一直不启动”的假通过。源回复测试保留真实应用、core 和模拟源链路，先替换视频再释放回复，之后用新视频源会话确认可正常显示。

Publication 测试是 Session/Job/Publication/Prepared 的隔离合同，不是完整 provider 引擎；其中 current(s)=false 不能单独充当真实会话替换证明，真实输出仍由应用用例和既有 core 集成测试共同支持。受控 permit/barrier 与 Prepared 文件顺序的断言有维护价值，但不覆盖所有调度交错。文档已经披露源共享 worker 的排空范围、宿主线程合同和真实取消/计费限制，接受时保留这些边界。

两个夹具/证据 runner 问题均保留了失败记录；修正没有改变生产或放松行为断言。首次未及时归档的 core XML 已明确标为后捕获，不据此增加首次通过的证据强度。

忽略的本地 `.devenv` 前端取证范围披露准确：五个执行前端与已接受 M2a 退出清单一致，其他环境文件不能声称有本轮独立入场哈希。未来任务应显式保护实际使用的忽略前端/初始化脚本，但当前没有发现它们在本轮被修改的证据。
