# Architecture

This page describes current source and its permission boundaries. [PROJECT-STATE](PROJECT-STATE.md) owns package/review status; [compatibility](COMPATIBILITY.md) separates declarations, compositions and phone observations.

## Modules and dependency direction

| Source area | Responsibility and dependency |
| --- | --- |
| `patches` | Kotlin fingerprints, typed bytecode/resource bindings and the single public `AI caption translator` root; injects calls into the independent `app.yydarlinker` extension |
| `caption-contracts`, `caption-shared` | Application actions/port, hashing, WebVTT speaker markers and shared caption values; no host/UI ownership |
| `translation-core` | Source/task planning, provider protocol, scheduling, validation, display plans and translation-cache publication; depends on shared values, not host/UI classes |
| `application-host` | Native caption/player observations, session reconciliation and application port implementation; connects UI actions, source/configuration adapters and core |
| `infrastructure` | Configuration, credentials, source retrieval/cache and bounded diagnostics; supplies adapters used by the host |
| `presentation` | Display decisions and numeric components such as `CaptionGlyphTransition`; uses shared contracts without depending on the translation controller |
| `ui` | Settings, actions and Android overlay/geometry application; `CaptionActions` delegates through application ports |
| `extensions/extension` | Compiles host, infrastructure, presentation and UI source directories together and depends on contracts/shared/core; generates `BuildConfig` identity and the raw DEX MPE |
| `ui-preview` | Independent UI fixture without a translation-core dependency; excluded from the production MPE |

The intended call direction is UI → application ports/host → core, with infrastructure adapters and shared contracts. Host, infrastructure, presentation and UI are source areas within the same extension compilation, **not separate Gradle-enforced modules**. [Extension build configuration](../extensions/extension/build.gradle.kts) defines that boundary; [source/compiled/package checks](../tools/verify_integration.py) enforce source ownership, legacy forbidden names, hook signatures, pinned protocol literals and package exclusions. The source guard discovers top-level Java/Kotlin main-source types across the listed areas, so new helpers and same-side forwarding cannot hide a forbidden edge. Core cannot refer to host/infrastructure/presentation/UI; UI/presentation cannot refer to core; shared/contracts retain their lower-layer direction. Imports (static, wildcard and Kotlin aliases), qualified references and same-package type names are checked after comments and literals are erased. This is a conservative lexical guard: shadowed identifiers, generated/external types, Kotlin string interpolation and dynamic/reflection relationships still need review. Compiled constants inspection scans only the supplied core output, not all extension classes; package checks are separate. [Tool contract tests](../tools/test_verification.py) exercise legal dependencies, isolated new-helper violations and restoration through the canonical full entry.

`translation-core/upstream` is a pinned snapshot of this project's earlier core, identified by [core provenance](core-provenance.json), not the Morphe official translation engine. Its `.java.txt` files are not compiled, but verification reads their bytes, license/notice and prompt/protocol literals. Historical 1.3.5 MPP bytes are retained privately, with original-path mapping in the [history index](history/README.md); generated Smali and old stage reports are no longer active source inputs. The generated adaptation diff was also retired; Git records code changes, while pinned snapshots and provenance hashes remain verification inputs. See the [history index](history/README.md).

## State ownership and permission

The [caption state contract](architecture/CAPTION-STATE-CONTRACT.md) contains the detailed source/test matrix, event ordering and thread/lock facts. The following are distinct permissions; an active engine alone does not mean a visible caption or an authorized cache write.

| State | Owner and boundary |
| --- | --- |
| Native language and CC | YouTube/the official Captions patch; `NativeCaptionBridge` and `CaptionNativeProjection` observe the current owned video/selection. Track catalogues and prefetched URLs do not choose the target or restore separate language memory |
| User AI choice | Both `DeepSeekConfig.enabled` and `CaptionSessionIntent.ai_enabled/revision` remain. `CaptionSessionReconciler` applies their different gates and the documented legacy backfill; two preference stores are not a transaction. The user AI toggle does not change native CC/language |
| Player/display eligibility | `CaptionPlayerAuthority` and `CaptionSurface` own Activity/video/player evidence. COMPACT, transitions and Shorts exit revoke display; overlay checks CC, geometry and owner again |
| Application/ready coordination | `CaptionSessionReconciler` coalesces ready callbacks and checks slot identity, generation, video and owner epoch; no permanent retry polling. `CaptionApplication` rechecks current selection/display permission at real application ports |
| Translation work | `RebuildController` owns active Session/Job, immutable request configuration, generation and job identity. `RebuildWorkSet` owns per-slot admission/accounting under the Session monitor; `RebuildReplyPreparation` prepares replies without acquiring publication authority. Seek, replacement, stop and configuration changes invalidate the relevant old work |
| Playback and presentation selection | `RebuildPlaybackSelection` and `RebuildPresentationSelection` own their session-local decisions. The controller samples the single CLOCK, keeps the transaction lock and rechecks generation/display guards before output |
| Source preparation | Internal `RebuildSourcePreparation` computes parsed/aligned source, authored/automatic blocks and cache identity. It receives source/configuration facts, the existing request control, a narrow live URL reader and a diagnostic consumer; it has no Session, Publication, View or installation authority |
| Translation-cache commit | `RebuildCache.Publication` admits permits only while OPEN. Revoke prevents new permits; an already admitted write may complete in its original scope. Prepared ordinals prevent an older candidate overwriting a newer committed candidate |
| Visible text and geometry | `CaptionOverlay` in `CaptionOverlayV2.java` checks core guard, UI command/render epoch, player owner, CC and actual geometry before applying text or deferred positioning |

Main-thread lifecycle operations revoke permission without waiting for network disconnect or disk completion. Background barriers drain admitted work. Retirement may let an already sent transport finish reading; it cannot admit another model HTTP attempt or publish into a replacement Session. Source-cache shared flights have their own consumer checks and pair commit lock, not translation Publication permits. See the [network contract](architecture/NETWORK-FAILURE-CONTRACT.md) and [cache contract](architecture/CACHE-FAILURE-CONTRACT.md) for the retained late-source window and process-local versus physical persistence limits.

The overlay uses the pending event's existing half-open start/end interval to decide whether it owns the current display position; status and waiting messages do not acquire an event window or end hold. The independently built UI preview uses synthetic caption data. It does not supply a second source, timeline or failure model to the product.

## Runtime data flow

1. Typed patch bindings observe native caption model/menu/draw/player seams. Required bindings must be complete before feature permission is published; ambiguous bindings fail closed. Resource IDs come from the actual target APK.
2. Host adapters capture immutable video, selected target, source-track and configuration context. `SourceTrackPolicy` prefers human subtitles in the spoken language, then human English and automatic speech. An original-track selection or a video-owned target track uses local source display with zero translation-provider requests.
3. Source retrieval retains timing evidence and hard breaks. Controller first checks raw ownership, installs raw/position and renders early. `RebuildSourcePreparation` then parses, classifies the current URL, optionally fetches/aligns reference timing using a fresh URL read, and computes blocks/key. Its diagnostic consumer sends the existing stages immediately through the controller with the original credential semantics. Controller captures cache generation after build, reads at most landing/next outside the Session lock with a current check between reads, then rechecks current/source-job under the original install lock. A seek during those reads drops warm hits without discarding the valid source build. Authored subtitles retain cue/row structure; automatic tracks use `SourceReadingWindows`. A shared 1500 ms same-language reference budget allows at most three attempts; unproven inner-word times remain estimates. Translation text omits bracketed furigana readings.
4. Core builds bounded semantic tasks/request blocks under the protected structural protocol and current reviewed guidance. `RebuildWorkSet` reserves actual work and accounts for retries; the controller dispatches Jobs outside the lock. Scheduling remains **focus 2 + prefetch 2 = total 4**. Request/configuration/cache identities, repair budgets and the current guidance retain their reviewed meanings.
5. Requests ask for ordered exact source quotes and translations, not model-generated numeric IDs. The parser derives token ranges locally at exact token boundaries before the same validation, streaming, salvage and cache paths. Mixed formats, altered/overlapping quotes and unowned source are rejected. Legacy ID replies retain their existing contradiction guard and cannot gain coverage from a wider quote. Source quotation is alignment evidence, not proof of translation equivalence. Long-event geometry warnings are advisory: pagination is local, not a reason for paid retranslation. Provider events are validated for source references, ordered ranges and coverage. Exact source quotes are rebound to real token ranges, including CJK without spaces, within the existing coverage allowance. If a substantially wider exact quote contradicts the claimed IDs and cannot be safely rebound, salvage drops that event: its translation may belong to either range. It becomes an explicit hole for the existing bounded repair path; valid neighbours remain usable. Presentation warnings, paid repair eligibility, content filtering and configuration failure are distinct decisions. A failed translated block displays a neutral `…`, never source text as failure fallback; valid retained plans and permission to send new requests remain separate.
6. `RebuildDisplayPlanning` owns the display planning context (read-only source, blocks and language), per-block plan/geometry/unit cache and source-time anchors. It reuses `RebuildDisplayGroups`, `RebuildCueProjection` and `RebuildCueContract` for automatic and authored pages. The controller initializes it from the same local source/blocks during the original locked source-load publication, reads the output budget and selects accepted/provisional plans. A cache hit returns the existing list; a miss exposes projection facts so the controller preserves diagnostic order before the component publishes its cache slot. `RebuildPresentationSelection` chooses content and cursor through the persistent read-only block view; `RebuildPlaybackSelection` owns session-local playback observations. The controller retains plan acceptance, repair orchestration, lifecycle, locks, render guards and submission. The planning component has no Session, platform callback, diagnostic sender or commit authority.
7. Shared script-aware pagination uses real geometry and source intervals. Missing punctuation in ASR does not itself justify merging readable model events: source dependencies, explicit introductory punctuation, existing connectives and sub-minimum fragments supply positive continuation evidence. The page planner merges punctuation and invisible event seams into one ordered cut set while preserving quoted spans. A balanced page cannot borrow a bare introduction from the next clause; if its target page count is infeasible, fewer coherent pages are tried before keeping the unit whole. Short fitting events stay whole; one line is preferred. Optional time paging first keeps any valid partition with a 2200 ms preferred minimum. Only when that fails may it use the shared 1200 ms minimum, reusing fragment folding and rejecting a bare introduction or an enumeration cut in this fallback. Existing valid multi-page plans return before that relaxation. Indivisible/time-short units fall back to measured pages. Accepted event IDs, text and times stay immutable. Positive source dependencies, recognized reporting complements and trailing introductions can form one multi-page display span; the single-page fit/time limits apply to optional grouping, not to these dependent chains. Hard source breaks, blocked events and request boundaries remain barriers. Known incomplete automatic stream tails wait for their continuation within the same running request before the cursor is recorded; this loading state does not request paid repair. Authored cues bypass this waiting gate. A shared immutable `CaptionEventTimeline` carries joined text offsets and original event windows through the guarded output channel. Final-width pagination keeps its text cuts, then estimates each internal turn inside its own event window; exact event seams are fixed. Short-page duration is retained where that event has room. Single events/authored cues keep their existing timing path. Layout keys include the mapping and asynchronous workers capture the same immutable snapshot as their text. Estimated target times do not imply measured target-language audio alignment. Fresh player-clock evidence and output guards control presentation after seek/video/session changes.

## Rendering, settings and diagnostics

The overlay uses a stable Activity root. It maps the visible video rectangle into host coordinates and uses its physical centre/gravity independently of text bidi direction. A content commit lays out its own measured anchor/text subtree before exposing the new page, including when the player defers its traversal. The caption TextView cannot scroll; its measured pages, text and rounded background share one viewport. Position-only changes reuse LayoutParams and pre-draw remains translation/scale only. Deferred geometry is coalesced and owner-guarded; player notifications do not synchronously scan the view tree. `CaptionPresentationDecision` owns reading category, base/frame width and stable-width sampling; the overlay keeps platform geometry, page reuse and permissions. These are source-area boundaries within the same extension compilation, not separate Android modules.

`CaptionGlyphTransition` alone owns painted glyph height, endpoints, pending state and caller-supplied frame start. It retains the 180 ms linear transition and two separate 2% comparisons. Overlay keeps Choreographer scheduling, coalescing and actual TextView scaling; the numeric component has no Android scheduler/clock or per-frame allocation.

Settings use the official Morphe language while preserving Activity/window ownership and editable draft identity. Strict configuration snapshots distinguish credential read failures and partial saves; request construction reuses the credential resolved by that snapshot without a global key cache. Main-thread startup reads, cross-store transactions and hardware Keystore/IO remain limited as described in the [configuration contract](architecture/CONFIG-CREDENTIAL-CONTRACT.md).

Diagnostics use immutable snapshots and bounded background lanes. Ordinary row binding/draw does not decrypt or archive synchronously. Failure reason, legacy accounting and actual controller decision are separate. Runtime official/Patcher identity stays `unknown/runtime_unverified`; build expectations and offline composition receipts are separate evidence. See the [diagnostics/performance contract](architecture/DIAGNOSTICS-PERFORMANCE-CONTRACT.md).

## Menu visibility

The regular-video and Shorts flyout toggles are independent, persisted and enabled by default. They only decide whether the AI row is inserted on the next menu opening; neither changes the engine, native language/CC, cache or API settings. The settings page can still control the engine.

The typed official addFlyoutButton bridge retains inflater/icon/localized label/index/divider behavior. Disabled rows return the unchanged official insertion index without changing container spacing; Shorts evidence is not carried into a later hidden invocation. Existing regular/Shorts overlap, menu-layout and preference framework regressions protect this. The two controls use all fourteen existing locales; old historical test counts are not a current acceptance claim.
