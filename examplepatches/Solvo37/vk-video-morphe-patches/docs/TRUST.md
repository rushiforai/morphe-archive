# Доверие и подпись релизов

## Проверка upstream

До патчинга принимается только APK с package:

```text
com.vk.vkvideo
```

Ожидаемый SHA-256 оригинального сертификата VK:

```text
057d974412032066f1b5edb1fdb550f71854189815c806b27c4d486fb4f1ef32
```

Несовпадение package или сертификата останавливает сборку.

## Подпись проекта

Модифицированный APK нельзя подписать приватным ключом VK, поэтому проект использует свой постоянный release key.

Ожидаемый SHA-256 сертификата проекта:

```text
D4:1F:49:2F:0E:2A:2E:39:90:AC:7F:8E:75:CC:5D:4B:
14:89:5F:7B:46:C0:B6:11:3B:78:82:C4:8A:A5:D4:0A
```

Subject:

```text
CN=Solvo37 VK Video Patched, OU=Morphe, O=Solvo37
```

Приватный ключ не хранится в Git и передаётся сборке только через GitHub Actions Secrets.

## Что это означает для обновлений

- первую проектную сборку нельзя установить поверх официального VK Видео;
- после первой установки проектные версии обновляют друг друга, пока используется тот же signing key;
- обычный VK может оставаться установленным благодаря compatibility patch;
- Release assets не перезаписываются, поэтому клиенты обновлений не получают битые ссылки на старые GitHub asset IDs.

## Native signature bypass

VK Видео 1.163 содержит native-проверку подписи в `lib/arm64-v8a/libvkcore.so`. Проектный patch меняет только заранее проверяемый binary pattern.

Если pattern в будущей версии изменится, pipeline должен остановиться вместо применения патча по неизвестному offset.

## Публикация

В публичном GitHub Release находится только подписанный APK. Проверочные JSON, checksum и build diagnostics сохраняются в GitHub Actions artifacts.
