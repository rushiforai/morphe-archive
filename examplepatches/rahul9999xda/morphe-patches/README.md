## ❓ About

I maintain these patches primarily for personal use, experimentation, compatibility testing, and development. The repository may expand with additional patches and supported applications over time.

Based on the Morphe patches ecosystem and prior Android patching work by ReVanced. Changes and their dates are recorded in the Git history.

## 🚀 How to use

Click the **ADD THIS SOURCE** button above to add these patches to Morphe.

Or manually add this repository URL as a patch source in Morphe:

```text
https://github.com/rahul9999xda/morphe-patches
```

## FAQ

### How do I use the patches?

Install [Morphe Manager](https://morphe.software), add a compatible patch source, and use the available patches when creating a patched APK.

### Which application versions are supported?

Compatibility depends on the patches and fingerprints maintained for each application version. A patch working on one version should not automatically be assumed to work on another.

### What APK version or format should I use?

Use a clean APK corresponding to a supported application build whenever possible. Prefer the appropriate architecture for the device and avoid already-modded or repacked APKs when testing patch compatibility.

### Why can a patched app behave differently from the original app?

Morphe patches modify application bytecode and the resulting application is re-signed. Features that depend on the original signing certificate, Google Play Services, server-side validation, remote configuration, or backend behaviour may not work the same way as in the unmodified application.

### Why can't every feature be modified?

Not every feature is controlled by client-side code. Server-side functionality, account permissions, remote configuration, and backend validation cannot necessarily be changed by an APK patch.

### Why does a patch work on one application build but not another?

Applications frequently change their internal classes, methods, instructions, and structure. A fingerprint that matches one version can stop matching after an update. Version-specific fingerprints and compatibility data may therefore be required.

### Where should I get APKs for testing?

Use clean APKs from reputable sources and verify that the package, version, architecture, and signing state are what you expect before patching.

### Is this repository affiliated with the applications being patched?

No. This repository is independent and is not affiliated with or endorsed by the developers or companies behind third-party applications that may be patched.
