# HLN empty listening carousel

HLN 9.22.0 has the same empty-history loading-card defect as ED. The independent
**Hide empty listening carousel** control skips loading cards before the
renderer opens a Compose group. Real history enters the original first
instruction, retaining the complete renderer and its playback callbacks.

## Publisher evidence

The supplied `hln-be-9-22-0.xapk` has SHA-256
`062d96cab3935c609b88a2635b1e1195a919d56d08c692eebd8d80b8d21dc32d`.
Its base APK has SHA-256
`44cf13c1b309fbeb5c67042c66cfe4c5118accbeac4f05b0999a424b1af4846f`,
matching the existing HLN preservation baseline. REA package inspection confirms
package `be.persgroep.android.news.mobilehln`, version 9.22.0,
version code 2009220000 and minimum SDK 32
(`ev_e4736a2f327a18b902e553ba586dcc8a662baae06ae8776857f2966ae6ef8c5b`).

REA decompilation of `a5d.a` shows the sample `detailepisode_` ID prefix
(`ev_2c5d1ede0fb999749cad0453132bba0dab3f09aa06958b25fe03a4ae006fd7b9`).
Apktool decoding of this same base APK establishes the rest of the chain:

- `nw.invokeSuspend` constructs `ix` from listening history, then returns null
  when its mapped list is empty.
- `had.h` contains eight copies of the sample `jw` card built from `a5d.a`.
- The Continue Listening arm of `p88.invoke` substitutes `had.h` for null and sets loading=true.
  Populated history sets loading=false. Both call
  `s09.k(Lix;IZLxe7;ZLtg3;I)V`.
- The fifth parameter (`p4`, physical register `v24` with 20 locals) controls
  loading styling and is passed into the card callback closure.

REA confirms the renderer's signature and loading-flag data flow
(`ev_52c2473687f74c984045cb201589407a0af467279d14da07053c3e1d1a94e1f6`),
and finds its two static callers, `p88.invoke` and the recomposition closure
`o4d.invoke`
(`ev_b52d9d67380e193d89581ec8e2222ff3f2e334bf392899f6193c9cf77adcf1c0`).
REA did not recover the `p88.invoke` body; its control flow above comes from
decoded DEX instructions rather than that unavailable decompilation.

## Verification boundary

`tests/hln_listening_originals.json` pins all 89 methods in the renderer utility,
history mapper, calling/recomposition closures, card callbacks, models and
fixture classes. The emitted verifier checks the loading guard's exact register,
return and branch destination, removes only those two instructions, then
compares the full original control flow, exception ranges, flags and locals.
The two array-data payloads in the utility class are pinned separately because
the shared control-flow parser omits their values.
With this control disabled, every pinned method must remain unchanged.

The analysis above is static and off-device evidence establishing the same code
defect and guard as ED. At that stage no HLN installation, navigation or capture
had been performed. The guard also hides legitimate transient loading
placeholders; real content can render as soon as history becomes available.

Local REA evidence and validation logs are retained under
`build/research/hln-9.22.0/` and `build/validation/hln-listening-default/`.

Off-device validation passed for the original, all six individual controls and
the combined selection: patch reports, APK signatures and decoded behavior.
A fresh decode of the combined APK also passes the expanded method and array
preservation checks. The Android bundle build and Medium extension unit tests
pass; the Python suite completes 377 tests with 39 skips and no failures,
15 Medium tooling tests pass, and all 80 bilingual app pages match newly
generated source metadata. Independent review found no remaining code issues.
Release versions and discovery metadata are generated by the release workflow.

After the checkout advanced to `a702b65` (v1.3.0 base), the Android build and
Python suite passed again. The HLN publisher baseline is unchanged. Fresh
carousel-only and combined candidates passed patch reports, signatures and
decoded-output verification under `build/validation/hln-listening-current/`.
The latest test APK is `hln-all.apk` in that directory. The user subsequently
waived further validation and authorized USB installation. Replacement
installation succeeded on the connected phone while retaining app data
(`ev_d3276a72778fb266e4049878f28280cdb76accea1438d500b6d592461e236f97`).
No navigation or runtime capture was performed by the agent. After installation,
the user confirmed "solved" and approved promotion to main. Live acceptance is
therefore user-confirmed rather than based on an agent recording.

The additional SDK hierarchy check fails on four unresolved references to
Amazon PrivacyPass classes. Those same references exist in the publisher's
original `jgj.a`, and the classes are absent from the supplied APK set. This
extra check is not a passing result; it does not identify a carousel edit.
