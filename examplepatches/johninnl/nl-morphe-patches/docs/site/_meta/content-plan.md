# User-guide editorial contract

Keep matching Dutch and English pages. Describe patch effects from the end-user perspective, with supported versions, defaults, original-input links and feature tradeoffs.

Name advertising and tracking providers and domains where useful. Leave implementation mechanics, reverse-engineering procedures, measurements, payload examples and internal evidence trails out of the public guide. Keep development and validation instructions in CONTRIBUTING.md.

Generate the homepage and compatibility catalogue from current metadata. Do not copy raw implementation descriptions or option JSON into public pages. Publish one production catalogue from main. Label the initial 0.0.0 source snapshot as unreleased until the first release supplies a version.

Check metadata coverage, bilingual parity, local links and the strict MkDocs build before committing.
