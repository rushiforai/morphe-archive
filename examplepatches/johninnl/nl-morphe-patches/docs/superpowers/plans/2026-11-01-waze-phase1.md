# Waze phase-one controls implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Add the six approved opt-in controls to Waze 5.26.90.901 / 1030746.

**Architecture:** Reuse `keepWazeConfig` and the existing phone Customization panel.
Resolve configuration IDs/types from the supplied APK; retain the shared native-thread
sync, locking and reset behavior. Do not introduce another override mechanism.

**Tech stack:** Kotlin patch definitions, Java extension, Robolectric, Morphe CLI.

**Spec:** The user approved the six-feature recommendation in this session:
auto zoom; lane guidance with straight-ahead hints; compass/toll display; speed-limit
display and limit-drop warnings; car alert notifications; car traffic meter.

## Global constraints

- Target 5.26.90.901; all six patches default off in Manager.
- Preserve the stock user lane-guidance preference; do not force its USER_ENABLED flag.
- Offer independent runtime switches for compass/tolls and limit display/drop warnings.
- Keep auto zoom and warning distance editable after patching.
- Leave existing reporting and sign-style patches independent.
- Do not add the deferred features or alter speed-bump behavior.
- Use only johninnl Git identity. Release automation owns versions and metadata.
- Keep original APKs, credentials and decompiled proprietary source out of Git.

## Review focus

- Selecting a patch alone must include its configuration and Customization dependencies.
- Switching one display control must not change its sibling or the stock lane preference.
- Invalid auto-zoom modes and warning distances must fail patching explicitly.
- Runtime editors must persist choices, reset them and reject out-of-range distances.
- Patch application does not prove live lane data, toll prices, road alerts or car rendering.
