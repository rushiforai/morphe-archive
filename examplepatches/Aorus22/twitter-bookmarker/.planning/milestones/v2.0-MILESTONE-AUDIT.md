- The cursor is emitted only when `has_more && len(rows)>0`, is never re-requested, and drops rows at or before the total-order key, so paging terminates.

## Tech Debt & Residuals

No blockers. The following are recorded, not swept up.

**Accessibility (Phase 10):**
- **Two moderate landmark violations** while the desktop filter Popover is open — `landmark-no-duplicate-banner` and `landmark-unique`, anchored to the page header. Root cause confirmed from the DOM: three `<header>` landmarks exist (two page-level plus `HEADER.flex` inside `role="dialog"`). Closed-page axe reports zero violations. This does **not** fail HARD-04, whose bar is zero serious/critical, and it is invisible to the project harness because `axe_check` filters to serious/critical only. **Suggested fix:** render the Popover panel's `<header>` as a `<div>`.
- **Gradient contrast is outside axe.** The active quick-range pill (`bg-grad-brand text-accent`) sits on a gradient axe cannot evaluate; measured coral-on-gradient ≈1.25–2.54:1. A deliberate design combination needing a human design decision, not a token change.

**Verification boundaries (inherent, stated plainly):**
- No real screen-reader pass (VoiceOver/NVDA) in any phase.
- PRD §82 step 21 (the original tweet actually opening) needs the public internet; asserted as the canonical `x.com/<user>/status/<id>` href + target/rel, documented as manual step F1-21.
- Lightbox scroll restoration is unit-tested, not asserted in the real-browser run.
- The real extension background-worker → `fetch` → Go leg is proven at the schema level plus a curl-shaped replica; the extension's own suite mocks `fetch`.

**Governance:**
- The active `verify:post` hook is `ui-review`, not `validate-phase`, so no `VALIDATION.md` exists and Nyquist compliance was not assessed (skipped per the workflow). `$gsd-ui-review` is available if a 6-pillar visual audit is wanted.
