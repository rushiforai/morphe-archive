# Phase 10: Hardening, Accessibility & Responsive — Plan 01

**Goal:** close out milestone v2.0 by proving the edge cases, finishing the error/retry UX,
completing the responsive behaviour, satisfying PRD §67 accessibility, and making the PRD §82
integration scenario executable end-to-end against a seeded storage directory.

**Scope:** `backend/internal/gallery/` tests, `web/src/` (shell, tests, tokens), the two
acceptance scripts, `docs/`, and `README.md`. No product feature is added. `.planning/ROADMAP.md`,
`STATE.md`, `REQUIREMENTS.md`, `PROJECT.md`, `state.json` and `PRD-2.md` are neither read nor
written by this plan's implementation (this file and `10-01-SUMMARY.md` are the only phase
artifacts). No `10-VERIFICATION.md` is created — the orchestrator owns it.

## Approach

1. **HARD-01 — prove the reader's fault tolerance.** The reader already degrades gracefully; this
   phase adds one focused `hardening_test.go` that asserts the four required behaviours as a set,
   including the 5,000-row performance bound and a `recover()` guard proving no call panics.
2. **HARD-02 — verify, then close the gaps.** Retry already exists on both pages; the missing
   proof is that a *collection-page* Retry recovers from a transport failure and that a homepage
   Retry recovers from a server-side gallery error. Extend the existing page tests.
3. **HARD-03 — breakpoints + the wordmark defect.** Extend the browser harness with the 768px
   case and hide the wordmark below `sm` (keeping the logo and an `aria-label` on the brand link),
   with a jsdom test plus a browser assertion.
4. **HARD-04 — a real axe run.** Install `axe-core` as a web devDependency, inject `axe.min.js`
   through `agent-browser eval --stdin`, and assert zero serious/critical violations on the four
   surfaces in both themes; also assert focus visibility, `alt` text and dialog keyboard
   behaviour. Every violation found is fixed at its root (the light `--accent` token fails WCAG AA).
5. **HARD-05 — make §82 executable.** Add an explicit §82 section to the HTTP harness for steps
   1–15/22–24, keep/extend the browser steps 16–21, and document the whole scenario with expected
   results in `docs/MANUAL-TEST-CHECKLIST.md`.
6. **HARD-06 — live CSV + focus refetch.** Append a row to a live CSV inside the browser harness,
   dispatch a real window focus, and assert the new post appears without a restart.
