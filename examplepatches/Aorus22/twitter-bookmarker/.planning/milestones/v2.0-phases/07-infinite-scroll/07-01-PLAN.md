# Phase 7: Infinite Scroll — Plan 01

**Goal:** turn the Phase 6 cursor-aware first page into a true cursor-paginated infinite scroller — an
`IntersectionObserver` sentinel requests the next page of 30 as the user nears the end, pages
accumulate without duplicates, the first load is covered by masonry skeletons and subsequent loads by
a small bottom loader, and the view refetches on route entry, query change, window focus and manual
refresh with no polling and no viewport jump.

**Scope:** `web/**` only. `.planning/ROADMAP.md`, `STATE.md`, `REQUIREMENTS.md`, `PROJECT.md`,
`state.json` and `PRD-2.md` are not read or written; nothing under `backend/`, `extension/` or the
root `Makefile` is touched. No server is started or bound: the operator-owned backend on its dev port
stays untouched, and every test mocks `fetch` in jsdom (`src/**/*.test.{ts,tsx}`).

**Seam inherited from Phase 6:** `usePosts(filename, requestParams)` already returns
`{ posts, status, error, errorMessage, collection, nextCursor, hasMore, refetch }`, is keyed by
`[filename, limit, sort, q, tweet_from, tweet_to, saved_from, saved_to]`, and already resets pages /
cursor synchronously on a key change. `useGalleryQuery` exposes `queryKey` / `requestParams`. The
cursor is deliberately absent from the URL. Phase 7 adds `loadMore`, accumulation and two presentational
components; it does not restructure the query layer.

## Decisions

1. **Paging lives in `usePosts`, not a new hook.** The hook already owns the request key, the cursor and
   the reset rule; accumulating pages there keeps one state machine and one stale-response guard. A
   separate `useCollectionPosts` would duplicate the key logic. The accumulated dataset is therefore
   `usePosts(...).posts` (the Phase 8 seam).
2. **A monotonic request *generation*, not just the React request key.** A `loadMore` in flight when the
   query changes (or when a same-key focus/Retry refetch starts) must not append to the new list. The
   generation is bumped at the start of every first-page request; a page response is dropped when its
   captured generation is stale. The existing `key` stamp still drives what the view renders.
3. **Defensive cursor contract in one pure helper.** `resolveNextPage` maps `{next_cursor, has_more}`
   to `{nextCursor, hasMore}`, returning "no next page" for `has_more: false` **and** for
   `has_more: true` with a null/empty cursor, so a malformed backend cannot loop the sentinel.
   `loadMore` additionally refuses a cursor identical to the one it last requested.
4. **Dedupe is a pure list function.** `mergeUniquePosts(existing, incoming)` iterates `existing` first
   and appends only unseen `tweet_id`s, so the first-seen instance and its position always win. It is
   unit-tested independently of React.
5. **Two small presentational components, no new dependency.** `InfiniteSentinel` is an `aria-hidden`
   zero-height marker that observes itself with `rootMargin: 600px 0px` and calls the latest
   `onIntersect` through a ref (so re-renders never re-observe or capture a stale callback).
   `GalleryBottomLoader` is a `role="status"` row with an `sr-only` label and an `aria-hidden` spinner.
6. **`hasMore` drives the sentinel, `isLoadingMore` drives the loader.** The sentinel stays mounted but
   `disabled` at the end of the list (the observer effect disconnects), so no request can be issued once
   the backend says there is no more.
7. **No scroll on append.** `loadMore` is pure state work; the only `scrollNearTop()` call remains the
   Phase 6 query-change effect (DISC-08), so appending pages cannot yank the viewport.

## Tasks

### 1. Pure pagination helpers (SCROLL-01, SCROLL-03, SCROLL-04)

New `web/src/lib/pagination.ts`:

- `MAX_POSTS_PAGE_LIMIT = 100` (PRD-2 §34 maximum) and `clampPageLimit(limit)` → integer in `[1, 100]`,
  non-finite → 100.
- `resolveNextPage({ next_cursor, has_more })` → `{ nextCursor: string | null; hasMore: boolean }`:
  `has_more: false` → no next page (cursor null); `has_more: true` with a null/non-string/empty cursor
  → no next page; otherwise the cursor verbatim.
- `mergeUniquePosts(existing, incoming)` → a new array: `existing` in order, then only `incoming` items
  whose `tweet_id` is not already present (dedupe within `incoming` too). Never mutates its inputs.

Tests (`pagination.test.ts`): verbatim opaque cursors survive (including `+`, `/`, `=`), `has_more:false`
stops, `has_more:true && next_cursor:null` stops, an overlapping `tweet_id` appears once at its
first-seen position, a fully-overlapping page adds no cards, and `clampPageLimit` never emits more than
100.

### 2. `usePosts` grows `loadMore` (SCROLL-01, SCROLL-03, SCROLL-04, SCROLL-05)

`web/src/hooks/use-posts.ts`:

- The first-page request now runs `resolveNextPage(response)` and clamps `limit` through
  `clampPageLimit`, so `nextCursor`/`hasMore` already encode the defensive stop.
- New `loadMore(): void` — no-op unless the current key's first page has loaded, `hasMore` is true, a
  non-null cursor exists, no page request is in flight, and the cursor differs from the last one
  requested. It captures the current generation, flips `loadingMore`, fetches
  `fetchPosts(filename, { ...params, cursor })`, and on success appends via `mergeUniquePosts`, advances
  the cursor and clears the flag. A page failure keeps the loaded cards and clears the flag (the next
  sentinel intersection retries).
- The first-page effect bumps the generation and clears the in-flight/last-cursor refs, so a query
  change or a focus/Retry refetch discards an in-flight page and resets to page one.
- Result gains `isLoadingMore: boolean` and `loadMore: () => void`; `posts` is now the accumulated
  list. No existing field changes shape.

Tests (appended to `use-posts.test.tsx`): appends page 2 in order with the cursor sent verbatim and
`limit=30`; stops after `has_more:false`; `has_more:true` + null cursor does not loop; three repeated
`loadMore` calls during one pending request produce exactly one additional request; an overlapping
`tweet_id` renders once at its first position; the same cursor is never requested twice; a `focus`
refetch resets to page one without duplicates; and advancing fake timers by 60 s issues no request
(no polling).

### 3. IntersectionObserver test stub (test infrastructure)

New `web/src/test/intersection-observer.ts`: a `MockIntersectionObserver` that records instances,
tracks observed targets, exposes the resolved `rootMargin`, and has a test-only `emit(isIntersecting)`
that invokes the callback with a synthetic entry. `src/test/setup.ts` installs it unconditionally (jsdom
has no `IntersectionObserver`) and resets the instance registry in the existing `afterEach`.

### 4. Sentinel and bottom loader (SCROLL-01, SCROLL-02, a11y)

- New `web/src/components/gallery/infinite-sentinel.tsx` — `InfiniteSentinel({ onIntersect, disabled =
  false, rootMargin = SENTINEL_ROOT_MARGIN, className? })`, `SENTINEL_ROOT_MARGIN = "600px 0px"`:
  a `data-testid="infinite-sentinel"` `aria-hidden="true"` empty `<div>`; an effect creates the observer
  and disconnects on cleanup/disable; the callback reads `onIntersect` from a ref.
- New `web/src/components/gallery/gallery-bottom-loader.tsx` — `GalleryBottomLoader({ label =
  LOADING_MORE_POSTS_LABEL, className? })`: a `role="status"` row with an `sr-only` label and an
  `aria-hidden` spinner.
- `web/src/lib/messages.ts` gains the `Loading posts` / `Loading more posts` labels.

Tests: the sentinel is empty and `aria-hidden`, observes one target with the 600px rootMargin, fires on
an intersecting entry only, ignores a non-intersecting one, stops observing while disabled, and always
calls the latest callback without re-observing. The loader is `role="status"` with the sr-only label and
a decorative spinner.

### 5. Page wiring (SCROLL-01, SCROLL-02, SCROLL-05)

`web/src/pages/collection-page.tsx`:

- Destructure `hasMore`, `isLoadingMore` and `loadMore` from `usePosts`.
- In the `posts` branch render `GalleryMasonry` (unchanged cards), then `GalleryBottomLoader` when
  `isLoadingMore`, then `InfiniteSentinel onIntersect={loadMore} disabled={!hasMore}`.
- The `loading` branch keeps `MasonrySkeleton` (the first-load affordance); a page load never returns to
  the loading branch, so cards stay mounted and the viewport is untouched.

Tests (`collection-page-paging.test.tsx`, cursor-routed mocked fetch): the first load shows masonry
skeletons and no bottom loader; an intersecting sentinel loads page 2 while the existing cards stay in
the DOM and the bottom loader is visible; repeated intersections during one in-flight request issue
exactly one extra request; three pages accumulate in order and stop at `has_more:false`; an overlapping
`tweet_id` renders once; `has_more:true` + null cursor issues no further request; a `focus` refetch
resets to page one; `loadMore` does not call `window.scrollTo`; there is no `Load More` button or
numbered pagination; the sentinel is `aria-hidden`; and the loader is `role="status"` with its
visually-hidden label.
