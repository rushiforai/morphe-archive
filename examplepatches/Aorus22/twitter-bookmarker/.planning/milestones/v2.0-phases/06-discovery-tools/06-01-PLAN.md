# Phase 6: Discovery Tools — Plan 01

**Goal:** give the Phase 5 `CollectionToolbar` its behaviour — debounced server-side search, a
Popover/Sheet filter control with the design's two date ranges and quick presets, exact
local→UTC inclusive date conversion, all four sort modes, URL-synced state that survives
refresh/back/forward, and a query-change transition that clears the loaded pages, resets the cursor,
scrolls near the top and refetches page 1 without letting a superseded response land in the view.

**Scope:** `web/**` only. `.planning/ROADMAP.md`, `STATE.md`, `REQUIREMENTS.md`, `PROJECT.md`,
`state.json` and `PRD-2.md` are not read or written; nothing under `backend/`, `extension/` or the
root `Makefile` is touched. No server is started or bound: the operator-owned backend already
listens on its dev port and stays untouched, and every test mocks `fetch` against
`src/**/*.test.{ts,tsx}` in jsdom.

**Seam inherited from Phase 5:** `CollectionToolbar({ search, onSearchChange, filterActive?,
onFilterClick?, sort, onSortChange, className? })` already exists and is tested. `SORT_OPTIONS`,
`DEFAULT_SORT` and `sortLabel` already exist in `lib/collection-sort.ts`; `selectPostsViewState` and
`CollectionFilterEmptyState({ onClearFilters })` already exist and are tested. This phase supplies
handlers and state, not new definitions.

## Tasks

### 1. Exact local → UTC date conversion (DISC-05 — highest-risk item)

New `web/src/lib/date-bounds.ts`:

- `isLocalDate(value)` — strict `^\d{4}-\d{2}-\d{2}$` plus a real-calendar check (so `2026-02-31`
  is rejected, not silently rolled over).
- `parseLocalDate(value)` → local `Date` at 00:00:00.000 built from components
  (`new Date(y, m - 1, d)`), never `new Date("YYYY-MM-DD")` (which is UTC midnight and would shift
  the displayed day in negative-offset zones).
- `toUtcFrom(value)` → `Date` at local 00:00:00.000 `.toISOString()`.
- `toUtcTo(value)` → `Date` at local 23:59:59.999 `.toISOString()` — the inclusive end of the day.
- `localDateToUtcBounds({ from, to })` → `{ from?: string; to?: string; inverted: boolean }`.
  An inverted range (`from` > `to`, ISO strings compare lexicographically) returns **no bounds**
  and `inverted: true`: the UI keeps the user's text (and flags it) but never sends a query the
  backend would answer with an empty set for a clearly-erroneous input.
- `formatLocalDateRange(from, to)` → `Jan 1, 2026 → Sep 27, 2026` (either side alone reads
  `From …` / `Until …`, neither reads `Any date`), reusing `formatLocalFullDate` from `lib/date.ts`.

Tests (`date-bounds.test.ts`) run **under any machine zone**: expectations for the zone-independent
cases are constructed from the local zone itself, and the DST cases deliberately set and restore
`process.env.TZ` around the assertions:

- from-boundary = local midnight instant; to-boundary = local 23:59:59.999 (inclusive).
- same from/to day is one inclusive day (to − from = 86 399 999 ms in a non-DST zone; a
  deliberately-chosen TZ for the DST case).
- **DST spring-forward day** (`America/New_York`, 2026-03-08): from `2026-03-08T05:00:00.000Z`
  (EST, −05:00), to `2026-03-09T03:59:59.999Z` (EDT, −04:00) — proving the offset changes inside
  the day and the whole local day is covered.
- **DST fall-back day** (`America/New_York`, 2026-11-01): from `2026-11-01T04:00:00.000Z` (EDT),
  to `2026-11-02T04:59:59.999Z` (EST).
- inverted range → both bounds omitted + `inverted: true`; cleared/empty fields → omitted;
  every emitted string matches the RFC3339 UTC shape and parses back to the same instant.

### 2. URL query state (DISC-07) and exact request params

New `web/src/lib/gallery-query.ts`:

- `GalleryQuery { q, sort, tweetFrom, tweetTo, savedFrom, savedTo }` — the four dates are local
  `YYYY-MM-DD` strings. **Decision:** the URL carries the *local date* the user picked (short,
  human-readable, and stable even if the browser's zone later changes); RFC3339 UTC is derived at
  request time only. This is documented in the module.
- `DEFAULT_GALLERY_QUERY` (`q: ""`, `sort: saved_desc`, no dates).
- `parseGalleryQuery(URLSearchParams)` — defensive: `q` trimmed; unknown/absent `sort` → default;
  malformed date → ignored; an inverted range is preserved in the URL (so the user can fix it) but
  produces no request bounds.
- `serializeGalleryQuery(query)` — writes `q` (when non-empty), `sort` (always, matching the PRD §76
  example), and each non-empty date; **never** writes a cursor.
- `galleryQueryKey(query)` — stable string for effects.
- `hasActiveDateFilters(query)` — true when a non-inverted date range is applied (`filterActive`).
- `hasActiveQuery(query)` — true when `q` or an applied date range exists (drives `empty-filters`).
- `galleryQueryToPostsParams(query, limit)` → `GalleryPostsParams` with `sort`, optional `q`, and
  the four **RFC3339 UTC** instants from `localDateToUtcBounds`, omitting cleared fields.

Tests: state → URL → state round-trip, unknown sort → default, malformed date ignored, empty params
→ default view, cursor never serialized, both ranges → both param pairs, and each emitted date param
being the exact inclusive-boundary RFC3339 string.

### 3. Quick presets (DISC-03)

New `web/src/lib/filter-presets.ts`:

- `QUICK_RANGE_PRESETS` = `Today`, `Last 7 Days`, `Last 30 Days`, `This Year` with PRD accessible
  names and the design spec's short display labels (`Today`, `7 days`, `30 days`, `This year`).
- `resolvePresetRange(id, now = new Date())` → `{ from, to }` local dates:
  `Today` = today..today; `Last 7 Days` = today−6..today; `Last 30 Days` = today−29..today;
  `This Year` = Jan 1 of the current local year..today (all ranges end on today, so the whole day
  is included via the inclusive end-of-day conversion).
- `activePresetFor({ from, to }, now)` → the preset whose range exactly matches, else `null`.

All presets target the **Bookmarked date** fields and only seed the draft; the fields remain
ordinary editable inputs afterwards, and an exact-match comparison (not a lock) drives the active
pill. Clicking an already-active pill clears the bookmarked range (a documented toggle).

### 4. `useGalleryQuery` — URL ↔ state with a 300 ms search debounce

New `web/src/hooks/use-gallery-query.ts`:

- Reads committed state with `useSearchParams`; exposes `query`, `search` (the immediate input
  echo), `setSearch`, `setSort`, `applyFilters(dates)`, `clearFilters()`, `filterActive`,
  `hasActiveQuery`, `queryKey` and `requestParams`.
- `setSearch` updates the input echo synchronously and schedules a **single** `replace: true` URL
  write 300 ms later (`SEARCH_DEBOUNCE_MS`), so typing never floods the back stack and produces
  exactly one request after the pause. A pending pause is cancelled and the echo resynced whenever
  the URL changes from outside this hook (back/forward), so Back reliably restores the previous
  query. Programmatic updates are flagged so our own writes are not mistaken for navigation.
- `setSort`, `applyFilters` and `clearFilters` **push** (explicit user actions); `clearFilters`
  additionally clears the search echo and cancels any pending debounce.
- `requestParams` reuses `POSTS_PAGE_LIMIT` (30) and the Phase 6 `usePosts` option names.
- `setSearch` never trims the echo but commits the trimmed query; a blank query removes `q`.

Tests: rapid keystrokes → exactly one URL write / one request after ~300 ms with fake timers; no
submit button; sort/filter commit; Back restores and refetches; unknown sort and malformed date
fall back safely.

### 5. Filter control — Popover ≥ md, Sheet < md (DISC-02)

- `web/src/hooks/use-media-query.ts` — `useIsDesktop()` on `(min-width: 768px)`, using
  `window.matchMedia` when present and falling back to `window.innerWidth >= 768` (jsdom has no
  `matchMedia`), with a resize/change listener and a desktop default for SSR/no-window.
- `web/src/components/gallery/date-range-filter.tsx` — one labelled native `<input type="date">`
  pair per range (explicit `aria-label` for each of the four fields; no new dependency, so no
  `react-day-picker`), wrapped in the design's `346×42 r12 surface-warm`+border field with a
  formatted range summary underneath and `aria-invalid` + an inline hint when the range is inverted.
- `web/src/components/gallery/filter-panel.tsx` — the design §3.4 contents shared by both surfaces:
  title `Filter your archive`, subtitle `Mix posted and bookmarked dates together.`, section labels,
  two `DateRangeFilter`s, the four quick pills (32 tall, r-pill; active gradient + SemiBold 11),
  `Reset` (78×40 r12) and `Apply` (92×40 r12 gradient, white SemiBold 11, right-aligned).
  Draft state lives here, seeded from the committed query each time the surface opens; `Reset`
  clears both ranges, `Apply` commits, and closing without Apply discards the draft so committed
  state cannot be corrupted.
- `web/src/components/gallery/filter-control.tsx` — the trigger (the same `collection-filter`
  button markup + active dot) plus the `Popover` or `Sheet` at the right breakpoint, with
  `data-testid="filter-popover"` / `filter-sheet` so the surface choice is asserted.
- `collection-toolbar.tsx` gains an optional `filterControl?: ReactNode`; when supplied it renders
  in place of the built-in Filter button, so the trigger can own the popover while the existing
  toolbar tests and the `onFilterClick` default keep working.

### 6. `usePosts` — query-keyed reset for DISC-08

`usePosts` gains a request signature over `[filename, limit, sort, q, *from/*to]` and keys its state
by it. A query change therefore returns `{ posts: [], status: "loading", nextCursor: null,
hasMore: false }` immediately (pages cleared, cursor reset) while a same-key refetch (focus, Retry)
keeps the current posts. The per-effect cancel flag is retained, and a new test resolves an older,
slower request after a newer one and asserts the newer posts win.

### 7. Page wiring

`collection-page.tsx` replaces the Phase 5 draft state with `useGalleryQuery` + `usePosts(filename,
requestParams)`:

- toolbar `search`/`onSearchChange` = the debounced echo/setter; `sort`/`onSortChange` =
  URL-synced; `filterActive` = `hasActiveDateFilters(query)`; `filterControl` = `<FilterControl>`.
- `selectPostsViewState(status, posts.length, hasActiveQuery(query))` so `empty-filters` lights up.
- `CollectionFilterEmptyState(onClearFilters = clearFilters)`.
- a mount-skipping effect on `queryKey` calls `scrollNearTop()` (`web/src/lib/scroll.ts`, a guarded
  `window.scrollTo({ top: 0, behavior: "auto" })`) whenever the query changes.

Tests (`collection-page-discovery.test.tsx`, plus the two obsolete Phase 5 seam tests updated):
search reaches the API as `q` with one debounced request and no submit button; sort reaches it as
`sort`; each date as the correct RFC3339 param; both ranges active → both param pairs; quick preset
sets the bookmarked range and stays editable; URL round-trip and Back-restores-and-refetches;
popover at desktop width vs Sheet at a narrow width; query change clears pages, resets the cursor,
calls `scrollTo` and refetches; the out-of-order race; and `Clear filters` resets search + dates and
refetches.
