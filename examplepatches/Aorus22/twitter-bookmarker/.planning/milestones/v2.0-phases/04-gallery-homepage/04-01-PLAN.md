# Phase 4: Gallery Homepage — Plan 01

**Goal:** replace the `GalleryPage` placeholder with the real `/` homepage from design spec §3.2 —
hero, section header, responsive collection grid and all four product states — backed by
`fetchCollections()` and a window-focus refetch, and stand up the vitest/jsdom test runner the rest
of the milestone builds on.

**Authority:** `04-CONTEXT.md` (phase contract), `docs/design/phase2-design-spec.md` §1/§2/§3.1/§3.2/§3.6/§6/§7,
`PRD-2.md` §16, §17, §32, §35, §38, §47, §59, §61, §62. `AppShell` and the Phase 3 exported surface
are frozen interfaces.

## Scope

**In:** `GalleryPage`, `GalleryHero`/`HeroArt`, `CollectionCard`, `CollectionCover`, `MediaImage`,
`MasonrySkeleton`, `GalleryEmptyState`, `GalleryErrorState`, `useCollections`, pure
`cover`/`placeholder`/`date`/`collection-meta` helpers, the vitest test infrastructure and suite.

**Out:** collection detail contents (Phase 5), search/filter/sort (Phase 6), infinite scroll
(Phase 7), lightbox (Phase 8), production serving (Phase 9). No backend, extension, Makefile or
`.planning` state-file changes; no new CSS variable set.

## Tasks

### 1. Test infrastructure (hard deliverable)

1. Add devDependencies: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`,
   `@testing-library/jest-dom`, `@testing-library/user-event`.
2. Add `web/vitest.config.ts` (`environment: "jsdom"`, `setupFiles: ["./src/test/setup.ts"]`,
   `@` alias, react plugin, `include: ["src/**/*.test.{ts,tsx}"]`).
3. `web/src/test/setup.ts` imports `@testing-library/jest-dom/vitest`, runs RTL cleanup and
   `vi.unstubAllGlobals()` after every test, and stubs `scrollIntoView`.
4. `web/package.json`: `"test": "vitest run"`.

Every test mocks `fetch` with `vi.stubGlobal`; no test touches the network or a server.

### 2. Pure helpers (`web/src/lib/`)

- `messages.ts` — the exact PRD-2 copy constants (`COULD_NOT_CONNECT_MESSAGE`,
  `COULD_NOT_LOAD_COLLECTION_MESSAGE`, `NO_COLLECTIONS_TITLE`, `NO_COLLECTIONS_MESSAGE`,
  `RETRY_LABEL`). `api/client.ts` imports `COULD_NOT_CONNECT_MESSAGE` instead of duplicating it.
- `cover.ts` — `selectCoverLayout(mediaCount) -> CoverLayout` discriminated union:
  `placeholder` (0) · `single` (1) · `stack` (2, two full-width rows) · `feature` (3, 2-top +
  1-wide-bottom) · `quad` (4+ → exactly 4 tiles). Plus `COVER_TILE_LIMIT = 4` and
  `sliceCoverMedia(media)` (first four = newest, because `cover_media` is already `saved_at` DESC).
- `placeholder.ts` — `pickPlaceholderGradient(key)` over the six `--grad-ph-*` pairs using an
  FNV-1a hash of the key, returning `{ id, cssVar, value: "var(--grad-ph-…)" }`. No new CSS.
- `date.ts` — `formatLocalDate`, `formatLocalDateTime` (browser-local timezone, PRD-2 §32) and
  `formatLastSaved(iso | null)` → `Last saved Sep 27` / `No saves yet`; a year suffix is added only
  when the local year differs from `now`'s year.
- `collection-meta.ts` — `formatCollectionMeta({post_count, media_count, last_saved_at})` →
  `83 posts · 126 media · Last saved Sep 27`.
- `index.ts` barrel.

### 3. Data hook

`useCollections()` → `{ collections, status: "loading" | "success" | "error", error, errorMessage, refetch }`.
Requests are keyed by an internal counter so `refetch()` re-runs the request; a cancelled flag drops
stale resolutions. A `window` `focus` listener calls `refetch()` (PRD-2 §47, HOME-09). Transport
failures surface the PRD-2 §61 copy through `ApiError`; other failures fall back to
`Could not load this collection`.

## Decisions recorded up front

1. **Two-media layout.** PRD-2 §17 only names 4+/3/1/0; for 2 the plan uses two full-width stacked
   tiles, which keeps tile height at the spec's 88px and stays balanced.
2. **Layout is chosen from usable cover tiles** (`cover_media` length, clamped to 4), so a
   `media_count > 0` collection with an empty/broken `cover_media` still renders the placeholder
   instead of an empty box.
3. **Secondary card line = filename.** The mockup's description slot is omitted by spec §7; the
   filename is real data and useful, so the slot is not left blank.
4. **Hero/CTA are real actions.** The CTA is an `<a href="#collections-grid">` (keyboard reachable,
   works without JS); the hero caption is derived from real counts, never invented copy.
5. **Placeholder gradients are applied as inline `background-image: var(--grad-ph-*)`** so no
   dynamic Tailwind class has to survive the scanner and no new token is introduced.
6. **`rounded-2xl` (24px) for the hero/art.** Spec §2.4 defines r-2xl as 24–26px, so the token is
   in range; the raw 26px literal is not added.
7. **`vitest.config.ts` is separate from `vite.config.ts`** so the dev/build config keeps importing
   `defineConfig` from `vite` and the test config can own its `test` block.
8. **One dark-mode gradient is added.** The spec's `--grad-hero` is a light cream panel and the dark
   frame (§2.2) defines no hero; white `--ink` on cream would fail contrast, so `.dark` overrides
   `--grad-hero` with a violet-tinted dark panel. No new variable name is introduced.
9. **Error copy mapping.** Transport failure (`ApiError.status === 0`) → the exact PRD §61
   connection string; every other gallery API failure → the §61 `Could not load this collection`
   class message. Both states get a working `Retry`.
