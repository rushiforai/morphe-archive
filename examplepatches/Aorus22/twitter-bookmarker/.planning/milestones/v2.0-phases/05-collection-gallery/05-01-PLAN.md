# Phase 5: Collection Gallery — Plan 01

**Goal:** replace the `CollectionPage` placeholder with the real `/collections/:filename` gallery from
design spec §3.3 — deterministic 96×96 icon header, counts meta, the present-but-not-yet-behaving
toolbar, and a responsive Pinterest masonry of 292-wide post cards with adaptive multi-media grids,
text-only quote panels, complete metadata, `Open on X`, text clamp + `Show more`, broken-media
degradation, and the three distinct empty/error states — backed by a first-page `usePosts` hook
structured for Phase 7 cursor pagination.

**Scope:** `web/**` only. No `.planning/` contract file is read or written beyond this phase's own
plan/summary, nothing under `backend/` or `extension/` is touched, and the root `Makefile` is
untouched. No server is started: every test mocks `fetch`, and the operator-owned backend on its dev
port is never referenced from `web/src` (it stays only in `web/vite.config.ts`'s dev proxy).

### 2. Data hooks

- `web/src/hooks/use-posts.ts` — `usePosts(filename, options?)`:
  one `fetchPosts(filename, { limit: 30, sort: "saved_desc", ...options })` for the first page plus
  one `fetchCollections()` for the header summary (no new endpoint). Returns
  `{ posts, status, error, errorMessage, collection, nextCursor, hasMore, refetch }`. The cursor
  fields live in state from day one so Phase 7 only adds `loadMore`. A per-effect `cancelled` flag
  drops stale resolutions; a `window` `focus` listener refetches (PRD-2 §47/§78). A summary-only
  failure does not blank the posts — the header falls back to the filename with no counts.
  Options are primitive fields (not an object) so the effect dependencies stay lint-clean.
- `web/src/hooks/use-masonry-columns.ts` — `useMasonryColumns(ref?)` measures the masonry container
  (`clientWidth`), falling back to `window.innerWidth` where there is no layout engine (jsdom), and
  recomputes on `resize`/`ResizeObserver`. Returns `columnsForWidth(width)`.

## Decisions recorded up front

1. **Masonry is CSS multi-column** (`columnCount` + `break-inside: avoid`), the design spec's first
   suggested implementation, with the column count from a pure helper. The container is capped at
   `n*292 + (n-1)*32` so cards are exactly 292 wide at every breakpoint instead of flexing.
2. **Breakpoints are exact-fit on the available container width** (616/940/1264/1588), measured from
   the masonry element, so `4 columns at 1440px` holds (the shell's content column is 1312 there)
   and no intermediate viewport width can overflow 292-wide cards. The shell caps the content column
   at 1312, so 5 columns is unreachable in practice but still mapped (PRD-2 §21 allows 4–5).
3. **The toolbar→masonry gap collapses with the omitted pill block.** The frame's masonry origin
   (y=448) sits below the media-type (y=350) and topic (y=394) pill rows that spec §7 deliberately
   omits; keeping a 116px hole under the toolbar would be a layout artefact of removed content, so
   the first card row starts 24px after the toolbar. Every masonry *measurement* (292 card, 32/22
   gaps, natural heights, r18/r14) is unchanged.
4. **The filter-no-match state is not faked.** Phase 5 cannot honestly reach "zero results because
   of filters" without a server-side query, so the branch is driven by an applied-filters value that
   stays default and the state is covered by the pure state selector plus the state-card component.
   `Clear filters` resets the draft toolbar state now and the applied query in Phase 6.
5. **Text-only posts render the quote panel in the media slot** and no separate body paragraph, so
   the tweet text is never duplicated; the clamp + `Show more` live inside the panel.
6. **The clamp threshold is a character count**, because jsdom (and any SSR pass) cannot measure
   rendered overflow; it is a pure, tested function so the affordance is deterministic.
7. **A 50% ink scrim sits over the quote gradient** so Playfair Regular 22 white text clears WCAG AA
   on all six placeholder pairs, including the light `sand→sage` and `gold→blue`.
