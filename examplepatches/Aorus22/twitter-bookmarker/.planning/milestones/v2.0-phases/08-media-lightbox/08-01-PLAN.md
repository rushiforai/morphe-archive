# Phase 8: Media Lightbox — Plan 01

**Goal:** turn the Phase 7 accumulated gallery into an accessible lightbox — clicking a media tile
opens a large media area beside a metadata panel (stacked below it on mobile), navigation is flattened
over every loaded media item so it crosses tweet boundaries, `Escape`/`←`/`→` work from a real Radix
focus trap, focus returns to the originating tile on close, and the gallery scroll offset survives the
dialog's body scroll lock.

**Scope:** `web/**` only. `.planning/ROADMAP.md`, `STATE.md`, `REQUIREMENTS.md`, `PROJECT.md`,
`state.json` and `PRD-2.md` are neither read nor written; nothing under `backend/`, `extension/` or the
root `Makefile` is touched. No server is started or bound — the operator-owned backend on its dev port
stays untouched and every test mocks `fetch` in jsdom (`src/**/*.test.{ts,tsx}`).

**Seam inherited from Phase 7:** `usePosts(filename, requestParams).posts` is the full, deduped,
accumulated loaded list held by `CollectionPage`; the lightbox receives **that** array, so cross-tweet
navigation is bounded by what is loaded and never triggers a page fetch.

## Approach

1. **Pure navigation first (`lib/lightbox.ts`).** Flattening and boundary detection are the only
   non-trivial logic, so they live in a pure module with a dedicated unit suite:
   `flattenMediaSlots` skips text-only posts, `findSlotIndex` maps a click to a position,
   `stepSlotIndex` clamps at both loaded edges (never wraps).
2. **Controller hook (`hooks/use-media-lightbox.ts`).** Owns a single `index: number | null` into the
   flattened sequence, converts an `(postIndex, mediaIndex)` click into that index, closes itself if
   the loaded slots disappear (query change), captures `window.scrollY` on open and restores it after
   the Radix lock is released on close.
3. **Triggers (`post-media-grid.tsx` / `post-card.tsx`).** An optional `onOpenMedia(mediaIndex)`
   renders each tile as a `<button aria-label={describeAlt(...)} aria-haspopup="dialog">` with a
   visible focus ring, and makes the inner image decorative. Without the prop the grid is byte-for-byte
   the Phase 5 static renderer, so existing suites and non-interactive renders are unchanged.
4. **Lightbox component + info panel.** `MediaLightbox` derives `slot`/`post`/`total`/`hasPrev`/
   `hasNext` from `posts` + `index` with the same pure helpers and renders the shadcn/Radix dialog
   (`Dialog` + `DialogContent`) so focus trapping, `Escape` and the scroll lock come from Radix; only
   the arrow keys are ours, on the content's `onKeyDown`.
5. **Wiring (`collection-page.tsx`).** `useMediaLightbox(posts)`, pass an `onOpenMedia` closer per
   card, render one `MediaLightbox` with `displayName` (the backend `DisplayName`).
