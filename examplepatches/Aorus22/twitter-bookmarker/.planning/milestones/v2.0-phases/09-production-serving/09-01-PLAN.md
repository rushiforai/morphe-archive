# Phase 9: Production Serving — Plan 01

**Goal:** make the single Go process serve the whole product. `web/dist` is served at `/`, the API
keeps precedence over static serving, unknown client routes get the SPA shell so a browser refresh
survives, unknown `/api/*` paths get the existing JSON error envelope, a missing `web/dist` degrades
with a clear message instead of a crash, and the root Makefile gains web targets without breaking the
frozen `make build` / `make test` contracts.

**Scope:** `backend/**` and the root `Makefile` only. Nothing under `extension/` or `web/` changes
(the frontend is complete through Phase 8; `web/dist` is already gitignored in both `.gitignore`
files, so no ignore change is needed). `.planning/ROADMAP.md`, `STATE.md`, `REQUIREMENTS.md`,
`PROJECT.md`, `state.json` and `PRD-2.md` are neither read nor written. No long-running server is
started: every check runs through `httptest` or the orchestrator's `unshare -rn` isolated harness.

**Frozen contracts that must not move:** `GET /health` → `{"status":"ok"}`; `GET /v1/index` →
`{"items":{…}}`; `POST /v1/bookmarks` → 201/409 with `{"filename":…,"tweet":{…}}`; stdlib-only Go
module (no new `require`).

## Approach

1. **Resolve the dist directory in `config` (PROD-01).** `config.WebDir()` follows the established
   `TWITTER_BOOKMARKER_DIR` pattern: `$TWITTER_BOOKMARKER_WEB_DIR` is authoritative when set (so a test
   can point at a temp dir *or* at a deliberately missing one), otherwise `<cwd>/web/dist` and then
   executable-relative candidates are tried, first existing directory wins. A pure
   `resolveWebDir(env, cwd, exeDir)` carries the order so it is unit-testable without `chdir`.
2. **A dedicated static/SPA handler (PROD-01/03).** Registered as the root `/` pattern; it looks the
   request up inside `os.DirFS(webDir)` via `http.ServeFileFS`, sets the cache policy by path, and only
   then decides between "missing asset → 404" and "client route → index.html".
3. **API precedence by construction (PROD-02/04).** Known API routes keep exact patterns but are
   registered without a method and gated by a `methodGate` helper, because a method-less catch-all
   shadows Go's automatic 405 (verified with a routing probe: `POST /health` and `GET /v1/bookmarks`
   landed on the catch-all instead of 405). `/api` + `/api/` + `/v1` + `/v1/` catch-alls answer the
   JSON envelope; the static handler re-checks API prefixes as defence in depth.
4. **Degrade, don't crash (PROD-05).** `NewServer` logs once at construction; a request-time stat of
   `index.html` decides behaviour. Without a build, `/` explains how to build it and every other
   unmatched non-API path stays a plain 404, which also preserves the pre-SPA 404 contract that
   `TestMethodNotAllowedAndNotFound` and the v1.0 "no categories/settings surface" test assert.
5. **Makefile (PROD-06).** Split the existing `build` body into `backend` / `extension` / `web`, make
   `build` compose all three, add `dev-web` / `dev-backend`, and add the web suite + typecheck to
   `test` / `lint` (documented in the header comment).
