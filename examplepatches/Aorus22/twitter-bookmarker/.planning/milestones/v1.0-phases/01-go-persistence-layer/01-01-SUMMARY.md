# Phase 1: Go Persistence Layer & HTTP API Summary

**Standard-library-only Go module with fixed loopback config, 0700 storage-dir bootstrap, PRD-exact domain model, structured slog logging, and a draining SIGINT/SIGTERM lifecycle.**

## Accomplishments
- `backend/go.mod` declares `module twitter-bookmarker` / `go 1.22` with **zero** `require` directives (`go list -m all` returns only the main module)
- One source constant pair (`config.Port = 43121`, `config.Host = "127.0.0.1"`) drives the only listen address; nothing in the request path can change it
- `config.EnsureStorageDir()` creates `~/.twitter-bookmarker` at 0700 (and chmod-repairs an existing dir); failure surfaces as a wrapped, human-readable error and exit 1
- `internal/model` defines every PRD type (`TweetInput`, `IndexEntry`, `IndexFile`, `SaveRequest`, `SaveResponse`, `DuplicateResponse`, `IndexResponse`, `HealthResponse`) with exact JSON tags (`tweet_date`, `saved_at`, `tweet_id`, `items`, `tweets`)
- `internal/logging` wraps `log/slog` with one method per PRD §56 event; startup, index rebuild, save (id + filename only), duplicate, invalid request, filesystem error and index-persistence warning are all covered
- `cmd/server/main.go` uses a `run() error` shell so `main` only maps errors to exit codes; explicit `net.Listen` makes port-in-use deterministic, and `signal.NotifyContext(…, os.Interrupt, syscall.SIGTERM)` + bounded `srv.Shutdown` drain in-flight requests

## Decisions Made
- Startup settings are compile-time constants (per PRD §5/§52); no UI or request configurability
- Storage directory is injectable (`NewStore(dir, …)`, `os.UserHomeDir` honouring `$HOME`) so the whole suite runs against `t.TempDir()`
- The PRD's illustrative multi-line startup banner is emitted as one structured slog record carrying `server`, `listening`, `storage` and `indexed_tweets` — same information, machine-readable, and consistent with the other log events
