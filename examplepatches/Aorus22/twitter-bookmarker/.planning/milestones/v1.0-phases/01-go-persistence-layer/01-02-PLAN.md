<task type="auto">
  <name>Task 2: URL normalization + tweet ID extraction</name>
  <files>backend/internal/storage/url.go</files>
  <action>
Implement:
- `NormalizeURL(raw string) (canonical string, tweetID string, err error)` using `net/url`:
  - parse; require a valid host (`x.com`, `www.x.com`, or `twitter.com`/`www.twitter.com` normalized to `x.com`); require scheme http/https.
  - locate the path segment `/status/<digits>` (tolerate a trailing path segment like `/photo/1`).
  - reject if no numeric status ID is found.
  - canonical form: `https://x.com/<username>/status/<id>` where `<username>` is the path segment immediately before `status` (no leading `@`); if absent, use `i` — but require presence of a username segment for the PRD examples.
  - drop query and fragment.
- `ExtractTweetID(raw string) (string, error)` delegating to NormalizeURL.
  </action>
  <verify>Unit tests: `?s=20`, `#hash`, trailing slash, `twitter.com` host, missing ID, non-numeric ID, `javascript:` scheme.</verify>
  <acceptance_criteria>
    - `https://x.com/foo/status/123?s=20` → canonical `https://x.com/foo/status/123`, id `123`
    - Hash and query are always stripped
    - Invalid/non-status URLs error
  </acceptance_criteria>

<task type="auto">
  <name>Task 3: Index load / rebuild / persist</name>
  <files>backend/internal/index/index.go</files>
  <action>
Implement an `Index` type holding `map[string]model.IndexEntry` + `sync.RWMutex`:
- `LoadOrRebuild(dir string, log *slog.Logger) (*Index, error)`:
  - if `index.json` exists and `json.Unmarshal` succeeds with `version==1`: use it.
  - if missing OR malformed: scan `dir/*.csv` (skip `index.json`), read each with `encoding/csv`, skip the header, and build entries keyed by the Tweet Status ID derived from each row's `url` column; derive `saved_at` from the row column.
  - empty directory → empty index (no error).
  - CSV is authority: never let a bad index destroy or rewrite CSV.
- `Lookup(id string) (model.IndexEntry, bool)`.
- `Add(id string, entry model.IndexEntry)`.
- `All() map[string]model.IndexEntry` (copy).
- `Count() int`.
- `Persist(dir string) error`: marshal `{"version":1,"tweets":{...}}`, write to a temp file in the same dir, `fsync`, then `os.Rename` over `index.json` (atomic best effort).
  </action>
  <verify>Unit tests: rebuild from a hand-written CSV; corrupt index.json triggers rebuild; missing index triggers rebuild; empty dir yields empty index; Persist round-trips.</verify>
  <acceptance_criteria>
    - All four PRD §23 startup cases (A–D) implemented
    - Rebuild works purely from CSVs
    - Persist is atomic (temp + rename)
  </acceptance_criteria>
  <done>Index package implements load/rebuild/persist.</done>

<task type="auto">
  <name>Task 4: CSV store with concurrency protection</name>
  <files>backend/internal/storage/csv.go</files>
  <action>
Implement a `Store` bound to a storage dir + `*index.Index`:
- One global `sync.Mutex` guarding the whole save critical section (PRD §24). CSV writes are synchronous.
- `Save(req model.SaveRequest) (model.SaveResponse, error)`:
  1. `ValidateFilename(req.Filename)`
  2. `NormalizeURL(req.Tweet.URL)` → canonical + tweetID
  3. validate required fields (`author`, `username`, `tweet_date` non-empty; parse `tweet_date` as RFC3339 and reject if unparseable)
  4. lock
  5. `index.Lookup(id)` → if present return a typed `ErrDuplicate{TweetID}` sentinel
  6. open file `os.O_CREATE|os.O_WRONLY|os.O_APPEND` 0600; if the file is empty/new, write the exact header `url,author,username,tweet_date,saved_at,text` first
  7. append the record with `encoding/csv` (`url, author, username, tweet_date, saved_at, text` where `saved_at = time.Now().UTC().Format(time.RFC3339)`)
  8. flush; on write error return error (caller → 500)
  9. update in-memory index
  10. `index.Persist(dir)` — on error, log a warning and STILL return success
  11. unlock
- Define error types/classifiers so the API layer can map: `ErrInvalid` (400) vs internal error (500) vs duplicate (409). A simple `type ValidationError struct{ Reason string }` + `errors.As` is enough.
- `Header = "url,author,username,tweet_date,saved_at,text"` as a single constant.
  </action>
  <verify>Integration tests: create → one row + header; append → second row, header not repeated; duplicate → sentinel error, row count unchanged; comma/emoji/multiline text round-trips through `encoding/csv`; 20 goroutines saving the same tweet → exactly 1 row; force `Persist` failure (read-only dir or mocked path) → Save still succeeds.</verify>
  <acceptance_criteria>
    - Header written exactly once per file
    - `encoding/csv` used (no manual escaping)
    - Global mutex prevents duplicate rows under concurrency
    - Index persistence failure does not fail the save
    - `saved_at` is UTC RFC3339
  </acceptance_criteria>
  <done>CSV persistence layer complete and race-tested.</done>
