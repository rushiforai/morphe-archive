<task type="auto">
  <name>Task 1: HTTP server + routes</name>
  <files>backend/internal/api/server.go, backend/internal/api/handlers.go</files>
  <action>
Create `api.NewServer(store *storage.Store, idx *index.Index, log *slog.Logger) http.Handler` using `http.ServeMux` (Go 1.22 method+path patterns: `GET /health`, `GET /v1/index`, `POST /v1/bookmarks`).

Handlers:
- `handleHealth`: `200` + `{"status":"ok"}`.
- `handleIndex`: `200` + `{"items": {id: {url,filename,saved_at}}}` from `idx.All()`.
- `handleSave`:
  - `http.MaxBytesReader` (e.g. 1 MiB) and `json.Decoder` with `DisallowUnknownFields()`.
  - decode into `model.SaveRequest`; decode error → `400 {"status":"error","reason":"invalid payload"}`.
  - missing/empty `filename` → 400; invalid filename → 400; invalid URL → 400; missing author/username/tweet_date → 400; bad tweet_date → 400.
  - duplicate → `409 {"status":"duplicate","tweet_id":"..."}`.
  - success → `201 {"status":"saved","tweet_id","url","filename","saved_at"}`.
  - unexpected/internal error → `500 {"status":"error","reason":"internal error"}` and log it.
- Every handler sets `Content-Type: application/json` and never `Access-Control-Allow-Origin: *` beyond what a chrome-extension same-origin needs. Add minimal CORS handling only if required for the extension fetch (`chrome-extension://` origin); do not expose to arbitrary origins.

Add a small `writeJSON(w, code, v)` helper. Method-not-allowed / not-found should be handled sanely (405/404).
  </action>
  <verify>`go test ./internal/api/...` with `httptest`: health 200; index shape; save 201; duplicate 409; each invalid case 400; storage error 500.</verify>
  <acceptance_criteria>
    - Status codes match PRD §17–21 exactly
    - Response JSON keys match the PRD examples
    - Unknown fields / oversized bodies rejected with 400
  </acceptance_criteria>
  <done>API handlers implemented and table-tested.</done>
