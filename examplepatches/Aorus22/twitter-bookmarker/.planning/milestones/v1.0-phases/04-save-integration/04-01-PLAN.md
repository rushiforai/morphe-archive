<task type="auto">
  <name>Task 2: Backend HTTP client</name>
  <files>extension/src/shared/api.ts</files>
  <action>
Implement thin fetch wrappers against `BACKEND_BASE_URL` (`http://127.0.0.1:43121`):
- `checkHealth(): Promise<boolean>` — GET `/health`, 1.5s AbortController timeout, `200` + `{status:"ok"}`.
- `fetchSavedIndex(): Promise<SavedIndex>` — GET `/v1/index`, return the parsed `{items}` body (callers take `Object.keys(items)`).
- `postBookmark(payload: SaveRequest): Promise<{ kind: "saved"; body: SaveResult } | { kind: "duplicate"; body: DuplicateResult }>` — POST `/v1/bookmarks` with `Content-Type: application/json`.
Map outcomes to the existing `BgError` union: network failure/abort → `backend_unavailable`; `400` → `invalid_request`; anything else non-2xx → `internal`. Define `BackendUnavailableError` and `BackendRequestError(code, kind)` sentinels.
  </action>
  <verify>Unit-test the status mapping with a stubbed `fetch`.</verify>
  <acceptance_criteria>
    - 201 → saved; 409 → duplicate; 400 → invalid_request; 5xx → internal; network failure → backend_unavailable
  </acceptance_criteria>
  <done>API client maps every outcome.</done>
</task>
