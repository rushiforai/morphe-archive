<task type="auto">
  <name>Task 2: Save state machine</name>
  <files>extension/src/content/save-controller.ts, extension/src/content/organizer.ts</files>
  <action>
Implement `createSaveController({ savedIds, settings, onSaved })` returning the real `OrganizerCallbacks.onSelect`:
- On select: guard `if (inFlight.has(tweetId)) return;` then `inFlight.add` and set the tweet's controls to disabled + `Saving…` (via `organizer.setSaving(article, true)`).
- Extract metadata fresh from the article (or use the already-extracted value) — if extraction fails, restore controls, toast `Could not read tweet data`, and abort (no request).
- Send `sendExtensionMessage<SaveTweetResponse>({ type: "SAVE_TWEET", payload: { filename: category.filename, tweet: { url, author, username, tweet_date: tweetDate, text } } })` inside a try/catch (a thrown `sendExtensionMessage` = backend unavailable).
- `resp.ok && resp.result` → `savedIds.add(id)`, `organizer.setSaved(article)`, toast success `Saved to <category.name>`, then call `onSaved({article, tweetId, category, savedAt: resp.result.saved_at})`.
- `resp.ok && resp.duplicate` → `savedIds.add(id)`, `organizer.setSaved(article)`, toast info `Already saved`.
- `!resp.ok && resp.error === "backend_unavailable"` (or a thrown send) → restore controls, toast error `Backend unavailable`.
- `!resp.ok && (invalid_request | internal)` → restore controls, toast error `Could not save tweet`.
- Always `inFlight.delete(tweetId)` in a `finally`; never allow two concurrent requests for the same tweet.
- Update `organizer.ts` to expose `setSaving(article, boolean)`, `setSaved(article)`, and to render category buttons with `disabled` during saving. Keep Phase 3's popover/inline behavior intact.
  </action>
