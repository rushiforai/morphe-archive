<task type="auto">
  <name>Task 3: Storage access + change propagation</name>
  <files>extension/src/shared/storage.ts, extension/src/shared/messages.ts</files>
  <action>
- `storage.ts`:
  - `getStore(): Promise<Store>` — read `chrome.storage.local`, merge over defaults, normalize `order` to 0..n-1.
  - `getCategories()`, `getSettings()`.
  - `addCategory({name,color})` → new uuid (`crypto.randomUUID()`), slug filename, `order = max+1`, persist, return the category.
  - `updateCategoryName(id,name)` → recompute `filename` from the new name (never touches files).
  - `updateCategoryColor(id,color)`, `deleteCategory(id)`, `reorderCategories(orderedIds)` → rewrite `order`.
  - `setSettings(partial)`.
  - `onStoreChanged(cb)` wrapping `chrome.storage.onChanged` filtered to `local` — the hook Phase 3 uses for live rerender.
  - Never call the backend from this module.
- `messages.ts`: typed message union and send/receive helpers for `HEALTH_CHECK`, `GET_SAVED_INDEX`, `SAVE_TWEET` (used in Phase 4; define now so contracts are stable).
  </action>
  <verify>Typecheck passes; a small unit test for order normalization and reorder mapping (pure functions extracted from chrome calls).</verify>

  </acceptance_criteria>
