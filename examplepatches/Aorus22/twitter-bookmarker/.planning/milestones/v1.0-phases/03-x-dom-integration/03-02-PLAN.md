<task type="auto">
  <name>Task 2: Container-scoped extraction</name>
  <files>extension/src/content/tweet-extractor.ts</files>
  <action>
Implement `extractTweet(article: HTMLElement): ExtractedTweet | null`:
- `getTweetId()` / `getCanonicalUrl()`: from the first status permalink whose subtree contains the tweet's `time`; normalize to `https://x.com/<user>/status/<id>` (strip query/hash); parse the numeric id.
- `getAuthor()`: display name from the first `[data-testid="User-Name"]` inside `article` (first text-bearing element).
- `getUsername()`: `@handle` from a link inside `[data-testid="User-Name"]` whose `href` starts with `/` (single path segment); ensure the `@` prefix.
- `getTweetDate()`: `datetime` attribute of the first `time[datetime]` inside `article`, normalized to ISO 8601 UTC (`new Date(dt).toISOString()`), preserving the original instant.
- `getMainText()`: the FIRST `[data-testid="tweetText"]` in DOM order that is NOT inside a quoted-tweet wrapper; extract `innerText`, preserve internal newlines, trim trailing whitespace. Return `""` when the tweet has no text (media-only).
- Return `null` (or a typed result with a reason) if `url`, `author`, `username`, or `tweet_date` is missing/empty; `text` is the only optional field.
- Never query `document` — only the passed article (except `closestArticle` for the caller).
  </action>
  <verify>Build fixture DOMs in tests: plain tweet; tweet with comma/emoji/multiline; quoted tweet (assert only parent text); image-only tweet (assert `text === ""`); malformed tweet missing username → null.</verify>
  <acceptance_criteria>
    - XI-05, XI-06, XI-07 satisfied
    - All metadata comes from the passed container
    - `text` empty is allowed; other fields are not
  </acceptance_criteria>
  <done>Extractor covers PRD §28–§30.</done>
</task>
