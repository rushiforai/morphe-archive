<task type="auto">
  <name>Task 2: Observer + tweet discovery</name>
  <files>extension/src/content/bookmark-page.ts</files>
  <action>
Implement `startBookmarksPage()` / `stopBookmarksPage()`:
- On start: fetch the saved index once via the message contract (`GET_SAVED_INDEX`; in Phase 3 the background may still be a stub — tolerate failure by falling back to an empty Set and logging a warning, never blocking injection), build an in-memory `Set<string>`, then do one initial sweep and attach a single `MutationObserver` to a stable container (`document.body` subtree).
- Sweep algorithm: process `mutation.addedNodes` for tweet `article` containers (including descendants via `closest`/`querySelectorAll`), plus a debounced (~100–150ms) sweep of `article[data-testid="tweet"]` that lack the marker attribute — bounded to the timeline, never a per-mutation full-document metadata scan.
- For each article: skip if missing `data-twitter-bookmarker-injected`; extract the tweet id; mark `data-twitter-bookmarker-injected="true"` BEFORE injecting to guarantee idempotency even if injection throws; then call the extractor + injector.
- On stop (route leave): disconnect the observer, clear timers, and remove all injected controls (`[data-twitter-bookmarker-root]`).
- Guard against the observer firing for our own injected nodes (ignore mutations whose targets are inside `[data-twitter-bookmarker-root]`).
  </action>
  <verify>Manual: scroll the bookmarks timeline; new rows get controls exactly once; navigate away and back; no duplicates accumulate.</verify>
  <acceptance_criteria>
    - XI-03: single observer, O(1) saved lookup, index fetched once per page entry
    - XI-04: marker guarantees no duplicate controls across DOM re-renders
  </acceptance_criteria>
  <done>Discovery loop stable under infinite scroll.</done>
</task>
