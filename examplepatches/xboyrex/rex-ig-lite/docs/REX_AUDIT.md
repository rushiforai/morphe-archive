# REX IG LITE v3.14.0 — COMPLETE REPOSITORY & FAILURE AUDIT (`REX_AUDIT.md`)

## 1. Executive Summary
This audit documents the complete inspection of the **`rex-ig-lite`** repository ([https://github.com/xboyrex/rex-ig-lite](https://github.com/xboyrex/rex-ig-lite)), upstream Piko repositories ([`crimera/piko`](https://github.com/crimera/piko) and [`crimera/piko-ig-lite`](https://github.com/crimera/piko-ig-lite)), and Morphe Manager remote bundle specification ([`MorpheApp/morphe-manager` Patch Sources Documentation](https://github.com/MorpheApp/morphe-manager/blob/main/docs/patch-sources.md)), alongside root-cause reproduction of every runtime failure and screenshot defect (`22778`–`22782`, `22808`–`22819`).

## 2. Root-Cause Reproduction & Analysis of Reported Bugs

| **`BUG-DL-001`** | **P0** | `DownloadUtils: Error at downloadDialogBox` — `com.instagram.model.mediasize.ImageInfoImpl.A31[]` (`22808`, `22809`) | 1. In `MediaDataEntity.kt`, `GetImageVariantsExtensionFingerprint.changeFirstString(candidatesMethodName, 1)` attempted to patch string index `1` of a method that only had **1 string literal** (`index 0`), leaving `getImageVariants()` unpatched as `"getImageVariants"` (which fails on obfuscated `ImageInfoImpl`).<br>2. `ExtMediaDictImageInfoMapperFingerprint` subsequently overwrote `GetImageVariantsExtensionFingerprint` (index `0`) with the `MediaDict -> ImageInfo` method name (`"A31"`), causing `ImageData.getImageVariants()` to invoke `ImageInfoImpl.A31()` and throw `NoSuchMethodException: ImageInfoImpl.A31[]`. | 1. Added `ResolveImageInfoObjectExtensionFingerprint` in `Fingerprint.kt` and `MediaData.resolveImageInfoObject(Object)` in `MediaData.java`.<br>2. Fixed `GetImageVariantsExtensionFingerprint.changeFirstString(candidatesMethodName)` (index `0`).<br>3. Routed `ExtMediaDictImageInfoMapperFingerprint` exclusively to `ResolveImageInfoObjectExtensionFingerprint`.<br>4. Added Pando/Immutable/Obfuscated reflection fallbacks in `ImageData.java`. |
| **`BUG-DL-002`** | **P0** | `RexDialogs: handlePostOptionClick error` — `com.instagram.model.mediasize.ImmutablePandoImageInfo.A31[]` (`22810`, `22813`) | In Instagram `452.1.0.53.64+`, GraphQL/Pando feed and Reel items use `ImmutablePandoImageInfo` instead of `ImageInfoImpl`. Because `getImageVariants()` was overwritten with `"A31"` and `Entity.java` only used `getDeclaredMethod` on the leaf class without traversing superclasses/interfaces or inspecting candidate lists, `ImmutablePandoImageInfo.A31[]` threw `NoSuchMethodException`. | Upgraded `Entity.java` (`findMethod`, `invokeCompatibleMethod`, `extractFieldByType`) and `ImageData.java` (`extractCandidatesFromImageInfo`) to inspect `getImageVariants()`, `getAdditionalImageCandidates()`, `getScansProfile()`, `List<ExtendedImageUrl>` getters, and fields across the full class/interface hierarchy. |
| **`BUG-CAROUSEL-001`** | **P0** | Carousel indicator shows `1/10` on screen (`22815`, `22816`), but menu displays `Download All Carousel Posts (0)` (`22818`). | In `MediaDataEntity.kt`, `EditMediaInfoFragmentMediaSizeFingerprint` matched a non-carousel `List` getter first, preventing `findMediaLazyGetterName(it, "carousel_media", "Ljava/util/List;")` from patching `carouselMediaMethodName()`. At runtime, `getCarouselMedia()` returned `null`/`empty`, so `DownloadUtils` computed `carouselSize = 0` while still rendering the carousel label with `(0)`. | 1. Added `CarouselMediaGetterFingerprint` and prioritized `findMediaLazyGetterName(it, "carousel_media", ...)` before `EditMediaInfoFragmentMediaSizeFingerprint`.<br>2. Added 4-stage runtime carousel list resolution in `MediaData.getCarouselMedia()` (patched getter -> inner `MediaDict` scan -> method scan of `List<MediaData>` -> field scan).<br>3. Updated `MediaContextResolver` and `MediaActionRegistry` to never render `(0)` and to expose `Download all (N)`, `Download first 10` (when `N > 10`), and `Select slides to download`. |
| **`BUG-MENU-001` & `BUG-UI-001`** | **P1** | Duplicate/fragmented download popups (`22811` compact 4-item sheet vs `22818` 9-item Post & Reel Options menu) and showing `Extract Audio (MP3)` on still images. | Download actions were split across hardcoded switch branches in `DownloadUtils.downloadDialogBox` and `RexDialogs.showPostTriggerPopup` without a unified capability resolver or single modal owner. | Created `MediaContextResolver.java` and `MediaActionRegistry.java` with capability flags (`hasVideo`, `hasAudio`, `isCarousel`, `hasCaption`, `hasProfileAvatar`) and 4 semantic sections (**Download**, **Copy & Caption**, **Tools**, **Share**), hiding MP3 audio extraction on image-only posts and enforcing single-modal ownership (`dismissActivePopup()`). |
| **`BUG-ERROR-001`** | **P1** | Raw internal class names (`com.instagram.model.mediasize.ImageInfoImpl.A31[]`) shown in user toasts (`22808`–`22813`). | Catch blocks concatenated `e.getMessage()` directly into `Utils.toast(...)`. | Added `DownloadUtils.userSafeErrorMessage(Throwable, String)` and stripped raw exception strings from all user-facing toasts in `DownloadUtils.java` and `RexDialogs.java`, logging full stack traces via `Logger.printException` only. |
| **`BUG-UI-002`** | **P2** | App Language & Translator picker clarity (`22819`). | Required preserving both distinct rows (`Instagram App Language` and `Translator Target Language`) with clear subtitles and distinct semantic Tabler icons (`language` and `message-language`). | Verified and styled both rows in `RexDialogs.showAppLanguagePicker` with AMOLED `#15181D`/`#20252C` cards, distinct icons, and active state pills. |
| **`BUG-SETTINGS-ICONS`** | **P0** | Settings menu items and custom widgets all showed the same generic `"settings"` gear icon. | `SettingsCategory.getRouteKey()` returned `"rex_frag_*"` keys and custom preference widgets used `"rex_nav_*"` / `"rex_focus_*"` keys that were absent from `RexIcon.PREF_KEY_TO_ICON`, falling through to `"settings"`. | Mapped all 23 `rex_frag_*` route keys, all `Settings.*` keys, and all custom widget keys (`241` total keys across `186` semantic Tabler icons) in `RexIcon.java` and `assets/icons/icon-manifest.json`, plus explicit `setIcon` calls in `NavigationBarPreference`, `NavigationStartupPreference`, `FocusLockDurationPreference`, and `ButtonPref`. |
| **`BUG-MORPHE-BUNDLE`** | **P0** | Morphe Manager displayed `"Unnamed — The patch bundle could not be downloaded"` (`22779`, `22780`). | 1. `patches-bundle.json` on `main` pointed to a release tag before the CI workflow finished uploading the `.mpp` asset, or the user added a non-raw GitHub URL.<br>2. `.github/workflows/build.yml` committed `patches-bundle.json` to `main` *before* running `gh release create`, creating a race window where `patches-bundle.json` referenced a 404 release asset. | 1. Reordered `.github/workflows/build.yml` and `.github/workflows/release.yml` so GitHub Releases uploads `patches-3.14.0.mpp` **first**, verifies the asset, and only then updates `patches-bundle.json` on both `main` and `dev`.<br>2. Verified `patches-bundle.json` schema (`name`, `version`, `description`, `created_at`, `download_url`, `signature_download_url`) against [`MorpheApp/morphe-manager` docs](https://github.com/MorpheApp/morphe-manager/blob/main/docs/patch-sources.md). |
