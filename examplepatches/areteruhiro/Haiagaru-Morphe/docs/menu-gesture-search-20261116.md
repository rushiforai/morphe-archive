# メニュー・画像操作・検索の調整（未公開）

## 設定

- Haiagaru設定の「スレ内検索・記者ID」に3点メニューの検索表示（初期OFF）、レス複数選択表示（初期ON）を追加。
- 「スレ一覧・HOME・履歴の表示」に「キーワードの表示名を設定」のメニュー表示（初期OFF）、HOMEの追加並び替え・固定（初期ON）を追加。OFFでも保存済みの並び順・固定設定は削除しない。
- 取得済みスレ検索の追加操作欄を表示／非表示にできる。初期ON。画面を開き直すと反映する。
- 画像切り替えは方向指定／ChMate標準／無効を選べる。方向指定は専用ビューアとネイティブビューアで共通化し、割り当てた方向は同方向の戻る操作より優先する。拡大・複数指操作は横取りしない。

## 検索負荷

- スレ内検索でレスの検索用文字列を再利用。本文・名前・ヘッダー・ID・設定値が変われば更新する。弱参照かつ4096件上限で保持する。
- AND条件の単語分割と一致／不一致用パターンの再生成を減らす。
- 取得済みスレ検索の追加操作欄を固定行へ移し、500msごとの最大4096アクセシビリティノード走査を廃止。クエリーに応じたチェックボックスの利用可否だけ更新する。
- HOMEの並び順JSONを内容が変わるまで再利用。検索履歴キーのハッシュ文字列化で繰り返しのString.formatを廃止。

## 動画サムネイル

- GETのリダイレクトを最大5回、同一の取得時間制限内で処理。HTTPSからHTTPへの切り替え・認証情報入りURLは拒否する。
- 先頭時刻のフレームが取得できないとき、代表フレーム／先頭付近の同期フレームを試す。解析は既存の非公開デコーダープロセス内で実行。
- Cloudflare確認ページ・HTML応答は動画として解析せず、アクセス確認が必要な旨を表示する。
- 報告されたimgpileのURLは開発PCでCloudflareの確認ページを返したが、後述の実機通常GETでは動画を取得できた。端末・接続条件で応答が変わる。ブラウザのCookieを取り出す処理は追加していない。

### 最終候補の確認

通常のLint/R8を含む `:patches:buildAndroid` 成功（3分39秒）。候補を191／226／242へ適用成功。Mi Note 10（Android 11）の別アプリ検証パッケージへ、既存証明書との一致を確認して更新した。各版で実装クラスを呼ぶメニュー10項目が成功。標準の画像一覧で191は24項目、226／242は20項目が成功し、左右逆転の方向指定、未割り当て方向、切り替え無効、元のActivity維持を確認。検証中の各設定は試験前の値へ戻す。混在メディアの226／242も各7項目成功。

追加で242の専用動画ビューア非導入APKを別パッケージへ導入し、画像操作20項目に成功。初回の補助テストでは専用ビューア側のモデル追跡に依存した現在位置取得がnullになったため、ネイティブ画像コンテナの位置を直接読む形に補助テストを修正した。アプリのクラッシュではなくテスト側の観測エラーで、修正後に全項目を再実行した。

提示のimgpile動画はブラウザで再生可能との利用者回答。実機の本番 `connectionForPreview` 経路ではHTTP200、video/mp4、7,310,958 bytes。ブラウザ相当UA＋Range指定ではHTTP403、`cf-mitigated: challenge`、HTMLだった。242の専用ビューアあり／なしの両APKで本番 `generate` を呼び出し、未登録状態からサムネイル登録までそれぞれ1,562ms／1,769msで成功した。これは単一画像モードの生成確認で、報告端末の通信条件や実スレ上の表示をすべて再現したものではない。通信条件による確認ページの問題は残り得る。
