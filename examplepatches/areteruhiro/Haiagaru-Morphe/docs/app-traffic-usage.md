# アプリ通信量の記録

Haiagaru設定「アプリ・通信」（基本設定側）に記録スイッチと閲覧ボタンを追加。初期ON。UID単位のAndroid TrafficStats受信・送信累積値を1分ごと／画面復帰時に取得し、前回との差分を日別に93日保持。記録開始前の用途別履歴は復元できないが、開始時点で前回の再起動以降にUIDが使用した累計値を参考表示する。再起動・カウンター減少・記録OFFをまたぐ差分は除外する。日付をまたぐ間隔は計測日に計上。起動中のプロセス以外の常駐サービスを追加しない。URL・本文は保存しない。

Wi-Fiとモバイル合算、フォアグラウンド／バックグラウンド別の集計ではない。端末の再起動番号が取得できない場合も経過時間カウンターが単調増加している限り計測を続ける。今日・今月・日別の受信と送信を表示、確認後に記録だけを消去可能。記録と画像等の保存容量は別。

拡張機能が本文を直接読む通信は、スレ一覧画像・冒頭レス、Webカード、Imgurプレビュー、動画サムネイル、GIF、X投稿プレビューのカテゴリ別に受信本文量を目安計上する。全体はAndroid UID累積カウンターで計測する。内訳はレスポンス本文量であり、HTTPヘッダーやChMate標準処理、他の拡張通信は未分類として差額に含まれる。以前の通信を機能別に遡及分類はできない。VPN内部の通信はUID側に反映されない場合がある。

SettingsProfilesへ記録ON/OFF設定を登録。記録本体のhaiagaru.traffic-usageは機種変更で過去カウンターを混ぜない独立領域。更新履歴の追加機能一覧にも設定・閲覧を配置。容量確認ボタンもアプリ・通信側へ配置。

Java/Kotlin release compile成功。実機242のFridaで新クラスDEXを使用し、模擬カウンターによる基準点・加算・同一値・カウンター減少・boot変更・OFF・ON再開・93日上限・表示文言・差分境界値の10項目成功。元の設定／通信記録をfinallyで復元。試験 scripts/frida-app-traffic-usage.js、結果 build/app-traffic-frida242.log。実APKへの適用・インストールはまだ行っていない。
