# 閲覧後の再通知・ミュート中の音声フォーカス

2026-11-09。公開dev.17の後のローカル修正。

## 閲覧済みのレスを新着として通知する問題

監視の確認済み件数は通知・監視時だけ更新され、標準ChMateの既読数を参照していなかった。通知後にアプリで追加分を読んで閉じても、次の監視で古い基準から通知する。加えて、本文取得中に確認済み件数が進んでも、古い範囲の本文候補が残っていた。

未修正の242候補で、監視count=12、標準bookmarks.read_count=20、subject=20の隔離データを作り、13〜20を通知することを再現した。初回試験は検証アプリの通知権限がOFFのため停止し、権限を一時許可して7番目の検査で再通知を再現。ネイティブDBの架空板・スレ1行と架空HTTP応答のみ使用。公開通信・投稿なし。

通知判定時に、対象の板IDとスレ番号に一致する標準bookmarks.read_countだけを読み取る。res_count/server_res_countは巡回やダウンロード済みを意味し、既読判定には使わない。本文取得後にも既読を再確認し、現在の監視件数・既読数より前の候補を除去する。初回の無通知、返信限定、通知済みレスの重複排除、期限・停止設定、通信失敗時の再試行は維持する。標準DB/DAT/既読位置を変更しない。新規ネイティブフック・全クラス走査なし。

## ミュートと音声フォーカス

Haiagaru専用VideoViewプレーヤーのPlaybackAudioFocusにミュート状態を反映する。ミュート再生では要求せず、再生中のミュート切替では音量を0にしてから解放する。再生中の解除は音量を戻す前に要求し、拒否されたら一時停止する。停止中の解除は要求しない。ミュート中に遅れて来たフォーカス喪失で動画を止めない。画面再作成時のミュート初期状態も開始前に反映する。

Android 8以降はVideoView自身のフォーカス処理を無効化しているため、上記制御で背景音声を維持できる。Android 7以前のVideoView内部の自動要求は今回変更しておらず、この動作を保証する対象には含めない。ChMate標準プレーヤー、YouTubeアプリ自体、実機での長時間確認は今回の検証とは区別する。
