# テキスト選択メニューを優先する

Haiagaru設定「レス本文の長押しコピー」と同じ画面に追加。初期OFF。文字選択中のコピー／全選択／切り取り／貼り付けは表示可能なら表に残し、ChMate独自のNGワード／Web検索／取得済みのスレから検索／共有は︙へ移します。項目の処理や選択範囲には変更を加えません。端末の標準メニュー配置にはOSの判断も含まれます。更新履歴の追加機能一覧からも切り替え可能。

元191のhWは独自4項目をshowAsAction=alwaysで定義した選択メニューです。単なるXML編集が効かなかった原因は未確定です。今回の実装は元APKで特定した191／226／242の選択用MenuInflater呼出し直後で設定を反映するため、リソースの難読化名に依存しません。対象メニューはNGワードとWeb検索の両項目で識別します。

元APKのInflater参照から対象ownerを確認し、class-bindingsへ固定登録。Frida検証は新規クラスDEXを読み込んだ実機242のAndroid PopupMenuでON/OFF/再OFF・標準項目・独自4項目・通常メニュー不変の24条件を確認。実APKに適用して選択バーを操作する試験とは別です。スクリプト scripts/frida-selection-menu-priority.js、結果 build/selection-priority-frida242.log。

191・226でも同じFrida検証24項目が成功（計72項目）。各アプリの元設定へ復元。データの登録・削除・投稿は行っていません。
