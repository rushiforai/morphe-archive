# 人気レスの判定方式と表示方法

検証済み範囲あり・未公開。2026-10-22。

従来の `popularReplyPopup` は、ポップアップ表示と直接返信判定を同時に有効にしていた。標準のツリー表示で返信の枝が閾値に含まれる動作と異なるため、Part3で標準方式の抽出件数を期待した利用者に1件が表示された。数字の桁落ちではない。

## 設定

Haiagaru設定の人気レス関連に次を独立して置く。

- 人気レスを直接返信数で判定する：OFFはChMate標準方式（通常表示とツリー表示を区別）。ONは直接返信のみで判定。
- 人気レスをポップアップで表示する：OFFはスレ内抽出、ONは現在の閲覧位置を変えずにポップアップ表示。

旧設定が明示されている場合は直接返信ON/OFFを移行し、既存の動作を勝手に変更しない。一度移行した判定方式はポップアップをOFFにしても変わらない。新規利用者は両方OFF。各方式の閾値も別保存し、標準方式の未設定時は本体の値を使う。共有設定へ二つのスイッチ・閾値を含める。

## 実装

- nativeの人気レス抽出直前に、生成済みの返信ツリーを表示用コピーとして捕捉する。実際の選択状態を一時的に切り替えて取得する方式は使わない。
- 191はadapterのG/I（表示方式／閾値）、226はM/D、242はrenderer引数のzzacn（Normal／Tree）と設定bを使う。ScopeUtil.aは表示方式ではなく選択状態なので使わない。標準の通常表示はnativeの返信カウント、ツリー表示はnativeの枝区切りと深さで判定する。
- 標準方式の件数・ポップアップ・スレ内抽出は同じ選択IDを使う。直接返信方式のポップアップOFFも実装し、nativeの読み込み済み行から表示用コピーを抽出する。
- nativeのレジスター数・元命令・取得済みログは変更しない。nativeがロードした閾値だけを任意設定で補正する。
- 返信ツリーの一時キャッシュは最大16件。未取得時は件数を「—」とし、直接返信数を標準件数と偽って表示しない。
