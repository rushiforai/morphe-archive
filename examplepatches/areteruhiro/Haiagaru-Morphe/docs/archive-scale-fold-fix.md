# エッヂ過去ログの倍率と折りたたみ判定（2026-10-21・未公開）

## 過去ログの表示倍率

検索欄・結果欄の倍率は保存され、元のTextViewにも反映されていましたが、Compose版はMaterialの文字サイズで描画していたため、設定を変更しても見た目が変わりませんでした。

コントローラーの70～150%設定を描画モデルのタグで通知し、Compose側の文字倍率へ接続しました。検索欄・操作ボタン・状態表示と、検索結果は別々の倍率です。システムの文字倍率にも重ねて適用します。タグの変更を再描画監視へ加え、結果の再検索やActivity再作成は不要です。検索条件・スクロール位置の既存処理は維持しています。

## フォルダブル

`screenWidthDp >= 600`による自動判定を廃止し、Jetpack WindowManager 1.3.0の`WindowInfoTracker.windowLayoutInfo(Activity)`から`FoldingFeature`を監視します。Activityの開始・停止・破棄、設定のオン／オフに合わせて監視を開始・解除します。ChMateのActivityの継承関係は変更しません。

折り目を確認した内側画面でタブレット、その端末で確認後に全画面の折り目情報がなくなればスマホ表示を選びます。初めて閉じたまま起動したとき・折り目未検出の普通の端末・取得エラー・折り目のない分割画面では推測して切り替えません。検出済み記録は端末モデルとOSビルドへ結び付けます。画面幅・DPI・機種名リストを基準にせず、投稿・メディア・設定中の保留と既存の読書位置引き継ぎは維持します。

メーカーから正しい折り目情報が届くことが前提で、全端末での物理状態の完全な保証はできません。初回は一度内側画面で開く必要がある場合があります。詳しくは[折りたたみ表示の説明](fold-layout.md)を参照してください。
