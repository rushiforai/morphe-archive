# 人気レスの断続的な表示欠落

## 報告と確認できた経路

1.12.0-dev.8でも、人気レスが存在するのに空になり、別のスレを開いて戻ると表示されるとの報告。自然発生時の端末内部状態は取得できていないため、報告の全原因を特定したとは扱わない。

修正前候補の242に対し、Fridaでメモリ上の判定用Snapshotだけを古い部分レイアウトへ一時置換した。現在のnative入力432レスに対し`filterCollected`の出力が0レスとなることを確認した（`build/popular-stale-before.log`）。実際のDAT・投稿・既読位置は変更せず、設定・Snapshot・一時選択値はfinallyで復元した。テスト入力はnative結果行を模した入力であり、その432件すべてが実際の人気レスという意味ではない。

標準方式で本体の出力を過去のSnapshotから再構築していたため、古い空／部分レイアウトが現在の結果を置換できていた。また、nativeRowsReadyは成功済みの0件を再確認せず、データが後から揃っても更新しない条件だった。191／226では件数表示・追加項目がともにオフだと、直接返信方式の行抽出まで省略していた。

## 修正

- 標準方式は本体が生成した現在の行を使用し、過去のSnapshotで置換しない。追加AA／自分／返信との絞り込みは維持。
- 新しいSnapshotが届いたら、前回0件でも再集計する。直接返信方式の抽出中なら再構築する。
- 同じレイアウトの繰り返し捕捉は再通知せず、更新ループを防ぐ。レス参照数・深さ・表示モード・閾値の変更を比較し、値が変わった場合は同じレスオブジェクトでも更新する。
- 直接返信方式は、件数表示・追加項目のオフと独立して行抽出する。

## 検証

- `:patches:buildAndroid --offline --no-daemon`成功、通常Lint込み（`build/popular-intermittent-final-build.log`）。
- 同一MPP SHA256 `4ED3294444E82FCFD1D954AB4949775A7E97C0BCC4F85E911177ADE2930B0437`から191／226／242を生成し、既存検証アプリへ署名照合後にinstall-r。台帳はandroid-installations.md。
- 242の同じ制御試験で入力438レスが438レスのまま保持された（`build/popular-stale-after242.log`）。前後で実スレの取得件数が増えているため、432対438の件数比較ではなく、それぞれの入力保持を確認している。
- 242で前回成功件数0の状態を再現し、nativeRowsReadyから157件へ復帰（`build/popular-late-after242.log`）。
- 242の実Part3で標準件数157と本体157が一致。直接返信ON・ポップアップOFFは2件を実行レイアウトへ保持（`build/popular-intermittent242-live.log`）。
- native popularity hookの元命令・レジスター・閾値と、native tool tabの元命令・分岐・Fragment基底検査は3版成功。

長時間使用時の自然発生条件をすべて再現したわけではない。修正前から存在するFrida計測中のART GC SIGSEGV（03:12 UTC）と191フォント読込ANR（02:47 UTC）は、最終候補の通常操作による発生と区別する。今回の試験だけで完全な解消・無クラッシュを保証しない。
