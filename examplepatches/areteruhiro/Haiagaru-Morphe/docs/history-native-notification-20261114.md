# 履歴の標準タブ・191通知の対象位置（2026-11-14）

対象は191・226・242の履歴ポップアップと、191の通知からのレス移動。
OneDriveを使わず、AGENTS.md指定のローカル開発先で実装。

## 履歴

「更新対象」OFFではstock popupを一切ラップしない。ONの場合もChMateの既存
タブバーとボタンモデルへ1項目を追加し、標準の描画・テーマ・サイズ・タッチ・
選択表示を利用する。191はsetButtons、226/242はsetToolbarStateへ接続する。
226の設定モデルは整数gravity、242はenum gravityという差を維持する。
保存済み更新対象と既存native adapter/長押し処理は引き続き利用する。
標準モデルがまだ初期化中なら従来の操作可能な表示を保持し、500ms間隔で準備を再試行。

## 通知の位置

ThreadWatchNavigationは対象レスを最初に見つけた直後にpendingを破棄していた。
このあとnative更新がadapter/既読位置を復元すると、通知の対象レスから離れる。
191では既存の40秒期限内でpendingを保持し、描画前に対象レスが画面内にあるか確認する。
画面外ならレス番号で再移動。すでに見えている場合は移動せず、最初の移動成功後は
追加更新を要求しない。ユーザーのタッチ、別スレへの切替、次の通知、期限切れで解除。
既存タブへの明示移動では以前のタッチ記録をリセットし、過去の操作で新しい通知が
即座にキャンセルされないようにした。

対象はHaiagaruのThreadWatchOpenActivityを通る通知。一般のURL起動や、対象レス番号を
持たない通知まで変更するものではない。通信中の実報告そのものの確認と、模擬の
adapter差替え試験は区別する。
