# MEGAバックアップ（開発中）

[READMEへ戻る](../README.md)

## 導入と注意事項

MEGA同期はパッチ導入時に「MEGAバックアップ・同期」を選択した場合のみ利用できます。
初期状態は未選択です。**MEGA同期にはAndroid 7.0以降が必要です。**
MEGAパッチの有無でChMate本体のAndroid下限は変更しません。
未選択のAPKへ更新すると、以前の同期設定やログイン情報が残っていても自動同期しません。
Android 7.0未満では、選択済みでもMEGAの操作は表示しません。

ローカルバックアップ・復元は標準機能として維持し、MEGAパッチやログインは不要です。
「レスのアーカイブ・保存用スレ」を選択すると、保存用スレの名前と各保存レスも含まれます。
複数の保存用スレ・従来の保存レスを保持し、復元後は「過去レスを見る」から開けます。
画像・動画ファイル自体はレスのアーカイブに含みません。既存の対象選択設定は維持します。
ChMate設定 → Haiagaru →「バックアップ・機種変更」から、用途ごとの入口を開きます。

- **ローカルバックアップ**：端末のファイルへの保存・復元、ローカル自動バックアップ。
- **MEGAバックアップ・同期**：MEGAへの保存・復元と同期。追加パッチとAndroid 7.0以降が必要です。

復元画面は、そのバックアップに保存されている項目を自動選択します。別の端末の現在の保存設定には合わせません。
復元前にチェックを変更でき、「内容・注意事項」から戻ってもその選択を保持します。
「設定」にはスレ新着通知の登録先・確認間隔・確認済みレス数も含めます（未公開）。復元後は通知確認の予約も再開します。
「設定」を復元すると、Haiagaruの表示・動作設定はそのバックアップの内容へ戻します。バックアップにない追加設定は初期値へ戻し、以前の復元で有効になった機能を残しません。初回案内の表示済み状態と保存対象外の認証情報は保持します。双方向同期の「不足分を追加」では、従来どおり既存の設定を保持します。
「お気に入り・閲覧履歴」には★状態も含まれます。同じスレが端末にある場合も、復元では保存済みの★を反映し、既読数と表示位置は端末側に残します。
双方向同期では端末側の★を残し、★がないスレへ保存済みの★を追加します。

手動・自動のローカル保存は、作成、書き込み、保存結果の確認の順に進みます。
保存先のストリームを閉じ、ファイルを読み直して内容が一致するまで完了とは表示しません。
書き戻し確認のため、容量の大きいバックアップは書き込み後も時間がかかります。
通知を許可していれば、画面を離れても進行中・完了・失敗を確認できます。
通知が許可されていない場合は、設定画面の「バックアップの通知を有効にする」から許可できます。
MEGAの処理にも進行中・完了・失敗の通知を表示します。
端末で保存結果を読み出せても、クラウドのファイル提供元によるサーバーへの転送完了までは保証できません。

Haiagaru形式のZIP（Cookieのみを含むものも同様）とChMate標準のSQLiteバックアップは別の形式です。
191の標準復元へHaiagaru形式のZIPが渡った場合は、SQLiteで開かずHaiagaruの復元画面へ切り替えます。
1.8.15形式のJSON/ZIPもHaiagaruのローカル復元から読み込めます。

## 同期対象と動作

上記のバックアップ画面から、
「お気に入り・閲覧履歴」「NG設定」「ChMate・Haiagaruの設定」
「書き込み履歴（postDataList.json）」「書き込みメモ（kakikomi.txt）」を個別に選べます。
加えて「レスのアーカイブ」「スレのアーカイブ」「取得済みスレログ（DAT）」
「フォント・テーマ・キーワードグループ」「標準画像アップロード履歴」を選べます。
DATとアップロード履歴は初期OFFです。アップロード履歴はサーバー削除用情報を含む場合があります。
スレのアーカイブはDATだけでなく、フォルダ内の付随ファイルもまとめて保存します。
文字列置換・スレ立てコマンド・高度なNGなどのHaiagaru追加設定も設定項目に含みます。
高度なNGの条件・スクリプト・板指定・各ルールと全体の有効／無効は「NG設定」だけを選択した場合も保存・復元します（1.8.11）。ローカル／MEGA共通です。「設定」経由の従来バックアップも引き続き復元できます。双方向同期では既存の値を保持し、未登録の設定値だけを取り込みます。復元後はChMateを再起動してください。
バックアップ時は選択項目だけを保存し、復元時にも対象を再確認します。
「MEGA → この端末」「この端末 → MEGA」の片方向同期と、双方の不足分だけを追加する
双方向同期を選択できます。復元前には変更候補を表示でき、設定から表示を省略できます。
双方向同期では既存の設定・履歴・NG・書き込みメモを消さず、不足している値だけを追加します。
自動同期は初期OFFで、分・時間・日単位の間隔を指定できます。自動同期はバックグラウンドでは
実行せず、アプリ起動時に前回の同期から指定間隔が経過していれば実行します。復元先では
MEGA側のバックアップが前回適用したものより新しい場合だけ復元します。

同期は完全なミラーリングではありません。MEGAから取り込むのは最新のバックアップ1件で、
過去の全バックアップを一括統合するものではありません。双方向では既存の設定値を優先し、
既存DAT・アーカイブの同名ファイルも保持します。一方の端末で削除した内容を他端末から削除する
「削除の伝播」は行いません。複数端末が同時に更新した場合の競合解決も未対応です。

利用者自身のMEGAアカウントでログインします。Google CloudやOAuth Playgroundは不要です。
パスワードと2段階認証コードは保存せず、ログイン後のセッションだけをAndroid Keystoreで
暗号化して端末内に保存します。セッションを含むスクリーンショットやログは共有しないでください。
MEGA同期にはAndroid 7.0以降が必要です（ChMate本体の対応範囲は変更しません）。

MEGA上に`Haiagaru`フォルダを作成し、選択した項目のスナップショットを保存します。
別の端末からは同じMEGAアカウントでログインして復元できます。MEGAの暗号化通信を
使用します。Cookieは初期OFFですが、明示的に選択するとChMateのログイン情報も含まれます。
ローカルのZIPファイルは暗号化されないため、保管先や共有先に注意してください。
この試験機能は[MEGA用Kotlinライブラリ](https://github.com/acarlsen/kmp-mega)を使用します。

## 認証情報（任意・初期OFF）

通常の設定バックアップでは認証情報を除外します。「認証情報・WebView Cookie・MEGAセッション」
を明示的に選択すると、認証用設定・通常のWebView Cookie・保存済みMEGAセッションも保存します。
MEGAセッションは復元先のKeystore鍵で暗号化し直します。パスワード入力の履歴を取得するものではありません。
保存されていないパスワードやOSアカウントの資格情報は取得しません。

**このファイルだけでアカウントを操作される危険があります。公開・共有せず、安全に保管してください。**
ローカルZIP自体にはパスワード暗号化を施していません。復元時はアカウントが切り替わる場合があります。
WebViewの分離Cookie、端末認証、サイト側で失効したセッション等は移行できず、再ログインが必要です。
外部ブラウザやGoogleアカウント管理サービスの情報は対象外です。

「端末依存の暗号化済みデータ」も別項目・初期OFFです。現在はMEGAの暗号化済み設定を保存し、
同じアプリの同じインストール環境でのみ復元できます。アンインストール後や別端末・別パッケージでは
この項目を外してください。**Android Keystoreの秘密鍵自体はOSの仕様で取り出せず、保存しません。**
MEGA接続設定・バックアップ端末ID・自動同期設定は端末間でコピーしません。

## 大容量バックアップ・復元元の選択

新しいバックアップはZIP形式です。旧JSONバックアップも復元できます。
**ZIP全体の32MiB上限を撤廃**し、DAT・アーカイブ・書き込み履歴・メモを順次読み書きします。
設定等の構造化JSON部分に限り64MiB、従来NGファイル等には個別の安全上限を残しています。
巨大なバックアップ全体をメモリに展開しませんが、作成・取得・復元前退避・上書き照合用の空き容量は必要です。
画像・動画キャッシュ、共有領域の任意ファイル、外部TXTのSAFアクセス権、OS権限は保存しません。
外部で選択したReplaceStr.txtの内容は別途保管し、移行後にファイルを選び直してください。

MEGAの復元は一覧からファイルを選びます。端末名を含むファイル名・作成日時・サイズを表示します。
日時の表示と新規バックアップ名の日時は端末のタイムゾーンに従い、時差表記は付けません。
端末のタイムゾーン変更は次の表示・作成から反映します。既存のファイル名は変更しません。
内部の保存時刻・最新順の判定は絶対時刻のまま維持します。
自動同期だけはMEGA上の作成日時が最新のファイルを使用します。
「この端末のバックアップを上書き」は初期OFFです。有効にすると、端末名＋インストール固有IDの
固定名を使用します。同じ機種でも別インストールは別ファイルになります。
新規アップロードのサイズと再取得したSHA-256を確認してから、同じ固定名の旧ファイルだけを
MEGAのゴミ箱へ移します。照合失敗時は旧ファイルを保持します。
任意の「上書き時、旧バックアップを完全削除」は初期OFFです。有効化時には確認を表示し、
新しいバックアップの照合成功後に限り、同じ固定名の旧ファイルをゴミ箱を経由せず削除します。
**完全削除した旧ファイルは復元できません。自動同期の上書きにも適用されます。**
他端末のバックアップ、別名の過去バックアップ、すでにゴミ箱にあるファイルは対象外です。
上書きをOFFにすると完全削除もOFFに戻ります。

復元前に現在の選択データをアプリ内`files/haiagaru-sync-recovery`へZIPで退避します。
パス逸脱・重複パス・CRC不一致は書き換え前に拒否し、各ファイルをAtomicFileで確定します。
全ファイル一括のトランザクションではないため、途中で容量不足になった場合は退避ZIPを使用してください。
双方向同期では既存DAT・アーカイブを上書きせず、不足ファイルを追加します。
書き込み履歴はレコード単位で重複を除いて統合し、メモは行を削除せず保持します。
復元後はChMateを再起動してください。ChMate標準ZIPとは別の形式です。

## パッチ選択の検証

`scripts/VerifyMegaSyncOption.java`で、191 devの未選択APKと242 devの選択済みAPKを検証。
選択マーカー、Android API 24条件、起動時同期・手動同期・ログインの入口ガード、
MEGA画面をスキップした後にもローカル保存・復元の経路が残ることを確認しました。
APKのAndroid下限はそれぞれ21／23のままです。
実際のMEGA通信は、利用者のログイン後に別途確認が必要です。


「設定」の保存にはローカル手動バックアップの対象選択、自動バックアップのON/OFF・保存先候補・間隔・保持数・対象、MEGAの対象選択・同期方向・間隔・差分確認の指定も含めます（未公開）。MEGAの自動実行・削除オプション、前回実行時刻や削除対象の所有記録は移しません。フォルダのアクセス権は再インストール後に再選択が必要です。
