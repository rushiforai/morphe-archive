# 容量エラー・レス限定アップロード先・通知位置

## 変更

191の標準添付先imgw.syoboi.jpに16,085,632 bytesのMP4を送った際、HTTP413/text/html/Request Entity Too Largeを返すことをFridaで確認した。利用者が再添付を操作し、監視はサイズと応答形式だけを記録した。空POSTは400/JSONを返すため全体停止とは判断しない。正確な設定上限や最近の変更は未確認。

191のlegacy送信では413をJSON解析より先に判定し「ファイルの容量が大きすぎます」に変更。「画像・動画のアップロード先を変更することでアップロードできる可能性があります」「開きますか？」のダイアログから既存設定を開く。カスタム送信先とImgur Web経路もHTTP413を容量エラーとして扱う。他のHTML応答はHTTPステータス付きの案内にし、生の解析例外は表示しない。

アップロード先設定へImgurログインを移動。任意のImgurログインパッチを導入している場合だけ表示する。「このレスでだけアップロード先を変更する」は書き込み欄のViewに紐付け、同じレスの複数添付に適用。投稿成功・欄の破棄・別の投稿先への変更で解除する。通常設定やAPIキーを永続保存せず、自動再送・既存添付の再送は行わない。アプリ設定から開いた場合は書き込み欄がないためレス限定の切替を無効にする。

通知の対象レスへの移動は、226/242でも初回成功直後に追跡を捨てず既存40秒以内で保持。226のListViewと242のRecyclerViewについて実レス番号と可視子Viewを照合し、更新により対象が画面外へ動いたときだけ再配置。すでに見えている場合は動かさず、手動タッチ・別スレ・期限で解除する。追加更新は最初の移動成功後には要求しない。

## 追加の書き込み設定

書き込み画面の「︙」に通常版連携を追加するかを独立した設定stockPostingShowMenuにした。利用者指定で初期オン。オフでは新規追加と既存メニュー表示を止め、古い項目の操作も起動しない。長押し・ツールバーは別設定のまま利用できる。

「名前欄をスレごとに保存する」を追加（初期オフ）。ユーザー指定で未保存のスレは空欄。ThreadCommandsの検証済みネイティブ名前欄に接続し、正規化したスレURLのSHA-256をキーにアプリ内の専用SharedPreferencesで名前を保存する。本文・メールは変更しない。空欄も保存する。新規スレ立てとスレURLを特定できない場合は標準動作。設定オフでは通常の板単位の入力に戻り、保存済みのスレ別データは残す。名前・トリップ文字列をログへ出さず、通常版への引き渡しにも追加しない。

最終候補は3版適用・ネイティブ名前欄接続成功。Mi Note 10へ署名一致で更新し、スレ別名前15項目ずつ、191の通常版relay/確認省略/メニュー初期ON・OFF/復帰/長押し・ツールバー独立動作19項目成功。公開投稿なし。証跡thread-names/result{191,226,242}.log、stock-return/final-result.log。
