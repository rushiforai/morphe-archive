# 人気レス絞り込み時の不要な全レス集計

## 報告と確認範囲

利用者報告: 新しいHaiagaruで人気レスの絞り込みがカクつく。比較対象は
ChMate 0.8.10.191 dev / OPPO CPH2797 / Android 16 / Haiagaru 1.9.3。
追加回答: 切替時とスクロール中の両方で発生。「直接返信数で判定」はOFF、
「フィルターに件数を表示」の項目は見当たらなかった。新しい版の正確な番号は未確定。
報告端末での再現・速度・改善は未確認。

1.9.3には存在しない`ExtraQuickFilters`に、件数OFFでも追加フィルターのボタン表示が
有効なら全レスを集計する経路があった。`quickFilterExtras`の初期値はtrueなので、
人気レスだけを選んでもAA判定・自分の投稿インデックス・返信アンカーを走査する。
これはコード上の追加コストであり、端末上のカクつきの主因を確定したものではない。

## 変更

- 件数OFF・AA/自分/返信の選択なし・標準人気判定の場合、191/226の表示行および242の
  表示スナップショットをそのまま返す。ボタン表示の有効/無効を集計の条件にしない。
- 集計が必要な場合も、選択されている追加フィルターが必要とする情報だけを読む。
  返信の選択時は、その前提になる自分の投稿インデックスも読む。
- 直接返信による人気判定と件数表示は、同じ再構築・同じ全レス一覧に限って本文の
  変換/直接返信数の解析結果を共有する。別スナップショット、次回更新、本文変更へ
  持ち越すキャッシュは設けない。
- ネイティブ側の絞り込み、閾値、構造行、他フィルターとの積集合は維持する。
  Kotlinのバイトコードフック・レジスター・元命令は変更しない。

## 検証

最終Javaをビルドして、その実クラスをホストJVM上でAndroid/ネイティブの模擬部品と
組み合わせた検査を実施。実端末のAndroid描画やフレーム時間の検査ではない。

- 83項目: 191/226/242相当の1000レス、未選択時の全レスアクセス省略、元表示の保持、
  AA/自分/返信の各組合せの呼出し回数と結果。
- 8項目: 191相当の直接返信人気判定、件数表示ON/OFFとも本文変換が1レス1回、
  重複返信の除外、構造行の保持、本文変更と異なる一覧への再計算。
- 既存`VerifyPopularReplyRules`: 範囲・複数・重複・未来/自分宛・巨大範囲を含む7例成功。
- `git diff --check`成功。
- 最終`:patches:buildAndroid`成功（2分55秒、通常Lint/R8を含む）。

スクロール時の呼出し経路も確認したが、191の`legacyRow`はレス行を追加ボタンの
ラッパーに変換せず返す。今回確認した集計はリスト再構築時の処理であり、スクロール中の
継続的なカクつきの原因・解消を確定したとは扱わない。

ローカルの模擬検査ソース・クラスは`build/quick-filter-work-check/`、通常Lint/R8を含む
`:patches:buildAndroid`のログは`build/popular-filter-performance-build.log`。
新規APK生成・端末導入・公式Releaseは実施していない。
