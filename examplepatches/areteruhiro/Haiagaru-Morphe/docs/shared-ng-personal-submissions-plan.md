# 個人NGの収集と共有配信（設計案・2026-10-28）

ユーザー指定: 初回同意後、既存の個人NGもまとめて送信する。以後の追加・変更も候補として送信し、運営側でフィルターする。設計に基づく実装・ローカル検証を進行中。現在の状態は shared-ng-review-implementation.md を参照。GAS受付・直接配信は配備済み。アプリReleaseは未公開。

## 収集

初回は送信対象カテゴリ、対象件数、送る値を表示して同意を得る。利用者の最新指定により送信先URLは説明欄に表示しない。共有NGのONから送信ONを選んだ同意画面へ進み、保存同意後に有効化する。同意後の初回スナップショットから既存NGを分割送信し、その後はNGストアの正常保存後の差分をキューへ入れる。起動時の差分照合で取りこぼしを回収する。表示処理からNG一覧を全走査しない。

対象候補はNGID・NGName（ワッチョイやトリップを含む）・NGWord。同意画面で種類ごとに選択可能。送信するのは種類、値、板指定、正規表現/一致方法など適用に必要な設定、操作種別と候補ID。Cookie・認証トークン・閲覧履歴・書き込み履歴・ローカルパス・元レス全文は送信しない。高度NGのJavaScriptは個人NG同期とは別扱いで送信しない。

日付/板が不明な過去のNGIDを現在日付や現在板に勝手に割り当てない。元の登録日時と実際の投稿日を区別し、対象期間不明として審査待ちへ送る。全板NGは全板指定として保存し、端末の開いている板で補完しない。ワッチョイ全文/上4桁/下4桁/正規表現を混同しない。

重複判定はインストール単位のランダムID＋正規化した条件ID＋操作ID。再送しても二重加票しない。端末識別は本人確認ではなく、複数インストールによる票増しを完全には防げない。

## 運営側

GAS受付は受理した候補を専用Inboxへ保存。Pendingは既存実装で書込ジャーナルに使用しているため審査待ち用途へ転用しない。未審査候補をRulesやGitHubへ直接流さない。

状態は審査待ち/採用/保留/却下。種類・板・期間・対象範囲・重複・過度に広い表現を検査する。票数は参考値に留め、古いID/期間不明/短い一般語/広範な正規表現等は自動採用しない。氏名や連絡先などが含まれる候補は公開前に除外できる。

元の個人NG削除は、その利用者の報告取消として扱う。他利用者の報告や承認済み条件を一方的に削除しない。承認済みの配信停止は別の管理操作とし、次回配信へ反映する。

## 配信と端末適用

承認済みのデータだけGASからJSONとして直接配信し、GitHub配信は任意。F9判定スクリプト配信とは形式・保存領域を分け、共有NGデータからコードを実行しない。全体版番号/全件置換/配信停止/生成時刻を持たせ、途中失敗では旧スナップショットを維持する。

受信条件は個人NGストアへ登録せず別キャッシュに保管して表示判定へ合成する。受信・復元・条件統合が新規ユーザー登録として再送されないよう由来を区別する。共有受信ON/OFF、個人NG送信ON/OFF、対象種類、判定強度、個別解除は独立。送信OFF時は未送信キューも止める。送信済み候補の削除申請と端末内解除は別操作。

## 実装順

1. 未統合の共有NG9コミットを現在のNG境界と比較し、3版の非表示/解除/再起動復元を検証。
2. 初回同意と既存NGプレビュー、由来識別、キューの保存/重複/取消を実装。
3. GASのInbox・審査・採用/却下を追加し、専用テスト板で往復確認。
4. GAS直接配信、配信停止、個人NGとの独立を検証。

初期設計時は既存公開GASを変更しなかった。その後の利用者承認に従いv2受付/v3直接配信を既存サービスへ配備済み。実ユーザーNGのテスト送信は行わない。

2026-10-30 送信契機の変更（利用者指定）

- NGWord保存処理の既存 `PersonalNgSubmissions.changed()` フックを契機に送信する。NGID・NGName・NGワードの追加・変更・削除を対象に、1秒以内の連続した保存をまとめる。
- 60秒ごとの全件照合、定期確認ON/OFFと秒数入力を削除。旧設定キーは初回移行時に除去する。起動時の1回の回復照合と、同意設定保存時の照合は残す。
- 成功後の15分待機を廃止。新しいNG保存は次の1秒予約で送信できる。1要求20件の上限は維持し、残りがあれば1秒後に次のバッチを処理する。
- 通信失敗・受領確認なしではキューを保持し、15分後の単発再試行を予約する。新しい保存があっても失敗時の待機時間は守る。同意解除で予約を取り消す。
- GAS受付・審査・直接配信の仕様は変更しない。初回同意と送信対象カテゴリ、掲示板の親区分、取消・重複防止も維持する。

2026-10-30 強さ設定の廃止（利用者指定）

「フィルターの強さ（禁止レベル）」の最小〜最強を設定画面から削除し、SharedNgIndexの `minLevel` による適用制限も削除。旧 `filterLevel` は初期化時に除去し、バックアップなどから戻っても参照しない。承認済み条件は必要な報告数・掲示板・種類・個別除外で絞る。「必要な報告数（判定レベル）」も「必要な報告数」へ改称する。

既存GAS・旧アプリとのJSON互換性のため、配信形式の `minLevel` 項目は引き続き読めるが、新アプリの適用可否には使わない。GASの辞書審査、承認・保留・却下は維持し、保留条件を無条件に適用する変更ではない。

2026-10-30 NGワード送信条件（利用者指定）

共有NGのkeywordはNFKC正規化・空白除去後にUnicodeコードポイント5文字以上とし、英字のみ（全角/ラテン拡張文字を含む）を除外する。単独かな・英字は最小文字数で除外。個人NGプレビュー/収集/手動報告/既存送信待ちすべてに適用。ローカルのChMate NG登録、ID/ワッチョイ上下4桁等は変更しない。以前の対象外upsertは未送信キューから除き、送信済みsnapshotにはdeleteを生成して報告の取消を維持する。
GASは旧アプリからの不適格keywordも受付ACK後にineligible_keywordとして却下し、同一バッチの正常条件を妨げない。既存Inboxにも再審査で適用、manual overrideでapprovedにしても再度却下。旧keywordのdeleteは受け付ける。配信キャッシュキーv6で旧判定cacheを除外。Android collector43/イベント14/移行8/同意6/報告数UI9、GAS moderation61/Inbox141/旧service41項目成功。通常LintVital/R8ビルドはbuild/shared-ng-keyword-policy-build.log。
