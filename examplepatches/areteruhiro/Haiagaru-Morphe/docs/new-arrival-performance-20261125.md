# 新着レス番号計算の軽量化

**この機能は撤去対象です。** 投稿後の更新で0件となる利用者報告を受け、2026-11-25に削除を指示されました。以下は1.54.0-dev.4までの比較資料であり、現行機能の説明ではありません。[撤去の経緯・保存したソース](research/new-arrival-numbers/README.md)を参照してください。

後続の報告で、手動更新でも件数差が0になる一方、HOMEへ戻ると未読が+1になるケースが確認されました。全レス番号セットのオプションは復活させず、通常差分が0のときだけ番号範囲を確認する小さなフォールバックを追加しています。これは全件を毎回スキャンして新着を再計算する旧オプションとは別の補正です。

## 対象と変更

191／226／242に共通する `NewArrivalNumbers`。「新しく取得したレス番号で新着件数を数える」は初期ONのまま、OFFでは従来の件数差分を使用する。新しい設定は増やさない。

変更前は、更新前の全レス番号をHashSetに格納して最大番号を探し、更新後も全レス番号をHashSetに格納した後、さらに新着番号の集合を作っていた。変更後は、更新前に最大番号だけを保持し、更新後はそれを超える番号だけを集合へ追加する。既存レス番号のボックス化・集合への格納と、計算時の集合の再作成を省く。

同じ型のレスでは番号フィールドの解決を使い回し、intフィールドは `Field.getInt` で読み取る。スナップショットの管理ロック中に全レスを走査しない。元の一覧や本文・既読位置には書き込まず、数値だけを保持する。リストの並び順は仮定せず、更新前後にそれぞれ1回走査するため、計算量は引き続きO(n)。解析失敗時の従来計算へのフォールバックも維持する。

削除・欠番・重複番号による過少／過大計数を防ぐ仕様と、新着番号に対するNG除外処理は変更しない。1.54.0-dev.2で修正したThreadLocalによる呼び出し元の受け渡しも維持し、nativeフック・レジスタ割当は変更していない。
