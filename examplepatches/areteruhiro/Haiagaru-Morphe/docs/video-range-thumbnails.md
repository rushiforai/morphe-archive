# 大きなX動画のサムネイル

実機 `730eae72` の表示と保存済み設定を読み取り、`video.twimg.com` のMP4が再生マークだけになることを確認。フレーム取得はON、上限24MiB、タイムアウト20秒、分割プレビューOFF。画面内の2件はHTTPヘッダー上39,369,971 / 189,947,127バイトで、既存の全体ダウンロード方式では両方とも上限で拒否される。

上限超過のX直リンクのみ、Android 6以降の `MediaDataSource` による範囲取得へ切り替える。先頭・末尾のMP4メタデータとフレームに必要な位置を256KiB単位で取得し、キャッシュは4ブロックまで。転送の累計は設定容量以下、通信には期限を設定する。リダイレクト・Range無視・不正なContent-Range・圧縮された部分応答は拒否する。既存のデコーダ専用プロセスを使い、失敗時はプレースホルダーを維持する。一般の動画や小さなファイルは既存経路を使用する。

ホストの合成100MiBデータ試験は8,206項目成功。先頭・末尾・ブロック境界・キャッシュ・EOF・転送上限・期限・不正/欠損応答を検証。Androidの合成AVC動画試験では、末尾にmoovを置いた48MiB超の仮想MP4を266,158バイト/2リクエストで処理し、フレーム生成・専用プロセスからのJPEG生成を確認した。報告動画の実機成功は未確認。

実機の使用中カスタムパッケージは更新せず、明示された検証用191パッケージへ導入する。ビルド・Android実行・導入の結果は別途台帳へ記録する。

失敗時は固定の日本語ラベル（通信、DNS、時間切れ、容量、HTTP、部分取得、解析、解析中断、メモリ、保存）をPNGで表示する。生のURL・例外メッセージ・端末パスは表示しない。失敗用画像は成功キャッシュに含めず、自動試行の待機を維持する。取得済みの正常なポスターがある場合はそれを優先する。

失敗サムネイルに「再取得」「再生」のAndroidボタンを追加する。再取得は実行中の同一要求を重複させず、完了済み失敗の待機を明示操作で解除する。解析中断フラグの解除は直列ワーカー内で行う。再生は原動画URLを標準ビューア入口へ渡し、専用動画ビューアを使う/使わない設定を引き継ぐ。サムネイル成功・別URLへの再利用時は操作を外す。画像URLバインドの追加フックは各版の固定クラス1箇所。

2026-11-06追加修正: 実機の本体クラッシュは、全レス連続表示への引数拡張時にクリック元Viewをnullへ変更していたことが原因（ImageListActivityでgetWidthのNPE）。3版ともViewを保持し、元Viewがない起動では拡張しない。191のサムネイルはFrameLayoutではなくView継承のため、ボタンを画面ルートに重ねて位置を追従させる方式へ変更。取り外し/別URLへの再利用時に解除する。

実機の解析用プロセスの終了理由はLOW_MEMORY。BIND_IMPORTANTで使用中の重要度を保ち、中断後は1分の待機後または手動再取得で復帰する。無限の即時自動再起動はしない。履歴を取得できるAndroidでは低メモリ/解析異常を表示理由へ反映する。途中終了で長さ0のPNGが残った場合も再生成し、以後は一時ファイルの書き込み完了後に置き換える。
