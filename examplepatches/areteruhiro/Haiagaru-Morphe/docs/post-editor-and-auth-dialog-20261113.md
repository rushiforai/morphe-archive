# 書き込み画面・外部板認証・設定見出しの改善

## 報告と対応範囲

ChMate 0.8.10.242 dev / Haiagaru 1.30.2でも、鉛筆から書き込みダイアログが
出ない報告が継続。Pixel 11に加え、Pixel 7 Pro / Android 17でOS更新直後に
発生したという情報がある。利用者は完全再現より、想定原因への対策と
プレリリースを優先するよう指示した。Pixel実機の原因確定・改善確認とは扱わない。

対象の浮動書き込み画面はnative RelativeLayoutとEditTextで構成される。
Composeを原因と断定せず、既存の242限定onLayout末尾フックを補強した。

- native IME観測用PopupWindowの高さが0になると、rootの下余白が全高と同じに
  なり、従来の補正はreturnして入力欄が0高になる。rootの実可視フレームを
  ローカル座標へ変換し、異常な余白を補正する。フレーム自体が未確定ならroot高へ戻す。
- 下余白が負数の場合も補正する。正常なキーボード用余白は維持する。
- 子の測定・配置サイズが0なら再計測。幅0を1pxに固定せず、元のLayoutParamsを使う。
- 異常な配置を修復する場合はLayoutTransitionを解除し、古い画面外座標へ戻る
  アニメーションを止める。本文・ボタン・リスナーは既存オブジェクトを保持する。

## 外部板認証

既存のException/AlertDialog/WebView監視では、ResEditFragment内のTextViewへ
直接表示する書き込みエラーを検出できなかった。各対応版の
String/booleanを受けるnativeエラー表示メソッドの入口へowner/messageの観測を追加。
投稿内容や成功応答は横取りしない。

「メニューに『外部板の認証ページ』を表示」が有効な場合に自動表示し、無効なら
自動表示もしない。同じダイアログ内にコピーと「認証サイトを開く」を配置する。
URLは既存の保存値・同一originの検出値・エッヂ既定値から補完し、その場で修正できる。
コピー後も開いたまま、URL不正時もダイアログ内で修正可能。別の設定ダイアログを
経由せず認証画面へ進む。CAPTCHA/計算ページも自動起動せず操作を待つ。
重複観測でダイアログを積み重ねず、移動時はdismissForNavigationで先に窓を外す。
自動認証・自動投稿・投稿の自動再送信は追加していない。

## 設定の親見出し

設定トップの親カテゴリ、内部のセクション見出し、折りたたみの親名を青色へ統一。
背景の明度で濃青/淡青を切り替える。標準的な白背景でコントラスト比5.76、
#121212背景で10.98。設定項目の本文と説明の色は既存どおり。

## 検証記録

- 旧候補の実native root / Android View測定に、下余白=全高の条件を与えると
  本文が650x0となり失敗。修正候補では通常・正常なIME余白・0/過大/負数の
  計測値・0サイズからの復旧・下書き保持の12項目成功（XIG05 Android 15の隔離package）。
- Android 16隔離エミュレータでは、実書き込み画面の縦・横・TabletHomeのnative
  コマンド・異常余白/0サイズの15項目、nativeサムネイル121項目成功。
  これは認証追加前の同じeditor修正に対する結果。
- API37エミュレータはアプリ導入前からsurfaceflingerのDMA assertionで再起動し、
  Android 17上の検証成功として扱わない。API36も初回はSystemUI ANRにより窓の寸法0、
  再試験では縦成功後の横再生成待ちで失敗し、次の試験で15項目成功。
- 通常Lint/R8ビルドは最初にホストの仮想メモリ不足で失敗。エミュレータを止め、
  worker数とJVM並列数を制限して再実行し、auth-final-build2.logで2分41秒成功。
- 既存の認証URL・コード抽出ポリシー70項目成功。
- 既存gateway試験器は旧「初期OFF」のassertionが現行のサイト別初期ONへの移行と
  食い違って停止。現行初期値を確認後、明示OFFにして既存OFF経路を試す形へ修正。

最終MPP・各APK・署名・導入日時はandroid-installations.md、実行ログは
build/editor-api37/に保存する。公開投稿・認証の実送信は行わない。
