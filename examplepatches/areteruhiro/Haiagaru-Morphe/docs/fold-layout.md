# 折り畳み端末のスマホ／タブレット自動切替（開発版）

Haiagaru設定 → **スレを読む → 画面と操作 → 折りたたみ状態でスマホ／タブレット表示を自動切替**をオンにします。初期値はオフです。設定検索からも変更できます。既存の設定キーは維持しています。

- Jetpack WindowManager 1.3.0の`WindowInfoTracker`から、そのActivityに通知される`FoldingFeature`を取得します。DPI・画面幅600dp・機種名リストでは判定しません。
- 折り目が通知された内側画面ではタブレット表示を選びます。その端末で折り目を確認した後、全画面で折り目が通知されなくなった場合は、閉じた／カバー画面としてスマホ表示を選びます。
- 普通のスマホ・タブレット、メーカーのWindow Extensionsが未対応／取得エラーの場合、閉じた状態での初回起動は判定できないため、現在の本体手動設定を維持します。閉じた状態からの検出を始めるには、一度内側画面でアプリを開いてください。検出済みの記録は端末のメーカー・機種・OSビルドに結び付け、別端末へ復元した設定だけでは判定しません。
- 分割画面では折り目がアプリ領域の外へ出る場合があるため、折り目情報がないときに閉じたとは判定しません。横向き・表示サイズ変更だけを折りたたみ操作として扱いません。
- OEMから正しい情報が届くことが前提です。どの端末でも物理状態を100%保証するAPIではありません。通知を350ms待ってまとめ、同じ表示区分なら再起動しません。
- 投稿、認証、設定、画像・動画画面では、閲覧画面へ戻るまで切替を保留します。閲覧画面上のダイアログや入力欄にも配慮し、フォーカスが戻ってから切り替えます。
- 本体の`enableTabletHome2`を変更して新しいHOME画面を開きます。単なる`recreate()`では本体が古い画面構成を復元するため、既存の閲覧画面を閉じて切り替えます。開いているタブ群は本体の保存処理を使います。
- 表示中のスレはURLと論理レス番号・表示オフセットを自動で捕捉し、切替後に同じスレを開いて位置を自動復元します。読み位置の保存・復元操作や有効化は不要で、専用の設定項目も設けません。単独の板一覧は取得できた板URLを引き継ぎます。検索語・フィルタなど、各画面の一時状態をすべて移行するものではありません。
- オフにすると、それ以降は自動変更せず本体の手動設定を使います。オンにする前のモードへ戻す操作ではありません。
