# ワッチョイ長押しメニューのNG優先順

Haiagaru設定「ワッチョイ長押しメニューをNG登録優先の順番にする」を追加。
初期値OFFで従来の順番・ラベルを維持。保存後、次に開くメニューから適用。

ON時の順番:

1. NGName に追加
2. ﾜｯﾁｮｲ下4桁でNGName登録
3. コピー
4. 取得済みのスレから検索
5. 必死チェッカーもどき(ﾜｯﾁｮｲ)

元の条件で表示されない項目は新たに生成しない。他の追加項目がある場合は
上記の後ろに元の相対順で残す。元のMenuItem/行オブジェクトをそのまま並べ替え、
callback、アイコン、enabled状態、下4桁項目の長押し動作は保持する。

- 191: 名前/SLIPメニューの構築完了後、カスタムMenu内のリストを安定ソート。
- 226/241/242: 有効なワッチョイでマークしたbuilderだけ、nativeの各項目追加後に安定ソート。
  これによりNG項目の後から追加されるコピー・取得済み検索も最終的に正しく並ぶ。
  未マークのbuilder（通常の他メニュー）は変更しない。
- builderフィールドは226:c / 241:b / 242:a。
  行のタイトルフィールドは226:h / 241:g / 242:j。JADXの表示上の別名ではなく元DEXを照合。

`VerifyWacchoiMenuOrder`で5項目の順番、操作オブジェクトの同一性、追加項目の保持、
複数回追加時の安定性、従来ラベルの分類、NGID/NG解除の誤分類防止を検証。

226/241の適用時、別の未公開変更（下4桁行のCompose長押し対応）の検出条件が
新しい6引数bridge + 同一クラスのcombinedClickableを必須として失敗することを検出。
226のsimple clickableは5引数、241では対応するcombined bridgeが同一クラスにない。
この追加ジェスチャーは互換bridgeがない場合にスキップし、既存View行フックは維持する。
通常のクリック・今回の並べ替えまで適用不能にしない。複数候補の曖昧判定は引き続き停止する。

検証結果: MPPビルド、191/226/241/242の適用が成功。
`VerifyWacchoiMenuOrderHooks`で191の構築完了フック1箇所、226/241/242の追加後フック
各2箇所を生成APKから確認。エミュレータは接続が失われたため今回のUI動作は未確認。
`frida-wacchoi-menu-order.js`は隔離パッケージ内の実191 MenuでON/OFFと操作同一性を
確認するための検証用で、今回は未実行。リリース・メタデータの更新はしていない。

1.8.2の最終確認では226の5引数bridge、241の最適化された7引数combinedClickableにも対応。
191/226/241/242の公開用MPP適用と並び順フック検査が成功し、226/241/242の実際の
スレ内メニューの長押しからNGName編集画面への遷移も確認した。dismiss用ラッパーを
認識する共通修正により、元のクリック処理を保持して長押しを追加している。

## 上4桁・下4桁のコピー

ﾜｯﾁｮｲ部分の長押しに「ﾜｯﾁｮｲ上4桁をコピー」「ﾜｯﾁｮｲ下4桁をコピー」を追加。たとえば `Ab12-xY+/` はそれぞれ `Ab12`、`xY+/` をコピーします。ハイフンや括弧は含めず、大文字・小文字・記号は保持します。本文の引用から別の投稿者のﾜｯﾁｮｲを推測することはありません。表示・検索カテゴリのワッチョイ長押し設定で、それぞれの表示を切り替えられます。NG優先順をONにしている場合は、既存のコピーと同じグループへ配置します。
