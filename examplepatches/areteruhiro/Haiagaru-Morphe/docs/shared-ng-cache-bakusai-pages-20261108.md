## 共有NGの容量削減

利用者確認：削除対象はオンライン共有NGを使用してダウンロードした端末内データ。

オンライン共有NGの設定へ「共有NGのダウンロード済みデータを削除」を追加。確認画面で保存容量を表示し、削除と同時に受信をオフにする。再度オンにするまで自動取得しない。個人NG・除外・端末内編集・報告キュー・報告数等は保持する。

削除対象は専用AtomicFile `shared-ng-cache-v2.json.gz` とその `.bak` / `.new` のみ。IO executor上で処理し、SOURCE_LOCK内で世代を進めて読込・同期の遅れた書戻しを拒否する。メモリの受信条件とMatchPlanを解放し、cursorを0へ戻す。再び有効にした際は全件取得する。

## 爆サイのページ取得

報告URL：`https://bakusai.com/thr_res/acode=15/ctgid=111/bid=4437/tid=8520877/`（551レス）。

- unpaged URLは、取得時にHTTP 200のエラーページ `thr_res:759` を返した。明示的な `p=1/tp=1/` は実本文と502〜551を返した。
- 続きのページは `#threadBody` を保持しながら本文を省略し、`#thr_pager` の「前スレ」リンクだけを入れていた。それをOP本文の変更と誤認して全体を取得失敗にしていた。
- 共通parserでナビゲーションをOPから分離し、ナビゲーションしかない枠をOPとして扱わない。明示的なページ指定がない初回エラー時は最初のページを1回試し、以後は既存のページリンク・選択肢に従う。途中ページから始まっても実レス番号と総数から最初のページの不足を判定する。特定tid/板の分岐は追加しない。
- 同じページの繰返し・本文の実変更・番号の欠落チェックと上限は維持する。取得できない内容を生成しない。

今回の実取得結果はOPと500レス。古い51レス（ページ11/12）は元サイトが `thr_res:778` / `thr_res:759` を返したため未取得。ネイティブDAT上では元の番号を保ち、未取得の各位置に理由を示す。全551レスの取得成功とは扱わない。

PC向けUAの調査では指定したページと同じ内容が繰り返し返った。製品に新たなUA切替は追加せず、従来のreaderのまま明示的なページURLを利用する。

Android live probeの初回はUnknownHostExceptionで失敗した。試験APKにINTERNETを宣言し、前面HomeActivityの待機を追加して再実行したところ、製品のHttpTransportで実GET12件・552行・51未取得を確認。これはホスト側と同じ結果。ログ `build/bakusai-8520877/live-with-permission.log`。投稿の送信・実ユーザーの共有NG/登録板設定の変更なし。
