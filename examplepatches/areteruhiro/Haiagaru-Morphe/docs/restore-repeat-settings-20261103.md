# 191で異なるバックアップを順番に復元した後の遅延調査

## 報告と確認

利用者提供のHaiagaru-sync ZIP2件。対象191、復元完了後の操作全体、特にスレを開く処理が遅い。完全再起動後も継続。異なる2つのZIPを順番に復元、最後にどちらを使ったかは不明。原本は変更せずCRC全件正常を確認。

Aは設定46件・履歴115件・DAT115/索引92。Bは設定66件・履歴160件・DAT無し。Aはタブ/カード/落ちスレ除外/直接本文選択の設定が未保存、BではON。認証・Cookie・端末固有情報を除いたコピーのみ、ネットワークOFFのemulator-5580/専用restoreperf191で使用。元ZIPの認証情報・投稿本文はログやGitへ出さない。

修正前のA→A→B→B→Aで、最後のAでもBの追加機能がONのまま残り、再起動してもUI設定66件のままだった。restoreSettingsが値を上書きするだけで、Aにないキーを残していたため。一方、履歴は160件で止まり、同一ZIPの再復元で件数増殖はない。HOME起動は約2.0〜2.6秒で、大幅な操作遅延そのものは未再現。

## 修正

設定カテゴリの通常復元で、Haiagaru UI設定ファイルに限りバックアップにない安全な設定キーを同じEditorで除去し初期値へ戻す。端末の初回案内表示済みフラグと保存対象外の認証キーは維持。ChMate標準設定の欠落キー、NGルール・履歴・DAT・認証ストア、自動バックアップの保存先/ONOFF/所有記録へこの除去は適用しない。双方向同期の不足分追加も従来どおり既存優先。

## 検証

通常Lint/R8 build/restore-ui-snapshot-final-build.log成功2m55s。最初のビルドはPCのnativeメモリ不足でdaemon終了、検証AVDをデータ保持で停止し再実行成功。MPP build/restore-ui-snapshot.mpp SHA256 478e0d383753745aff2593c4f53043c822348c1a427e4753e7af7aebc14ef2cb。191用APKを同署名の専用packageへinstall-r、実APK hash一致、新規fatal無し。nativeフック・register・命令への変更無し。共通Java設定処理であり、今回の報告対象191を検証、226/242の重複端末試験は未実施。

合成設定48項目成功: 3回のB→A往復で追加4機能を初期値へ、保存済み設定適用、再復元の同一結果、初回フラグ/除外キー/標準設定/ローカル自動バックアップ保持、不足分同期の既存保持。scripts/restore-ui-settings-runtime.js。

提供ZIP全体の安全なコピーをA→A→B→B→Aで復元・各回完全再起動。AのUI設定は47件（46件+端末の初回案内）、Bは66件へ戻り、Aの追加4機能OFFを全回確認。DAT関連207件・履歴160件で増殖無し。full restore各1.69〜3.80秒、HOME起動各2.19〜2.73秒。build/restore-full-fixed191-results.json。
