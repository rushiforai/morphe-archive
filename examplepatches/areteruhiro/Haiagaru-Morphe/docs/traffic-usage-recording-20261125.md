# アプリ通信量記録の負荷軽減

## 変更

- 「アプリの通信量を記録する」は初期OFF。OFFでは定期計測を開始せず、画面再開時の計測も実行しない。
- ONの場合はAndroidのUID通信カウンターを約1分ごとに記録する。画面再開による計測も60秒に1回までに制限する。
- 機能別の受信量は、ファイルやレスの読み込みごとにJSON全体を読み直して保存する方式から、日付・機能別にメモリ上で合算し、2秒後にまとめて保存する方式へ変更する。再試行が必要な保存エラーでは集計値を保留し、5秒後に再試行する。
- 日別履歴は従来どおり最大93日。機能別の一時集計は通信本文・URLを含まず、バイト数だけを保持する。

## Frida確認

Android 16 AVDの隔離 reporter 191／226／242に適用し、合成した1,000回の通信量記録呼び出しを検査した。各版で1,000バイトが保留中に合算され、2.6秒後に集計値が保存され、保留分が空になることを確認した。記録関数呼び出しの所要時間は191が183ms、226が103ms、242が100msだった。初期OFF時に記録が無効で、定期サンプラーも起動しないことも各版で確認した。画面描画や実ネットワークを含むベンチマークではない。

同じ候補APKで新着0件補正7ケース／版と空のエッヂ下書き14ケース／版もFridaで確認した。新着ケースには非表示NG対象を除外する確認を含む。公開投稿や既存スレ履歴の変更はない。試験後は通信量設定と既存機能別集計を復元した。

候補APK、MPP、署名、各版のハッシュおよび実行ログは `build/new-arrival-zero-fallback-20261125/final-candidate/` に保存する。
