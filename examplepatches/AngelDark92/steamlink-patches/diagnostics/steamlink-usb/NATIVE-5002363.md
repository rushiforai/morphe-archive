Java corroboration, all under `smali/com/valvesoftware/steamlink/`:

- `SteamLink.smali:1650`: `onResume` calls `ShellUsbTetherInfo.Start()`; this registers a callback, not an active network request.
- `SteamLink.smali:2168`: `trySetupUsbNetwork()` calls `enableIPv4()` then `Request()`.
- `SteamLink$ShellUsbTetherInfo.smali:59`: on SDK >31, `Request()` asks for transport `8` (USB), removing capabilities `12` and `14`; no network specifier.
- `SteamLink$ShellUsbTetherInfo.smali:238`: `enableIPv4()` sends `horizonos.net.ethernet.SET_LOCAL_IP` to package `android`, requesting `10.86.13.37/29`. The subsequent success log acknowledges only broadcast dispatch, not OS configuration success.
- `SteamLink$ShellWiredInfo.smali:56`: a separate generic Ethernet transport `3` callback exists. Its native `BWiredNetworkConnected()` reader has no Oculus manufacturer gate. Android tethering downstream interfaces need not appear as such a ConnectivityManager network.

## Renderer accepts `usb0` IPv4

`SVLDataLinkUber::ScanForLinkChanges()` at `0x173788` enumerates interfaces with `getifaddrs()` (`0x1737c0`), stores names, IPv4/IPv6 addresses and prefixes, then calls `HandleInterfaceListChange()` (`0x173f14`). It does not depend on the shell USB support flag.

`SVLDataLinkUber::HandleInterfaceListChange()` at `0x1727a0` has a special branch for the `usb0` name prefix. Follow the complete branch before interpreting its family test:

```text
VA        original bytes  instruction
0x172a54  d3000034        cbz w19, 0x172a6c   ; generic path when name is not usb0
0x172a58  1f290071        cmp w8, 10         ; AF_INET6
0x172a5c  28008052        mov w8, 1
0x172a60  e9179f1a        cset w9, eq
0x172a64  49030039        strb w9, [x26]
0x172a68  7cffff17        b 0x172858
0x172858  48030039        strb w8, [x26]     ; overwrites previous store with 1
```

**The final enabled byte is 1 for both IPv4 and IPv6.** The earlier family-dependent store is overwritten. An initial interpretation of this block as an IPv4 rejection was rejected after tracing the merge target. Do not patch it as an IPv4 exclusion.

Generic filtering covers loopback/dummy/foxnet names, loopback and certain link-local addresses, and duplicate/subnet cases; `usb0` takes the early accepted path. `ScanForLinkChanges` also categorizes certain Valve-specific address ranges and interface prefixes, but an ordinary `usb0` IPv4 address does not require one of those ranges to survive this acceptance branch.

The accepted list reaches `SVLDataLinkTransferUDP::Init()` at `0x174fe4` through `AddAndInitLinkTransfer()` (`HandleInterfaceListChange` call at `0x1731a4`). `Init` retains the interface name and address. `GuessBestCorrespondenceAddress()` at `0x17251c` compares address prefixes. These are ordinary network-interface paths, not USB bulk/accessory streaming.

The legacy `SVLDataLinkUDP::Reconnect()` also creates a UDP socket, accepts a remote IPv4 address, optionally uses `SO_BINDTODEVICE` (`setsockopt` at `0x1779e4`), and connects (`0x177a60`). This legacy path's presence does not prove that a particular modern session selected it; modern 2.0.23 captures use the transfer/uber path, as recorded in [the host comparison](../steamlink-hitches/XR-HOST-COMPARISON-2026-09-15.md).

## Adaptation decision

An externally configured working RNDIS IP link can bypass the need for the Quest-specific automatic setup path. Static code does not justify a native renderer byte change for `usb0` IPv4. First establish the Windows network driver, IP addresses, app-usable Android routes, PC reachability, and actual streaming socket/packet path. Shell/root ping alone does not establish the app UID's routing behavior.

A future UI adaptation could detect configured USB interfaces directly and report their state, while retaining stock Quest behavior. That would be a setup/status change, not proof of a transport repair. A reported HMD identity override does not change the OS properties used by the native gates, and removing those gates cannot provide missing Samsung OS networking facilities.

## Read-only reproduction

Run from the repository root with the existing Python launcher and retained audit libraries. This prints hashes, segment mappings and the decisive disassembly to stdout; it creates no outputs and touches no device.

```powershell
@'
import hashlib, io, sys
from pathlib import Path
sys.path.insert(0, 'build/oled-native-audit/python')
from elftools.elf.elffile import ELFFile
from capstone import Cs, CS_ARCH_ARM64, CS_MODE_ARM
root = Path('decoded-apk-android-steamlinkvr-release-base-2.0.23-5002363/lib/arm64-v8a')
regions = {
    'libshell_arm64-v8a.so': [(0x1025a00, 828), (0x1032694, 404), (0x1032828, 356)],
    'libvrlink_scene.so': [(0x172a4c, 36), (0x172858, 4), (0x173788, 64)],
}
for name, ranges in regions.items():
    data = (root / name).read_bytes()
    elf = ELFFile(io.BytesIO(data))
    loads = [s for s in elf.iter_segments() if s['p_type'] == 'PT_LOAD']
    print(name, len(data), hashlib.sha256(data).hexdigest())
    for s in loads:
        print('LOAD', hex(s['p_offset']), hex(s['p_vaddr']), hex(s['p_filesz']))
    for address, size in ranges:
        seg = next(s for s in loads if s['p_vaddr'] <= address < s['p_vaddr'] + s['p_filesz'])
        offset = address - seg['p_vaddr'] + seg['p_offset']
        for ins in Cs(CS_ARCH_ARM64, CS_MODE_ARM).disasm(data[offset:offset+size], address):
            print(hex(ins.address), ins.bytes.hex(), ins.mnemonic, ins.op_str)
'@ | py -
```

To reproduce call-site enumeration, resolve target symbols from `.dynsym` and `.rela.plt` (AArch64 PLT entries start at `.plt` VA +32 with a 16-byte stride), then scan executable `PT_LOAD` words for `B`/`BL`: `(word & 0x7c000000) == 0x14000000`; target is current VA plus signed 26-bit immediate multiplied by 4. Attribute sites to containing exported function ranges. This audit does not claim exhaustive indirect-call analysis.
