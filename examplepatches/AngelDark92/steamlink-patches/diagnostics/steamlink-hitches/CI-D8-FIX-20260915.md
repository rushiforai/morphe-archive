# CI Android packaging: duplicate apksig classes

Date: 2026-09-15. Failed release attempt: `1.18.0-dev.1`.

## Cause

The supplied log confirms that production compilation, test compilation, tests,
JAR assembly, catalog generation and reference rendering succeeded. The failure
occurred later in `publish -> :patches:buildAndroid`, after release preparation
had created the tag.

The earlier compile-only fix pinned `apksig:8.7.3`. Morphe Patcher
`1.9.0-dev.1` supplies `apksig:9.1.1` as an implementation/runtime dependency.
The compile and runtime configurations resolve independently. Morphe plugin
`1.3.3` combines their files for D8, deduplicating file paths rather than module
versions. Both JARs therefore reached D8, producing the reported duplicate
`com.android.apksig.ApkVerifier$Builder`. This was a dependency conflict introduced
by the earlier version choice; it did not require restoring deleted files.

## Fix

- Pin compile-only `apksig` to `9.1.1`, matching the pinned Morphe runtime.
- Resolve the main compile classpath consistently with the runtime classpath,
  preventing shared modules from supplying 2 versions to the D8 file union.
  Preserve runtime-provided dependencies and their exclusion from the MPP.
- Make `generatePatchesList` depend on both `build` and `buildAndroid`. Existing
  semantic-release preparation now requires tests and DEX packaging before its
  release commit/tag. The native APK audit remains in the archive as its caller
  requires; no audit or production patch source was removed.
- Include tests alongside Android packaging in the nonrelease workflow fallback.

## Verification

- A Gradle 9.6.1 regression harness resolved the original union to both
  `apksig-8.7.3.jar` and `apksig-9.1.1.jar`. The fixed configuration resolves only
  `9.1.1`. Consistency alone also resolves an old `8.7.3` request to `9.1.1`.
- Rebuilt current source and ran all **112 tests: 112 passed**.
- Exercised **D8/R8 9.1.31**, the version from the plugin's AGP 9.1.0 dependency,
  using the same program-resource provider, RELEASE mode, minimum API 26 and
  classpath-union setup against the freshly built patch archive. The remaining
  local classpath used cached Morphe tooling with its bundled apksig removed;
  Android 33's `android.jar` was the desugaring library.
- Original classpath reproduced the exact `Classpath type already present`
  error. Both fixed and consistency-only classpaths succeeded, producing a
  **398,908-byte `classes.dex`**.
- Merged DEX into the isolated MPP; all **153 pre-existing archive entries**
  remained byte-identical. No duplicate ZIP entries; final archive has 154 entries.
- Generated all 4 catalogs from the DEX-containing archive. Their channel content
  matches the tracked catalogs: stable 26 patches, experimental/all 27. Production
  reference-document rendering passed.
- `git diff --check` and independent cavecrew review passed.

The exact local Gradle release command still stops at resolution of the existing
`app.morphe.patches:1.3.3` plugin. The controlled Gradle graph and actual D8 checks
prove this failure/fix, but do not claim a successful authenticated full Gradle
release or GitHub publication. No APK/device/SteamVR action was performed.
