# CI test compilation: JUnit framework mismatch

Date: 2026-09-15. Reported release attempt: `1.18.0-dev.1`.

## Cause and cleanup audit

`DecoderInputBufferingPatchTest.kt` used 2 `org.junit.jupiter.api.Assumptions`
calls, while `patches/build.gradle.kts` declares `kotlin("test-junit")` (JUnit 4).
Both calls and the JUnit 4 dependency already existed in commit `4449a8f`, before
cleanup commit `f420521`. The cleanup changed neither that test nor its dependency.
No JUnit library or test source was among the removed files.

The cleanup audit rechecked all 36 deleted IDE source/resource copies against
their canonical counterparts; all counterparts remain. The additional IDE DEX
copy is generated by Gradle. No restoration is indicated for this compiler error.

The previous apksig fix validated production compilation only and missed this
test-source failure. The cached runner also used a JUnit 5 Kotlin adapter and a
platform console JAR on the compiler classpath, masking the mismatch.

## Fix

- Use JUnit 4 `Assume.assumeTrue(message, condition)` for both fixture guards.
  Missing fixtures still skip the integration audit; no test is disabled or removed.
- Align the cached runner with JUnit 4 and JVM 11. Keep the platform console off
  the compiler classpath and use its Vintage engine only when running tests.
- Document the required separate JUnit 4, Hamcrest and Kotlin adapter JARs.

API reference: [JUnit 4 assumptions](https://junit.org/junit4/javadoc/4.13.2/org/junit/Assume.html).
