# Contributing

Bug fixes, feature proposals and compatibility reports are welcome. Check existing issues before starting a large change, and open pull requests against `dev`.

## Setup

Install Java 21, Node.js 24, PowerShell 7, Android SDK Platform 36 and Build-Tools 36.0.0. Configure GitHub Packages read access with `gpr.user` and `gpr.key` in your user-level Gradle properties.

From the repository root:

```powershell
./scripts/bootstrap-tools.ps1
npm.cmd ci
./scripts/build.ps1
```

Builds produce `patches/build/libs/patches-<version>.mpp`. Use the tool versions pinned in `config/toolchain.json` and `gradle/libs.versions.toml`.

## Making changes

Patch definitions and bytecode transformations live in `patches/`; Android runtime code lives in `extensions/twitch/`. Keep changes within the affected feature. Use Kotlin for patches and Java for runtime code.

Match hooks using strings, types and control flow from an original APK. Require unique matches, derive obfuscated members from those matches, and report a clear error when a contract changes. Preserve register types, labels, exception handlers and Twitch's scheduling.

All modifying patches depend on the shared settings integration. UI options belong in the [UI settings registry](docs/UI_SETTINGS.md), with customization disabled by default. Keep preference keys stable. Check the [screen inventory](docs/SCREENS.md) when a change affects multiple player layouts.

Comments should explain constraints that are not clear from the code. Retain upstream licenses and attribution. Store original APKs, decompilations, keys and build artifacts under `.local/`.

## Verification

```powershell
./scripts/check-source.ps1
./scripts/build.ps1
./scripts/test.ps1
npm.cmd test
```

Add a focused parser, lifecycle or synthetic DEX test for changed behavior. For bytecode changes, rebuild the full APK and run original-aware SDK verification with `scripts/patch.ps1`. Record the Twitch version, selected patches, tool versions and device results in `config/compatibility.json`.

Device checks should cover both directions of changed settings and the affected native and React Native layouts. The following probes cover reusable controls, replay touch routing and fullscreen settings windows:

```powershell
./scripts/test-reload-ui.ps1
./scripts/test-chat-ui.ps1
```

Before a release, patch the original APK in Morphe Manager and test its output. See [the upgrade workflow](docs/UPGRADES.md) for APK intake, signing and device recovery.

## Pull requests

Describe the problem, resulting behavior and verification performed. Include reproduction steps for bugs and identify any untested layouts or events. Use semantic commit subjects such as `fix: refresh reused player controls` or `feat: add a chat preference`.

Keep generated assets consistent with their source. Release versions and changelogs are generated by the existing workflow; [maintenance](docs/MAINTENANCE.md) describes publication.

AI-assisted contributions are welcome and receive the same review and testing requirements as other changes. Contributors are responsible for correctness, licensing and validation.
