## 1. ERA MAP — the two eras and why the project changed shape

### Era A — "Morphe patch bundle" (2026-11-04 → 2026-11-12)
- **Vehicle:** a Morphe patch bundle (`patches-<version>.mpp`, Ed25519-signed) applied to Opera **by a Morphe patcher** (Morphe Desktop CLI on host; Morphe Manager on device). Versions v1.0.0 → v1.3.0 (CHANGELOG.md). Target apps: Opera stable 103.3.5234.91185, Opera Beta 104.0.5262.91143, Opera GX 3.3.18 (WebView app, no abp.manifest) (evidence/ANALYSIS.md).
- **Content arc:** v1.0.0 four patches (ad modules, sponsored Speed Dial, Acceptable-Ads whitelist, CREATOR-proxy signature spoof) → v1.1.x hide-broken-installation-dialog + memory-optimized string patches → v1.2.0 "Ignore browser boot failures" (welcome-splash hang fix) → v1.2.1 analytics-endpoint rewrite + real-framework extension compile + AuditExtDex → v1.2.2 CREATOR final-field fix → v1.2.3 two-layer call-site-redirect spoof (158 sites on Beta) → v1.2.4 Startup diagnostics self-reporting dex → v1.2.5 modded-APK cross-analysis: permission-hygiene patch + endpoint net 81→93 → v1.2.6 durable signing key + repo-as-state → v1.3.0 hardened diagnostics (logcat mirror, fsync, heartbeat) (CHANGELOG.md).
- **On-host verification ladder (Nov 2026-11-08 → 11-12):** DIAG pack (DIAG00/DIAG1/DIAG2, beta-diagnostic-README.md) → six-rung ladder B0/B0b/B1/B2/B2b/B3 (docs/ladder-README.md) → bisect rungs C1/C2, D0/D1, E1/E2, F1/F2, K1, G0/G1/G2, N0, S1–S6, W1/W2, X1/X2 (STATE.md; docs/S-RUNG-README.md, W-RUNG-README.md, X-RUNG-README.md; docs/v1.3.1/*, docs/v1.3.1-R2, R3). Verdicts in §2 below.
- **Why it ended (evidence-based drivers, in order of documentation):**
  1. **Update fragility of the Manager route.** Morphe Manager pins the bundle signer on first install; the three sandbox-recycle key rotations (v1.1.2, v1.2.4, v1.2.5) made Manager refuse updates for installed sources until the durable key of v1.2.6 (CHANGELOG.md v1.2.6).
  2. **Expressiveness ceiling.** The requested features outgrew what bundle patches express: binary `assets/op/abp.manifest` surgery + 39-list defaults (v1.3.2 recon, evidence/adblock-defaults-recon.md), onboarding flow-machine control (q0o/cfn/m9k, STATE.md W2 post-mortem), later a full embedded VPN (new dex + native libs + manifest AXML, PATCH-NOTES-v8.md). The cross-analysis explicitly notes class deletion is "impossible in Morphe patches" (evidence/MODDED_APK_CROSS_ANALYSIS.md).
  3. **Pipeline control.** The D-rung proved full apktool rebuilds break install-time parsing, forcing byte-exact pipelines the team had to own end-to-end (docs/v1.3.1/BINARY-BUILD.md; git 3c1f1eff, b3627b80).
  4. **Release-process drag.** Each bundle release needed a fresh PAT, a host `build_bisect.sh` run and manual upload (docs/v1.3.1/HANDOFF.md); self-built universal APKs install in place over each other under one durable key (PATCH-NOTES-v10/11/12).

### Era B — "direct custom APK" (≈2026-11-13 → today)
- **Vehicle:** self-built **universal** APKs (`OperaBeta-104.0.5262.91143-custom-vN-universal.apk`), v2…v12, currently shipped. APKEditor split-merge (base + 39 splits) or splice onto a proven substrate, smali/binary patch layers, zipalign + apksigner v1+v2+v3. Two signing sub-lineages: **morphe.keystore** (v2…v8; "same key as v4-v7", PATCH-NOTES-v8.md) and **opera-custom-build.keystore** cert `62:C9:FA:…:6A:DF` (v9…v12, in-place upgrades, PATCH-NOTES-v10/11/12).
- **Content arc:** v5 22-patch set (defaults, VPN-Pro removal, rewards/eSIM removal, unlocks, splash) (git e1e01a87) → v6 22+3 patches (adblock CUSTOM mode + 39-list seed + zi3 pin, Minipay/Rewards/notification rows, nonews variant) (episodes/2026-11-14-v6-universal-build.md) → v7 11-patch set (lost to recycle; spec preserved in V8 doc §6) → v8 embedded system-wide free VPN (classes5.dex VpnService + hev-socks5-tunnel + opera-proxy `liboprx.so`) (PATCH-NOTES-v8.md; episodes/2026-11-15) → v9 structural rebuild (dex verbatim, no patches) → v10 v9 base + P1–P5 re-applied (work/recover/PATCH-NOTES-v10.md) → v11 full 40-patch set + patch-persistence mechanism + adblock asset pipeline (PATCH-NOTES-v11.md) → v12 crash fix + maintainer-direct blocklist updates, 44 patches (download/PATCH-NOTES-v12.md; git 29bb8d95).
- The X-rung device round was still pending when the custom era began; the custom era implemented the first-run skip differently (P1 `OperaApplication.a()Z → true`, skipping the whole onboarding machine) rather than returning to X2.

## 3. THE THREE MODERN CRASH ROOT CAUSES

### 3.1 v8 — `ClassNotFoundException: Lz4;` (dex re-merge lost classes)
- **Mechanism.** The v7/v8 pipeline rebuilt dexes through a baksmali → patch → smali reassembly → splice round-trip (v8 additionally added a new classes5.dex and re-spliced classes.dex/classes3.dex). That re-merge **lost classes** from the dexes. At first launch the ART runtime resolved a reference to class `Lz4;` (one of the base's 45,244 classes) and threw `ClassNotFoundException` — instant startup crash (work/v10scripts/README.md "Build lineage"; download context).
- **How it was proven.** Root-cause analysis shipped as `Opera_Beta_104_v8_Crash_Investigation.docx/.pdf` (hashed in work/recover/V9-V10-SHA256SUMS.txt; summarized by the v10 README). Crucially, **every host check had passed**: "ALL v8 markers OK; v4+v5+v6 regression OK" (episodes/2026-11-15; NEXT_SESSION.md) — the marker suite proved patch presence, not class-set integrity, so the defect was only observable on device.
- **The fix.** v9 was a ground-up structural rebuild: APKEditor merge of `base.apk` + `split_config.*` with the dex files copied **verbatim** (no smali round-trip on the base), and class-set equality verified against stock — 45,244/45,244 classes (work/v10scripts/README.md; work/recover/PATCH-NOTES-v10.md).
- **Guardrail now.** Class-set equality is a hard build step in every later pipeline ("smali reassembly + class-set equality vs stock", build_v11.sh/build_v12.sh), and `scripts/verify_v9.py` runs structural checks on the **signed APK**: all 45,244 classes, `Lz4;` present, manifest/services/kotlin_module preserved, arsc + 10 `.so` STORED (patches/PATCHES.md §Build pipeline guarantees; PATCH-NOTES-v12 verification list).

### 3.2 v9 — silent feature regression (patch layer never replayed)
- **Mechanism.** v9 fixed the structure but was built from scripts in which **the behavior patches were never re-applied** — "the patches lived only in a one-off build script that wasn't run" (work/recover/PATCH-NOTES-v11.md). v9 therefore shipped structurally perfect and behaviorally **stock** (first-run dialogs back, promos back). Not a crash: a silent regression that was only caught because the user knew what the build should do (work/v10scripts/README.md: "This was the regression you observed").
- **How it was proven.** Device observation of stock behavior on a build whose structural checks all passed, plus the v11 post-mortem attribution above.
- **The fix.** v10 re-applied the v7-era patch set (P1–P5) on the v9 base and — new discipline — verified the patches **inside the final signed APK** by re-disassembly (work/recover/PATCH-NOTES-v10.md).
- **Guardrail now.** The v11 "never lose a patch" persistence mechanism: `patches/` is the single declarative source of truth; `apply.py apply` **aborts the build** unless every anchor matches exactly; `apply.py verify` re-disassembles the produced dexes and re-checks **every patch postcondition** on the real output; `PATCHES.md` + `manifest.json` ledgers are committed to git and shipped in every release's patch bundle, so any shipped APK can be audited at any time (work/recover/PATCHES-v11-ledger.md; patches/PATCHES.md; work/v11bundle/build_v11.sh; sandbox-backup/v12/build_v12.sh).

### 3.3 v11 — corrupted `assets/op/abp.manifest` (ADBLOCK_CSS section), startup crash ~10 s white screen
- **Mechanism.** v11's `asset_pipeline.py` rebuilt `abp.manifest` with a parser that only understood the **first** section (ADBLOCK_URL, 44 entries). Removing `opera_fixes` + the tier allow-rules there was fine (44→41), but its "region-B excision" also deleted an `opera_fixes` entry found in the tail — which actually belonged to the **ADBLOCK_CSS section (42 entries)** — **without decrementing that section's u16 count**. The stream misaligned (`bad hash None` at `ADBLOCK_CSS[41]`); Opera's parser `z4o.l0` threw; `zi3.h()` caught it and fell back to an **empty manifest with a null base Uri**; the blocklist subsystem failed during engine init: white screen ~10 s, then crash — reproducing every launch (work/DIAGNOSIS-v12.md; download/PATCH-NOTES-v12.md).
- **How it was proven.** An exact re-implementation of Opera's parser (`scripts/abp_validate.py`): the v11 manifest fails at `ADBLOCK_CSS[41]`, the v9/v10 stock manifest parses cleanly (work/DIAGNOSIS-v12.md; work/abp_validate.out.json this host).
- **The fix.** v12 ships the **exact v9/v10 asset layer byte-identical** (stock `abp.manifest` + the 12 bundled list files) and removes the asset pipeline from the build entirely ("no abp pipeline, no manifest rebuild, no asset replacement", sandbox-backup/v12/build_v12.sh). No behavior is lost: the acceptable-ads allowlists and `opera_fixes` are simply *not selected* (PD.9 selects 39 lists that exclude them) — the proven v6/v7-lineage approach (download/PATCH-NOTES-v12.md).
- **Guardrail now.** "Assets untouched" policy: patched dexes are spliced into a stock-asset base (build_v12.sh step 5); the manifest is never rewritten. Should manifest surgery ever return, the v1.3.2 recon's discipline is the documented prerequisite: a rewriter validated by **byte-exact round-trip on stock bytes** before any mutation (`scripts/abp_manifest_patch.py`, evidence/adblock-defaults-recon.md), plus section-aware validation with exact-length framing.

## 4. THE OLDER CONVICTIONS (ladder era)

### 4.1 Legacy 02b — phantom sparse-switch (ART verifier rejection)
- **Mechanism.** The legacy patch wrote `const/4 v0,0; return v0` **over the `r65.l(Z)Z` method head**, splitting the following 2-unit `if-nez`; the orphaned bytes decoded as a **phantom sparse-switch** in dead code → ART verifier rejection → instant crash. This killed E1/E2 (and, unknowingly, F1/F2) (STATE.md conviction 1; git 3e453960).
- **Proof.** Byte forensics: G1 differs from crashing E2 by **exactly 2 bytes** in `r65.l`; F1 vs G2 differs by exactly the **3 bytes** of the method head (exposing the F-rung mislabel); a full structural walk reproduces the old defect precisely — the ART-style structural gate reads **1 failure on E2, 0 on C1** (STATE.md "Calibration"; S-RUNG-README.md; git 3e453960). K1 boots proved the new key wasn't the cause.
- **Fix & retirement.** The fix is a **1-byte operand flip** (`const/4 v0,0x1` → `const/4 v0,0x0` + `return`, original body left as dead code — no structural damage). The fixed form was proven **innocent** on device in S4 (boots). Legacy form retired; the structural gate (every method of every dex) became standard in `v131_binary_patch.py` (STATE.md; S-RUNG-README.md; BINARY-BUILD.md).

### 4.2 02a read-bypass — semantic deadlock at "Almost there!"
- **Mechanism.** Forcing the four `SettingsManager.i("eula_accepted.gdpr")` **reads** true skips the T&C leaf but never **writes** the pref and never runs the real accept path (`WelcomeActivity.X()`). The onboarding state machine then deadlocks at the `g49` "Almost there!" finalization gate (the fresh-install startup-dependency waiter `m9k`, fully mapped in the W2 post-mortem); relaunch renders black (STATE.md convictions 2 + W2 post-mortem).
- **Proof.** S1 (C1 + 02a only): T&C dialog gone, then permanent hang at "Almost there!", black screen on reopen — while S3–S6 and W1 boot. W2 later reproduced the identical stall with a *write*-correct 02a' because the waiter itself never resolves in the patched flow (STATE.md; W-RUNG-README.md; X-RUNG-README.md).
- **Fix & retirement.** The read-bypass is retired. v1.3.1-R2's **02a'** redirects the fresh-install branch to the real `X()` handler ("byte-for-byte the same state as pressing Next"), and R3's **02f** forces the `m9k` waiter's initial value to TRUE (first-run parity with steady-state) (docs/v1.3.1-R2/README.md; docs/v1.3.1-R3/README.md + patches/02f).

### 4.3 03a manifest component cut — startup resolution crash
- **Mechanism.** Removing the three VpnPro component declarations (`VpnProReceiver`, `VpnProQuickSettingsTileService`, `VpnProAppWidget`) from the binary manifest breaks a startup component resolution → crash before the first frame (STATE.md conviction 3; evidence/vpn-pro-recon.md lists the components).
- **Proof.** S2 (C1 + 03a only): instant crash (STATE.md).
- **Retirement decision.** Manifest surgery is **retired**; the declarations stay (they are invisible unless the user adds the tile/widget manually) and VPN Pro removal moved to code/resource level (03b/03c, later 03d `nt8` emptied). v8 later reaffirmed the boundary: manifest **additions/edits** (VPN service labels, extractNativeLibs) were fine — the conviction applies to removals of declared components (V8-VPN-DESIGN §2 "adding, NOT removing — the S2/03a conviction only applies to removals").

### 4.4 The innocent findings (02b-fixed / 02c / 03b) — why they were inert
- **S4** (02b fixed 1-byte form): boots → innocent; but the data-collection (CMP) onboarding dialog still showed — the standalone `r65` re-prompt gate is not the first-run dialog (STATE.md; W-RUNG-README.md).
- **S5** (02c `mm6.e` → false): boots → innocent; the default-browser **onboarding** dialog still showed (the startpage re-prompt gate is a different surface) (STATE.md).
- **S6** (03b `wdn.a` → false): boots → innocent; the user-visible "VPN Pro button + dialog" is the **omnibox feature-suggestion chip** (`nt8` enum: ESIM + VPN_PRO, `ofa://ui/upgrade?source=feature_suggestion`), not wdn.a-gated — hence still visible in S6 (STATE.md conviction 6).
- **S3** (03c): boots → innocent and the **only patch with a visible effect** (part of a VPN Pro notice blanked) (STATE.md; W-RUNG-README.md).
- **Synthesis (recorded):** the dialogs the user wanted gone are steps of the `q0o.g()` onboarding machine (`m0o`: FEATURES_ONBOARDING[DEFAULT_BROWSER, NOTIFICATIONS, CMP_INTRO], CONSENT, PERSONALIZATION) gated by `cfn` lambda cases — which is what W2's 02d/02e kill, keeping PERSONALIZATION (STATE.md conviction 4; docs/v1.3.1-R2/README.md).
- **Exonerations:** the binary patcher's zip-rewrite path was exonerated de facto (S3–S6 all pass through it and boot); the null-patch control N0 became moot and was never flashed (STATE.md convictions 5; S-RUNG-README.md). The signing key was exonerated by K1. The Pangle-split merge was exonerated by B0b (STATE.md).

## 5. WHAT WORKED (process wins, each with its motivating incident)

1. **Assert-before-write byte patching + structural gate** — every edit first verifies expected original bytes (method heads, invoke+move-result shapes, manifest component names, string-pool footprints), exits non-zero on mismatch; DEX adler32+SHA-1 recomputed; ART-style structural walk over every method of every dex. *Motivated by:* the legacy-02b phantom sparse-switch (E/F/G crashes) and the D-rung parse failures. (docs/v1.3.1/BINARY-BUILD.md; git 3e453960; STATE.md Calibration.)
2. **Byte-diff vs a reference build as a release gate** — CRC/entry-level diff vs substrate proving the delta is exactly the intended patch bytes. *Motivated by:* the F1/F2 mislabel (only a byte-diff against G exposed that F shipped legacy 02b). (S-RUNG-README.md; BINARY-BUILD.md `validate_build.py`.)
3. **Class-set equality vs stock** after any smali reassembly (45,244/45,244; `Lz4;` present). *Motivated by:* v8 `ClassNotFoundException: Lz4;`. (work/v10scripts/README.md; build_v11.sh/build_v12.sh; patches/PATCHES.md guarantee 2.)
4. **Verification inside the final signed artifact** — re-disassemble the shipped APK's dexes and re-check every patch (opcode level); markers re-verified inside signed APKs (e.g. all 9 X-rung markers, 44/44 v12 patches). *Motivated by:* v9 silent loss + F1/F2. (PATCH-NOTES-v10/11/12; STATE.md X-rung verification.)
5. **Patch persistence (patches/ + apply.py apply/verify + PATCHES.md + manifest.json, committed and shipped).** *Motivated by:* v9. (work/recover/PATCHES-v11-ledger.md; patches/PATCHES.md.)
6. **Single-patch bisect on a fixed substrate, with deliberate controls** — S-rung one-patch-per-build on the booting C1 substrate; N0 null-patch control; G0 deliberate forensic reproduction. *Motivated by:* E/F/G attribution chaos. (S-RUNG-README.md.)
7. **Durable signing key + repo-as-state + release-based sandbox backups** — one permanent key from v1.2.6 (stored as the `morphe-signing.key` release asset); `STATE.md` carries the investigation memory; big binaries (inputs, keystores, rung APKs, SHA256SUMS) live on the `sandbox-storage` GitHub release and are hash-verified after every recycle; custom builds pin one cert across v9–v12 for in-place upgrades. *Motivated by:* three key rotations (v1.1.2, v1.2.4, v1.2.5) and the 2026-11-10/11-12/11-15 wipes. (CHANGELOG.md v1.2.6; STATE.md header; HANDOFF.md; ADRs 0001–0004; lessons.md.)
8. **Event-driven backups (ADR 0004)** — backup.sh is the mandatory last step of every execution plan; the reply goes out only after it returns. *Motivated by:* v7 scripts/APK lost by skipping it. (episodes/2026-11-12-event-driven-backup-policy.md; V8-VPN-DESIGN §4; lessons.md.)
9. **Self-reporting startup diagnostics** (diag.mpe: breadcrumbs, logcat mirror before file write, fsync per line, 500 ms heartbeat, launcher-activity injection, cert self-report, chained crash handler). *Motivated by:* v1.2.0–v1.2.3 crashes with zero device evidence, then the Test A empty-log incident. (CHANGELOG.md v1.2.4, v1.3.0.)
10. **Local end-to-end reproduction before shipping** — v1.2.4 reproduced the whole Morphe pipeline on real inputs and audited the output byte-by-byte, exonerating the pipeline and narrowing the killer to content (the spoof). *Motivated by:* the v1.2.0–v1.2.3 unknown crash. (CHANGELOG.md v1.2.4.)
11. **Framework-reference audit of generated dex** (`tools/AuditExtDex.java` — every `android/*` reference resolved against the real framework; build fails otherwise). *Motivated by:* the v1.2.0 stub-shape crash (`ExceptionInInitializerError`). (CHANGELOG.md v1.2.1; evidence/ANALYSIS.md §6.3.)
12. **The hybrid smali pipeline** (decode the single target dex → edit → rebuild → byte-preserving splice → binary-patch → sign) that avoids full-apktool resource re-encoding entirely. *Motivated by:* D0/D1 parse failures. (docs/v1.3.1-R2/README.md; BINARY-BUILD.md.)
13. **Fail-loud patch tooling with cumulative planning** — v8's 21 patches fail-loud with post-sign verification; the v6/v8 gotchas (marker-after-deleted-block false-positive, label renumbering, same-file patches must chain) are recorded and engineered against in apply.py's exact-match-count + postcondition model. *Motivated by:* v6's silently-skipped N1/C7 and v8's T8a/T8b clobbering. (PATCH-NOTES-v8.md; V8-VPN-DESIGN §6 "v7 key findings"; episodes/2026-11-14, 2026-11-15.)

## 6. WHAT FAILED (process failures + lessons)

1. **Sandbox recycles losing keys, artifacts, history.** Three bundle-key rotations (v1.1.2, v1.2.4, v1.2.5) each broke Manager updates for installed sources; the 2026-11-10 wipe destroyed the v1.3.0 artifacts before the release was cut; recycles before W-rung and #3 (2026-11-12) destroyed toolchains/work trees; the 2026-11-15 recycle destroyed v7's scripts and APK (only the spec survived in a doc). **Lesson:** nothing lives only in the sandbox. **Mechanism now:** durable key (v1.2.6), repo-as-state, `sandbox-storage` release + SHA256SUMS re-verification after each recycle, event-driven backups (ADR 0004). (CHANGELOG.md; STATE.md header; HANDOFF.md; V8-VPN-DESIGN §4; lessons.md.) — *Mechanism exists.*
2. **Silent patch loss (v9).** Patches in a one-off script that wasn't re-run; all structural checks green; stock behavior shipped. **Lesson:** the patch layer must be declarative, enforced, and re-verified on the shipped artifact. **Mechanism now:** apply.py apply/verify + ledgers (v11). *Exists.*
3. **Over-eager asset rewriting (v11).** A single-section parser mutated a 4-section binary manifest and corrupted ADBLOCK_CSS. **Lesson:** byte-exact round-trip proof before mutation; prefer "don't rewrite, just don't select". **Mechanism now:** v12 ships stock assets; abp_validate.py exists; the v1.3.2 rewriter's round-trip test is the documented template. *Exists.*
4. **Mislabeled builds (F1/F2).** Two builds were labeled "fixed v1.3.1" but shipped the legacy 02b; an entire device round produced no information. **Lesson:** label ≠ content; only a byte-diff against a reference is content truth. **Mechanism now:** entry-diff/CRC-diff vs substrate + in-APK marker verification became mandatory from the S-rung on. *Exists.*
5. **Lost diagnostics (Test A).** The v1.2.4 diagnostics build produced an empty 0-byte `vogelkop-diag.log` with no breadcrumbs when the engine died ~5 s in (buffered writes + native abort). **Lesson:** a diagnostic layer must survive the crash it is diagnosing. **Mechanism now:** v1.3.0 hardened diagnostics (logcat mirror first, fsync per line, heartbeat, second injection point). *Exists.* (CHANGELOG.md v1.3.0.)
6. **Full-apktool rebuild lineage (D0/D1).** Host checks passed; the device installer rejected the package ("There was a problem parsing the package"; isSplitRequired residue). **Lesson:** never re-encode resources/manifest. **Mechanism now:** binary-only edits on device-proven substrates (E-rung) and the single-dex hybrid splice. *Exists.* (git b3627b80; BINARY-BUILD.md.)
7. **False-positive marker checks (v6-era).** N1 (bo3) "always present" because the marker was the code *after* the deleted block; C7 used a wrong anchor and was never applied in v5/v6; v7's d8d observer re-showed N2 rows. **Lesson:** verify postconditions, not presence; exact match counts. **Mechanism now:** apply.py verify re-checks postconditions on re-disassembled output; RS8 (v8) finally fixed the Rewards row properly. *Exists.*
8. **Same-file patch clobbering (v8).** T8a was silently lost to T8b for two builds because patches were planned against the original text instead of cumulatively. **Lesson:** plan patches against the chained, edited text. **Mechanism now:** recorded as a key lesson; fail-loud apply model catches mismatches. *Partially procedural.* (NEXT_SESSION.md; episodes/2026-11-15.)
9. **Controls that never returned data (G0 "not reported", N0 "not flashed", B0/B2/B2b/B3 verdicts lost with the pre-reconstruct STATE).** Attribution stayed partly inferential. **Lesson:** record every verdict, even for controls; the reconstructed STATE.md exists precisely because §1–§10 of the original were lost. *Mechanism: repo-as-state + episodes.* (STATE.md; git edbe9034.)
10. **Era-A heavy release path.** PAT re-issue → clone → host build → boot test → upload → revoke (HANDOFF.md); Manager's signer pinning made every key event a user-facing trust prompt. **Lesson (superseding):** self-built APKs + one pinned cert. *Replaced by era B.*

## 7. RECURRENCE ANALYSIS — the single pattern

**Every incident is a state/verification gap between two build steps: step *N+1* consumed step *N*'s output on trust, with no end-to-end postcondition tying the final artifact back to the intended semantics.**

- Legacy 02b: bytes written over a method head with no structural verification of the surrounding code → ART verifier (STATE.md).
- F1/F2: labeling/assembly trusted over bytes → wrong build shipped (S-RUNG-README.md).
- v8: marker verification (patches present) consumed the re-merged dexes without a class-set postcondition → `ClassNotFoundException: Lz4;` (work/v10scripts/README.md).
- v9: structural verification (classes intact) consumed a build whose patch step had not run → stock behavior (PATCH-NOTES-v11.md).
- v11: dex-side verification was complete, but the **asset** step had no section-aware/round-trip validation → corrupted `abp.manifest` (DIAGNOSIS-v12.md).
- (Era A mirrors it: v1.2.0 extension compiled against stubs with no framework-reference audit; Test A's diag trail buffered with no fsync.)

**How the v12-era pipeline closes the loop:** the chain is now *apply → assemble → equality → verify → splice → sign → structural-verify*, with an explicit check at every seam:
1. `apply.py apply` — anchors must match exactly N times or the build aborts (no silent skips);
2. smali reassembly + **class-set equality vs stock** (v8 seam);
3. `apply.py verify` — **postconditions re-checked on re-disassembled output** (v9 seam);
4. splice into a **stock-asset base** — assets byte-identical to the proven v9/v10 layer (v11 seam);
5. zipalign + sign with the **pinned v9/v10 certificate** (in-place upgrades, signer drift impossible);
6. `verify_v9.py` structural checks on the signed APK (45,244 classes, `Lz4;`, manifest, arsc/.so STORED);
7. the regenerated `PATCHES.md` + `manifest.json` ledger committed and shipped with the release (auditability forever).
(sandbox-backup/v12/build_v12.sh steps 1–8; patches/PATCHES.md guarantees 1–6; download/PATCH-NOTES-v12.md verification list.)

The remaining unverified seam is the **device**: every guard above is host-side; the device verdict still arrives only by a human flashing the APK — exactly the step still pending for v12.
